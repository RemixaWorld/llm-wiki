# Harnessing GPT-4o’s Vision for Advanced Search: Building Image Embeddings with Qdrant

This article provides a high-level overview of how to leverage OpenAI’s new GPT-4o Omni model for advanced vision applications. Throughout this piece, we will develop an application designed to analyze images, extract pertinent details, and index these in Qdrant for sophisticated vector-based searching.


### The Architecture

The architecture depicted in the image illustrates a multi-modal search application that leverages both image embeddings and vision model responses, using `Qdrant`

as the vector database for storage and retrieval.

The process begins with an input image that needs to be processed and indexed. This input image is first passed to an embedding model, specifically the `CLIP`

(Contrastive Language–Image Pre-training) model with the `ViT-B-32`

variant. The CLIP model generates an image embedding, which is a high-dimensional vector representation of the image’s visual features.

Simultaneously, the input image is also processed by a vision model, identified as `GPT-4o`

in the diagram. This model analyzes the image and produces a JSON response that might include various attributes, tags, or descriptions derived from the image.

The image embedding and the JSON response are then combined into a single data point. This combined data point includes both the high-dimensional vector from the embedding and the structured information from the JSON response. This comprehensive data point is then stored in `Qdrant`

, a vector database designed to handle high-dimensional vectors and associated metadata. `Qdrant`

facilitates efficient storage, indexing, and retrieval of vector data, enabling the search application to perform similarity searches and other vector-based queries.

`from llama_index.multi_modal_llms.openai import OpenAIMultiModal`

from llama_index.core import SimpleDirectoryReader

from dotenv import load_dotenv, find_dotenv

from qdrant_client import QdrantClient, models

from qdrant_client.http.models import PointStruct, VectorParams, Distance

from sentence_transformers import SentenceTransformer

from PIL import Image

import os

import json


IMAGE_DIR = './tesla_images'

_ = load_dotenv(find_dotenv())


gpt_4o = OpenAIMultiModal(model="gpt-4o", max_new_tokens=1500)


client = QdrantClient(host="localhost", port=6333)

# need to create the collection only the first time

client.create_collection(collection_name='tesla_details',

vectors_config=VectorParams(size=512, distance=Distance.COSINE))


image_embedding_model = SentenceTransformer("clip-ViT-B-32")

images = os.listdir(IMAGE_DIR)



def clean_and_convert_to_json(response_str):

# Remove the backticks and the "json" keyword if present

clean_str = response_str.replace("```json", "").replace("```", "").strip()


# Convert the cleaned string to a JSON object

json_obj = json.loads(clean_str)


return json_obj



for index, image in enumerate(images):

path = os.path.join(IMAGE_DIR, image)

with Image.open(path) as img:

embedding = image_embedding_model.encode(img).tolist()

# print(path)

document = SimpleDirectoryReader(input_files=[path]).load_data()

response_2 = gpt_4o.complete(

prompt="get price, Liters of Cargo, Range, Acceleration, Drive, Seating, "

"Wheels, Weight, Top Speed of the given image. No additional information is needed. "

"I need the information as JSON object and that JSON should be a valid JSON object "

"with out `None` fields",

image_documents=document,

)

response = clean_and_convert_to_json(response_2.text)

# print(response)

points = [

PointStruct(id=1, vector=embedding, payload=response),

]

result = client.upsert(collection_name="tesla_details", points=points)

print(result)

The script imports necessary libraries and modules. `OpenAIMultiModal`

from `llama_index.multi_modal_llms.openai`

is used to leverage the GPT-4 Omni model for processing images and text. `SimpleDirectoryReader`

from `llama_index.core`

reads files from directories. The `dotenv`

library manages environment variables, which is essential for hiding sensitive information like API keys or database credentials. The `QdrantClient`

and its associated classes (`PointStruct`

, `VectorParams`

, `Distance`

) are used to interact with the Qdrant vector database, facilitating operations like creating collections and inserting data. `SentenceTransformer`

is utilized to generate embeddings from images, and `PIL.Image`

handles image file operations.

The script defines `IMAGE_DIR`

as the directory containing the images to be processed. It then loads environment variables from a `.env`

file which might contain configuration settings or credentials. An instance of `OpenAIMultiModal`

is configured with the model identifier for GPT-4 Omni and a token limit for generated responses. The `QdrantClient`

is set up to connect to a local Qdrant server.

A new collection named `tesla_details`

is created in Qdrant (only necessary the first time the script runs), configured to store 512-dimensional vectors using cosine distance for similarity measurements. This setup is suitable for applications where similarity is measured in terms of angle rather than magnitude, common in text and image embeddings.

The `SentenceTransformer`

library is employed to load the "clip-ViT-B-32" model, which is pivotal for generating embeddings from images. This model is based on CLIP (Contrastive Language–Image Pre-training) technology developed by OpenAI, which has been fine-tuned to understand a wide range of visual concepts in a manner that correlates well with textual descriptions. The "ViT-B-32" in the model's name refers to the "Vision Transformer" architecture with a "Base" size, using patches of size 32x32 pixels. This model excels in creating high-dimensional vector representations of images, which capture the semantic content of the visual input.

In the script, after each image is opened and processed by PIL, the `SentenceTransformer`

using the "clip-ViT-B-32" model generates an embedding for the image. This embedding is then transformed into a list format, making it suitable for storage in the Qdrant vector database alongside the extracted information from the GPT-4 Omni model. These embeddings play a crucial role in enabling the vector search capabilities of the Qdrant database, as they represent the images in a form that can be efficiently indexed and queried based on similarity.

The response from GPT-4 Omni is cleaned and converted to a JSON object using the `clean_and_convert_to_json`

function, which removes unnecessary formatting and ensures the string is valid JSON. This JSON object, along with the image's embedding, is used to create a `PointStruct`

(a structure suitable for insertion into Qdrant). Each point (consisting of an embedding and its associated JSON payload) is then upserted into the `tesla_details`

collection in Qdrant.

Finally, the result of each upsert operation is printed, which likely includes confirmation of the insertion or any errors encountered. This script effectively combines cutting-edge tools for processing and storing complex multimodal data, facilitating advanced search and retrieval capabilities based on image content and extracted metadata.
