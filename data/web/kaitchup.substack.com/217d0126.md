Ollama lets you deploy large language models (LLMs) locally and serve them online. It provides a command-line interface (CLI) to download, manage, and use models like Llama 3.2, Mistral, and Qwen2.5.

It is a wrapper for llama.cpp, designed to be much more user-friendly. You only need a basic configuration file to run a model or a LoRA adapter. It can also integrate with LangChain to create more complex applications like Retrieval-Augmented Generation (RAG) systems.

This article explains how to set up Ollama and how to use it. It shows **how to start a custom model with a LoRA adapter** , serve it as a chatbot, and examples of how to interact with a PDF using a RAG system with Ollama and LangChain. The code examples in this tutorial use Llama 3.2.

## Ollama: How Does It Work?

Ollama provides a library of curated models that you can quickly download and use with just two command-line commands. Its GitHub repository has a clear and detailed documentation to help you get started.

  * GitHub: [ollama/ollama](<https://github.com/ollama/ollama>)

In this article, we will focus on using our own models and adapters instead of the pre-curated models maintained by Ollama.

To begin, install Ollama (the example below is for Linux; refer to the GitHub page for instructions for other operating systems):
    
    
    curl -fsSL https://ollama.com/install.sh | sh

This will install all the dependencies. You can now start the Ollama process. I recommend starting it in your terminal rather than in a notebook to facilitate debugging:
    
    
    ollama serve &

I also recommend installing the following for much faster downloads:
    
    
    pip install huggingface_hub[hf_transfer]

We are going to see how to use models locally. For testing, let’s download a model, for instance, Llama 3.2 instruct. 

Set your HF token:
    
    
    from huggingface_hub import login
    login(token='hf_yourtoken')

Then, download the model:
    
    
    HF_HUB_ENABLE_HF_TRANSFER=1 huggingface-cli download "meta-llama/Llama-3.2-3B-Instruct"  --local-dir llama-3.2-instruct-local

 _Note: HF_HUB_ENABLE_HF_TRANSFER=1 exploits the package we installed above for a much faster download._

Ollama generates a runnable model using a "Modelfile," a configuration file written in a straightforward, specialized syntax. Below is an example of a Modelfile configured for a local Llama 3.2 3B Instruct model:
    
    
    FROM llama-3.2-instruct-local
    PARAMETER temperature 0.9
    PARAMETER num_ctx 1024

  * FROM: The path (relative or absolute) to the local directory containing the model.

  * PARAMETER: Some inference hyperparameters. You can find [the list of supported hyperparameters/arguments here](<https://github.com/ollama/ollama/blob/main/docs/modelfile.md#valid-parameters-and-values>).

Save this configuration in a file. I named it “Modelfile-llama3.2-instruct-local”.

Now, we can create the runnable model using this configuration:
    
    
    ollama create llama3.2-instruct-local -f Modelfile-llama3.2-instruct-local

This may take a few minutes. Once finished, you can run your model with Ollama:
    
    
    ollama run llama3.2-instruct-local

I recommend running this command in another terminal also to facilitate debugging.

You can query the model with Ollama’s chat API, using curl on Linux:
    
    
    curl http://localhost:11434/api/chat -d '{
      "model": "llama3.2-instruct-local",
      "messages": [
        { "role": "user", "content": "why is the sky blue?" }
      ],
      "stream": false
    }'

  * **model** : This should match the model name you specified when starting with `ollama run`.

  * **messages** : Follows the typical chat format, including `role` and `content` fields.

  * **stream** : Set to `False` to receive the complete answer only after the generation is finished.

## Making a Custom Modelfile with LoRA Adapter

You can tell Ollama to load an adapter on top of the model in the Modelfile by adding the instruction “ADAPTER”. For instance, let’s take this adapter that I briefly fine-tuned for Llama 3.2 3B Instruct:

  * [kaitchup/Llama-3.2-3B-Instruct-UltraChat](<https://huggingface.co/kaitchup/Llama-3.2-3B-Instruct-UltraChat>)

 _Note: This adapter is undertrained. I use it only for demonstration purposes._

As for the base model, we have to download this adapter to have it locally:
    
    
    HF_HUB_ENABLE_HF_TRANSFER=1 huggingface-cli download "kaitchup/Llama-3.2-3B-Instruct-UltraChat"  --local-dir Llama-3.2-3B-Instruct-UltraChat

Then, create a new configuration file pointing to this adapter:
    
    
    FROM llama-3.2-instruct-local
    ADAPTER Llama-3.2-3B-Instruct-UltraChat
    PARAMETER temperature 0.9
    PARAMETER num_ctx 1024

The remaining steps, creating the runnable model, launching it, and querying the model, are all the same as if we didn’t have the adapter.

## Example of Ollaam Modelfile with LoRA Adapter for Local RAG

Ollama provides many examples of AI applications in this directory:

  * GitHub: [Ollama examples](<https://github.com/ollama/ollama/tree/main/examples>)

They are all very simple to run. For instance, let’s take this example using Ollama and LangChain to chat with a PDF using a [RAG approach](<https://kaitchup.substack.com/p/rag-for-mistral-7b-instruct-with>):

  * [LangChain Document QA](<https://github.com/ollama/ollama/tree/main/examples/langchain-python-rag-document>)

If we look at the code, it first loads the PDF and chunks it:
    
    
    loader = OnlinePDFLoader("https://d18rn0p25nwr6d.cloudfront.net/CIK-0001813756/975b3e9b-268e-4798-a9e4-2a9a7c92dc10.pdf")
    data = loader.load()
    
    from langchain.text_splitter import RecursiveCharacterTextSplitter
    text_splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=0)
    all_splits = text_splitter.split_documents(data)

The chunks contain 500 words each. Given the user query (question), the relevant chunks will be retrieved and added as context in this prompt:
    
    
        # Prompt
        template = """Use the following pieces of context to answer the question at the end.
        If you don't know the answer, just say that you don't know, don't try to make up an answer.
        Use three sentences maximum and keep the answer as concise as possible.
        {context}
        Question: {question}
        Helpful Answer:"""

LangChain will create this prompt. Then, Ollama is called to complete it with an answer:
    
    
        QA_CHAIN_PROMPT = PromptTemplate(
            input_variables=["context", "question"],
            template=template,
        )
    
        llm = Ollama(model="llama3.2", callback_manager=CallbackManager([StreamingStdOutCallbackHandler()]))
        qa_chain = RetrievalQA.from_chain_type(
            llm,
            retriever=vectorstore.as_retriever(),
            chain_type_kwargs={"prompt": QA_CHAIN_PROMPT},
        )
    
        result = qa_chain({"query": query})

Instead of “llama3.2”, you can call your own model.

In the same examples directory, you will find slightly more advanced RAG applications using Ollama such as a [“private GPT”](<https://github.com/ollama/ollama/tree/main/examples/langchain-python-rag-privategpt>) which indexes and uses many more types of documents as context.

## Conclusion

Ollama is a convenient framework for deploying your own model. It has a user-friendly interface that simplifies tasks compared to alternatives like [vLLM](<https://kaitchup.substack.com/p/vllm-serve-fast-mistral-7b-and-llama>) or TGI. However, it is less flexible than these frameworks. To me, Ollama is for inference what [Axolotl is for fine-tuning](<https://kaitchup.substack.com/p/simple-qlora-fine-tuning-with-axolotl>): less flexible tools but that will cover most use cases.

It's important to note that Ollama is primarily a wrapper for llama.cpp. 

If you're already familiar with llama.cpp and comfortable using it despite its limited documentation, switching to Ollama might not be beneficial. Ollama has fewer features than llama.cpp and relies on llama.cpp for model support. This means it will not support new models unless llama.cpp supports them first.

Additionally, I’ve included examples of Ollama usage in the Qwen2.5 and Llama 3.1/3.2 toolboxes.
