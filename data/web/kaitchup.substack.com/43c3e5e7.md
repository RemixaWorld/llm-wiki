Most large language models (LLMs) are far too large to fine-tune on consumer hardware. For example, fine-tuning a 70-billion-parameter model typically requires a multi-GPU node, such as 8 NVIDIA H100s, an extremely costly setup that can run into hundreds of thousands of dollars. In practice, this means relying on cloud computing, where costs can still escalate quickly to unaffordable levels.

With QLoRA ([Dettmers et al., 2023](<https://arxiv.org/pdf/2305.14314.pdf>)), you could do it with only one GPU, instead of 8.

In this article, we won’t be fine-tuning a massive 70B model, but rather a smaller one that would still require expensive GPUs, unless we use a parameter-efficient fine-tuning method like QLoRA. I’ll introduce QLoRA, explain how it works, and demonstrate how to use it to fine-tune a 4-billion-parameter Qwen3 base model directly on your GPU.

_Note: I ran all the code in this post on an RTX 4090 from[RunPod (referral link)](<https://runpod.io?ref=1ip9lvtj>), but you can achieve the same results using a free Google Colab instance. If your GPU has less memory, you can simply choose a smaller LLM._

### QLoRA: Quantized LLMs with Low-Rank Adapters

In June 2021, [Hu et al. (2021)](<https://arxiv.org/abs/2106.09685>) introduced low-rank adapters (LoRA) for LLMs.

LoRA adds a small set of trainable parameters, known as adapters, to each layer of an LLM while freezing all original model parameters. During fine-tuning, only these adapter parameters are updated, which greatly reduces memory usage.  
In contrast, full fine-tuning (without LoRA or QLoRA) updates every parameter of the model, requiring substantially more memory, particularly because the optimizer states store two extra values for each parameter.

QLoRA builds on LoRA and makes fine-tuning even more memory-efficient by introducing three key techniques:

  1. **4-bit NormalFloat (NF4) quantization**  
Improves upon quantile quantization by ensuring each quantization bin contains an equal number of values. This prevents issues with outlier values and reduces computational errors.

  2. **Double quantization**  
Quantizes not only the model weights but also the quantization constants themselves, achieving further memory savings.

  3. **Unified memory paging**  
Leverages NVIDIA’s Unified Memory to automatically move data between CPU and GPU memory pages. This prevents GPU out-of-memory errors during training.

Together, these optimizations dramatically reduce memory consumption while achieving performance close to standard full fine-tuning.

Although QLoRA was introduced with NF4 quantization, it is best understood as a framework independent of a specific quantization format. For example, it can be done with GPTQ quantization (which uses a different data type and skips double quantization) or used without optimizer paging. ### Fine-tuning a GPT model with QLoRA

All the following code can run on a free instance of Google Colab. You can try it using the notebook #2 that you will find here:

#### **Hardware Requirements for QLoRA with a 4B Model**

  * **GPU** :

    * Works on GPUs with as little as 8 GB VRAM (e.g., NVIDIA RTX 3050).

    * Larger GPUs allow for larger models. For example, with 24 GB VRAM, you can fine-tune models up to ~20B parameters (e.g., GPT-OSS 20B).

  * CPU RAM:

    * Minimum: ~6 GB, though actual needs depend on dataset size. Larger datasets require more RAM. Most modern computers already have sufficient RAM.

    * If using optimizer paging to offload GPU memory usage, ensure enough CPU RAM to store optimizer states (typically small with QLoRA).

  * Storage:

    * Estimate model size in GB as:
          
          Model size (in billions of parameters) × 2 ≈ Storage in GB

    * For example, a 4B model takes ~8 GB.

    * Also, allow space for your dataset and training checkpoints (checkpoints are typically a few dozen MB each).

If your machine doesn’t meet these specs, you can run QLoRA on the free Google Colab instance as an alternative.

#### Software requirements for QLoRA:

We need CUDA. Make sure it is installed on your machine.

We will also need to install all the dependencies:

  * **PyTorch:** Better to get the latest version.

  * **bitsandbytes** : A library that contains all we need to quantize an LLM.

  * **Hugging Face Transformers, TRL, and Accelerate** : These are standard libraries that are used to train models from the Hugging Face Hub efficiently.

  * **PEFT** : A library that provides the implementations for various methods to only fine-tune a small number of (extra) model parameters. We need it for LoRA.

  * **Datasets** : We will only use it to get a dataset for fine-tuning. Of course, you can provide instead your own dataset.

I also recommend installing [FlashAttention (flash_attn) to speed up fine-tuning and reduce memory consumption](<https://kaitchup.substack.com/p/use-flashattention-2-for-faster-fine>).

We can get all of them with PIP:
    
    
    pip install torch torchvision
    pip install -q -U transformers bitsandbytes peft accelerate datasets trl flash_attn

#### Loading and Quantization of a GPT Model

We need the following imports to load and quantize an LLM. I also initialize several variables that will be useful later.
    
    
    import torch, os, multiprocessing
    from datasets import load_dataset
    from peft import LoraConfig, prepare_model_for_kbit_training
    from transformers import (
        AutoModelForCausalLM,
        AutoTokenizer,
        BitsAndBytesConfig,
        set_seed
    )
    from trl import SFTTrainer, SFTConfig
    
    set_seed(1234) #Useful only for reproducibility
    
    compute_dtype = torch.bfloat16
    attn_implementation = 'flash_attention_2'
    model_name = "Qwen/Qwen3-4B-Base"
    batch_size = 1
    gradient_accumulation_steps = 16
    output_dir = "./QLoRA/"

We will fine-tune [Qwen3-4B-Base](<https://huggingface.co/Qwen/Qwen3-4B-Base>) pre-trained by the Qwen team. This is a model with 4 billion parameters. _Note: Qwen3-4B-Base_ _has a permissive license (Apache 2.0) that allows commercial use._

We can get this model and its tokenizer from Hugging Face Hub. It is automatically downloaded when running the following code, which loads and quantizes the model:
    
    
    bnb_config = BitsAndBytesConfig(
            load_in_4bit=True,
            bnb_4bit_quant_type="nf4",
            bnb_4bit_compute_dtype=compute_dtype,
            bnb_4bit_use_double_quant=True,
    )
    model = AutoModelForCausalLM.from_pretrained(
              model_name, quantization_config=bnb_config, device_map={"": 0}, attn_implementation=attn_implementation
    )

For faster and better training stability, I recommend using FlashAttention and the bfloat16 data type for the model’s parameters instead of float16. You can test whether your GPU is compatible with bfloat16 and FlashAttention as follows:
    
    
    major_version, minor_version = torch.cuda.get_device_capability()
    if major_version >= 8:
      !pip install flash-attn
      torch_dtype = torch.bfloat16
      attn_implementation='flash_attention_2'
      print("Your GPU is compatible with FlashAttention and bfloat16.")
    else:
      torch_dtype = torch.float16
      attn_implementation='eager'
      print("Your GPU is not compatible with FlashAttention and bfloat16.")

The `BitsAndBytesConfig `is what defines the quantization configuration:
    
    
    quant_config = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_use_double_quant=True,
        bnb_4bit_quant_type="nf4",
        bnb_4bit_compute_dtype=torch_dtype
    )

  * `load_in_4bit`: The model will be loaded in memory with 4-bit precision.

  * `bnb_4bit_use_double_quant`: We will do the double quantization proposed by the QLoRA paper.

  * `bnb_4bit_quant_type`: This is the type of quantization. “nf4” stands for 4-bit NormalFloat.

  * `bnb_4bit_compute_dtype`: While we load and store the model in 4-bit, we will partially dequantize it when needed, and the computations will be with a 16-bit precision (bfloat16 or float16, depending on your GPU).

Then, we [enable gradient checkpointing](<https://kaitchup.substack.com/p/gradient-checkpointing-llms>) and prepare the model for training:
    
    
    model = prepare_model_for_kbit_training(model, gradient_checkpointing_kwargs={'use_reentrant':True})

#### Preprocessing the model for LoRA

This is where we use PEFT. We prepare the model for LoRA, adding trainable adapters for each linear layer.
    
    
    peft_config = LoraConfig(
            lora_alpha=16,
            lora_dropout=0.05,
            r=16,
            bias="none",
            task_type="CAUSAL_LM",
            target_modules= ['k_proj', 'q_proj', 'v_proj', 'o_proj', "gate_proj", "down_proj", "up_proj"]
    )

In LoraConfig, you can play with the rank (r), alpha, and dropout to obtain better results on your task. You can find more options and details in the [PEFT repository](<https://github.com/huggingface/peft/tree/main>). To know which modules you can target, you can print the model:
    
    
    print(model)

It prints:
    
    
    Qwen3ForCausalLM(
      (model): Qwen3Model(
        (embed_tokens): Embedding(151936, 2560)
        (layers): ModuleList(
          (0-35): 36 x Qwen3DecoderLayer(
            (self_attn): Qwen3Attention(
              (q_proj): Linear4bit(in_features=2560, out_features=4096, bias=False)
              (k_proj): Linear4bit(in_features=2560, out_features=1024, bias=False)
              (v_proj): Linear4bit(in_features=2560, out_features=1024, bias=False)
              (o_proj): Linear4bit(in_features=4096, out_features=2560, bias=False)
              (q_norm): Qwen3RMSNorm((128,), eps=1e-06)
              (k_norm): Qwen3RMSNorm((128,), eps=1e-06)
            )
            (mlp): Qwen3MLP(
              (gate_proj): Linear4bit(in_features=2560, out_features=9728, bias=False)
              (up_proj): Linear4bit(in_features=2560, out_features=9728, bias=False)
              (down_proj): Linear4bit(in_features=9728, out_features=2560, bias=False)
              (act_fn): SiLU()
            )
            (input_layernorm): Qwen3RMSNorm((2560,), eps=1e-06)
            (post_attention_layernorm): Qwen3RMSNorm((2560,), eps=1e-06)
          )
        )
        (norm): Qwen3RMSNorm((2560,), eps=1e-06)
        (rotary_emb): Qwen3RotaryEmbedding()
      )
      (lm_head): Linear(in_features=2560, out_features=151936, bias=False)
    )

In the LoRA configuration, I target all the layers. Targeting all the linear layers often achieves the best results.

By only targeting these layers, we add a f3 million parameters. We will only train these parameters and freeze everything else. Fine-tuning will be very memory-efficient compared to a standard full fine-tuning.

#### Get your dataset ready

I use the “[HuggingFaceH4/ultrachat_200k](<https://huggingface.co/datasets/HuggingFaceH4/ultrachat_200k>)” dataset for fine-tuning. This is a dataset of conversations from which the model will learn how to answer user prompts. Make sure to remove the “prompt” column so that TRL knows that it has to use the “messages” column for training.
    
    
    #Since this is a large dataset, we take only a subsample of the dataset for this tutorial
    ds_train = load_dataset("HuggingFaceH4/ultrachat_200k", split="train_sft[:10000]")
    ds_test = load_dataset("HuggingFaceH4/ultrachat_200k", split="test_sft[:1000]")
    
    ds_train = ds_train.remove_columns(["prompt"])
    ds_test = ds_test.remove_columns(["prompt"])
    
    tokenizer = AutoTokenizer.from_pretrained(model_name)

#### Hyperparameters

Finally, we need to configure the training arguments and hyperparameters. There’s quite a bit happening in this step. For a detailed explanation of each setting, refer to my guide:
    
    
    training_arguments = SFTConfig(
          output_dir=output_dir,
          eval_strategy="steps",
          do_eval=True,
          optim="paged_adamw_8bit",
          per_device_train_batch_size=batch_size,
          gradient_accumulation_steps=gradient_accumulation_steps,
          per_device_eval_batch_size=batch_size,
          log_level="debug",
          save_strategy="epoch",
          logging_steps=25,
          learning_rate=1e-5,
          bf16 = True,
          eval_steps=25,
          max_steps=200,
          warmup_ratio=0.1,
          lr_scheduler_type="linear",
          dataset_text_field="text",
          max_length=1024,
    )
    
    trainer = SFTTrainer(
            model=model,
            train_dataset=ds_train,
            eval_dataset=ds_test,
            peft_config=peft_config,
            processing_class=tokenizer,
            args=training_arguments,
    )

Don’t forget `optim="paged_adamw_8bit"`. It activates the optimizer paging for better memory management.

Then start fine-tuning:
    
    
    trainer.train()

Running this fine-tuning should only take 2.5 hours on Google Colab. If everything goes well, you should see something like this:
