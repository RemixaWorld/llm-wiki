When released, large language models (LLMs) are evaluated on various benchmarks that test different skills, such as commonsense reasoning, coding skills, language understanding, problem-solving, and world knowledge. 

Language understanding and world knowledge are frequently assessed using the MMLU benchmark (or its various adaptations), which consists of thousands of multiple-choice questions (MCQ), each with four possible answers, one of which is correct. Unlike generative benchmarks, MMLU does not evaluate the model's ability to generate text. Instead, the LLM assigns a score to each of the four answers, and if the correct answer receives the highest score, the LLM is deemed to "know" the answer.

Do LLMs**really** know that this answer is correct?

State-of-the-art LLMs with 7B+ parameters can now achieve an accuracy exceeding 70% on MMLU. Considering the inherent noise in MMLU, including ambiguous questions and occasional errors in the gold answers, this performance is not so far from the benchmark's practical limits. If an LLM genuinely "knows" the correct answer, minor changes to the prompt format or the task description should not significantly affect the results. Furthermore, a truly knowledgeable LLM should not only identify the correct answer but also recognize that the other options are incorrect.

In this article, I present a new evaluation benchmark, MULULU (**M** ulti-task **U** niversal **L** anguage **U** nderstanding with **L** ower **U** ncertainty; name found by ChatGPT), that I derived from MMLU to test how consistent an LLM is in its answer, and robust to small changes in MCQ benchmarks like MMLU. We’ll observe that altering the format of answer IDs, such as switching from uppercase to lowercase, or from letters to numbers, can significantly affect the accuracy of the models, even though such changes wouldn’t pose any issue for humans. Additionally, we’ll see that most LLMs still struggle to identify an incorrect answer when explicitly asked to do so.

For this evaluation, I used the [Evaluation Harness](<https://github.com/EleutherAI/lm-evaluation-harness>) (lm-eval). In the notebook below, I show how to integrate a custom benchmark into this framework and use it to evaluate LLMs.

## MMLU: How Does It Work?

Before crafting some variations of MMLU, we must know how this benchmark works. 

MMLU is old. It has been proposed in 2020, only 3 months after GPT-3:

[Measuring Massive Multitask Language Understanding](<https://arxiv.org/abs/2009.03300>)

MMLU’s original purpose was to evaluate the language understanding abilities of language models. Each sample in the dataset is organized into 4 columns:

  * **question** : The question that the model has to answer;

example:

    
    
    Find the degree for the given field extension Q(sqrt(2), sqrt(3), sqrt(18)) over Q.

  * **choices** : A list of 4 possible answers, only one is correct;

example:

    
    
    [ "0", "4", "2", "6" ]

  * **answer** : The id of the correct answer in the “choices“ (it starts from 0);

example:

    
    
    1

  * **subject** : It refers to the task to which the sample belongs;

example

    
    
    abstract_algebra

The model evaluated on MMLU must find “answer”, among “choices”, given “question”.

Nowadays, LLMs are evaluated on MMLU by simply computing the probability for each possible answer, considering that the answer that has the highest probability is the one picked by the LLM. 

If we take the sample above, the LLM will typically be prompted as follows:
    
    
    The following are multiple choice questions (with answers) about abstract algebra.
    Find the degree for the given field extension Q(sqrt(2), sqrt(3), sqrt(18)) over Q.
    A. 0
    B. 4
    C. 2
    D. 6
    Answer:

Then, the completion with each answer’s identifier is scored, e.g, for the answer “A”, the following sequence of tokens is scored:
    
    
    The following are multiple choice questions (with answers) about abstract algebra.
    Find the degree for the given field extension Q(sqrt(2), sqrt(3), sqrt(18)) over Q.
    A. 0
    B. 4
    C. 2
    D. 6
    Answer: A

Another example for answer B, we just change the letter:
    
    
    The following are multiple choice questions (with answers) about abstract algebra.
    Find the degree for the given field extension Q(sqrt(2), sqrt(3), sqrt(18)) over Q.
    A. 0
    B. 4
    C. 2
    D. 6
    Answer: B

We do the same for C and D. If B (the correct answer) has the highest score, the benchmark will consider that the model knows the answer to the question. 

It’s worth noting that MMLU is typically used as a 5-shot benchmark, meaning the model is provided with example questions and answers. Back in 2020, this was necessary to help the models understand the task. However, today, even smaller models are capable of recognizing that they are dealing with an MCQ with four answers. Including examples no longer improves accuracy significantly (for most recent LLMs), but it does considerably increase evaluation costs, along with other issues I’ve discussed in _The Salt_ :

## Does the LLM Really Know?

Imagine an LLM correctly identifies the right answer to a question. If the model truly knows the answer and understands the question, changing the format of the question or asking it to identify a wrong answer shouldn’t throw it off. For comparison, humans wouldn’t struggle with variations in format, such as in the following example:
    
    
    The following are multiple choice questions (with answers) about abstract algebra.
    Find the degree for the given field extension Q(sqrt(2), sqrt(3), sqrt(18)) over Q.
    A. 0
    B. 4
    C. 2
    D. 6
    Answer: B

which is equivalent to:
    
    
    The following are multiple choice questions (with answers) about abstract algebra.
    Find the degree for the given field extension Q(sqrt(2), sqrt(3), sqrt(18)) over Q.
    a. 0
    b. 4
    c. 2
    d. 6
    Answer: b

If the LLM was able to score “B” the highest, it should also be able to score “b” the highest.

If we modify the prompt to explicitly ask for a wrong answer instead of the correct one, the model should assign the lowest likelihood to the correct option (i.e., scoring "B" the lowest).

To test the consistency of LLMs’ answers, I created 18 variations of the MMLU benchmark and evaluated 22 models to analyze how their performance was impacted by these variations.

## MULULU: Benchmarking LLMs with Variations of MMLU

I used the Evaluation Harness framework for this analysis. Adding a benchmark to the framework is straightforward, and since I only modified the format of the MMLU samples, there was no need to alter the dataset itself—only the prompt template defined within the Evaluation Harness. In the accompanying notebook, I demonstrate how to integrate a benchmark into the Evaluation Harness.

#### Changing the introduction to the question

In this variation, I only changed the introduction to the question. I propose 3 variants. If the LLM knows the answer to a question, all 3 variants should yield the same result. _Note: I think LLMs should be able to understand that they are given an MCQ without us telling it. Ultimately, we shouldn’t have to provide this introduction. However, I chose not to test an “empty” introduction since some samples of MMLU might be ambiguous enough that even humans wouldn’t understand well that this is a question._

Variant “default”:
    
    
    Choose the correct answer to the following multiple choice question.\n\n

Variant “default-1”:
    
    
    What is the correct answer to this multiple choice question:\n\n

Variant “default-2”:
    
    
    Question:\n

#### Changing the structure

In this category, we will significantly change the format of the prompt.

Variant “answerfirst”:
    
    
    Choose the correct answer to the following multiple choice question.
    
    Answers:
    A. 0
    B. 4
    C. 2
    D. 6
    Question:
    Find the degree for the given field extension Q(sqrt(2), sqrt(3), sqrt(18)) over Q.
    Answer:

The answers are listed before the question, and then we request the correct answer. This is less natural but still straightforward for humans to understand.

Variant “e”:
    
    
    A. 0
    B. 4
    C. 2
    D. 6
    E. Answer E

The model scores the following list of answers: ["A", "B", "C", "D", “E”].

A fifth choice is added. It is always the same, a simple statement “Answer E” which is never correct (presumably…). This would look strange in a real MCQ but still, humans wouldn’t choose this answer. For LLMs, as we will see, it could be confusing since it contains “Answer” which LLMs, overtrained on MMLU-like tasks, might be seen as the statement that “E” is the correct answer.

Variant “spaced”:
    
    
    A.                  0
    B.                  4
    C.                  2
    D.                  6

This variant adds multiple spaces between the ID of the answer and the answer. This is almost transparent for humans but for LLMs, each space can be a new token that must be encoded.

#### Changing the goal: Choose a wrong answer

In these variants, we want to pick a wrong answer. I tried 3 different prompts. This problem is much easier than picking the right answer since there are 3 wrong answers for only one correct answer. If the LLM truly knows the right answer, it should also know that the other answers are wrong. 

Specifically, if an LLM scores 70 on MMLU, it should achieve a similar or higher score on the _wrong_ variant by selecting incorrect answers instead of correct ones for the questions it initially got right (leading to the score of 70) while accurately identifying incorrect answers for the remaining questions.

Variant “wrong”:
    
    
    Choose a wrong answer to the following multiple choice question.

Variant “wrong-2”:
    
    
    Several answers to the following multiple choice question are not correct. Choose one.

As we will see, this is particularly challenging for LLMs as they have to infer that “one” refers to a “not correct” answer among the “several answers”. This requires some reasoning. In my opinion, this is still easy for humans to understand.

Variant “wrong-3”
    
    
    Choose an incorrect answer to this multiple choice question:

This is a paraphrase of _wrong_.

Overall, we have a high variability in the results. Most LLMs didn’t catch that _wrong-2_ is asking for an incorrect answer. Qwen2.5 14B and Gemma 2 9B completely failed at this while Qwen2.5 7B understood the prompt, but still performed much lower than with the two other variants.

#### Introducing straightforward mismatches _answer’s IDs-scored IDs_

For example, if the answer IDs are **A, B, C,** and **D** , but the evaluation uses **a, b, c,** and **d** (lowercase instead of uppercase), an LLM should assign the highest score to "a" if the correct answer is "A." This behavior aligns with what a human would intuitively do.

Variant “lowercase-restricted”:
    
    
    A. 0
    B. 4
    C. 2
    D. 6

The model scores the following answers: ["a", "b", "c", "d"].

Variant “uppercase-restricted”:
    
    
    a. 0
    b. 4
    c. 2
    d. 6

The model scores the following answers: ["A", "B", "C", "D"].

## Discussion

The results are much better than I expected, but they highlight important challenges. Handling "wrong answers" remains the most difficult task for LLMs, and variations in itemization style or formatting have a noticeable impact on performance. To truly evaluate what an LLM knows—independent of formatting—normalizing these variables is essential. The goal should be consistency over raw accuracy to better understand model robustness.

**Think about this:**

We have LLM _A_ better on MMLU than LLM _B_. _A_ is thus deemed better at language understanding and world knowledge. However, after we change the format of the samples, e.g., using another variant proposed by MULULU, _B_ obtains a higher score than _A._**So which LLM is actually better?** As we saw in the results above, the best (or worst) LLMs are not always the same depending on minor changes in the prompt.

With MULULU, I want to emphasize the importance of consistency. We could penalize or rank lower LLMs that fail to answer similarly when varying the format of the question. 

Among all formats tested, the default format consistently yielded the best results, likely because LLMs are specifically trained on and optimized for this structure.

Ultimately, this underscores the importance of designing benchmarks that test not just accuracy but also resilience to variations in input format, ensuring fair and meaningful evaluations of LLM performance.

#### Why did I do this?

I started this project in October with the initial goal of evaluating whether LLMs could be influenced to choose better answers when incentivized with a reward, such as, "Choose the right answer and I’ll give you $1M." For example, Hugging Face incorporates this type of framing in their smolagents prompts.

However, I didn’t observe any significant impact of the monetary incentive on MMLU results. Instead, I noticed that the model’s performance varied more depending on the format of the prompts rather than the promised reward. This led me to design and test a series of format variations.

Looking ahead, I plan to refine these variations to better evaluate how consistent new LLMs are in their answers, with slight changes in prompt formatting. This could provide deeper insights into model robustness and adaptability.
