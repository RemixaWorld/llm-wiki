Mixtral-8x7B is one of the best pre-trained LLMs that you can find. This model is a mixture of experts (MoE) with 46 billion parameters but uses only 14 billion parameters for inference. Yet, we still need to load the entire model in memory.

You would need more than 90 GB of GPU VRAM to load it, i.e., even a state-of-the-art GPU such as the H100 is not enough. Even 4-bit quantization still produces a model that is too large for a high-end consumer-grade GPU (e.g., the RTX 4090 24 GB). 

We could offload experts of Mixtral-8x7B to the CPU RAM but, as we saw in a previous article, it significantly slows inference down. 

Another alternative is to quantize the model to a lower precision. 3-bit and 2-bit quantizations are getting more accurate with recent research progress, especially for very large models such as Mixtral-8x7B.

In this article, I present AQLM: A method for 2-bit quantization that has been applied to Mixtral to make it nearly 8x smaller. I briefly explain how AQLM works and demonstrate how to use Mixtral 2-bit. I also show how to quantize a model with AQLM, using TinyLlama as an example.

## AQLM: Additive Quantization for LLM

AQLM is presented in this paper:

[Extreme Compression of Large Language Models via Additive Quantization](<https://arxiv.org/pdf/2401.06118.pdf>)

It relies on additive quantization (AQ) while most methods that I have described here before rely on post-training quantization (PTQ). For instance, GPTQ aims at compressing rows of weights (a.k.a, parameters), while AQ compresses input vectors. AQ is radically different and much more complex.

AQ operates under the assumption that the query distribution is unknown, whereas PTQ relies on calibration data to optimize for specific input embeddings. Calibration is a costly step of algorithms such as GPTQ but, as we will see, AQ is much more expensive.

AQ quantizes weight rows of an LLM by grouping them and representing each **group** with a sum of vectors selected from multiple **codebooks**. 

> _**Definition: Codebook**_
> 
> A set of learnable candidate vectors that can be used to encode data.

Quantized weights are expressed as a concatenation of vectors chosen from each codebook for every group, aiming to encode groups of weights efficiently using a **fixed number of bits**. The approach includes learning the codebooks and the discrete codes through an iterative process that alternates between updating the codes and the codebooks to minimize loss, using residual K-means for initialization.

![source](https://substackcdn.com/image/fetch/$s_!gDmv!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F264f5f29-d5b2-4b81-8cdf-25a6b4fff996_558x306.png) 

Two critical hyperparameters will impact the quantization accuracy and the efficiency of the model during inference:

  * The number of codebooks

  * The fixed number of bits used for encoding

The overall strategy of AQLM is to find an effective weight representation that reduces the error between the original and quantized layer outputs, with the algorithm proceeding through three phases to optimize the quantized weights and codebooks. This involves a sophisticated method of quantizing weights that accounts for the interaction between layers and the discrete and continuous nature of codes and codebooks, respectively.

These optimization steps are complex and are the costly part of AQLM. In a nutshell:

  * Beam search for codes

  * Codebook update

  * Fine-tuning for intra-layer cohesion

For large LLM, we need expensive hardware to quantize with AQLM. However, this cost could be justified. As we will see in the next section, the performance of the resulting models is impressive.

## Inference with AQLM LLMs

The implementation of AQLM is available here:

  * [Vahe1994/AQLM](<https://github.com/Vahe1994/AQLM>) (Apache 2.0 license)

AQLM is almost fully supported by Hugging Face Transformers. For this support, an AQLM model contains the code to configure and run it. For instance, for the model [BlackSamorez/Llama-2-7b-AQLM-2Bit-1x16-hf](<https://huggingface.co/BlackSamorez/Llama-2-7b-AQLM-2Bit-1x16-hf>): 

  * [configuration_llama_aqlm.py](<https://huggingface.co/BlackSamorez/Llama-2-7b-AQLM-2Bit-1x16-hf/blob/main/configuration_llama_aqlm.py>)

  * [modeling_llama_aqlm.py](<https://huggingface.co/BlackSamorez/Llama-2-7b-AQLM-2Bit-1x16-hf/blob/main/modeling_llama_aqlm.py>)

Then, when we load the model with Transformers, setting “trust_remote_code=True“, these files are automatically interpreted. Note: _This will change shortly. A pull request is ready to be merged (if not merged already when you read this) in Transformers to support AQLM without the need for these Python files._

Let’s try it with the Mixtral AQLM model released by the AQLM team:

  * [BlackSamorez/Mixtral-8x7b-AQLM-2Bit-1x16-hf](<https://huggingface.co/BlackSamorez/Mixtral-8x7b-AQLM-2Bit-1x16-hf>)

This model was quantized with 1 codebook of 16 bits resulting in a size of 12.6 GB on the hard drive against 96.8 GB for the original Mixtral-8x7B. This AQLM version is 7.7 times smaller.

You only need a GPU with 16 GB of VRAM to run it! 

To use it, we first need to install AQLM with the last version of Accelerate:
    
    
    pip install aqlm[gpu,cpu]
    pip install git+https://github.com/huggingface/accelerate.git@main

Then, we can load the model, setting “trust_remote_code=True“:
    
    
    quantized_model = AutoModelForCausalLM.from_pretrained(
        "BlackSamorez/Mixtral-8x7b-AQLM-2Bit-1x16-hf",
        trust_remote_code=True, torch_dtype="auto", device_map="cuda"
    ).cuda()

The tokenizer is not included in this repository but it is the same as the original Mixtral model so we can load it from the original repository:
    
    
    tokenizer = AutoTokenizer.from_pretrained("mistralai/Mixtral-8x7B-v0.1")

Prompting the model is also standard:
    
    
    tokenized_prompt = tokenizer("The best recipe for pasta is", return_tensors="pt")["input_ids"].cuda()
    
    output = quantized_model.generate(tokenized_prompt, temperature=1, top_p=0.7, do_sample=True, max_new_tokens=50)
    output_detok = tokenizer.decode(output[0])
    
    print(output_detok)

The output generated seems normal and does not show any of the problems that can be seen sometimes with 2-bit quantization: gibberish, repetitions of the same sequences of tokens, etc.

## Quantize with AQLM

The authors published their recipe for quantization in the same repository. I tried it to see whether it works and how costly it is. Since I expected the need for a big GPU for several hours, I used Google Colab’s A100 and only tried to quantize a small LLM. I chose TinyLlama which has only 1.1B parameters.

Note: _Since TinyLlama is already quite small, we should expect low-precision quantization with AQLM to severely degrade the model’s performance._

Here is how I did it.

First, we need to clone the AQLM repository and install its requirements:
    
    
    git clone https://github.com/Vahe1994/AQLM.git
    cd AQLM && pip install -r requirements.txt

Then, we need to download the dataset that will be used to train the AQLM quantization. This dataset must already be tokenized and similar to the dataset used to pre-train the LLM we want to quantize. Fortunately, the authors of AQLM released a tokenized version of RedPajama that they used to quantize Llama 2. RedPajama is one of the datasets used to train TinyLlama.
    
    
    from huggingface_hub import hf_hub_download
    
    hf_hub_download(repo_id="Vahe1994/AQLM", filename="data/red_pajama_n=4096_4096_context_length_llama.pth",repo_type="dataset")

Note: _This will output the location of the dataset once downloaded. We will use this information later._

Then, the model that we want to quantize must also be in the Hugging Face cache. To do this, we only have to load the model with Transformers:
    
    
    from transformers import AutoTokenizer, AutoModelForCausalLM
    model_name = "TinyLlama/TinyLlama-1.1B-intermediate-step-1431k-3T"
    tokenizer = AutoTokenizer.from_pretrained(model_name, torch_dtype="auto")
    model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype="auto")

We can now proceed to the quantization. I used the hyperparameters suggested in the AQLM repository:
    
    
    export CUDA_VISIBLE_DEVICES=0   # or e.g. 0,1,2,3
    
    
    python AQLM/main.py TinyLlama/TinyLlama-1.1B-intermediate-step-1431k-3T /root/.cache/huggingface/hub/datasets--Vahe1994--AQLM/snapshots/cc9e141074275aacdb5e13f7f5a9102be9778f5b/data/red_pajama_n=4096_4096_context_length_mistral.pth --nsamples=1024 \
     --num_codebooks=1 --nbits_per_codebook=16 --in_group_size=8 \
     --relative_mse_tolerance=0.01 --finetune_relative_mse_tolerance=0.001 \
     --finetune_batch_size=32 --local_batch_size=1 --offload_activations \
    --save quantized_model/

AQLM works layer by layer. It took nearly 4 hours using an A100 but I believe it can be much faster with a modern CPU (Google Colab has a small old CPU). Note that it surprisingly required a huge amount of CPU RAM. CPU RAM usage peaked at 73.2 GB, almost reaching Google Colab’s limit. I’m not sure why, and by how much this would increase when quantizing larger LLMs.

It produces a directory of binary files, 1 file per layer. We still have to pack everything in a single binary file that Transformers can load.

AQLM proposes a script for this:
    
    
    mkdir hf_quantized_model
    python AQLM/convert_to_hf.py  TinyLlama/TinyLlama-1.1B-intermediate-step-1431k-3T  quantized_model  hf_quantized_model

The result is a very tiny model weighing only 600 MB.

However, this only produces a config.json and the .bin file which is the model. The directory doesn’t contain the tokenizer and the code to run the model.

To use the model, I added in the “hf_quantized_model” directory all the files from the [AQLM version of Llama 2](<http://BlackSamorez/Llama-2-7b-AQLM-2Bit-1x16-hf>) made by the authors. Note:_Don’t replace the files that are already in hf_quantized_model._

Since TinyLlama and Llama 2 have the same architecture, I assumed it would work and it did. Then, you can load the model with Transformers and start inference:
    
    
    from transformers import AutoModelForCausalLM
    from transformers import AutoTokenizer
    quantized_model = AutoModelForCausalLM.from_pretrained(
        "hf_quantized_model/",
        trust_remote_code=True, torch_dtype="auto"
    ).cuda()
    
    tokenizer = AutoTokenizer.from_pretrained("hf_quantized_model/")
    output = quantized_model.generate(tokenizer("This is a pizza a lot of", return_tensors="pt")["input_ids"].cuda(), num_beams=5, do_sample=True, max_new_tokens=150)
    output = tokenizer.decode(output[0])
    print(output)

Quantizing 1.1B parameters to 2-bit is still challenging and I’m not even sure that it is very useful since a 1.1B model would already fit on most GPUs. Nonetheless, I confirm that the AQLM quantization code works. 

## Conclusion

AQLM is very impressive. This is the first time that a 2-bit Llama 2 70B achieves a better performance than the original 16-bit Llama 2 7B and 13B. If you have enough memory to run Llama 2 13B, consider using the smaller 2-bit Llama 2 70B instead to get better results.

One of the downsides of AQLM is that this method is extremely costly. It also has several hyperparameters that are critical but difficult to set correctly, i.e., you may have to quantize the model several times with different hyperparameters before finding a good configuration.

AQLM is already well-supported by Transformers. I tried with vLLM but it didn’t work. Nonetheless, I would expect many more frameworks to support AQLM very soon.
