# 使用OmniParser和VLM实现可视化界面交互的Agent系统

该文章介绍了如何构建一个AI代理，以处理互动任务，例如自动在浏览器中搜索和购买商品。
- AI代理的工作原理
    1. **用户输入**：用户通过语句（如“打开Chrome并购买牛奶”）与AI代理交互。 
    2. **屏幕解析**：使用OmniParser解析当前屏幕信息，以提取UI元素的信息。
    3. **任务分析**：利用大型语言模型（LLM）理解用户意图并决定下一步行动。
    4. **行动生成**：生成鼠标移动、键入和点击等动作，并在电脑上执行。
    5. **任务反馈**：检查动作是否完成，若未完成则重复以上步骤，直至完成任务。
- 设置步骤
    1. **克隆代码库**：
   - 使用命令：`git clone --recursive https://github.com/FareedKhan-dev/ai-desktop`
    2. **安装依赖**：在项目目录内运行`pip install -r requirements.txt`。
- OmniParser模块
    1. **背景**：OmniParser是一个用于屏幕解析的模型，准确性高，主要用于提取UI元素的文本和位置。
    2. **模型加载**：
       - 通过读取配置模型路径来加载SOM模型和文本处理器。
    3. **图像处理**：将截取的屏幕图像转换为base64格式，并解析出结构化的UI元素信息。
- 截图工具
    - 使用`pyautogui`库来实现自动化截屏功能，并将截图保存为图像文件，以便后续解析。
- 行动执行
    1. **定义能执行的操作**：
       - 包括移动鼠标、单击、输入文本等。
    2. **实现ComputerActions_Tool**：
       - 该工具负责将用户指定的操作转化为实际的计算机互动（使用`pyautogui`）。
- 行动调度器
    - **ActionOrchestrator_Agent**类负责协调所有行动，接收AI代理的指令并通过ComputerActions_Tool执行，实现完整的行动链。
- LLM的思考功能
    1. **用户的目标与当前状态**：LLM依赖用户输入（如“购买机票”）和目前屏幕上的UI元素信息进行决策。
    2. **JSON格式的响应**：LLM的决策会返回一个结构化的JSON，包括推理过程、执行的下一步行动和相关参数，以便AI代理理解下一步如何执行。
- Prompt设计
    - 为LLM提供清晰的说明：告诉它角色、能力、屏幕状态、目标和响应格式。这种设计确保LLM能够产生有效的指令。
- VLMAgent集成
    - 该类将所有组件整合到一起，核心方法`run_agent_task`实现了整个任务执行流程，包括截图、解析、发送给LLM、行动执行和反馈更新。
- 任务执行示例
    1. **成功案例**：
       - “获取Google的股价”：正确打开浏览器并输入搜索内容。
       - “在Amazon上买一个足球”：正确搜索并加入购物车。
    2. **失败案例**：
       - “克隆我的GitHub仓库”：无法执行预期操作，随机点击不同的搜索框。
