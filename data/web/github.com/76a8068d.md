# 使用Octopus系列路由+Adapter构造各种小型模型来实现匹敌大型模型的RAG

理想情况下，小型模型（比如3B）可以通过切换不同的Adapter来适应场景从而达到更好效果，对于不同的Adapter或者不同的模式，可以考虑使用Octopus系列模型（v4版本擅长将query定向到适当的专用模型，确保精确有效的查询处理）进行路由。

- 基本配置
    - Nomic's embedding model
    - Llama3.2 3B instruct
    - Langchain RAG workflow
    - Nexa SDK Embedding & Inference
    - Chroma DB

但基于基本配置还不够，3B模型还是无法处理复杂的任务，所以需要使用LoRA或者Search-Optimized微调——为同个基座赋予不同的Adapter从而转换为对应细分领域的专家。但需要引入一个路由机制来说明在何时切换使用何种Adapter，所以需要引入“query转发至专家”的专用模型Octopus系列（Octopus-v2）来对query进行路由，比如：
- 当它看到``或``标签时 → 触发RAG进行文档搜索
- 当看到类似“column chart”或“pie chart”时 → 切换到可视化 LoRA
- 用于常规聊天 → 使用基本模型
