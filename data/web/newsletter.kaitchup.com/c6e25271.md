# Generate Synthetic Data from Personas to Train AI Chatbots

### Using Personas and Efficient Inference to Create Targeted Training Data for AI Chatbots

When fine-tuning large language models (LLMs) to train an AI chatbot, the quality of your fine-tuning dataset is the most crucial factor in determining whether your chatbot will excel in its target task.

However, sourcing a suitable dataset can be challenging. Your company’s or personal data may be too limited, while public datasets are often too broad or too narrowly focused. A popular solution is to generate custom datasets using LLMs to train an AI chatbot effectively on data that truly fits your needs.

For instance, if your goal is to develop a chatbot that can answer questions across various fields, generating a training dataset can save you the time and effort of gathering data from multiple sources and standardizing its format, style, and tone.

In this article, we’ll explore how to generate thousands of question-answer pairs. Using FinePersonasV0.1 to prompt Qwen2.5, we’ll create synthetic questions and answers in various domains and for various *personas*.

## Preparing Prompts with Fine Personas

Our goal is to fine-tune an LLM to be a chatbot capable of answering questions in a wide variety of domains, with an educational tone.

To do that, we have to make the LLM behave like an educator in a specialized domain. We can use argilla/FinePersonas-v0.1 for this purpose. This dataset contains 21 million detailed personas.


PersonaA persona is a detailed description of an individual’s characteristics, background, and goals, designed to reflect diverse identities and experiences. In the context of FinePersonas, each persona represents a unique set of attributes that can enrich synthetic data.


source: argilla/FinePersonas-v0.1

The dataset is organized into 5 columns:

ID: A unique ID for the given persona. We won’t use it.

persona: A description of the persona.

model_name_embeddings: The name of the model used to compute the embedding of the persona.

embedding: The embedding of the persona. It can be used, for instance, to find similar or very different personas. We won’t use it.

labels: Some general characteristics attached to the persona, e.g., “Education” or “Science”.


For this article, we want to train an educational chatbot. So we are more interested in personas with the label “Education”. Many personas in the dataset have this label. A few thousand will be enough to generate synthetic data. Remember that for fine-tuning LLMs, quality is more important than quantity.

I subsampled 5000 personas with the label "Education" using this code:

```
import sys
from tqdm import tqdm
from datasets import load_dataset
dataset = load_dataset("argilla/FinePersonas-v0.1", split="train", streaming=True)
dataset = dataset.filter(lambda example: "Education" in example["labels"])
questions = []
counter = 0
max_personas = 5000
for d in tqdm(dataset):
questions.append([{
"role": "user",
"content": "Generate a question that this persona can answer with expertise:\n\n"+d['persona']
}])
if max_personas == counter+1:
break
counter += 1
print(len(questions))
```


*Note: This code requires *`tqdm `

*and *`datasets `

*to be installed.*

For each persona, I created a prompt in JSON format, with the content "Generate a question that this persona can answer with expertise:\n\n{persona}".

We will use this prompt to generate questions that could ask a user.

## Generating Questions for Personas with vLLM

To generate our synthetic data, we will use vLLM. I use vLLM because it is one of the fastest inference engines and it automatically adjusts the inference batch size given the GPU RAM available. You can learn more about vLLM here:

Install vLLM:

`pip install vllm`


For generation, I use Qwen2.5 7B which is one of the best models that you can run on consumer hardware. For better synthetic data, you might want to use the 72B version instead.

We load the model as follows:

```
from vllm import LLM, SamplingParams
llm = LLM(model="Qwen/Qwen2.5-7B-Instruct", max_model_len=8192)
sampling_params = SamplingParams(temperature=0.7, top_p=0.95, max_tokens=1024)
```


We have 5000 personas. We want to generate questions that could be answered by these personas to train our AI chatbot. We can leverage inference’s random sampling for this. vLLM uses a random seed for inference. If we run the inference engine twice for the same prompt, and if we set random sampling hyperparameters (e.g., top_p), vLLM will *probably *generate a different output.

To do this, I ran vLLM 5 times for each prompt. Thanks to batching, this is very fast. We will get 5 questions for each persona, i.e., 25000 questions in total.

```
question_prompts = []
for sd in range(5):
outputs = llm.chat(messages=questions,
sampling_params=sampling_params,
use_tqdm=True)
for output in outputs:
c_persona = output.prompt.split('\n\n')[1].split("<|im_end|>")[0].strip()
generated_text = "You are this persona: "+c_persona+"\n\nAnswer the following question:\n"+output.outputs[0].text
question_prompts.append([{
"role": "user",
"content":generated_text
}])
```


In this loop, I also get the generated question and prepare a prompt for the following step which is answer generation:

`You are this persona: {persona}\n\nAnswer the following question:\n{question}`


## Generate the Answers

Now, we can generate the answer for each question, using these prompts:

```
sampling_params = SamplingParams(temperature=0.7, top_p=0.95, max_tokens=1024)
outputs = llm.chat(messages=question_prompts,
sampling_params=sampling_params,
use_tqdm=True)
```


I set the maximum tokens to 1024 which appears to be enough even though Qwen2.5 7B is quite verbose when answering these questions. This can be quite long. For the 25000 questions, it took 5 hours with Google Colab’s L4.

The next step is to get the generated answers and format the dataset with the pairs of generated questions and answers.

## Format Your Synthetic Dataset

In theory, two columns in our dataset could be enough: question and answer. But then, we would lose some useful information on how the pair question-answer was created. For instance, we might want to train the chatbot only using the question-answer generated for specific personas. In that case, we should also have a column persona.

In datasets used to train an AI chatbot, it is also common to have the column "prompt". I added this column and it contains the prompt used to generate the answer.

Finally, inspired by what Hugging Face has done with the dataset HuggingFaceH4/ultrachat_200k, I also added a column "messages", which contains the question and answer in JSON and as dialogue turns between "user" and "assistant", following this template:

```
[
{'content': {question}, 'role':'user'}
{'content': {answer}, 'role':'assisant'}
]
```


This template has the advantage of being directly supported by TRL, Hugging Face’s library for supervised fine-tuning.

Then, we can create this dataset in JSON, as follows:

```
generated_dataset = []
deduper = set()
for output in outputs:
example = {}
example['prompt'] = output.prompt.split("<|im_start|>user\n")[1].split("<|im_end|>\n")[0]
segments = output.prompt.split("\n\nAnswer the following question:\n")
example['question'] = segments[-1].split("<|im_end|>\n")[0]
example['persona'] = segments[0].split("You are this persona: ")[-1]
example['answer'] = output.outputs[0].text
unique = example['question']+example['answer']
if unique in deduper:
continue
deduper.add(unique)
messages = [{'context':example['question'],'role':'user'},{'context':example['answer'] ,'role':'assistant'}]
example['messages'] = messages
generated_dataset.append(example)
import json
with open('qa_dataset.json', 'w') as fp:
json.dump(generated_dataset, fp)
```


*Note: with the *`deduper `

*I check that the question-answer pair answer hasn’t already been generated.*

In this example, I also split the dataset to make train/test splits. 5% of the examples will be in the test split. This split will be particularly useful for validation when you will train chatbots on this dataset.
