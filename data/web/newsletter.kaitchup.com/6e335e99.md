# Llama 3.2 Embeddings: Training and Evaluation with LLM2Vec

### A step-by-step tutorial

The embedding model plays a key role in many applications such as in Retrieval-Augmented Generation (RAG) for large language models (LLMs). In RAG systems, it encodes both the knowledge base and the user query. I explained the RAG concept in this article:

Using an embedding model that is trained or fine-tuned on the same domain as the LLM can greatly improve a RAG system. With LLM2Vec, we can extract an inaccurate embedding model directly from the LLM. Then, we can improve this model with a two-stage training including masked next-token prediction and contrastive learning. We saw how to do this in previous articles with Llama 3 8B. However, because Llama 3 8B is a large model, it produces high-dimensional text embeddings, which can be costly to train and deploy in downstream tasks.

In this article, we will see how to make text embeddings from Llama 3.2 1B. We will see in detail all the steps: masked next-token prediction training, contrastive learning, and then how to evaluate the resulting embeddings. ## Train an Embedding Model with LLM2Vec

#### Step 1: Masked Next-Token Prediction Training

The first step in the LLM2Vec method is to transform an LLM into an embedding model by removing the causal attention mask.

This change allows each token to interact with all other tokens in the sequence, turning the LLM into a bidirectional model. However, since decoder-only LLMs aren’t designed to encode future tokens, this modification alone can degrade the quality of representations. A new training is necessary to make the model use its new bidirectional attention.

LLM2Vec uses a training objective called masked next-token prediction (MNTP). MNTP combines next-token prediction with masked language modeling, similar to what BERT uses. To apply this, we take a sequence (x1, x2, ..., xN), mask some tokens, and train the model to predict these masked tokens using context from both past and future tokens. When predicting a masked token at position i, the loss is based on the logits from the representation at the previous positions (i - 1), instead of the masked position itself, unlike in BERT.

By converting the LLM into a bidirectional model and training it with MNTP, the method aims to adapt any decoder-only LLM into an encoder. However, this alone doesn’t fully address the need for sequence-level representations.

#### Step 2: Unsupervised Contrastive Learning

Typically, bidirectional encoders like BERT include a next-sentence prediction task in pre-training, which LLMs lack. LLM2Vec resolves this by running each input sequence twice through the model with different random dropout masks, creating two different representations of the same sequence. The training objective is to increase the similarity between these two representations while decreasing their similarity to representations of other sequences in the same batch. This final step is called “Unsupervised Contrastive Learning”.

For this learning, LLM2Vec uses SimCSE (Simple Contrastive Learning of Sentence Embeddings).

The SimCSE training goal is to increase the similarity between these two representations while decreasing their similarity to representations of other sequences in the same batch.

A key advantage of this method is that it can be unsupervised, meaning it doesn’t need paired data and works with any set of sequences.

According to the LLM2Vec paper, the unsupervised SimCSE approach already provides significant improvements for embedding models trained with the MNTP objective.

## Create Llama 3.2 Embeddings with LLM2Vec

I only used an RTX 3090 (24 GB) for all the following steps. If you have a GPU with less memory, reduce the batch size.

#### Installing LLM2Vec with the Evaluation Dependencies


#### Train Llama 3.2 with Masked Next-Token Prediction

LLM2Vec does this training with LoRA. We only train an adapter that we will load for the next steps. It makes training relatively cheap.

I use the following configuration file:

```
{
"model_name_or_path": "meta-llama/Llama-3.2-1B",
"dataset_name": "wikitext",
"dataset_config_name": "wikitext-103-raw-v1",
"per_device_train_batch_size": 16,
"per_device_eval_batch_size": 16,
"gradient_accumulation_steps": 2,
"do_train": true,
"do_eval": true,
"max_seq_length": 512,
"mask_token_type": "blank",
"data_collator_type": "default",
"mlm_probability": 0.2,
"overwrite_output_dir": true,
"output_dir": "output/mntp/Llama-3.2-1B",
"evaluation_strategy": "steps",
"eval_steps": 100,
"save_steps": 200,
"stop_after_n_steps": 1000,
"lora_r": 16,
"gradient_checkpointing": true,
"torch_dtype": "bfloat16",
"attn_implementation": "flash_attention_2"
}
```


I saved it to a file named mtnp_config.json.

Let’s check the most important arguments:

**model_name_or_path**: This is the model from which you want to train an embedding model. It can be a Hugging Face repository or a local directory.**dataset_name**: The dataset used for training. I recommend using a general-domain dataset, such as Wikipedia, or a dataset in the same domain as your target tasks.**per_device_*_batch_size**: How many samples can fit in the memory of your GPU? Choose the highest possible value. For a 24 GB, we can fit 16 training samples of 512 tokens.**gradient_accumulation_steps**: How many batches should we process before updating the weights? Make sure to use Transformers >4.46 to get the correct gradient accumulation.**max_seq_length**: I recommend adjusting this argument depending on your target task. For instance, if you plan to use the embedding model in a RAG application with chunks of 256 tokens, a max_seq_length of 256 could be a good value and will save memory.**stop_after_n_steps**: How many training steps to do for training? In the LLM2Vec paper, they did 1000 steps.**gradient_checkpointing**: Save memory by recomputing some of the activations for the backward pass.**attn_implementation**: Save memory and accelerate computation with FlashAttention 2, especially for long sequences.

Then, run:

`python llm2vec/experiments/run_mntp.py mtnp_config.json`


With an RTX 3090, this training takes exactly 1 hour.

The evaluation runs show two evaluation metrics, the evaluation loss and the evaluation accuracy.

`{'eval_loss': 1.6513913869857788, 'eval_accuracy': 0.6552914566882266, 'eval_runtime': 17.2998, 'eval_samples_per_second': 28.844, 'eval_steps_per_second': 1.85, 'epoch': 0.13}`


During this training, the eval_loss decreased and the eval_accuracy increased. We may increase "stop_after_n_steps" to train longer for better results.

After 1000 steps, the adapter is saved in the directory "output_dir".

#### Merge the Adapter into the Main Model

We have trained an adapter. However, most downstream frameworks using embedding models still rarely support adapters. We must merge it into the main model. We can do it as follows with LLM2Vec:

```
import torch
from llm2vec import LLM2Vec
l2v_model = LLM2Vec.from_pretrained(
"meta-llama/Llama-3.2-1B",
peft_model_name_or_path="output/mntp-simcse/Llama-3.2-1B/checkpoint-1000/",
device_map="cuda" if torch.cuda.is_available() else "cpu",
torch_dtype=torch.bfloat16,
merge_peft=True
)
l2v_model.save("Llama-3.2-1B-mntp-simcse")
```


This will save the model in a directory named "Llama-3.2-1B-mntp-simcse".

## Evaluate Llama 3.2 Embedding Model with MTEB

*How good is this embedding model?*

The Massive Text Embedding Benchmark (MTEB) is an evaluation framework designed to assess the effectiveness of text embeddings across diverse tasks, datasets, and languages. It includes 8 tasks, 58 datasets, and 112 languages.

It includes tasks like clustering, reranking, classification, semantic textual similarity (STS), and retrieval to ensure a holistic assessment of embeddings.

You can evaluate your embedding model as follows. Here, for all the STS tasks:

```
for t in ["STS16","STS13","STS14","STS15","STS17","STS22","STS12","BIOSSES","STSBenchmark","SICK-R"]:
!python llm2vec/experiments/mteb_eval_custom.py --base_model_name_or_path meta-llama/Llama-3.2-1B --peft_model_name_or_path output/mntp-simcse/Llama-3.2-1B/checkpoint-1000/ \
--task_name {t} \
--task_to_instructions_fp llm2vec/test_configs/mteb/task_to_instructions.json \
--output_dir results
```


The file "llm2vec/test_configs/mteb/task_to_instructions.json" will give you the names of all the other tasks.

This evaluation is especially useful to diagnose whether the training worked well. For instance, this model achieves a "main score" of 0.77 for STS16 which is in the range of normal scores for this task. Don’t focus much on improving these scores. Most of the STS datasets used in MTEB are old and certainly were in the pre-training/post-training data of recent LLMs.

It won’t tell you whether the model will be good for your target applications. For this, you will have to make your own benchmarks.

## Conclusion

Transforming an LLM like Llama 3.2 into effective embedding models involves a series of adaptations to improve how these models represent text. Techniques such as masked next-token prediction and contrastive learning are steps in this process. They allow the model to better capture richer and more accurate sequence-level representations. I particularly recommend this technique if you plan to use Llama 3.1 or 3.2 in a RAG system.

For a 1B model, this process with LLM2Vec is particularly cheap: 1 hour for MNTP and another hour for contrastive learning.

However, training good models delivering high-quality results in practical applications will often require further fine-tuning on domain-specific data and creating benchmarks that reflect the intended use case.

The LLM-Based embedding model indeed demonstrates certain generalization patterns, such as the ability to match Chinese query to English documents with the same meaning, which was not observed in previous BERT-Based models.
