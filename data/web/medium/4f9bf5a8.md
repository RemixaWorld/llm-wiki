## Background

To understand DeepSeek’s multi-token prediction, let’s first take a closer look at how LLMs generate text.

### Next-Token Prediction

LLMs typically generate text using an autoregressive approach, where, given a sequence of previous tokens, new tokens are generated one at a time by predicting the most likely next token.

For example, given the text “The cat sat”, it will be tokenized into a sequence of tokens as shown below:

``` "The cat sat" -> ["The", "cat", "sat"] ```

Each token has a token ID corresponding to its index in the vocabulary, and it is mapped to a dense vector by looking it up in an embedding matrix using this index. In most cases, a positional embedding is added to this dense vector to form the final embedding that will be received by the LLM:

``` Emb("The") = vector("The") + PositionalEncoding(1)Emb("cat") = vector("cat") + PositionalEncoding(2)Emb("sat") = vector("sat") + PositionalEncoding(3) ```

After passing through the Transformer layers in the LLM, the final layer is typically a linear projection that maps each embedding vector back to the vocabulary space, followed by a Softmax that outputs the probability distribution over the vocabulary. In our toy example here, the tokens with the highest probabilities could be:

``` P("on") = 0.7P("under") = 0.3... ```

Therefore, the model will choose the most likely token “on,” so the generated text will be: “The cat sat on”.

``` "The cat sat on" ```

This token-by-token process continues until a maximum length or an EOS (end-of-sentence) token is reached. Since it generates a single token at each step, it is often referred to as next-token prediction, and can be described more formally as:

* t stands for the t-th time step.
* x_{t:1} stands for the sequence of past tokens from x_1 to x_t.
* x_{t+1} is the next future token.

Next-token prediction sounds very natural from a modeling perspective, but it has some limitations:

* Firstly, it cannot be parallelized since it processes one token at a time sequentially.
* Moreover, each prediction requires a full forward pass, making both training and inference inefficient, especially for real-time generation of long text.

To mitigate these limitations, multi-token prediction is proposed.

### Prior Multi-Token Prediction Methods

In [3], the authors extend next-token prediction to a multi-token prediction mechanism:

Where, given the same input sequence, the model will generate n tokens from x_{t+1} to x_{t+n} with a single forward pass.

Note that this doesn’t mean selecting n tokens simultaneously from the probabilities produced by a single Softmax, as Softmax does not support selecting n tokens at once from a single probability distribution.

This is because Softmax is designed for categorical distributions, which model the probability of a single discrete event among multiple mutually exclusive choices. Therefore, Softmax can only generate one token at each time step, and to predict multiple tokens, we need multiple Softmax layers, each dedicated to generating a separate token.

For that reason, the above multi-token prediction loss is factorized into a series of single-token prediction operation heads, and each single-token prediction head runs a separate Softmax to select the corresponding token.

Now let’s dive deeper into this architecture, particularly focusing on the design choices behind the shared and independent components:

* **Shared f_s:** As mentioned before, this allows us to obtain z_{t:1} with a single forward pass, enabling the generation of n tokens. This design leads to better computational efficiency compared to next-token prediction.
* **Shared unembedding matrix f_u:** This saves on parameter budget without significantly affecting performance, as the unembedding matrix is typically very large with dimensions d×V, where d is the hidden layer dimension and V is the vocabulary size (typically ranging from 50K to 200K).
* **Independent heads:** This is the only independent part of the architecture. As mentioned before, each token requires a separate Softmax, which means we cannot share all components.

Using independent output heads decouples the generation process of the n tokens, making them independent of each other. On one hand, this enables parallel token generation, which can potentially improve training efficiency. However, generating tokens independently can lead to incoherent or inconsistent outputs. Additionally, the model may suffer from mode collapse, where it produces generic, frequent words instead of nuanced responses, thus reducing the diversity and richness of the output.

In the next section, we will explore how DeepSeek’s multi-token prediction technique addresses this issue.

### DeepSeek’s Multi-Token Prediction

As mentioned earlier, the multi-token prediction approach in [3] generates n tokens independently, which can result in incoherent output or even mode collapse. To address this, DeepSeek implements multi-token prediction by preserving the full causal chain for each token’s prediction, as illustrated in the figure below.

* An independent Transformer block.

So how does that work?

### Speculative Decoding

Speculative decoding is a technique aimed at accelerating the autoregressive generation process using a draft-then-verify approach [4, 5]: it first generates multiple candidate tokens in parallel, then verifies or corrects them using the original autoregressive (AR) model, as illustrated in the figure below.

Figure 3. The draft-then-verify diagram for speculative decoding. Image from [5].

More specifically, speculative decoding consists of two stages:

* **Parallel drafting** : rather than generating tokens sequentially with the original AR model, speculative decoding generates multiple tokens in parallel.
* **Batch verification** : the original AR model performs a single forward pass to verify the drafted tokens, accepting them as-is or correcting them when necessary.

Since the drafted tokens may be either accepted or rejected, the actual speedup largely depends on the acceptance rate.

* In the ideal scenario, all K drafted tokens are accepted, enabling the model to advance by K steps in a single forward pass and achieve a K-fold speedup.
* If some drafted tokens are rejected, the generation process still gains speed, since only the rejected tokens need to be regenerated instead of recomputing the entire sequence.

In other words, a higher acceptance rate results in greater speedup. In the next section, we’ll explore how DeepSeek applies this technique during inference.

### Impact on Inference Efficiency

As mentioned earlier, rather than fully discarding the MTP modules at inference time, they can be combined with speculative decoding to accelerate the inference process.

In [2], the authors experiment with predicting the next 2 tokens using the MTP technique combined with speculative decoding, and observe an acceptance rate of around 85% to 90% for the second token. This indicates that the generation quality of their MTP strategy remains consistently reliable.

More importantly, with such a high acceptance rate, integrating MTP with speculative decoding achieves a 1.8x speedup in inference, as measured by tokens per second (TPS).
