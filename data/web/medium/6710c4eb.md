Continuing my series, my latest post is on a Python library called `**dateparser**`, and it does what it says on the tin, i.e. parses human-readable date and time strings into `datetime` objects

I’ll leave links to some of my other articles in this series at the end.

Dateparser has several key features and capabilities, including,

* Support for almost every existing date format: absolute dates, relative dates (`"two weeks ago"` or `"tomorrow"`), timestamps, etc.
* Support for more than 200 language locales.
* Language autodetection
* Customizable behaviour through settings.
* Support for non-Gregorian calendar systems.
* Support for dates with timezones abbreviations or UTC offsets (`"August 14, 2015 EST"`, `"21 July 2013 10:15 pm +0500"`...)
* Search for dates in long texts.

### Basic Parsing in Multiple Languages

```python import dateparserfrom datetime import datetimeprint(datetime.now())print()# Englishdt_en = dateparser.parse("January 5, 2023 at 5:00 PM")print(dt_en) # 2023-01-05 17:00:00# Spanishdt_es = dateparser.parse("5 Enero 2023 17:00", languages=["es"])print(dt_es) # 2023-01-05 17:00:00# Frenchdt_fr = dateparser.parse("5 janvier 2023 à 17h00")print(dt_fr) # 2023-01-05 17:00:00>>>>>>>>>>2024-12-28 17:58:46.1948222023-01-05 17:00:002023-01-05 17:00:002023-01-05 17:00:00 ```

If you provide a language list, dateparser will go through those first when trying to understand its input. However, even without this, dateparser will attempt auto-detecting the chosen language.

### Parsing relative dates/times

### Handling Ambiguous Formats & Forcing a Date Order

Sometimes `MM/DD/YYYY` vs. `DD/MM/YYYY` can be ambiguous. For example, “06/07/2024” might be interpreted as June 7th or July 6th, depending on your locale or detection logic.

Use the `DATE_ORDER` setting to force which component is the day vs. month.

```json dt_us = dateparser.parse("06/07/2024", settings={"DATE_ORDER": "MDY"})print('USA Date format: ', dt_us) # 2024-06-07 00:00:00 (June 7)dt_eu = dateparser.parse("06/07/2024", settings={"DATE_ORDER": "DMY"})print('EU date format: ', dt_eu) # 2024-07-06 00:00:00 (July 6)>>>>>>>>>>>>>>USA Date format: 2024-06-07 00:00:00EU date format: 2024-07-06 00:00:00 ```

### Dealing with “Fuzzy” or “Human-Style” Strings

Dateparser is pretty good at dealing with human-defined dates and times. For example,

```python import dateparserfrom datetime import datetimeprint('Now: ',datetime.now())print()examples = [ "tomorrow at noon", "midnight", "the day after tomorrow at 8pm", "in 3 days at 5:00"]for phrase in examples: print(phrase, "->", dateparser.parse(phrase))>>>>>>Now: 2024-12-28 18:14:35.459748tomorrow at noon -> 2024-12-29 12:00:00midnight -> 2024-12-28 00:00:00the day after tomorrow at 8pm -> 2024-12-30 20:00:00in 3 days at 5:00 -> 2024-12-31 05:00:00 ```

### Using a Custom “Reference” (RELATIVE_BASE)

If you want to parse “yesterday,” “last week,” etc., but not relative to _now_ , you can specify your reference datetime starting point. This is especially useful in data pipelines or logs with a known “base” time you want to treat as “current.”

```python import dateparserfrom datetime import datetimeprint('Now: ',datetime.now())print()reference_time = datetime(2024, 12, 26, 9, 0, 0) # 2024-12-26 09:00:00print('Reference: ', reference_time)# relative to the new base reference date/timedt_custom_ref = dateparser.parse( "yesterday at 6pm", settings={"RELATIVE_BASE": reference_time})print('Yesterday, 6PM: ', dt_custom_ref) ```

### Searching for Date Strings in a Larger Text

Dateparser can scan longer pieces of text and pick out dates and times mentioned in them.

```python from dateparser.search import search_datesimport dateparserfrom datetime import datetimeprint('Now: ', datetime.now())print()text = """Our first meeting was two weeks ago. Then we met again today. Let's plan the next meeting in 10 days time.Call me in an hour from now to confirm"""results = search_dates(text)for (date_str, dt_obj) in results: print(f"Found '{date_str}' -> {dt_obj}")>>>>>>>>>>Now: 2024-12-28 18:31:09.894924Found 'two weeks ago' -> 2024-12-14 18:31:09.961449Found 'today' -> 2024-12-28 18:31:09.961449Found 'in 10 days' -> 2025-01-07 18:31:09.961449Found 'in an hour' -> 2024-12-28 19:31:09.961449 ```

If you work a lot with date and time data in Python, you could do a lot worse than take a look at the dateparser library.

It’s a powerful and flexible tool for parsing human-readable date and time strings into `datetime` objects. It supports a wide variety of date and time formats, including natural language expressions and formats from multiple languages and locales.
