## Danube3–0.5-chat

h2o-danube3–500m-chat is a chat fine-tuned model by H2O.ai with 500 million parameters. According to the[ model card on Hugging Face Hub](<https://huggingface.co/h2oai/h2o-danube3-500m-chat>) it can be run natively and fully offline on phones — and you can try it yourself with [H2O AI Personal GPT](<https://h2o.ai/platform/danube/personal-gpt/>).

### Model Architecture

H2O adjusted the Llama 2 architecture for a total of around 500m parameters. For details, we can refer to the [Technical Report](<https://arxiv.org/abs/2407.09276>). The Team decided to use the Mistral tokenizer with a vocabulary size of 32,000 and train the model up to a context length of 8,192 tokens.

## What we can do with this model?

I would say that even if it is so small, you can really ask anything to Danube3. There is enough context length to have some in context Learning, Chain of Thought and RAG.

Honestly I don’t like using a chat model for math problems or complex multi hop reasoning: for that maybe it is too early, and there are dedicated models. But as a work or study assistant, this 500 Million parameters model is a rockstar!

### Import the libraries

This is a necessary step.

```python import streamlit as stimport datetimeimport osimport warningswarnings.filterwarnings(action='ignore')import tiktokenimport randomimport stringfrom time import sleep# this is to count the tokensencoding = tiktoken.get_encoding("r50k_base") ```

The basic settings for the chat and Streamlit interface are the following:

``` #AVATARS 👷🐦 🥶🌀av_us = 'man.png' #"🦖" #A single emoji, e.g. "🧑‍💻", "🤖", "🦖". Shortcodes are not supported.av_ass = 'h2oAI.jpg'modelname = 'h2o-danube3-500m-chat'modelfile = 'h2o-danube3-500m-chat-Q8_0.gguf'# Set the webpage titlest.set_page_config( page_title=f"Your LocalGPT with 🌟 {modelname}", page_icon="🌟", layout="wide") ```

Then we have 2 important functions: the first one is included in the `@st.cache_resource` decorator. This is really important, because this function will not be rerun every time, but only once!

The second one is to write a text file with the logs of your chatbot.

```python @st.cache_resource def create_chat(): # Set HF API token and HF repo from llama_cpp import Llama llm = Llama( model_path='models/h2o-danube3-500m-chat-Q8_0.gguf', n_gpu_layers=0, temperature=0.1, top_p = 0.5, n_ctx=8192, max_tokens=300, repeat_penalty=1.45, stop=['</s>'], verbose=True, ) print(f'loading {modelfile} with LlamaCPP...') return llmdef writehistory(filename,text): with open(filename, 'a', encoding='utf-8') as f: f.write(text) f.write('
') f.close() ```

Note that the initial settings for the model will be changed during the inference time (`temperature`, `max_tokens`, `top_p `and `repeat_penalty`).

The next part is for the main window elements: we will also use a function to assign a random alpha-numeric code to identify our log file, and store it into a global variable (in streamlit these special objects are called `session_state `and they persist even when you rerun the application).

```python # Create a header elementmytitle = f'<p style="color:DarkOrange; font-size: 32px;text-align:center;"><b>Your own LocalGPT with 🌟 {modelname}</b></p>'st.markdown(mytitle, unsafe_allow_html=True)subtitle = '<p style="color:DeepSkyBlue; font-size: 20px;text-align:center;"><b><i>Powerwed by Danube3-chat - 0.5b parameter model. 8k conext window</i></b></p>'st.markdown(subtitle, unsafe_allow_html=True)def genRANstring(n): """ n = int number of char to randomize """ N = n res = ''.join(random.choices(string.ascii_uppercase + string.digits, k=N)) return res# create THE SESSIoN STATESif "logfilename" not in st.session_state:## Logger file logfile = f'{genRANstring(5)}_log.txt' st.session_state.logfilename = logfile #Write in the history the first 2 sessions writehistory(st.session_state.logfilename,f'{str(datetime.datetime.now())}

Your own LocalGPT with 🌀{modelname}
---
🧠🫡: You are a helpful assistant.') writehistory(st.session_state.logfilename,f'🌀: How may I help you today?') ```

The first time the log filename is initiated, we also set a timestamp and a header in the text file.

Now we declare all the other global variables and we call the function to instantiate the llm with llama-cpp-python. You may see in the terminal, when you run the app) all the verbose details of the GGUF file: it can be disabled changing the parameter `verbose=False` in the `create_chat()` function.

``` if "len_context" not in st.session_state: st.session_state.len_context = 0if "limiter" not in st.session_state: st.session_state.limiter = 0if "bufstatus" not in st.session_state: st.session_state.bufstatus = "**:green[Good]**"if "temperature" not in st.session_state: st.session_state.temperature = 0.1if "repeat" not in st.session_state: st.session_state.repeat = 1.2if "maxlength" not in st.session_state: st.session_state.maxlength = 500# Point to the local serverllm = create_chat() ```

### The Chat messages

Modern Chat LLM use chat-template format to interact with the models. In this part we are setting the list of messages following the official template: you can customize it.

Note that I left also the system message, that this model cannot support: I wanted to give you a Streamlit app easily customizable with other models.

```python # We initialize it with the first message we want to be greeted with.if "messages" not in st.session_state: st.session_state.messages = [ {"role": "system", "content": "You are Danube3-chat, a helpful assistant. You reply only to the user questions. You always reply in the language of the instructions.",}, {"role": "user", "content": "Hi, I am Fabio."}, {"role": "assistant", "content": "Hi there Fabio, I am Danube3-chat: with my 0.5b parameters I can be useful to you. how may I help you today?"} ]def clearHistory(): st.session_state.messages = [ {"role": "system", "content": "You are Danube3-chat, a helpful assistant. You reply only to the user questions. You always reply in the language of the instructions.",}, {"role": "user", "content": "Hi, I am Fabio."}, {"role": "assistant", "content": "Hi there Fabio, I am Danube3-chat: with my 0.5b parameters I can be useful to you. how may I help you today?"} ] st.session_state.len_context = len(st.session_state.messages)if btnClear: clearHistory() st.session_state.len_context = len(st.session_state.messages) ```

The `clearHistory()` function will delete the old chat messages from the interface. Note that in this application we do not stack the old messages in the prompt (it means that the model will not remember what you asked before…): it is easy to do it, but we need to add more conditions to avoid going over the context window. When you have a longer prompt than the context window the model will give you an error and abort the generation.

Finally we render all the messages in the list to display them in the Chat interface: this is required because Streamlit reruns the code every time there is a change or an event.

```json # We loop through each message in the session state and render it as# a chat message.for message in st.session_state.messages[1:]: if message["role"] == "user": with st.chat_message(message["role"],avatar=av_us): st.markdown(message["content"]) else: with st.chat_message(message["role"],avatar=av_ass): st.markdown(message["content"]) ```

## Accept user input and generate the AI response

This code snippet may look scary… don’t worry I am explaining it all!

```json # We take questions/instructions from the chat input to pass to the LLMif user_prompt := st.chat_input("Your message here. Shift+Enter to add a new line", key="user_input"): # Add our input to the session state st.session_state.messages.append( {"role": "user", "content": user_prompt} ) # Add our input to the chat window with st.chat_message("user", avatar=av_us): st.markdown(user_prompt) writehistory(st.session_state.logfilename,f'👷: {user_prompt}') with st.chat_message("assistant",avatar=av_ass): message_placeholder = st.empty() with st.spinner("Thinking..."): response = '' conv_messages = [] #conv_messages.append({"role": "system", "content": "You are a helpful AI assistant."}) conv_messages.append(st.session_state.messages[-1]) st.session_state.len_context = len(st.session_state.messages) st.session_state.bufstatus = "**:green[Good]**" full_response = "" for chunk in llm.create_chat_completion( messages=conv_messages, temperature=st.session_state.temperature, repeat_penalty= st.session_state.repeat, stop=['</s>'], max_tokens=st.session_state.maxlength, stream=True,): try: if chunk["choices"][0]["delta"]["content"]: full_response += chunk["choices"][0]["delta"]["content"] message_placeholder.markdown(full_response + "🌟") except: pass toregister = full_response + f"""```prompt tokens: {len(encoding.encode(st.session_state.messages[-1]['content']))}generated tokens: {len(encoding.encode(full_response))}```""" message_placeholder.markdown(toregister) writehistory(st.session_state.logfilename,f'🌟: {toregister}

---

') # Add the response to the session state st.session_state.messages.append( {"role": "assistant", "content": toregister} ) st.session_state.len_context = len(st.session_state.messages) ```

In the first lines we wait for the user to send a prompt: when we press Enter we render the input message on the Chat interface and start the generation call.

The Generation is identified by `with st.chat_message(“assistant”,avatar=av_ass):` in this loop we take only the last message in the history (our prompt) and we feed it to the `llm`.

When we call the `chat_completion `method we ask `llama-cpp-python` to stream back to us the AI generation token by token. At the end of the generation we add also information about the token in the prompt and in the output using `tiktoken`.

Finally we save the generated text into the `st.session_state.messages` to render it in the Chat interface.
