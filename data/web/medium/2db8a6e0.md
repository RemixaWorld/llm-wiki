## Introduction

If you’re a hedge fund manager managing an investment portfolio, your goal is to maximize returns by year-end. However, you have limits on how much or when you can invest in certain assets. This is where Mixed-Integer Linear Programming (MILP) comes in.

I use a practical example — optimizing shift schedules for customer service agents — to show its application. After reading this paper, you may discover many other valuable uses of MILP in your field.

Additionally, this paper will show you how to set up an optimization model, translating real-world problems into mathematical terms when balancing goals and constraints.

## Project Overview

> Imagine you’re managing a call center with five agents.
>
> Every day, you assign them to one of the shifts: early (E) or late (F). The challenge is to balance the workload while ensuring the agents don’t work too many consecutive days. Shifts should be distributed fairly among the agents to prevent any one person from being overloaded.
>
> You have a 30-day month with two shifts per day and five agents. One key rule is that no agent should work more than five consecutive days. In addition, each agent can only work one shift per day. These are constraints that must be followed when assigning shifts.

This project aims to ensure a fair distribution of shifts among the agents. This is done by minimizing the workload variance — the difference between the total number of shifts assigned to each agent. For example, if Agent 1 works 20 shifts and Agent 2 works 15, the imbalance is 5. The smaller this difference, the more evenly the workload is distributed.

In short, we minimize workload imbalances across agents while ensuring shifts are fairly distributed throughout the month, all within the given constraints.

## Understanding Integer Linear Programming (MILP)

In an optimization project, knowing how to translate a problem into a math model is often more important than solving it. For instance, if you know how to fix a car, you’re much better at using it. Knowing how to solve a problem is like having that mechanical knowledge — it helps you avoid breakdowns and make better decisions.

Let’s revisit the investment example. You’re managing a portfolio and deciding how much to invest in two assets, stocks A and B. Your goal is still to maximize returns but with some added restrictions. Unlike before, where you could buy fractional shares, now you’re limited to whole numbers — meaning 2 or 3 shares, not 2.5. And, of course, your total investment has to stay within a fixed budget.

So how do you allocate your money wisely under these constraints? We will use this example to illustrate how to solve Mixed-Integer Linear Programming (MILP).

**The Linear Part**

Let’s start simple. Suppose you have a basic linear problem. If you want to maximize your profit, say:

Now, you can’t invest more than your budget. You have $100, and each stock costs $10 and $15, respectively. Your budget constraint would look like this:

This is a typical Linear Programming (LP) problem, where you can buy fractions of shares.

LP problems can be visualized as polygon shapes because the objective function and constraints form geometric boundaries. These constraints, written as linear equations or inequalities, create straight boundary lines. These lines define a “feasible region” often shaped like a polygon (or polyhedron in more dimensions), where every point represents a possible solution. However, the optimal solution can only be found at partial vertices.

Now imagine you’re trapped inside this polygon. The only way out is through the vertices, where the lines intersect. To escape, one feasible way is to walk along the edges, testing each vertex (exit) to find the best one that maximizes your profit. This is how the **Simplex Method** works.

The Simplex Method is one of the most widely used techniques for solving LP problems. Many software tools, like MATLAB, Excel Solver, and Python’s PuLP, offer built-in functions for applying the Simplex algorithm to optimization problems.

**The Integer Part**

But here’s where things get tricky. Stocks don’t come in fractions — no one wants to buy 1.7 shares. You need whole numbers for _x_1_ ​ and _x_2_ ​, meaning they are integers.

This changes everything. Instead of solving in a smooth, continuous space, you’re dealing with specific points — no fractions allowed. MILP handles this by looking for integer solutions that still fit the budget.

Now, I will introduce one of the solutions — Branch and Bound.

Assuming the LP solver finds that the best solution is to buy 4.5 shares of stock A and 3.2 shares of stock B. This isn’t realistic. So, MILP splits the problem in two:

* What if I round _x_1_ ​ down to 4 and solve again?
* What if I round _x_1_ ​ up to 5 and solve again?

It does the same for _x_2_ ​and keeps doing it until it finds the best combination of whole numbers for _x_1_ and _x_2_ ​. This process is called **branching**.

And to make it faster, MILP uses bounding to stop exploring paths that clearly won’t work. For example, if buying 5 shares of stock A breaks your budget, MILP won’t even bother checking that path. It sets a ‘bound’ and ‘Nope’.

## Implementation

To solve this problem, we use the Simplex algorithm via the Pulp package in Python. Even though the Simplex method is highly effective for solving LP problems, it can also handle Mixed-Integer Linear Programming (MILP) for our customer service scheduling problem.

The code below solves a scheduling problem using Mixed-Integer Linear Programming (MILP). It assigns shifts to customer service agents over a given period (30 days) while minimizing workload variance and adhering to constraints like shift limits and consecutive workdays. Below is a step-by-step explanation focusing on the algorithmic and mathematical aspects.

1\. **Set** p**arameters**

``` num_days = 30 num_agents = 5 shifts = ['E', 'F']max_consecutive_days = 5 min_shifts_per_day = 1 ```

Here, the parameters define the key components of the problem:

* _num_days:_ Time horizon for the scheduling.
* _num_agents:_ The number of agents to be scheduled.
* _shifts:_ Two shifts a day (_E_ for early and _F_ for late).
* _max_consecutive_days:_ A constraint to prevent agents from working too many consecutive days.
* _min_shifts_per_day:_ Minimum number of shifts per day

2\. **Defining the MILP**

``` prob = pulp.LpProblem("SchedulingProblem", pulp.LpMinimize) ```

This defines a linear optimization problem using PuLP to minimize the objective function. The objective is to minimize the variance in workloads (i.e., make the workloads as balanced as possible among the agents).

3\. **Decision Variables**

``` x = pulp.LpVariable.dicts("x", ((i, d, s) for i in range(num_agents) for d in range(num_days) for s in shifts), cat='Binary') ```

This creates the binary decision variables _x[i, d, s]_ , where:

* _i_ : The agent.
* _d_ : The day.
* _s_ : The shift ( _E_ or _F_).

The binary decision variable _x[i,d,s]_ equals 1 if agent _i_ is assigned to shift _s_ on day _d_ , and 0 otherwise.

This results in 5*30*2=300 binary decision variables for the scheduling problem.

4\. **Objective Function: Minimizing Workload Variance**

``` workload_variance = pulp.LpVariable("workload_variance", lowBound=0, cat='Continuous')workloads = [pulp.lpSum([x[i, d, s] for d in range(num_days) for s in shifts]) for i in range(num_agents)] ```

* workload_variance: A continuous variable that represents the variance in workloads across agents. It is the variable being minimized.
* workloads[i]: This is the total number of shifts assigned to agent _i_ over the 30 days. It sums up the binary variables for each agent across all days and shifts:

5\. **Minimization of Workload Variance**

``` prob += workload_variance ```

This sets the objective function as minimizing the variance across the workloads.

6\. **Constraints**

a) One shift per day:

``` for i in range(num_agents): for d in range(num_days): prob += pulp.lpSum([x[i, d, s] for s in shifts]) <= 1 ```

This ensures that each agent works at most one shift per day. The constraint can be written as:

b) At least one agent per shift:

``` for d in range(num_days): prob += pulp.lpSum([x[i, d, 'E'] for i in range(num_agents)]) >= 1 prob += pulp.lpSum([x[i, d, 'F'] for i in range(num_agents)]) >= 1 ```

This means at least one agent must be assigned to each shift (early and late). The constraints ensure that every day has an agent for both shifts:

c) Maximum consecutive workdays:

``` for i in range(num_agents): for d in range(num_days - max_consecutive_days): prob += pulp.lpSum([x[i, d+k, s] for k in range(max_consecutive_days) for s in shifts]) <= max_consecutive_days ```

This constraint ensures that no agent works more than 5 consecutive days. It applies a sliding window of size 5 days, ensuring that the total number of shifts within any 5 consecutive days is at most 5. In mathematical terms, this can be expressed as:

d) Balance workload variance:

``` for i in range(num_agents): prob += workloads[i] - workload_variance <= 0 prob += workload_variance - workloads[i] <= 0 ```

These constraints minimize the difference between each agent’s total workload and the overall variance. This implies the variance captures the difference between the heaviest and lightest workloads.

7\. **Solving the Problem**

``` prob.solve() ```

The problem is solved using a solver (like CBC or GLPK), which handles the Mixed-Integer Linear Programming (MILP). The solver will find the optimal schedule that minimizes workload variance while satisfying the constraints.

**8\. Result**

After solving, the results are displayed. For each agent, day, and shift, the schedule is printed only if the agent is assigned to a particular shift.

``` for i in range(num_agents): print(f"Agent {i+1}'s schedule:") for d in range(num_days): for s in shifts: if pulp.value(x[i, d, s]) == 1: print(f" Day {d+1}: Shift {s}") ```

## Model Validation

To ensure the model works correctly, we need to validate it.

Validation involves checking whether the model meets the requirements and constraints, such as minimizing workload variance and ensuring no agent works more than three consecutive days. The key steps in validating the MILP model include:

1. **Constraint Checking:** Verify that no agent is assigned more than one shift per day, and that early (E) and late (F) shifts are covered.
2. **Workload Balancing:** Check that the model correctly balances the workloads among the agents, ensuring that the variance is minimized.
3. **Consecutive Days Rule:** Confirm no agent works more than 5 consecutive days.

To validate, we’ll compare the model’s outputs against these rules using code that checks each constraint.

Here is the validation code:

``` # Validationerrors = []for i in range(num_agents): # Check for more than one shift per day for d in range(num_days): if sum(pulp.value(x[i, d, s]) for s in shifts) > 1: errors.append(f"Agent {i+1} has more than one shift on Day {d+1}") # Check for consecutive days constraint for d in range(num_days - max_consecutive_days + 1): if sum(pulp.value(x[i, d + k, s]) for k in range(max_consecutive_days) for s in shifts) > max_consecutive_days: errors.append(f"Agent {i+1} works more than {max_consecutive_days} consecutive days starting on Day {d+1}")if errors: print("Model validation failed with the following errors:") for error in errors: print(error)else: print("Model validation passed!") ```
