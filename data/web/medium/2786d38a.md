## Intro — Cursor AI is beyond co-pilot

If you think that a picture is worth 1000 words, then a video should be worth like a 100,000? Anyhow, you can watch me go over all of the sections live on my channel.

This is a power tool that lets you describe what you want and get it. What’s special about it? Why not continue using web based code assistance? Or just use a co-pilot?

> Cursor AI allows you to stay within the IDE’s without ever wanting to leave.

It lets you choose the context you need, without copy pasting. It knows your whole project and understands its structure. It manipulates the files in an iterative way letting you reject and apply the changes visually by showing a diff (similar to code diff tools). Web based flow is great for quick patches but working in Cursor AI does feel like working with another person, for better and worse.

In the following blog I showcase 5 examples of how I am using it in my flow:

1. Staying in control by providing a spec
2. Manipulating non-code files (.csvs, .txt). Bonus for data scientists
3. Ask to create tests even after method generation
4. Multiple files for context — great for refactoring
5. Debugging command line errors

I’ve totally incorporated Cursor into my flow, but only under my side projects. Why only side projects?

> Warning: Be mindful when using it for production! **You’ll understand the code less than if you wrote it yourself.** Writing code is often easier than reading it.

## 1\. Staying in control by providing a spec

First tip — always start with a spec. You can have a UML, a sketch, an image, whatever fits you.

When using code assistants it’s invaluable to know where you headed. When working with AI assistants you suddenly become a manager of sorts or a tech lead. So what does a good technical manager who is a bit obsessed with quality? He writes a spec for his colleagues.

The better you understand yourself what and how you want to accomplish, the better you will be able to understand the proposed AI solution.

## 2\. Manipulating non-code files (.csvs, .txt). Bonus for data scientists

Data scientist are used to stare at .csv files or other type of aggregated information. There are times that you want to create some local transformations for example to fix some error in the format.

Up until now you had to write code for it and specify what exactly do you need. With Cursor AI you pick the right context and ask the right question.

A small caveat, if the .csv is large, any manipulation on top of it (without code) can take a while.

As a data scientist I constantly do varios error analysis routines. Looking at the input, model output and annotations is a huge chunk of my work. There are ways to do automatic weak labeling by using LLMs, this is not new. What’s different with Cursor AI is that I can do this kind of labeling without writing any code!

## 5\. Debugging command line errors

This is by far my favourite tip. We often get runtime errors. This is the nature of our work, code crashes in different unexpected ways. This happens not only with your code but also installing dependencies, running tests from the wrong context and so forth.

The positive side of this is the error message. This is a breadcrumb to lead you to the solution, unlike logical errors that can happen and are X10 harder to debug.

With Cursor AI you can use the error message, without leaving the comfy space that is the IDE, and add it in the prompt for Cursor to help you debug it.
