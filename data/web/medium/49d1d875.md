[FLUX.1](<https://blackforestlabs.ai/announcing-black-forest-labs/>) took the world by storm, and in this post, I’ll walk you through how to train a LoRA (Low-Rank Adaptation) on custom images, enabling FLUX1 to learn specific styles or characters and reproduce them.

I chose something a bit unusual as my target: X-ray images!

![Spoiler alert: all these X-rays are hallucinated.](https://miro.medium.com/v2/resize:fit:1000/1*fRPvnAiCtCtC8HHzBkDWdA.png)

This guide will show you how to train a LoRA like this yourself, on photos of yourself, styles or any kind of image; in under an hour using the [AI Toolkit](<https://github.com/ostris/ai-toolkit>) by [Ostris](<https://x.com/ostrisai>) and a cheap cloud GPU or your home setup.

### Step 5: Start training

Define the training parameters:

``` INPUT_FOLDER = "/workspace/images"OUTPUT_FOLDER = "/workspace/output"TRIGGER_WORD = "eksray"LORA_RANK = 16BATCHSIZE = 1LEARNING_RATE = 0.0001STEPS_TRAIN = 3000STEPS_SAVE = 250STEPS_SAMPLE = 250 ```

* **Trigger word** (`TRIGGER_WORD`): Can be any word that FLUX1 is not yet familiar with. This unique word (e.g., `eksray`) will trigger the features we’ve trained on. If your caption text files do not contain the trigger word, it will be added automatically.
* **LoRA rank** (`LORA_RANK`): Balances trainable parameters and model capacity . Higher ranks might be needed for more complex adaptations but require more VRAM. In my experience `16` is a good start but with the X-Rays, the generations are definitely better with a higher rank like `32`.
* **Batch size** (`BATCHSIZE`): A low batch size of `1` minimizes VRAM usage and reduces the risk of running out of memory, but slows down training and might not fully utilize the GPU's capabilities. Again, higher batch size requires more VRAM and with a 24GB VRAM GPU we are stuck with a batch size of `1`.
* **Learning rate** (`LEARNING_RATE`): Specifies how much the weights are changed in direction of the gradient during each update step. I chose `0.0001` here which is what most trainers use as a starting point. Training on characters (faces) also works with a higher LR of `0.0004`. Higher values will still yield a good adapter depending on the dataset but everything above `0.001` is not a good idea in my experience.
* **Training steps** (`STEPS_TRAIN`): Provides sufficient training time to learn desired features, but can be time-consuming. I went for `3000` steps for the X-Rays but depending on the training set and the other parameters you can expect nice results with as few as `500`to `1000` steps.
* **Save steps** (`STEPS_SAVE`): How often to save an adapter. I suggest to keep this low and save often to see at which point the generations start looking like what you expect and what this point is passed (overtraining)
* **Sample steps** (`STEPS_SAMPLE`): How often to generate sample images.

Create a dictionary containing all the parameters for AI Toolkit.

```python from collections import OrderedDictjob_to_run = OrderedDict([ ('job', 'extension'), ('config', OrderedDict([ # this name will be the folder and filename name ('name', 'my_first_flux_lora_v1'), ('process', [ OrderedDict([ ('type', 'sd_trainer'), ('training_folder', OUTPUT_FOLDER), ('performance_log_every', 100), ('device', 'cuda:0'), ('trigger_word', TRIGGER_WORD), ('network', OrderedDict([ ('type', 'lora'), ('linear', LORA_RANK), ('linear_alpha', LORA_RANK) ])), ('save', OrderedDict([ ('dtype', 'float16'), # precision to save ('save_every', STEPS_SAVE), # save every this many steps ('max_step_saves_to_keep', 10) # how many intermittent saves to keep ])), ('datasets', [ # datasets are a folder of images. captions need to be txt files with the same name as the image # for instance image2.jpg and image2.txt. Only jpg, jpeg, and png are supported currently # images will automatically be resized and bucketed into the resolution specified OrderedDict([ ('folder_path', INPUT_FOLDER), ('caption_ext', 'txt'), ('caption_dropout_rate', 0.05), # will drop out the caption 5% of time ('shuffle_tokens', False), # shuffle caption order, split by commas ('cache_latents_to_disk', True), # leave this true unless you know what you're doing ('resolution', [512, 768, 1024]) # flux enjoys multiple resolutions ]) ]), ('train', OrderedDict([ ('batch_size', BATCHSIZE), ('steps', STEPS_TRAIN), # total number of steps to train 500 - 4000 is a good range ('gradient_accumulation_steps', 1), ('train_unet', True), ('train_text_encoder', False), # probably won't work with flux ('content_or_style', 'balanced'), # content, style, balanced ('gradient_checkpointing', True), # need the on unless you have a ton of vram ('noise_scheduler', 'flowmatch'), # for training only ('optimizer', 'adamw8bit'), ('lr', LEARNING_RATE), # ema will smooth out learning, but could slow it down. Recommended to leave on. ('ema_config', OrderedDict([ ('use_ema', True), ('ema_decay', 0.99) ])), # will probably need this if gpu supports it for flux, other dtypes may not work correctly ('dtype', 'bf16') ])), ('model', OrderedDict([ # huggingface model name or path ('name_or_path', 'black-forest-labs/FLUX.1-dev'), ('is_flux', True), ('quantize', True), # run 8bit mixed precision #('low_vram', True), # uncomment this if the GPU is connected to your monitors. It will use less vram to quantize, but is slower. ])), ('sample', OrderedDict([ ('sampler', 'flowmatch'), # must match train.noise_scheduler ('sample_every', STEPS_SAMPLE), # sample every this many steps ('width', 1024), ('height', 1024), ('prompts', [ # you can add [trigger] to the prompts here and it will be replaced with the trigger word 'xray of a Boeing 747 [trigger]', 'xray of a woman holding a coffee cup [trigger]', 'xray of a dog [trigger]', ]), ('neg', ''), # not used on flux ('seed', 42), ('walk_seed', True), ('guidance_scale', 4), ('sample_steps', 20) ])) ]) ]) ])), # you can add any additional meta info here. [name] is replaced with config name at top ('meta', OrderedDict([ ('name', '[name]'), ('version', '1.0') ]))]) ```

And we are ready to start training our adapter:

```python import osimport syssys.path.append('/workspace/ai-toolkit')from toolkit.job import run_jobrun_job(job_to_run) ```

## Results

I trained the model for `3000`steps with a learning rate of `0.0001`. Initially, the results were underwhelming.

![Prompt: “alien head”](https://miro.medium.com/v2/resize:fit:1000/1*vlC-h2Pi7k5wvVfhDGzmfA.jpeg)

However, I noticed that adding “X-ray of” to the prompt significantly improved the results.

![Prompt “Xray of a Boeing 747” without the adapter (left) and with the adapter loaded (right)](https://miro.medium.com/v2/resize:fit:1000/1*esEP6KxSBEmZCU6GGsqURw.jpeg)

This consistently gave me what I was looking for with a LoRA scale of `1.0`.

![Prompt “Xray of ..“: “a Boeing 747”, “a tyrannosaurus Rex”, “a skyscraper”, “a man who was shot in the head”](https://miro.medium.com/v2/resize:fit:700/1*APb-VazSRhRxI6QhJduFmg.png)

This is all prompted without the trigger word. Adding the trigger word makes the images more X-Ray-like, mostly perfect front/side views and less blue.

![image](https://miro.medium.com/v2/resize:fit:700/1*aO_lAdJJ1zfSauN02in9og.jpeg)

Another interesting thing I noticed is that prompts with features that cannot be expressed on an X-Ray yield images that are partially “real.” For example, “happy family” versus “family.”

![“xray of a happy family” (left) versus “xray of a family” (right)](https://miro.medium.com/v2/resize:fit:700/1*0HFkAOVlnLytmfaMBzh0Gw.png)

## Summary

In this blog post, we walked through the process of **training FLUX1-dev on images**. I chose X-rays for this example, but you can use any type of image, including **photos of yourself or specific styles**. The default parameters are a good starting point, but you might want to use **higher ranks** on a more powerful GPU to ensure the model learns all the features you value. **Increasing the learning rate** might allow you to use fewer steps, depending on your training set.
