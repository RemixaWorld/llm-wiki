**Challenges of High-Dimensional Vectors in Production**

While embeddings provide significant value to generative AI applications, they also present unique challenges in production.

**Storage Costs:** Embeddings are numerical representations, often stored as 32-bit floating-point numbers with high dimensionality. When you multiply the large number of data points by the high dimensions, the result is substantial storage requirements. For example, as illustrated in an article by HuggingFace, storing 250 million embeddings with 1,024 dimensions can cost approximately $3,600 per month on platforms like AWS when stored in float32 format.

**Computational Complexity and Latency:** Just as reading a 300-page novel takes longer than reading a 2-page poster, high-dimensional embeddings increase the time and computational power required for calculations and searches. This becomes especially critical in real-time production applications, where speed is paramount. For instance, if a user requests a recommendation for the nearest Indian restaurant, latency can negatively affect the user experience, potentially causing them to switch to another application. We’ll explore indexing techniques like Hierarchical Navigable Small World (HNSW) later.

**Financial Implications for Scalability:** As AI applications gain popularity and user engagement grows with increasing intelligence, the high storage and computational costs can create financial barriers to achieving optimal ROI. Data volumes can grow significantly before the user base/query volume significantly scales, yet indexing and serving vectors can be prohibitively expensive and prevent these use cases from getting off the ground.

## Before State: Navigating Without a Shrink Ray

As previously mentioned, embeddings require significant storage space and are computationally intensive. To manage these large vectors, various indexing techniques can enhance search speed. One popular method is Apache Lucene’s Hierarchical Navigable Small World (HNSW) indexing, which accelerates the search for embeddings by navigating through a graph of embeddings. However, HNSW has its limitations, as the graph must be stored in RAM for optimal efficiency. Now, let’s explore how HNSW operates in more detail.

### Understand the concept of HNSW

Let’s explore a small world together. You are currently in Paris as a tourist and are searching for the Airbnb you booked in Maisons-Alfort for tonight. Fortunately, you were able to rent a car as soon as you arrived from your flight. Transportation within Paris can be modeled as a multi-level graph:

* First, you drive on highways to bypass many neighborhoods and quickly reach the district where the Airbnb is booked.
* Once you exit the highway, main roads will guide you through the district to reach the nearest neighborhoods where your hotel is located.
* After crossing a few small streets, you will arrive directly at your Airbnb.

Hierarchical Navigable Small World

Thanks to this Hierarchical Navigable Small World, the system guides the search in a hierarchical way, quickly narrowing down the search results instead of wandering.

The HNSW algorithm in Apache Lucene enables fast approximate nearest neighbor (ANN) searches in high-dimensional spaces. It builds a multi-layered graph, where each node represents a high-dimensional vector, and edges connect similar nodes. This graph structure allows the search algorithm to efficiently navigate the vector space by moving between neighboring nodes, significantly speeding up the search process.

### Challenges with HNSW

Remember that creating this “graph” of the high-dimensional world requires a lot of resources.

* **Memory-Intensive Nature** : all the embeddings and their connections are stored in memory to build the graph. More embeddings require more memory to serve low-latency queries.
* **Segment Builds and Merges** : In Lucene, data is divided into segments. When new data with new embeddings is added, the system must process and reorganize the vectors and HNSW graph. This process is similar to updating a large map every time a new landmark appears or when roads are restructured. It is a time-consuming and resource-intensive task. Segment merging also requires additional resources and will occur as a background process according to a merge policy.

## Quantization Techniques

Vector quantization compresses embeddings into smaller forms, reducing their storage requirements. This makes it possible to scale Gen AI applications by reducing their constantly increasing cost.

Quantization reduces the precision of vector data, effectively “shrinking” each vector’s size. We will explore the following most popular quantization techniques:

* **Scalar Quantization** reduces the precision of each element in a vector to a predefined set of levels like int8
* **Binary Quantization** compresses vectors by converting each element to a binary value, such as 0 or 1
* **Product Quantization** splits each vector into smaller sub-vectors, each quantized separately and looked up via PQ codebooks

### Why Vector Quantization is Essential in Production

In production, vector quantization has become increasingly crucial for three reasons:

1\. **Significant Storage Cost Reductions** :

Vector quantization reduces the storage size of embeddings, which ultimately leads to a reduction in storage costs. According to the HuggingFace[ article](<https://huggingface.co/blog/embedding-quantization>), scalar or binary quantization can result in**a 32x reduction in storage size while maintaining around 73–96% of the original accuracy**. These storage reductions can directly decrease the monthly costs of cloud storage platforms.

### Vector Quantizations

Each type of quantization offers unique advantages, allowing production systems to customize storage and performance optimizations to their specific needs.

### Scalar Quantization: The Simplest Shrink Ray

Scalar quantization is a method that can reduce the size of data by simplifying numbers. It involves taking a collection of precise numbers with many decimal points (e.g., 0.123456) and rounding them to smaller options. For each dimension in the vector, a maximum and minimum is determined across all of the vectors in the dataset. Evenly sized bins are produced between these values, 255 in the case of int8 scalar quantization to correspond to the 255 unique values than can be represented by a signed integer. Each element is then mapped to the bin that it corresponds to. When repeated across every dimension of the vector, an int vector can be produced from a floating point vector.

Although we may sacrifice some precision, the overall meaning of the data remains largely unchanged and there is still plenty of representational capacity leftover. This is particularly valuable for applications such as image compression, audio files, and machine learning models, where a slight reduction in detail still yields satisfactory results while significantly conserving storage space.

### Binary Quantization: Simplifying Data with a Binary Twist

Binary quantization simplifies each embedding to just two values: 0 or 1. This method involves a straightforward decision-making process: if a number is above zero, it’s represented as 1; if it’s zero or below, it’s represented as 0. For example, if you have temperature readings from different cities, instead of storing the exact temperature values, binary quantization only notes whether each temperature is above or below 0. Note that this method assumes vectors are L2-normalized between -1 and 1. Distribution-aware binary quantization, similar to what was performed for scalar quantization in the previous section, can also be applied in scenarios where this assumption does not hold.

### Product Quantization: The Art of Efficient Data Compression

Product Quantization involves splitting a large, high-dimensional vector into shorter segments called sub-vectors. Each sub-vector is individually quantized, simplifying it into smaller values by rounding off numbers to the nearest whole number.

**How PQ Works?**

1\. **Splitting** : The large vector is initially divided into equally-sized chunks or sub-vectors.

2\. **Quantizing** : Each sub-vector is then matched to the closest “centroid” from a predefined list known as a codebook. Centroids act as representative averages that summarize groups of similar items.

3\. **Encoding** : Finally, each sub-sector’s centroid is replaced with a unique ID, effectively reducing the data needed to represent the original vector. Instead of storing detailed information for each sub-vector, only the ID of its nearest centroid is kept.

**Binary Quantization** is the fastest and most memory-efficient, offering up to 30x storage reduction and significant speed improvements. However, it is most suitable for models with a centered distribution of vector components. Use this method in production only with models that have been thoroughly tested under binary quantization conditions.

**Scalar Quantization** is suggested as the default quantization method when binary quantization is not suitable, particularly for applications where high accuracy is crucial, providing a universal approach that balances accuracy, speed, and storage savings.

**Product Quantization** offers higher compression but may result in a performance decrease. It is recommended for applications where memory footprint is the top priority and retrieval speed is less critical.

## Addressing Recall Loss in Quantized Models: Production-Ready Solutions

Quantization methods offer significant storage and speed benefits, but they can also result in recall loss, which means relevant items may not be retrieved due to reduced precision. In user-facing applications, maintaining high recall accuracy is crucial in production settings. Two main strategies — rescoring and oversampling — can help address these issues.

### Oversampling

**Oversampling** retrieves a larger number of candidates to increase the possibility of including relevant items. For example, instead of retrieving the top 10 results, oversampling retrieves the top 50.

### Rescoring

**Rescoring** involves refining search results by recalculating the similarity of top candidates with high-precision vectors. After an initial retrieval using quantized vectors:

* **Accuracy Boost** : The top results are re-evaluated using the original float32 vectors, improving relevance and ranking.
* **Selective Application** : Only a subset of candidates is rescored, typically the top 10% or 20%, minimizing computational overhead.

This technique is instrumental in recommendation systems, where relevant items must be accurately prioritized.

### Combining Rescoring and Oversampling

In a production recommendation engine:

1\. **Initial Quantized Search** : Quickly retrieves a larger set of candidates using quantized vectors.

2\. **Oversampling** : Retrieves more candidates to capture additional relevant items.

3\. **Rescoring** : Applies high-precision rescoring to the top results, ensuring the final recommendations are highly accurate and relevant.

These techniques balance the efficiency of quantized models with the accuracy required for user-facing applications, allowing production systems to optimize storage costs and retrieval precision.

## After State: Navigating With a Shrink Ray in Production

### Quantization with HNSW (Hierarchical Navigable Small World)

**HNSW** is widely used for approximate nearest neighbor (ANN) search, organizing vectors into a layered graph. By combining HNSW with quantized embeddings:

• **Memory Reduction** : Quantization reduces the memory required to store high-dimensional vectors in HNSW graphs, making HNSW more manageable and cost-effective for large datasets.

• **Fast Retrieval** : HNSW’s layered structure, when paired with binary or scalar quantized vectors, enhances retrieval speed without requiring excessive memory for each node. Quantized vectors allow faster traversal of the HNSW graph, supporting real-time applications.

For instance, a production system using binary quantized vectors within HNSW can achieve high-speed retrieval while minimizing storage costs. It is ideal for applications like recommendation engines or search platforms that process large data volumes.
