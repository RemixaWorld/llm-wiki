**Solution**

First things first. Let is unpack the use case and use that to understand what does that multi-turn agent means. Imagine a car dealership company where we have previously placed an order for a car. Now, after a few days, I change my mind and want a silver car instead of red one that I placed. Lets trace what are the steps needed to get this done.

* Firstly, when I go to the chatbot (powered by LLMs), I should be able to select my line of enquiry with the chatbot. (establishing some context)
* Next, the chatbot should initiate an agent based on my question, and the agent needs to provide me guidelines as what is needed for that line of enquiry.
* The above step is critical as the agent not only wants to get the user input but it needs to provide me the guidance and guardrails as to what details and needed and what is pending. The agent need to be in a state and continue to operate on that state unless it is ready to take an action.
* Next, the agent should take an action (which can be an API calls or Data base call etc.) based on the set of Tools available at its disposal.
* Once the response is generated by one Agent, the central orchestrator should be able to understand and evaluate the goal and then use the response to call next agent.
* The call to next agent can be conditional. Imagine that I shared my order details with the agent and the agent came back with the details of my order, it can then ask me to confirm or deny the details. If the details are correct (conditional), then it can call the next agent or if I confirm that the details are false (conditional), then the agent can select a separate agent for next set of actions.

Hence, in simple terms, the multi turn agent can take multiple turns to conditionally navigate the state from one agent to another keeping the overall goal in mind. The conditional multi step can be linear (see below) or can he hierarchical (after this diagram).

![image](https://miro.medium.com/v2/resize:fit:700/1*miUFLT8oPfqgJMa0KMFCgw.png)

In both these approaches above, the logic remains the same. The agents needs to talk to the central orchestrator to find the logical sequence and pass the memory, state and context to the next agent after its own work is complete.

The above diagram provides a quick view and reference to the goal oriented multi-step agentic approach. The center of the agent ecosystem is the central router (which entails the shared memory, context, state and most importantly the conditional execution process). The agents in the peripheral are independent agents who have a very specific task in hand

![image](https://miro.medium.com/v2/resize:fit:700/1*nCjnCl3KqBmjer1z4C5R4A.png)

Lets dive in with actual implementation. In the first screen you see below, the sequence remains same. User can choose a series of agents from agent marketplace. In production setup, we do not need to choose a set of agents as they will be down selected in the development environment beforehand. In this example, we want to mimic the multi turn use case where user needs a way to change his existing car order placed.

For this use case, we select the “Order Management of Cars” Agent from the list of left.

![image](https://miro.medium.com/v2/resize:fit:700/1*1WhOfgcqSwK5b8aGqhLaIw.png)

Next, when we greet the system, the system tells us that it has multiple capabilities including the one to manage car orders. The system then asks us to select our line of enquiry.

![image](https://miro.medium.com/v2/resize:fit:700/1*wjusVl02Gs3sTZ1AjIII6g.png)

Once, we say we want to discuss about the Car Order Management, it calls its first agent which interns enters into a finite state automation and establishes that we need to provide details like name, phone, email and order id to proceed. This showcases the guardrails and governance so that user can only move ahead once he/ she provides the basic details.

![image](https://miro.medium.com/v2/resize:fit:700/1*31uQGs__CfB_2DX0-dS8sw.png)

I show based in next 2 screens where as a user even if I provide incorrect or partial information, the state management of the agents will keep asking me for the right information. Once all the details are provided, agent takes an action to call API.

![image](https://miro.medium.com/v2/resize:fit:700/1*Ft0_wXo6iDCAEmUzVSb6DQ.png)

The api provides my order details and tells me my order information (in actual world, we can share OTP for user to authenticate himself/ herself). Once the orders is fetched, the agent passes its state to the next agent which is the “Confirmation Agent”. The confirmation agent wants to know if this is the correct order and asks for confirmation.

![image](https://miro.medium.com/v2/resize:fit:700/1*4jtlafGo-jJi3ItcFW3D7A.png)

For the confirmation agent, I can provide answer as yes/ no. If I provide the answer as “No” (as in this case), the agent calls a different agent conditionally. This is the part where the system can take multiple steps (multi steps) to reach the goal. For an answer “no”, it can call different set of agents to attain the goal and for and answer “yes”, it can call a separate set of agents.

Once I provide “no” as an answer, it calls the Car Order Management Agent again to take a new set of information to call the API and fetch me the right information.

![image](https://miro.medium.com/v2/resize:fit:700/1*lELO-sW2d3XV6fZbe-mWlQ.png)

It follows the same process where I need to provide the whole details needed by the agent to trigger action.

![image](https://miro.medium.com/v2/resize:fit:700/1*sIICqILf54mdRnhGJCi1cg.png)

This time, when the confirmation agent is called, I say ”yes” to confirmation and the agent invokes the new path which is the New Enquiry agent.

![image](https://miro.medium.com/v2/resize:fit:700/1*BGEWw71Skdyo5V2MGj4TBw.png)

In the new enquiry agent, I go into the state managemnt again where the agent asks me to provide my query. I do mention this time that I want to change my car color.

![image](https://miro.medium.com/v2/resize:fit:700/1*BEnlo-d-OgRVdQUq0t_f4g.png)

The new enquiry agent then calls the API and fetches new inventory details before passing the content and state to the final agent which is the “inventory selection” agent.

![image](https://miro.medium.com/v2/resize:fit:700/1*QXe4UOdbcR8LS7V83WzAVQ.png)

The inventory selection agent then has its own state management and asks me to confirm if I like one of the available inventories and correspondingly takes an action (which in this case is to place an inventory hold and send email)

![image](https://miro.medium.com/v2/resize:fit:700/1*6-ptVbImqgbdECUZ3NzveQ.png)
