## What is Llama 3.2 and how about the performance ?

Llama 3.2 is an open-source AI model (LLM) from Meta, available in multiple versions (1B and 3B parameters for multilingual text only, and 11B and 90B parameters for multimodal inputs that take both text and image inputs and output text).

In terms of benchmark performance, The lightweight models are compared to Gemma 2 2B IT from Google and Phi-3.5 from Microsoft. The **Llama 3.2 models (1B and 3B) generally perform better than Gemma 2** **but slightly lower than Phi-3.5 across most benchmarks for the 1B versions**

![image](https://miro.medium.com/v2/resize:fit:977/1*9jLhlUTyfOff2GZdo63o0A.png) ![Llama Lightweight and Multimodal Models Benchmark. Image Source : https://www.llama.com/](https://miro.medium.com/v2/resize:fit:1070/1*zaoFoNgqz5wHuaVaqSRCiQ.png)

The multimodal models generally perform well across benchmarks. The **LLaMA 3.2 90B** **surpasses Claude3-Haiku and GPT-4o-mini in image-related tasks** , such as AI2 Diagram and VQA, but**slightly trails behind GPT-4o-mini in multilingual tasks (MGSM)**

## Fine-tune and use Llama 3.2 locally

For the fine-tuning, I will use [**this dataset**](<https://huggingface.co/datasets/mlabonne/FineTome-100k>)with more than 100,000 examples of conversations collected from multiple sources. If you want to fine-tune it for your specific tasks, you just need to provide your own dataset.

You will find **the official Colab** from **Unsloth** for fine-tuning in the **resources section**. Let’s explain the code step by step

### I — Loading the model and basic configuration

First of all, we need to install the**latest version of Unsloth**(nightly Unsloth)

```python %%capture!pip install unsloth# Also get the latest nightly Unsloth!!pip uninstall unsloth -y && pip install --upgrade --no-cache-dir "unsloth[colab-new] @ git+https://github.com/unslothai/unsloth.git" ```

Then, start using `FastLanguageModel` from Unsloth and select the model you want to use. You can find more supported models [here](<https://huggingface.co/unsloth>). For me, I will be using the Llama 3.2 3B Instruct, so I will load both the model and the tokenizer using `FastLanguageModel`

**Note :**

* I am using the model from Unsloth, but you can also use the Meta version directly from Hugging Face.
* At the time of this article, Unsloth does not yet support the vision model.

The next parameter to define is the `max_seq_length` (_this parameter depends on your training dataset, so observe the maximum length from your training set to set the_ `max_seq_length`)

**Note :**

* Setting `max_seq_length` to a **higher value** will require the use of **more VRAM**

Regarding `dtype`, you can set it to `Float16`, but keep it as `None` for autodetection. For quantization, I will choose 4-bit to reduce memory usage

```python from unsloth import FastLanguageModelimport torchmax_seq_length = 2048 # Choose any! We auto support RoPE Scaling internally!dtype = None # None for auto detection. Float16 for Tesla T4, V100, Bfloat16 for Ampere+load_in_4bit = True # Use 4bit quantization to reduce memory usage. Can be False.model, tokenizer = FastLanguageModel.from_pretrained( model_name = "unsloth/Llama-3.2-3B-Instruct", max_seq_length = max_seq_length, dtype = dtype, load_in_4bit = load_in_4bit, # token = "hf_...", # use one if using gated models like meta-llama/Llama-2-7b-hf) ``` ![Loading the model. Image Source : Dr. Walid Soula](https://miro.medium.com/v2/resize:fit:700/1*ZiHIGGhW652_XY9LP4L07g.png)

Next, we will add LoRA adapters so we only need to **update 1% to 10%** of all **parameters**. We are **not using full parameter fine-tuning** (You can find my article about [LoRA and QLoRA](<https://ai.plainenglish.io/lora-and-qlora-0c0a96f1ca9a>) in the resources section.)

For the **rank** , **I recommend using 16 or 32** (I am using 16). Beyond that, you may get better results, but the **computation necessary for it is not worth the minor improvements you will achieve.**

``` model = FastLanguageModel.get_peft_model( model, r = 16, # Choose any number > 0 ! Suggested 8, 16, 32, 64, 128 (the greater the better) target_modules = ["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj",], lora_alpha = 16, lora_dropout = 0, # Supports any, but = 0 is optimized bias = "none", # Supports any, but = "none" is optimized # [NEW] "unsloth" uses 30% less VRAM, fits 2x larger batch sizes! use_gradient_checkpointing = "unsloth", # True or "unsloth" for very long context random_state = 3407, use_rslora = False, # We support rank stabilized LoRA loftq_config = None, # And LoftQ) ```

### **II — Data Preparation**

We now need to prepare the data for fine-tuning. We will use the `get_chat_template` function from Unsloth to obtain the correct chat template

**Note :**

* If you are using the base model, you can use your own template
* `chat_template = "llama-3.1"` is similar to llama-3.2

```python from unsloth.chat_templates import get_chat_templatetokenizer = get_chat_template( tokenizer, chat_template = "llama-3.1",)def formatting_prompts_func(examples): convos = examples["conversations"] texts = [tokenizer.apply_chat_template(convo, tokenize = False, add_generation_prompt = False) for convo in convos] return { "text" : texts, }passfrom datasets import load_datasetdataset = load_dataset("mlabonne/FineTome-100k", split = "train") ```

We now use `standardize_sharegpt` to convert ShareGPT-style datasets into Hugging Face's generic format. This changes the dataset from 👇🏼

```json {"from": "system", "value": "You are an assistant"}{"from": "human", "value": "What is 2+2?"}{"from": "gpt", "value": "It's 4."}# TO{"role": "system", "content": "You are an assistant"}{"role": "user", "content": "What is 2+2?"}{"role": "assistant", "content": "It's 4."} ``` ```python from unsloth.chat_templates import standardize_sharegptdataset = standardize_sharegpt(dataset)dataset = dataset.map(formatting_prompts_func, batched = True,)dataset[5]["conversations"] ``` ![dataset sample after preparation. Image Source : Dr. Walid Soula](https://miro.medium.com/v2/resize:fit:700/1*afuuIb30UbvP3ijLw2FhJw.png)

**Note :** Llama 3.1 Instruct’s default chat template default adds “ _Cutting Knowledge Date: December 2023

``` dataset[5]["text"] ``` ![Llama 3.1 Instruct’s default chat template default. Image Source : Dr. Walid Soula](https://miro.medium.com/v2/resize:fit:700/1*A0oQ4qPKRMjRlLYIG4VDBA.png)

### II — Training the model

We will be using the Supervised Fine-Tuning Trainer since we are performing supervised fine-tuning

```python from trl import SFTTrainerfrom transformers import TrainingArguments, DataCollatorForSeq2Seqfrom unsloth import is_bfloat16_supportedtrainer = SFTTrainer( model = model, tokenizer = tokenizer, train_dataset = dataset, dataset_text_field = "text", max_seq_length = max_seq_length, data_collator = DataCollatorForSeq2Seq(tokenizer = tokenizer), dataset_num_proc = 2, packing = False, # Can make training 5x faster for short sequences. args = TrainingArguments( per_device_train_batch_size = 2, gradient_accumulation_steps = 4, warmup_steps = 5, # num_train_epochs = 1, # Set this for 1 full training run. max_steps = 60, learning_rate = 2e-4, fp16 = not is_bfloat16_supported(), bf16 = is_bfloat16_supported(), logging_steps = 1, optim = "adamw_8bit", weight_decay = 0.01, lr_scheduler_type = "linear", seed = 3407, output_dir = "outputs", ),) ```

**Note I :**

You can either use `max_steps` or `num_train_epochs`. The `num_train_epochs` is commented out because if it is set to 1, it will need to go through all the data during training (100,000 examples), which will take a while. That’s why I set `max_steps = 60`. Since we are using a training batch size of 2, we would have a maximum of 50,000 steps possible, and we are just taking a small fraction of the total steps to achieve faster results.

Keep in mind that this is just for the demo; for good results, you need to train it longer.

**Note II :** I will only train the output of the model with the following

```python from unsloth.chat_templates import train_on_responses_onlytrainer = train_on_responses_only( trainer, instruction_part = "<|start_header_id|>user<|end_header_id|>

", response_part = "<|start_header_id|>assistant<|end_header_id|>

",) ```

We can see how the tokenized version of the dataset looks

``` tokenizer.decode(trainer.train_dataset[5]["input_ids"]) ``` ![Tokenized version of the dataset. Image Source: Dr. Walid Soula](https://miro.medium.com/v2/resize:fit:700/1*HRJu0XnQ0LxbAiHw_mkqwg.png)

You can also mask the original system message to see only the output

``` space = tokenizer(" ", add_special_tokens = False).input_ids[0]tokenizer.decode([space if x == -100 else x for x in trainer.train_dataset[5]["labels"]]) ``` ![Tokenized version of the dataset (System masked). Image Source: Dr. Walid Soula](https://miro.medium.com/v2/resize:fit:700/1*yessC3xNOyz6eNrWRNYBEQ.png)

### **V — Run Locally it with Ollama**

First, we need to create a model file for the model using **Ollama**. Open a folder where your models are located and start **VSCode** there.

Then, create a file inside the folder with any name you want and write the following inside

``` FROM unsloth.F16.gguf ```

* You can also add a template and system prompt if you want

**Note :** `unsloth.F16` is the name of my model; replace it with the name of your model

Next, in the terminal, write the following:

```python #If you do not have Ollama : pip install ollamaollama create medium -f./medium ``` ![Transferring model data. Image Source : Dr. Walid Soula](https://miro.medium.com/v2/resize:fit:481/1*MIMap8QGGlb_HhbJ3puXNA.png)

When the process is finished, you can see your model using the following:

``` ollama list ``` ![Models list. Image Source : Dr. Walid Soula](https://miro.medium.com/v2/resize:fit:518/1*neSBJHsCLvW7fH5Jzsd0Iw.png)

Finally, to run the model, just type `ollama run` followed by the name of the model
