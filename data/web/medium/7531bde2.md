## 1\. Overview of the Quantization

Quantization is the technique that maps a floating-point number into lower-bit integers. It is super effective in reducing LLMs’ model size and inference costs. For instance, when we quantize the 7B model with roughly 4 x 7B = 28GB size in float32 into float16, we can decrease 2 x 7B = 14GB size. If we can quantize the float32 model into int8, the size will be 1 x 7B = 7GB! The illustration below shows the bit representation for each data type. They are common data types to be used for LLMs.

Common data type used by LLMs

Now, how can we actually reduce the bit size? The answer is “rounding” values from one data type to another. To understand the quantization concept concretely, we will learn two basic ways to round the values: Zero-point and absolute maximum quantization.

* **Zero-point quantization**

Zero-point quantization maps the minimum and maximum values in the given data into the minimum and maximum values of the target data type range. Let’s think of converting FP16 values into Int8. This quantization illustration is shown below.

Zero-point quantization image adopted by [the documentation](<https://intellabs.github.io/distiller/algo_quantization.html>)

We want to scale our data into the Int8 scale (0 ~ 255 in this case). Thus, we calculate the relative values in the original scale and rescale them by multiplying the Int8 scale, which is 255. The formula can be described as follows.

The rounding formula for zero-point quantization

_n_ is the number of bits used for quantization (8 in this case). Note that if we want to rescale values into -127 ~ 127, we subtract 127 from the above result, and round them.

This method can represent the original data more precisely than the other quantization methods. On the other hand, this method needs more complex calculations, so we must balance accuracy and complexity.

* **Absolute maximum quantization**

Absolute maximum quantization maps the maximum absolute values in the given data into the target data type’s signed range. Again, let’s think of converting FP16 values into Int8. For simplicity, we consider the restricted quantization range, which means -127 ~ 127. For your information, the full quantization range is -128 ~ 127. This quantization illustration is shown below.

We first calculate the absolute maximum value in the data and use it to rescale the original data. The formula can be described as follows.

This method is simpler than zero-point quantization when it comes to calculation. However, this method is strongly affected by the outlier in the data, so we need to inspect whether our data fits this method carefully.

These methods are the family of round-to-nearest (RTN) quantization. If you are interested in other quantization techniques, you can read [this blog](<https://iq.opengenus.org/basics-of-quantization-in-ml/>).

On the other hand, naive quantization has a problem with accuracy degradation because we cut the information with decreasing bits. Thus, recent quantization techniques try to minimize this degradation as much as possible while decreasing the bit size. There are two mainstream recent quantization techniques.

* **Quantization aware training (QAT)**

QAT allows quantizing a model and applying fine-tuning to restore accuracy degradation caused by quantization. Although it can keep model accuracy more than the PTQ method later explained, it generally needs additional training and expensive computational resources, such as A100 or H100 machines.

* **Post-training quantization (PTQ)**

PTQ allows quantizing a model for a pre-trained model without additional training. Therefore, it can save the necessary GPU VRAM size for quantizing and be a more practical solution for general users. Many researchers recently researched quantization in this direction, and many sophisticated methods have been developed.

In this blog, we will learn popular quantization techniques like GPTQ, AWQ, and Bitsandbytes (QLoRA). GPTQ and AWQ are classified as PTQ, and QLoRA is classified as QAT. These algorithms are already integrated into the transformers library so users can use them efficiently. In the following sections, we will check the theory of these algorithms briefly.

## 2\. What is Group-wise Precision Tuning Quantization (GPTQ)?

Group-wise Precision Tuning Quantization (GPTQ) [1] is one of the early success quantization algorithms developed in 2022. At that time, this technique quantized large models with 175B, such as BLOOM or OPT-175B, into 4-bit for the first time.

Technically, GPTQ quantizes each row of the weight matrix independently to find the optimal weight to minimize the quantization error. For precise quantization, it utilizes the Hessian matrix to calculate an optimal update for the remaining weights, mitigating the loss incurred by the compression process. Note that GPTQ keeps the embedding and output layer in full FP16 precision for the model accuracy. The following pseudocode describes the GPTQ algorithm.

## 3\. What is Activation-aware Weight Quantization (AWQ)?

Activation-aware weight quantization (AWQ) [2] has recently been one of the most popular quantization algorithms. This algorithm focuses on the salient weights that are quite important for LLM performance. The authors’ research shows that LLM has a small fraction of weights (0.1~1%), significantly affecting quantization error. They utilize activation magnitude to find this small fraction of weights and apply per-channel scaling to mitigate the quantization error from salient weights. ## 4\. What is BitsandBytes?

BitsandBytes is a quantization library that quantizes models into 8 or 4 bits. Due to its convenience and effectiveness, it is the most common quantization library.

BitsandBytes’s 8-bit quantization is based on LLM.int8() paper [3]. To mitigate the quantization error, it keeps the sensitive outliers of model weights in the FP16 and others in INT8, and then, it proceeds with matrix multiplication separately. Finally, it adds them together to return to the FP16 format. The illustration below shows this procedure.

Press enter or click to view image in full size

LLM.int8() architecture adapted by the paper [3]

This technique can be applied up to 170B scale models, but it still needs 8 x 24GB VRAM to run 170B models and 4 x 24GB VRAM to run 66B models. It is still not enough to run large-size models on consumer-size GPUs.

Thus, 4-bit quantization is developed to solve this issue. Bitsandbytes’s 4-bit quantization is commonly used with QLoRA [4] to finetune quantized LLMs. Intuitively, QLoRA quantizes the target model in 4-bit, makes it frozen, and finetunes the frozen 4-bit model using LoRA. Here is the comparison among full finetuning, LoRA, and QLoRA.

Press enter or click to view image in full size

The architecture comparison among full finetuning, LoRA, and QLoRA adapted by the paper [4]

Technically, QLoRA mainly utilizes the features below.

* **4-bit NormalFloat quantization**

This technique utilizes the fact that the pre-trained neural network weights have a normal distribution and introduces the new data type called 4-bit NormalFloat type, which ensures an equal expected number of values in each quantization bin.

* **Paged optimizers**

QLoRA applies the paged optimizers to avoid sudden GPU memory spikes. The paged optimizer uses the NVIDIA unified memory feature to switch page-to-page transfers between the CPU and GPU automatically (In this context, you can imagine the GPU page is similar to the CPU page in memory).

* **Double quantization**

When you apply quantization to the model weights, you need the quantization constant in the same data type as the model weights. Since there are many parameters in LLMs, quantization constants also burden for memory space. To minimize the memory footprint per parameter, the authors quantize the quantization constants.

You can check [this article](<https://towardsdatascience.com/qlora-how-to-fine-tune-an-llm-on-a-single-gpu-4e44d6b5be32>) to understand these features in more detail. The following table shows the parameter size vs GPU VRAM consumption.

Parameters size vs memory consumption adapted by the paper [4]

Note that the memory column shows the memory requirement of the model, so it doesn’t contain a finetuning portion. Although it depends on the dataset or hyperparameter settings, we may finetune up to 13B parameter models using a consumer-size 24GB VRAM machine.

We should use QLoRA when the zero-shot LLM accuracy is not enough for our target task. Regarding the real-world AI projects, we often use this technique because base models usually don’t work for specific field data.

## 5\. What is Unsloth?

Although Unsloth is not the quantization method, I want to introduce this open-source super-efficient finetuning library for LLMs. [Unsloth](<https://github.com/unslothai/unsloth>) is the library fully integrated parameter-efficient finetuning methods such as LoRA and QLoRA. It optimizes each kernel for open-source famous LLMs and achieves up to ~70% memory use reduction! For instance, it supports open-source LLMS, such as Llama, Mistral, Phi, Qwen, and Gemma.

Unsloth support table adapted by [the official repository](<https://github.com/unslothai/unsloth>)

Unsloth is compatible with HuggingFace and vllm, and we can exchangeably change the format among them. We should use Unsloth to save memory and increase performance when the model is supported.

Just recently (Dec 4, 2024), Unsloth released a new quantization method called Unsloth — Dynamic 4-bit quantization. This technique is built on top of the BitsandBytes 4-bit quantization and determines whether or not to quantize certain parameters dynamically. Currently, only multimodal model’s quantized versions are first released. Language models will be supported subsequently.

So far, we have seen popular quantization techniques and libraries. In summary, we can use these quantization techniques in the situation below.
\- You want to use LLMs in the zero-shot setting → GPTQ or AWQ
\- You want to use finetuned LLMs with own data → QLoRA (BitsandBytes or Unsloth)

In the next section, we will learn how to implement them on Google Colab Notebook.

### BitsandBytes implementation
