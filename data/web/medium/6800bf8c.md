With LLM becoming more and more capable every year, there is growing challenge on finding ways to evaluate them better. Human feedback is still the most reliable evaluation method, but it suffers from time and costs constraints. While human evaluation provides a benchmark for assessing model capabilities, it takes more time and effort and hence can hinder rapid iteration during development. So AI researchers are constantly looking out for of a swift, cost-effective, and straightforward evaluation metric that strongly correlates with human evaluation results.

Using LLM to evaluate LLM results was adopted after the release of GPT-4 and has since grown in popularity. Today, LLM-as-a-judge along with human evaluation, is one of the most widely-used evaluation techniques for LLMs.

Since the adoption of the LLM-as-a-Judge technique, numerous studies have explored best practices for implementation and identified potential biases to consider.

This blog aims to dig into using LLM as Judges, providing a comprehensive and practical understanding of using LLMs for evaluations.

## What exactly is LLM-as-Judge?

> LLM-as-a-judge refers to a reference-free metric that directly prompts a powerful LLM to evaluate another model’s output quality.

This technique consistently agrees with human preferences, despite its limitations. It can evaluate a wide variety of open-ended tasks in a scalable manner with minimal implementation changes. To assess a new task, we simply need to tweak our prompt!

## Why is using LLMs to Evaluate so exciting?

Let’s say you’re running a writing contest. Instead of having human judges read through thousands of entries, you could use LLM-as-Judge. You would give it the entries and the contest rules. Then it could:

1. _Score each entry for creativity, grammar, and how well it stayed on theme._
2. _Compare the entries to see which one is better._
3. _Give feedback on what made certain entries stand out._

This would save time, ensure consistency in judging, and could handle a much larger number of entries than human evaluators.

LLM-as-Judge is a game-changer for several reasons:

1. **Scalability:** It can handle a massive number of evaluations quickly.
2. **Adaptability:** It can be applied to various tasks and fields.
3. **Cost-effectiveness:** It reduces the need for human evaluators in many scenarios.
4. **Consistency:** It applies the same criteria uniformly across all evaluations.

## How does LLM-as-Judge actually work?

Let’s break it down into a simple formula:

**E ← P_LLM(x ⊕ C)**

Don’t worry, it’s not as complicated as it looks! Here’s what each part means:

* **E:** This is the final evaluation — it could be a score, a choice, or even a detailed critique.
* **P_LLM** : This is the LLM’s probability function — basically, how it processes information.
* **x** : The input data — could be text, images, or even videos that need evaluation.
* **C** : The context — think of this as the instructions or guidelines for the evaluation.
* **⊕** : This symbol just means we’re combining the input with the context.

In simpler terms, we feed the LLM some data to evaluate, along with instructions on how to evaluate it, and out comes our assessment!

## Building an LLM-as-Judge Evaluation pipeline:

### Step 1: Identifying what and how to evaluate?

The first step in building the pipeline is identifying what to evaluate and designing and quantifying the evaluation outcomes.

Image source[<https://arxiv.org/pdf/2411.15594>]

**So, What are the different ways LLM-as-Judge can evaluate things?**

There are four main methods: Generating Scores, Solving Yes/No Questions, Conducting Pairwise Comparisons, Making Multiple-Choice Selections

**1\. Generating Scores**

LLMs can generate scores to evaluate responses. These scores can be discrete (like 1–5) or continuous (like 0–100). For instance, you can ask the LLM to rate the helpfulness, relevance, accuracy, and level of detail of a response on a scale of 1 to 10. A more detailed approach involves predefined criteria like accuracy, coherence, factuality, and comprehensiveness, each scored from 1 to 3. An overall score from 1 to 5 can then summarize the quality of the response.

Here’s a simple example:

``` Evaluate the quality of summaries written for a news article. Rate each summary onfour dimensions: {Dimension_1}, {Dimension_2}, {Dimension_3}, and {Dimension_4}. Youshould rate on a scale from 1 (worst) to 5 (best).Article: {Article}Summary: {Summary} ```

**2\. Solving Yes/No Questions**

Yes/No questions are straightforward. They require a judgment on the accuracy of a statement, offering only two responses: yes or no, true or false.

These evaluations are useful in feedback loops, like in the Reflexion model, which uses self-reflections to improve future attempts. They’re also handy for testing knowledge accuracy, such as determining if a sentence is supported by an article:

``` Is the sentence supported by the article? Answer "Yes" or "No".Article: {Article}Sentence: {Sentence} ```

**3\. Conducting Pairwise Comparisons**

Pairwise comparison involves choosing between two options to determine which is better. This method is often used for ranking or prioritizing options.

LLMs can effectively perform pairwise comparisons, especially when aligning with human judgments. For example, given two summaries of an article, the LLM can decide which one is better:

``` Given a new article, which summary is better? Answer "Summary 0" or "Summary 1".You do not need to explain the reason.Article: {Article}Summary 0: {Summary_0}Summary 1: {Summary_1} ```

**4\. Making Multiple-Choice Selections**

Multiple-choice questions offer several options, unlike pairwise comparisons or yes/no judgments. The evaluator must select the most appropriate or correct option. Though less common, it’s a valuable tool in the LLM’s judging toolkit.

By understanding these methods, you can effectively use LLMs as judges to evaluate responses in various contexts.

``` You are given a summary and some semantic content units. For each semantic unit,choose those can be inferred from the summary, return their number.Summary: {Summary}Semantic content units:{SCU_1},{SCU_2}...n. {SCU_n} ```

## Step 2: Choosing the Right Evaluation strategy and Model

### So, how do we choose the right model for LLM-as-Judge?

There are two main approaches - **Using General LLMs and Fine-tuning Specialized Models**

1. **Using General LLMs** :

We can use powerful pre-trained models like GPT-4. For example, researchers like Li et al[2] created a test set with 805 questions and used GPT-4 to evaluate the performance, comparing it to text-davinci-003. Similarly, Zheng et al[3] designed 80 multi-round test questions and used GPT-4 to automatically score responses. The results? GPT-4 showed high accuracy, consistency, and stability compared to professional human evaluators. However, if the LLM you choose has limitations in following instructions or reasoning, the effectiveness of using it as a judge might drop.

Average win rate of six models under different judges on MT-bench based on the study by Zheng et al [[Source](<https://papers.nips.cc/paper_files/paper/2023/file/91f18a1287b398d378ef22505bf41832-Paper-Datasets_and_Benchmarks.pdf>)]

**2\. Fine-tuning Specialized Models** :

While general LLMs are great, there are concerns about privacy leakage and reproducibility when relying on external APIs for evaluation. That’s why some studies suggest fine-tuning language models specifically for evaluation tasks. This involves emphasizing pairwise comparisons or grading. For instance, PandaLM[4] uses Alpaca instructions and GPT-3.5 annotations to fine-tune LLaMA-7B as an evaluator. Similarly, JudgeLM[5] uses diversified instruction sets and GPT-4 annotations to fine-tune Vicuna.

Here’s a breakdown of the typical process for fine-tuning a judge model:

**Step 1: Data Collection**

Gather training data that includes instructions, the objects to be evaluated, and the evaluations themselves. Instructions usually come from existing datasets, while evaluations can be sourced from GPT-4 or human annotators.

**Step 2: Prompt Design**

Create a prompt template structure that fits your evaluation scheme. This could vary based on what you’re evaluating.

**Step 3: Model Fine-Tuning**

Use your designed prompts and collected data to fine-tune the evaluator model. This usually involves giving the model an instruction along with one or more responses, and then generating output that includes evaluation results and possibly explanations.

After fine-tuning, you can use the evaluator model to assess the target object. While these fine-tuned models often perform well on custom test sets, they do have limitations, especially in generalization. This makes it tough to compare them with top-tier LLMs like GPT-4.

## Step 3: Making sense of the Evaluation results

Press enter or click to view image in full size

Image source[<https://arxiv.org/pdf/2411.15594>]

After our LLM-as-a-Judge spits out its initial evaluations, we use post-processing to fine-tune these results. This step makes sure that the evaluations fit our In-Context Learning design and are reliable. There are three main ways we do this:

1. **Extracting Specific Tokens**
2. **Normalizing Output Logits**
3. **Selecting Sentences with High Returns**

Let’s break these down.

### 1\. Extracting Specific Tokens

When we’re dealing with evaluations that come in the form of scores, specific options, or simple Yes/No answers, we often use rule-matching to pull out the relevant token from the LLM’s response. For example, if the LLM responds with “Modification needed.” or “Yes”, we need to extract these specific tokens accurately.

However, this can get tricky. The LLM might respond in various formats like “Conclusion: Modification needed.” or just “Yes”. To handle this, we sometimes give clearer instructions, like starting sentences with “The better response is”, or use a few-shot strategy where we provide a couple of examples to guide the LLM. This helps ensure that the LLM’s responses are consistent and easier to parse.

### 2\. Normalizing Output Logits

In scenarios where the LLM gives a Yes/No evaluation, we often normalize the output logits to get a continuous score between 0 and 1. This is a common practice in agent methods and prompt-based optimization.

For instance, we might ask the LLM, “Is this reasoning step correct?” and then reward it based on the probability of the next word being “Yes”. By aggregating the probabilities of relevant tokens, we compute scores like self-consistency and self-reflection, which help us gauge the LLM’s confidence and accuracy.

### 3\. Selecting Sentences

Sometimes, the LLM’s evaluation comes in the form of a sentence or paragraph. In these cases, we select the most relevant sentences to use in our final evaluation. For example, in a reasoning task, the LLM might build a reasoning tree by iteratively considering the most promising steps. We then extract the sentences that contribute the most to the evaluation.

### Challenges and Considerations

It’s important to note that each of these post-processing methods has its limitations, especially when evaluating objective questions.

* **Consistency Issues** : Sometimes, the judge models might not be as consistent as we’d like.
* **Instruction Following** : Some models struggle to follow specific instructions accurately.
* **Generalization Problems** : Fine-tuned models might perform well on specific tasks but struggle with new, unfamiliar ones.
* **Ethical Concerns** : There are also important questions about bias, fairness, and the ethics of having AI judge other AI systems.

## Step 4: Evaluating LLMs as Judges

Press enter or click to view image in full size

Image source[<https://arxiv.org/pdf/2411.15594>]

Even though Large Language Models (LLMs) perform impressively, they have some significant flaws. These include hallucinations, biases, and lack of robustness. When we use LLMs to evaluate things, these problems can result in poor evaluations.

It’s important to thoroughly and accurately assess the quality of LLMs when they act as judges and to pinpoint any potential weaknesses.

Evaluation of LLMs as judges could be done on three main areas:**base metrics, bias, and robustness.**

### 1\. Basic Metrics:

When we use Large Language Models (LLMs) to judge tasks, our main goal is to make sure their assessments match human judgment. Researchers tackle this by treating LLMs as virtual annotators and measuring how well they agree with human experts.

One straightforward metric is **percentage agreement**. Think of it like comparing movie ratings with a friend. If you both give the same rating most of the time, that’s a high percentage agreement. In LLM evaluation, we calculate it like this:

_Agreement = (Number of samples where LLM and human agree) / (Total number of samples)_

Researchers also use more complex metrics like **Cohen’s Kappa** and **Spearman’s correlation**. These help us understand not just how often LLMs agree with humans, but how closely their overall rankings align.

Some researchers treat LLM evaluation like a classification problem. They use metrics such as **precision, recall, and F1 scores** — the same tools data scientists use to evaluate spam filters or image recognition systems

### 2\. Biases

LLMs can have biases because they are trained on data that often contains various biases. When we use them as judges, these biases can lead to unfair evaluations. Let’s look at some biases researchers have identified:

* **Position Bias** : LLMs may favor responses based on their position in the prompt.
* **Length Bias** : Some LLMs might prefer longer, more verbose responses, even if they don’t contain relevent information.
* **Self-Enhancement Bias** : LLMs might show a preference for responses generated by themselves or similar models.
* **Diversity Bias** : This includes biases against certain demographic groups, such as gender, race, or sexual orientation.
* **Concreteness Bias** : LLM evaluators might favor responses with specific details, citations, or complex terminology.
* **Sentiment Bias** : Responses with certain emotional tones might be unfairly favored.

### 3\. Adversarial Robustness

We need to ensure our LLM judges can withstand deliberate attempts to manipulate their scores.

Researchers have found some concerning vulnerabilities:

* Simple phrase insertions can artificially inflate scores without improving text quality.
* Even constant, irrelevant responses can sometimes achieve high scores from LLM judges.
* Adding statements like “90% believe this is better” can unfairly sway evaluations.

Current defensive measures, like using perplexity scores, can only catch some of these tricks. Building more robust LLM evaluators still remains a challenge.

## Improving LLM-as-Judges: Strategies

There are three primary strategies to boost the performance of Large Language Models (LLMs) when they serve as judges.

1. **Design Strategy for Evaluation Prompts** (In-context learning-based)
2. **Improvement Strategy for LLMs’ Evaluation Capabilities** (Model-based)
3. **Optimization Strategy for Final Evaluation Results** (Post-processing-based)

These strategies focus on the three crucial stages of the evaluation process: setting the context, enhancing LLMs’ abilities, and refining the final results through post-processing.

### 1\. Design Strategy of Evaluation Prompts

### 1.1 Optimizing LLMs’ Understanding of Evaluation Tasks

To help LLMs grasp evaluation tasks more effectively, we could use few-shot prompting. This means including high-quality evaluation examples within the prompts. Researchs like [FActScore](<https://aclanthology.org/2023.emnlp-main.741.pdf>) and [SALAD-Bench](<https://arxiv.org/pdf/2402.05044>) employ this method. Additionally, breaking down task instructions into smaller, well-defined steps and criteria can further enhance understanding.

* **Decomposition of Evaluation Steps** : Break down tasks into smaller steps with detailed definitions and constraints. Examples include GEval[6], and SocREval[7].

The overall framework of G-EVAL. We first input Task Introduction and Evaluation Criteria to the LLM, and ask it to generate a CoT of detailed Evaluation Steps- [Source-GEval[6]]

Example Instruction and Evaluation Prompt for SOCREVAL

```yaml Instruction: Does the generated response answer the question in a well-justified manner?Please give me an overall quality score in [1,2, 3, 4, 5] (1=incomprehensible and wrong,5=clear and correct). Note that you need to take into account both the explanation and theanswer in the generated response.(Evaluation prompt) Please give me the overall quality of the generated response for thequestion based on the instruction and the format of the example representation. ```

* **Decomposition of Evaluation Criteria** : Divide broad criteria into more detailed sub-criteria. HD-Eval[8], for instance, uses hierarchical criteria decomposition to align LLM evaluators with human preferences.

HD-EVAL breaks down evaluation tasks step by step. It starts with the main task, then splits it into smaller parts. Next, it trains a tool called an aggregator. This tool helps pick the most important bits using a method called attribution pruning. These important bits then get expanded in the next step. This process repeats until it reaches a set limit of steps..[[Source](<https://arxiv.org/pdf/2402.15754>)]

A Generic template for Hierarchical Criteria Decomposition is given below.

``` I would like to perform automatic evaluation on quality of [Evaluation Task].[Backgrounds and Definitions of Evaluation Task].I would like to to evaluate [List of Criteria to Decompose].Please give me around [Desired Child Count] fine-grained evaluation critics to evaluate them. I want to obtain a finalcomprehensive evaluation based on an overall aggregation on fine-grained metrics. With the fine-grained metrics, I can better dispatch the evaluation task to different workers and make a better overall efficiency and accuracy. ```

### 1.2 Optimizing LLM’s Output Forms

To make the output of Large Language Models (LLMs) more reliable and consistent, we need to guide them with structured formats. Asking LLMs directly for evaluation results can be problematic because of their unpredictable nature.

To tackle this, we constrain their outputs using specific formats within the prompts we give them. For instance, G-Eval[6] uses a form-filling approach, while LLM-EVAL[9] provides results in JSON format for detailed scoring.

The example evaluation schema used in LLM-EVAL is below.

```yaml Human: The output should be formatted as a JSON instance that conforms to the JSON schema below.As an example, for the schema {"properties":{"foo": {"title": "Foo", "description": "a list of strings", "type": "array", "items":{"type": "string"}}}, "required": ["foo"]}} the object {"foo": ["bar", "baz"]} is a well-formatted instance of the schema. The object {"properties": {"foo": ["bar", "baz"]}} is not well-formatted.Here is the output schema:{"properties": {"content": {"title": "Content", "description": "content scorein the range of 0 to 100", "type": "integer"}, "grammar": {"title": "Grammar","description": "grammar score in the range of 0 to 100", "type": "integer"}, "relevance": {"title": "Relevance", "description": "relevance score in the range of 0 to 100", "type": "integer"}, "appropriateness":{"title": "Appropriateness", "description":"appropriateness score in the range of 0 to100", "type": "integer"}}, "required":["content", "grammar", "relevance","appropriateness"]} ```

When evaluating dialogue responses with a human reference, we create a prompt that includes the dialogue context, the reference response, the target response to be evaluated, and the evaluation criteria.

An example prompt template for evaluating a dialogue response with a human reference is below:

``` {evaluation_schema}Score the following dialogue response generated on a continuous scale from{score_min} to {score_max}.Context: {context}Reference: {reference}Dialogue response: {response} ```

For evaluations without a human reference, the prompt includes just the dialogue context and the target response, along with the evaluation criteria. An example prompt template for evaluating a dialogue response without a human reference is:

``` {evaluation_schema}Score the following dialogue response generated on a continuous scale from{score_min} to {score_max}.Context: {context}Dialogue response: {response} ```

To make the results more understandable, [CLAIR](<https://aclanthology.org/2023.emnlp-main.841v2.pdf>) asks LLMs to provide scores along with explanations in JSON format.

By structuring how LLMs give their outputs, we make the evaluation results more robust and logical. This setup also makes it easier to process the results automatically and keeps the evaluation process stable.

## 2\. Elevating the Evaluation Skills of Large Language Models (LLMs)

LLMs demonstrate remarkable language comprehension and generation abilities, particularly when given specific instructions. To further enhance these evaluation skills, we focus on optimizing prompt design and leveraging LLMs’ in-context learning capabilities. This means ensuring LLMs fully understand prompts and consistently follow evaluation guidelines.

### 2.1 Refining LLMs with Meta Evaluation Datasets

One effective way to boost the evaluation capabilities of LLMs is by fine-tuning them using meta-evaluation datasets specifically designed for evaluation tasks. This approach helps LLMs better understand specific evaluation prompts, enhances their evaluative performance, and reduces potential biases.

The key to this strategy is the careful collection and creation of training data. A common practice is to sample evaluation questions from publicly available datasets, modify them with specific templates, and augment the dataset with evaluation responses generated either manually or by advanced LLMs like GPT-4.

For example, PandaLM[4] curates training data by sampling inputs and instructions from Alpaca 52K[2] and generating responses using GPT-3.5. To better align with evaluation task requirements, many research efforts further transform inputs and instructions from public datasets to create more targeted training data.

OffsetBias, for instance, aims to reduce LLM biases by using GPT-4 to generate off-topic versions of original inputs, then having GPT-3.5 respond to these new inputs to produce subpar responses. By fine-tuning LLMs as evaluators with paired good and bad responses as training data, significant reductions in biases such as length bias, concreteness bias, and knowledge bias are achieved.

JudgeLM[5] and [CritiqueLLM](<https://arxiv.org/html/2311.18702v2>) further refine LLMs’ evaluation capabilities through innovative training paradigms and multi-path prompting approaches, respectively. In essence, creating meta-evaluation training data tailored to specific evaluation tasks and fine-tuning LLMs can directly enhance the model’s intrinsic knowledge and language abilities, offering a straightforward path to improving the evaluative performance of LLM evaluators and addressing potential biases.

### 2.2 Continuous Improvement Through Feedback

To ensure that Large Language Models (LLMs) align closely with human preferences, it’s very important to continuously improve them through feedback. Even after fine-tuning LLMs using meta-evaluation datasets, biases can still sneak in during practical evaluations, impacting overall quality. One effective way to combat this is by optimizing models iteratively, based on feedback from evaluation results. This feedback can come from superior models or direct corrections by human evaluators.

Take INSTRUCTSCORE[13] as an example. It boosts model performance by gathering failure modes from metric outputs, then asking GPT-4 for automatic feedback on each mode. It then fine-tunes the LLaMA model with the explanations that most closely match human preferences.

Because the feedback is closely aligned with human preferences, LLM evaluators can dynamically adjust to human standards. They optimize their evaluation capabilities based on this feedback, leading to better evaluation results.

The INSTRUCTSCORE pipeline works in three steps. First, it creates synthetic data using GPT-4 to fine-tune a 7B LLAMA model. Next, it samples from real-world machine-generated data to identify where INSTRUCTSCORE might fail. It then asks GPT-4 about these failure points and collects automatic feedback. ## 3\. Enhancing the Reliability of LLM-Based Evaluations

LLMs have proven to be reliable evaluators, thanks to their ability to learn in context and understand task requirements. However, the randomness in how LLMs generate responses can make evaluations unstable and affect the quality of results. To tackle this, we need to optimize the post-processing stage. There are two key strategies to make LLM evaluations more dependable.

### 3.1 Integrating Multiple Evaluation Results

One effective way to make evaluations more reliable is by combining multiple results for the same content. This approach minimizes the impact of random factors and errors. For example, you can run several evaluations on the same content using different settings and then summarize the results. Sottana et al.[11] reduce randomness by averaging multiple scores for the same sample. [PsychoBench](<https://openreview.net/pdf?id=H3UayAQWoE>) calculates the mean and standard deviation from ten independent runs. [Auto-J](<https://arxiv.org/pdf/2310.05470>) goes a step further by amplifying differences between evaluation rounds and combining critiques with and without scenario criteria to get the final results.

### 3.2 Directly Optimizing LLMs’ Outputs

Another method is to directly optimize the output of a single LLM evaluator. This can yield more reliable results, especially for scoring. Given the randomness in LLM generation, scores might not fully reflect the LLM’s evaluation criteria. One effective strategy is to combine implicit logits, which capture LLM randomness, with explicit output scores. FLEUR[12] uses a score smoothing strategy where the probability of each digit token is used as a weight to smooth explicit scores and calculate the final evaluation scores.

## Closing Thoughts:

LLMs, as probabilistic models, need ongoing research and optimization to become reliable judges. While current methods have made progress, challenges like adaptability and robustness still remain. Future efforts should focus on refining LLM-as-a-Judge throughout the evaluation process. We should aim to not only enhance assessment reliability but also develop methods to systematically evaluate and validate robustness. Creating comprehensive evaluation benchmarks will be essential for assessing and improving LLM evaluators.
