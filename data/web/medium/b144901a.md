The FLUX.1 dev and schnell open source text-to-image generation models offer unmatched quality and perform on par with proprietary models.

However, running these new models, FLUX.1 dev in particular, requires 16–24GB of VRAM to run the full uncompressed model — which many people don’t have readily available.

Enter quantized models.

## What are Quantized Models

Borrowing from open-source LLM counterparts, quantized models are essentially full-sized models that have been compressed. The greater the compression, the greater the reduction in required VRAM, at the cost of less accuracy/quality in the final output.

However, this quality cost allows the model to run on lower-end hardware.

There are many different quantization strategies. If you want to learn more, [consider reading this terrific article by Maarten Grootendorst](<https://newsletter.maartengrootendorst.com/p/which-quantization-method-is-right>).

## Why Do You Need a Quantized Model Now When Stable Diffusion Did Not?

Previous text-to-image generative models from Stability like Stable Diffusion 1.5, SD2, and SDXL simply weren’t complex enough to necessitate the use of quantized models.

In addition to a larger model from FLUX.1, you also need to use both a CLIP and T5-XXL encoder model — the latter also has quantized models available to reduce VRAM footprint.

## Setup

For the setup, we’ll go over where to download and place the model files along with installing the custom node in ComfyUI.

You can also watch a step-by-step process in this short video:

### Downloading & Placing Models

Developer city96 has graciously made available on HuggingFace both the [FLUX.1 dev](<https://huggingface.co/city96/FLUX.1-dev-gguf/>) and [schnell models](<https://huggingface.co/city96/FLUX.1-schnell-gguf>) quantized models, which range from 2 to 16-bit (the original FLUX model is 32-bit).

Deciding on the right bit quantization isn’t straightforward as it varies depending on your specific machine. However, for most, a 4 or 6-bit model (Q4 or Q6) will be a good place to start.

When downloading the .gguf file, you’ll want to place it in the `ComfyUI/models/unet` directory.

For the T5-XXL encoder model, [which you can find here](<https://huggingface.co/city96/t5-v1_1-xxl-encoder-gguf>), the author states that “it’s therefore recommended to use Q5_K_M or larger for the best results”.

Place the quantized T5-XXL model in the `ComfyUI/models/clip` directory.

### Installing the ComfyUI-GGUF Custom Node

Within the ComfyUI manager, you’ll want to install the [ComfyUI-GGUF custom node](<https://github.com/city96/ComfyUI-GGUF>). This adds the `UNet Loader GGUF` and `DualClip Loader GGUF` nodes to your ComfyUI instance.

## Running in ComfyUI

Running the FLUX.1 GGUF file in ComfyUI is straightforward. You’ll just need to do the following:

### 1\. Set the Custom Nodes

To use GGUF files, we’ll add the `UNet Loader GGUF` and `DualClip Loader GGUF` nodes to the start of our workflow:

![image](https://miro.medium.com/v2/resize:fit:1000/1*u1PMwL03uHj-pBykpjIYzw.png)

Be sure to set the `DualClip Loader GGUF` to include both the CLIP and T5-XXL (GGUF) models along with the `flux` option for the `type`. While FLUX doesn't support negative prompts, you'll still need to connect the CLIP output to the CLIP inputs for both the `CLIP Text Encode (Prompt)` nodes; otherwise, ComfyUI will throw an error.

The `UNet Loader GGUF` node will support any GGUF file provided in the `ComfyUI/models/unet` directory.

**Note** : The `ae.safetensors` file is the VAE provided by the Black Forest Labs team. [You can download it on HuggingFace](<https://huggingface.co/black-forest-labs/FLUX.1-schnell/blob/main/ae.safetensors>) if you don't have it already.

### 2\. Prompt, KSampler, & Latent Space

The advantage of FLUX over previous models is that it can follow prompts extraordinarily well.

So instead of saying `1block, green, natural lighting`, you can be much more descriptive, and the model will produce better results that align with your prompt. Be sure to adopt this approach when working with a FLUX model.

As mentioned previously, the negative prompt will be left blank. For the `KSampler` node, you'll want to set the following:

* CFG: 1.0
* Sampler Name: Euler
* Scheduler: Simple

Lastly, the Latent Space size can vary greatly, with supported resolutions ranging between 0.1 and 2 megapixels.

The final workflow will look like this:

![image](https://miro.medium.com/v2/resize:fit:1000/1*oBnuka4ckCOH_EvMeBWZJA.png)

You can also find a link to download this workflow [over on the Prompting Pixels website](<https://promptingpixels.com/flux-gguf/>).

### 3\. Queue Prompt & Review The Results

Lastly, hit the `Queue Prompt` and review the results in ComfyUI. For a 512x512 image with the prompt `a photo of green pyramid block next to a red circle block. behind the blocks is a wooden chair`, FLUX generated this image:

![🔥 Spot on in the composition!](https://miro.medium.com/v2/resize:fit:512/1*Yzj5388IB9fvP97a2Kjzuw.png)

Just for some general details, the above image took 34 seconds to render and had a total VRAM usage of 7.6 GB (using FLUX Q2 and T5-XXL Q3).
