**Example 1 — Memoising Expensive Computations with Persistent Caching**

Long-running calculations can bog down your application. With Diskcache, you can memoize function results so that repeated calls — even across process restarts — return instantly. Diskcache’s `@cache.memoize` decorator supports expiration times and tagging, ensuring that cached results remain valid only as long as you need them.

Below, we simulate an expensive computation, cache the result with a 60‑second TTL, and tag the cache entry for easy metadata management.

The TTL means this is the amount of time the cache will “live” for. Before that time expires, your result will be immediately returned (on subsequent runs). After that time, the cache will need to be refreshed.

```python from diskcache import Cacheimport time# Initialize the cache; the directory will be created if it doesn't exist.cache = Cache('/tmp/expensive_cache')@cache.memoize(expire=60, tag='computation')def expensive_computation(n): print("Performing heavy computation...") time.sleep(2) # Simulate an expensive calculation. return sum(i * i for i in range(n))if __name__ == '__main__': # Measure time for the first call. start_time = time.perf_counter() result1 = expensive_computation(10000000) end_time = time.perf_counter() print("Result:", result1) print(f"Time for first computation: {end_time - start_time:.4f} seconds
") # Measure time for the second call (should hit the cache). start_time = time.perf_counter() result2 = expensive_computation(10000000) end_time = time.perf_counter() print("Result (from cache):", result2) print(f"Time for second computation: {end_time - start_time:.4f} seconds") ```

Running this the first time resulted in this output.

``` Performing heavy computation...Result: 333333283333335000000Time for first computation: 3.2539 secondsResult (from cache): 333333283333335000000Time for second computation: 0.0001 seconds ```

### Example 2 — Caching API Requests to Avoid Rate Limits

Repeated API calls can slow down your application and risk hitting rate limits. Diskcache lets you cache API responses with extra metadata like expiration and tags. In this example, we cache the JSON response from an API. Notice that we store the response as a file-like object (using `read=True`) so that when retrieving it, we can efficiently stream its content.

Also, note that we are caching to disk this time instead of in memory.

```python import requestsimport jsonfrom io import BytesIOfrom diskcache import Cachecache = Cache('/tmp/api_cache')def fetch_data(url): key = f"api_response:{url}" if key in cache: print("Serving data from cache.") # Retrieve the stored value as a file-like object along with extra metadata. reader, expire_time, tag = cache.get(key, read=True, expire_time=True, tag=True) # Read and decode the JSON data. data = json.loads(reader.read().decode('utf-8')) return data print("Fetching data from API.") response = requests.get(url) response.raise_for_status() data = response.json() # Store the API response for 5 minutes (300 seconds). cache.set(key, BytesIO(json.dumps(data).encode('utf-8')), expire=300, read=True, tag='api') return dataif __name__ == '__main__': url = 'https://jsonplaceholder.typicode.com/posts/1' data = fetch_data(url) print(json.dumps(data, indent=4)) # A subsequent call retrieves the data from cache. data = fetch_data(url) print(json.dumps(data, indent=4)) ```

The first call prints “Fetching data from API.” and caches the JSON response. The second call prints “Serving data from cache.” and retrieves the cached response, avoiding an extra network call.

**Example 3 — Implementing a Persistent FIFO Job Queue with Diskcache.Deque**

Diskcache also offers persistent data types such as **Deque** , which provides a double-ended queue that is both thread- and process-safe. This is ideal for job queues where tasks must persist across process restarts. In the example below, we enqueue ten jobs and use three worker threads to process them concurrently.

```python from diskcache import Dequeimport timeimport threading# Initialize a persistent deque stored in /tmp/job_queue.job_queue = Deque('jobs', directory='/tmp/job_queue')def worker(worker_id): while True: try: # popleft() retrieves and removes the leftmost item. job = job_queue.popleft() print(f"Worker {worker_id} processing {job}") time.sleep(1) # Simulate processing time. except IndexError: # The deque is empty when no jobs remain. print(f"Worker {worker_id} found no jobs. Exiting.") breakif __name__ == '__main__': # Enqueue 10 jobs. for i in range(10): job_queue.append(f"Job-{i}") # Launch 3 worker threads. threads = [threading.Thread(target=worker, args=(i,)) for i in range(1, 4)] for t in threads: t.start() for t in threads: t.join() print("All jobs have been processed.") ```

Each worker thread pulls jobs from the persistent deque. Even if your application restarts, the jobs remain in /tmp/job_queue until they are processed.

And the output.

Exiting.Worker 1 found no jobs. Exiting.Worker 3 found no jobs. Exiting.All jobs have been processed. ```

**Example 4 — Using TTL, Touch, and Expiration Policies**

Diskcache supports expiration policies via TTL (time-to-live) settings. Sometimes, you might want to extend a key’s life without modifying its value. The `touch()` method updates the expiration time atomically. In this example, we simulate fetching configuration data that expires after 10 seconds. We then use `touch()` to prolong its validity.

```python from diskcache import Cacheimport timecache = Cache('/tmp/ttl_cache')def get_configuration(): key = "app_config" if key in cache: print("Loaded configuration from cache.") return cache.get(key) print("Fetching configuration from external source.") config = { "version": 1.2, "feature_enabled": True, "timestamp": time.time() } # Cache the configuration for 10 seconds with a tag. cache.set(key, config, expire=10, tag='config') return configif __name__ == '__main__': # First retrieval: cache miss and then set. config = get_configuration() print("Configuration:", config) # Wait 5 seconds and then refresh the expiration with touch. time.sleep(5) cache.touch("app_config", expire=10) # Remove expiration (or extend it). config = get_configuration() print("Configuration after touch:", config) # Wait another 6 seconds. Without touch, the configuration would normally expire. time.sleep(6) config = get_configuration() print("Configuration after TTL period:", config) # Wait another 6 seconds. This time the cache will have expired. time.sleep(6) config = get_configuration() print("Configuration after TTL period:", config) ```

Initially, the configuration is fetched and cached. After 5 seconds, the expiration is updated using the `touch()` method, so a subsequent call still finds the configuration in the cache. Finally, if the TTL expires without further touches, a new configuration is fetched.

``` Loaded configuration from cache.Configuration: {'version': 1.2, 'feature_enabled': True, 'timestamp': 1739351822.1815312}Loaded configuration from cache.Configuration after touch: {'version': 1.2, 'feature_enabled': True, 'timestamp': 1739351822.1815312}Loaded configuration from cache.Configuration after TTL period: {'version': 1.2, 'feature_enabled': True, 'timestamp': 1739351822.1815312}Fetching configuration from external source.Configuration after TTL period: {'version': 1.2, 'feature_enabled': True, 'timestamp': 1739351983.812601} ```

**Example 5 — Caching Database Queries with Transactions**

Database queries can be a significant performance bottleneck in data-intensive applications. Diskcache allows you to cache query results — complete with atomic transactions to ensure consistency. In this example, we simulate a query against a SQLite database and cache the results with a 30‑second expiration. We use a transaction block (`cache.transact()`) to ensure that the cache set operation occurs atomically.

> **_Note:_**_Ensure you have a SQLite database (e.g.,_`_example.db_` _) with a table (e.g.,_`_sales_` _) set up prior to running this example._
>
> _You can use the following code for that._

```python import sqlite3# Connect to the database (this will create the file if it doesn't exist)conn = sqlite3.connect('example.db')cursor = conn.cursor()# Create the 'sales' table if it doesn't existcursor.execute(''' CREATE TABLE IF NOT EXISTS sales ( id INTEGER PRIMARY KEY AUTOINCREMENT, product TEXT NOT NULL, quantity INTEGER NOT NULL )''')# Optional: Clear out any existing data (uncomment if needed)# cursor.execute("DELETE FROM sales")# Insert sample data into the 'sales' tablesample_data = [ ('Apple', 10), ('Banana', 5), ('Apple', 20), ('Orange', 8), ('Banana', 7), ('Apple', 15), ('Orange', 12)]cursor.executemany('INSERT INTO sales (product, quantity) VALUES (?, ?)', sample_data)# Commit the changes and close the connectionconn.commit()conn.close()print("Database and 'sales' table have been created and populated with sample data.") ```

Now that we have our data, we can run some code.

```python import sqlite3from diskcache import Cacheimport timecache = Cache('/tmp/db_cache')def query_database(query, params=(), ttl=30): key = f"db_query:{query}:{params}" if key in cache: print("Cache hit for query.") return cache.get(key) print("Executing query against the database.") conn = sqlite3.connect('example.db') cursor = conn.cursor() cursor.execute(query, params) result = cursor.fetchall() conn.close() # Use a transaction to atomically cache the query result. with cache.transact(): cache.set(key, result, expire=ttl, tag='db') return resultif __name__ == '__main__': query = "SELECT product, SUM(quantity) FROM sales GROUP BY product" # First execution: runs the query and caches the result. result = query_database(query) print("Query Result:", result) # Subsequent execution within 30 seconds retrieves the cached result. result = query_database(query) print("Query Result (from cache):", result) ```

So, on the first call, the query is executed, and the result is stored atomically within a transaction. Any subsequent calls within 30 seconds fetch the cached result, reducing the load on the database.

``` Executing query against the database.Query Result: [('Apple', 45), ('Banana', 12), ('Orange', 20)]Cache hit for query.Query Result (from cache): [('Apple', 45), ('Banana', 12), ('Orange', 20)] ```
