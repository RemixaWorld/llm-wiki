Brian Niccol became the CEO of Starbucks in August this year. Unfortunately, our LLMs were trained much before this, so they might still think the CEO is Kevin Johnson and that Brian Niccol is the CEO of Chipotle. That begs the question, "How do we change facts in LLMs without retraining them every time?"

[This paper](<https://arxiv.org/abs/2202.05262>), published in 2022, introduced **Rank-One Model Editing** , which allows you to edit facts in a model without retraining it. If the CEO of a company like Starbucks changes, we'd certainly like to keep the LLM's memory up-to-date so that it answers questions effectively.

When I read this paper, it was insightful.

It not only proved that (i) MLPs stored facts but also showed (ii) how to change weights in an MLP to change the stored facts. If (ii) works, then (i) is implied. And (ii) did work. It had limitations, but as a tool to better understand LLMs, it got much attention since 2022.

In this blog, I'll explain an LLM's MLP mechanisms and how the paper uses it to edit facts in an LLM. Read this [previous blog](</@nikhilanandnj/where-are-facts-stored-in-large-language-models-0869914cfcbf>) first to understand how we know where facts are stored in LLMs.

## Factual Association Hypothesis

This hypothesis states that every MLP layer can be modelled like this:

![image](https://miro.medium.com/v2/resize:fit:700/1*Oo7gtxoJtSNGnIjUX7fMfg.png)

And this "Factual Association" is localised to:

1. The MLP blocks
2. The Subject's last token
3. Specific middle layers

Think of an MLP block like a dictionary, i.e., a key-value map.

"Brian Niccol" -> "CEO of Chipotle"

![image](https://miro.medium.com/v2/resize:fit:700/1*dWWPmAQFAaxnuiEdIPe4tg.png)

If the Subject is _"Brian Niccol"_ , the last subject token might be _"Niccol",_ and we expect it to map to some memorised property, like _"CEO of Chipotle"_.

![image](https://miro.medium.com/v2/resize:fit:700/1*V4TVoAvt-FbYBTaHbLkexw.png)

But he's not the CEO of Chipotle Mexican Grill anymore. We need to change the facts.

"Brian Niccol" -> "CEO of Starbucks"

Can we zoom in further to understand what's happening inside the MLP?

## MLP Mechanism

The MLP is made up of two layers. They're both essentially linear projections. Let's first understand what a linear projection is.

![image](https://miro.medium.com/v2/resize:fit:700/1*Qb7d4PMMaWVRBF7W5CNURw.png)

When a matrix W (m × n) is multiplied by a vector x (n × 1), the result is a vector y (m × 1). This is essentially a linear projection, and if m > n, then we are **projecting _x_ to a higher dimensional space**, while if m < n, we are **projecting _x_ to a lower dimensional space**.

We're ready for the following diagram (an MLP block comprising two layers and a sigmoid activation function after the first layer).

![image](https://miro.medium.com/v2/resize:fit:700/1*xnnNuF9n6Juz75tq0FnqBw.png)

Here, h_i represents the layer's residual stream vector before passing into the MLP. We project it onto a **higher dimensional space of dimension D** using the first linear layer and **apply the sigmoid activation function** to get the key k*.

![image](https://miro.medium.com/v2/resize:fit:700/1*y2DRdSg-J49mPo3_WEwPPQ.png)

Then, we project it back down to the **lower dimensional space of dimension H**.

![image](https://miro.medium.com/v2/resize:fit:700/1*aoWhdZ8HMUPUM1o61BhUKg.png)

And that's how an MLP works. A non-linear transformation is applied to the input vector _h_i_ to get the output vector _v*_. But if we play with the "dictionary" analogy, the keys are k*, the values are v*, and Wproj is the mapping function from the keys to the values. If**we want to change the facts, we must edit Wproj**.

![image](https://miro.medium.com/v2/resize:fit:700/1*AJCBK30AmLrNzbRPZQBvqw.png)

In other words, we want to insert the following key-value pair into the memory.

![image](https://miro.medium.com/v2/resize:fit:700/1*bzCiHbNMMYOc6NbgzbZ8iw.png)

How do we exactly add a key-value pair to the memory?

Note that the key k* isn't exactly "Niccol". It's the vector obtained between the MLP layers when we input "Niccol" into the LLM.

Similarly, the value v* isn't exactly "Starbucks". It's the vector obtained after the MLP that eventually leads to the prediction of the token "Starbucks".

Let's first assume we know what k* and v* are. In that case, how do we figure out how to edit the weight matrix?

As we can see, the line changes its direction slightly. It's almost a linear regression problem where we find the line that optimally fits the points. However, unlike linear regression,**it must precisely touch (k*, v*) and remain as close to the other points as possible**.

Let's consider **W** as the weight matrix optimised across all pairs **except** (k*, v*). K and V represent the sets of keys and values excluding k* and v*.

![image](https://miro.medium.com/v2/resize:fit:700/1*NJJGCP6BUVfmOi-L8TnY5Q.png)

So, we want to find the line (Ŵ) that perfectly fits the point (k*, v*) but remains as close to the remaining keys and values as possible.

### How do we get k* and v*?

We still need to figure out how to obtain k* and v*.

* **Obtaining _k*_ **is straightforward. We input the prompt ("Niccol") into the LLM, do a forward pass, and record the activations between the two MLP layers in the specific layer and token position we decided on. These activations are taken as the value of _k*_.
* **Obtaining _v*_** is less straightforward. We need to find out which value of _v*_ is most likely to give the desired output ("Starbucks") rather than the undesired one ("Chipotle"). To do this, we choose a _z_ that minimises the following objective, where the _z_ for which the expression is minimised is taken as _v*_.

The term (a) allows us to find the hidden state _v*_ that maximises the probability of outputting _o*_ ("Starbucks"). The term (b) ensures that the KL-divergence between the overall probability distributions isn't too high.

In summary, we ensure _v*_ is chosen to maximise the probability of "Starbucks" while the overall probability distribution faces as little change as possible.

## Conclusions

The factual association hypothesis tells us factual associations are probably stored in MLPs. Thus, we understood how to obtain a key-value pair _(k*, v*)_ for any fact we want to store in the LLM and how to edit the weights of a particular MLP to store that specific fact.

This method inspired further research to understand how LLMs work and use those insights to build meaningful solutions. One of its major strengths is that it works well despite a simplistic approach. Methods like these are breakthroughs in understanding how transformers do what they do.

## Limitations

The results from this paper should be considered an inspiration for further research but should be considered cautiously.

* **The method itself is not broadly applicable** since you can only edit one fact at a time. However, this paper presents a strong argument when considered with the follow-up papers that came after.
* **Fact editing a specific token does not also edit other similar or synonymous tokens.** For example, we could add a fact like "Dogs are herbivores". Then, the LLM may consider "Dogs are herbivores" as a truth but may still consider "Canines are omnivores".
* **Fact editing a subject-object relationship does not automatically change the fact when the Subject and object are interchanged.** For example, the LLM may say "Dogs are herbivores" but may not say "Herbivores include dogs".
