## 5 LLM Concepts that were foundational to the method

### 1\. Supervised Finetuning in LLMs

Supervised finetuning in LLMs is carried out to “train” LLMs to behave in a certain way.

This is usually an important step in LLM training after the pretraining phase — once the LLM has learnt to output fluent language, we train it to behave in a certain way.

Imagine you have a dog and you want it to raise its paw whenever you say “Shake”. In that case, you would provide an input to the dog (saying “shake”), and the expected output is for the dog to raise its paw. Here, the inputs are called features and the outputs are labels, and these labels represent what our expected behaviour of the dog is. If the dog’s current behaviour is not the same as its expected behaviour, we change the parameters of the dog so that its output is closer to the expected behaviour (raising its paw).

Press enter or click to view image in full size

An illustration of what supervised training or finetuning could look like. (Image by author)

One of the main issues with supervised finetuning is that the process takes time and is less efficient, since it involves several iterations of changing the parameters of the model until it behaves like we want it to.

If you want to change your model’s behaviour in a specific way, you might also be able to run inference-time methods which take much less time to run. The next LLM concept is one such inference-time method.

### 2\. Contrastive decoding

Let’s break this down a bit.

Firstly, in typical LLM generation pipelines, the LLM generates a set of logits at the end, which are then converted into next-token probabilities using the softmax function. The token with the maximum probability is chosen as the next token and the process repeats.

However, in alternate decoding, we apply some transformation to the logits before converting it into probabilities. The goal of this transformation is to get the LLM to behave differently.

Press enter or click to view image in full size

Normal decoding (left), decoding with some transformation (right). (Image by author)

Contrastive decoding is a specific form of alternate decoding.

Here, the transformation we use is a contrasting function, which contrasts two logit distributions and boosts the logits which are most contrasted between the distributions.

### 4\. The importance of clean data for effective fine-tuning

When I was going through the papers that DeepSeek wrote, specifically DeepSeekMath, I learnt something interesting:

> Ensuring that the data used in fine-tuning is actually representative of the kind of behaviour you want to induce is crucial to ensuring that the resulting behaviour changes are as optimised as possible.

One of the key changes they made compared to previous methods was related to the way they sourced the data, and now, DeepSeek is in the headlines with its amazing reasoning performance.

### 5\. Retrieval heads

This is the important part. Essentially, these are attention heads in LLMs (specific blocks in the transformer neural network) that copy-paste text from the context directly into the model’s output.

## The Method

Now, we put these insights together to develop an approach to improve an LLM’s contextual faithfulness.

There are 3 key steps to this approach:

### **1\. Mask the retrieval heads to generate unfaithful outputs.**

In my [previous blog](</how-rag-llms-reproduce-the-context-by-literally-copy-pasting-information-7b7c2096f597>), I explained how this works; essentially, the retrieval heads are responsible for copy-pasting information from the context, so masking them ensures that the LLM ignores the context while generating a response, leading to an unfaithful response.

Press enter or click to view image in full size

We mask out retrieval heads and see if the LLM still copies text from the context. ([Image](</how-rag-llms-reproduce-the-context-by-literally-copy-pasting-information-7b7c2096f597>) by author)

### 2\. Fine-tune the LLM to generate faithful or unfaithful response depending on the control code

Here, [POS] and [NEG] are **control codes** (similar to the options A and B we saw earlier).

If we provide the [POS] control code as a prefix to the answer, the LLM should continue the response faithfully to the context. If we instead provide the [NEG] control code, the LLM should continue the response unfaithfully.

Press enter or click to view image in full size

The goal is for the LLM to output a faithful or unfaithful response depending on the control code. (Image by author)

How do we get the LLM to behave in this specific way?

We **fine-tune** the LLM, thereby teaching it through several examples that it needs to respond faithfully in one situation and unfaithfully in the other.

In order to fine-tune the LLM, we need to provide it with examples of what constitutes unfaithful behaviour and what constitutes faithful behaviour. This data is generated by the LLM in the previous step, where we mask out the retrieval heads to generate unfaithful data.

Note that this **data is “clean”** since it truly represents unfaithful behaviour. The paper showed this by showing that the unfaithful behaviour induced by masking retrieval heads mirrored actual error distributions.

We might’ve generated this data in other ways, but _this was the cleanest way_.

### 3\. Use contrastive decoding to enhance faithfulness

We provide two versions of the prompt to the LLM, one with the [POS] control code and one with the [NEG] control code. Since the LLM is fine-tuned accordingly, it generates an unfaithful output in the latter case and a faithful output in the former case.

We then take the logit outputs of both cases, and contrast them, boosting those logits which were strong in [POS] but weak in [NEG].

Press enter or click to view image in full size

By boosting faithful logits and inhibiting unfaithful logits, we expect more faithful outputs. (Image by author)

## Conclusion

In summary, here’s what we did:

* Masked the retrieval heads to generate realistic unfaithful outputs.
* Fine-tuned LLM to generate unfaithful or faithful outputs depending on the control code.
* Used contrastive decoding between outputs to boost faithfulness.

This is a great case study in how research ideas can pop up. By understanding the conclusions other people have made from existing research, we can put them together, follow certain established principles, and then develop our own methods hoping that it’ll work. It’s all about trial and error. Once we find something that works, we can publish our results.

The more observations we make, the more data we have to develop a more principled model.
