## What Is an Image?

An image is fundamentally a **2D array** of pixel values, where each pixel represents the smallest unit of the image. The way pixel values are interpreted depends on the image type:

* **Binary Images** : Pixels are either black or white.
* **Grayscale Images** : Each pixel has a single intensity value ranging from 0 (black) to 255 (white) in 8-bit images.
* **Color Images** : Pixels are represented by a tuple of values corresponding to different color channels.

### Pixels and Color Depth

* **Color Depth** : The number of bits used to represent the color of a single pixel. Common depths are 8-bit (256 colors) and 24-bit (16 million colors).
* **Channels** : Separate components of a color model (e.g., Red, Green, and Blue in RGB).

## Exploring Color Models

Color models define how colors are represented and manipulated in an image. Understanding these models is essential for color correction, filtering, and segmentation tasks.

### **1\. RGB (Red, Green, Blue)**

* **Additive Color Model** : Colors are created by combining red, green, and blue light.
* **Usage** : Digital screens, cameras.

### 2\. CMYK (Cyan, Magenta, Yellow, Key/Black)

* **Subtractive Color Model** : Colors are created by subtracting light using pigments or dyes.
* **Usage** : Printing.

### 3\. HSV/HSL (Hue, Saturation, Value/Lightness)

* **Hue** : The color type (e.g., red, blue).
* **Saturation** : Intensity or purity of the color.
* **Value/Lightness** : Brightness of the color.
* **Usage** : Color selection tools, image analysis.

### 4\. YUV/YIQ/YCbCr

* **Luminance-Chrominance Models** : Separate brightness (luminance) from color information (chrominance).
* **Usage** : Video compression, broadcasting.

## Creating Images Using Pillow

Pillow is a popular Python library for image processing, offering extensive support for opening, manipulating, and saving many different image file formats. It is an improved fork of the **Python Imaging Library (PIL)** , which is no longer actively maintained.

## Creating Images Using OpenCV

OpenCV represents images as NumPy arrays, enabling powerful matrix operations and manipulations. Unlike Pillow, OpenCV uses the **BGR** (Blue, Green, Red) color format by default.

### Loading image with OpenCV

``` image_cv = cv2.imread('./data/beach-blue.jpg') ```

### Example 1: Creating BGR Image in OpenCV

```python import numpy as npimport cv2# Create a blank 500x500 image with 3 channels (BGR) and 8-bit unsigned integersimage_opencv = np.zeros((250, 250, 3), dtype=np.uint8)# Set the entire image to orange color in BGR formatimage_opencv[:] = (0, 100, 255) # Orange in BGR# Display the imagecv2.imshow('Orange Image', image_opencv)cv2.waitKey(0)cv2.destroyAllWindows() ```

**Output:** A 100×100 orange square.

**Explanation** :

* `np.zeros((500, 500, 3), dtype=np.uint8)`: Creates a 500x500 black image.
* `image_opencv[:] = (0, 100, 255)`: Sets all pixels to orange in BGR format. Value of G is in the same place but the values of R & B are swapped.
* `cv2.imshow()`: Displays the image in a window.

### Example 2: Convert to RGB from BGR Image OpenCV

```python import cv2import matplotlib.pyplot as plt# Convert BGR to RGBimage_rgb = cv2.cvtColor(image_opencv, cv2.COLOR_BGR2RGB)# Create figure with two subplotsfig, (ax1, ax2) = plt.subplots(1, 2, figsize=(12, 5))# Display original BGR image (will look incorrect due to matplotlib expecting RGB)ax1.imshow(image_opencv)ax1.set_title('Original BGR Image
(Incorrect colors in matplotlib)')ax1.axis('off')# Display converted RGB imageax2.imshow(image_rgb)ax2.set_title('Converted RGB Image
(Correct colors)')ax2.axis('off')plt.tight_layout()plt.show() ```

**Output:**

![image](https://miro.medium.com/v2/resize:fit:700/1*1wgH-mypo622SkXnZIsadQ.png)

**Explanation:**

* The left image shows how a BGR image appears incorrectly in `matplotlib` because matplotlib expects RGB format — what should be red appears as blue
* The right image shows the same image after proper BGR to RGB conversion using `cv2.cvtColor()`, displaying the correct orange/red color
* This demonstrates why color space conversion is crucial when working with OpenCV (which uses BGR) and matplotlib (which uses RGB) together, as the color channels are in different orders

**Why BGR Instead of RGB?**

OpenCV was originally developed in the C/C++ languages, and BGR was the default color order due to historical reasons.

## Metadata: EXIF Information

**EXIF** (**E** xchangeable **I** mage **F** ile Format) is a standard for storing metadata in digital image files. This metadata includes crucial information about:

* Camera settings (aperture, shutter speed, ISO)
* Date and time the photo was taken
* GPS coordinates (if available)
* Image orientation
* And much more

### Reading EXIF Data with Pillow

```python from PIL import Image, ExifTags# Open the image file - This image is used from Live Complete Computer Vision # Vision With Generative AI Bootcamp. Please try your own image and see # the resultsimage = Image.open('./data/GP_PXL_20240926_003004774.jpg')# Extract EXIF dataexif_data = image._getexif()# Map EXIF tags to human-readable namesif exif_data is not None: for tag_id, value in exif_data.items(): tag = ExifTags.TAGS.get(tag_id, tag_id) print(f"{tag}: {value}")else: print("No EXIF metadata found.") ```

### Modifying EXIF Data

While Pillow is great for reading EXIF data, `piexif` provides more robust capabilities for modifying EXIF information:

```python # Print EXIF tags and values in a more human-readable formatimport piexif# Load EXIF dataexif_data = image.info.get('exif', b'')exif_dict = piexif.load(exif_data)# Define a function to display the EXIF data in a human-friendly formatdef print_exif_dict(exif_dict): for ifd_name, ifd_content in exif_dict.items(): if isinstance(ifd_content, dict): # Ensure the section is a dictionary print(f"
{ifd_name} Tags:") for tag, value in ifd_content.items(): tag_name = piexif.TAGS[ifd_name].get(tag, {"name": f"Unknown Tag {tag}"})["name"] print(f" {tag_name} ({tag}): {value}") else: print(f"
{ifd_name} contains non-dictionary data.")# Display the EXIF dataprint_exif_dict(exif_dict)# Update the orientation to 5 (Mirrored and rotated 90° counterclockwise)exif_dict["0th"][piexif.ImageIFD.Orientation] = 5# Insert the modified EXIF data back into the imageexif_bytes = piexif.dump(exif_dict)image.save('./temp/GP_PXL_20240926_003004774_with_updated_exif.jpg', exif=exif_bytes) ```

**Output:**

We will also get mirrored horizontally and rotated 90 degrees counterclockwise version of the image that was opened.

### Understanding Image Orientation in EXIF

One of the most important EXIF tags is the orientation flag, which tells image viewers how to display the image correctly. There are 8 possible orientation values:

1. `1` — Normal orientation (0 degrees)
2. `2` — Mirrored horizontally (0 degrees)
3. `3` — Rotated 180 degrees
4. `4` — Mirrored vertically (180 degrees)
5. `5` — Mirrored horizontally and rotated 90 degrees counterclockwise
6. `6` — Rotated 90 degrees clockwise
7. `7` — Mirrored horizontally and rotated 90 degrees clockwise
8. `8` — Rotated 90 degrees counterclockwise

**Note** : Modifying EXIF data should be done cautiously, as it can affect how images are processed by other software.
