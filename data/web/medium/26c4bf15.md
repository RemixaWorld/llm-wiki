## What Is a Multi-Hop Question?

A multi-hop question is a type of question that requires multiple steps or “hops” to arrive at an answer. Rather than being a straightforward query with a single answer, a multi-hop question involves breaking down the original question into smaller parts, each of which requires its own analysis.

They typically require critical thinking skills and the ability to connect information from different sources or domains. Multi-hop questions are common in complex problem-solving scenarios and research tasks, where the goal is to assess not only factual knowledge but also the ability to reason and synthesize information.

Here’s an example of a multi-hop question:

**Texts:**

\- Text 1: “The Nile is the longest river in Africa and flows through several countries including Egypt and Sudan.”

\- Text 2: “The ancient city of Thebes was located in Egypt along the banks of the Nile.”

\- Text 3: “Thebes was known for its vast number of temples and was often referred to as the city of a hundred gates.”

**Multi-Hop Question:**

\- “Which city known for its many temples was located along the longest river in Africa?”

How to Answer:

\- First Hop: Identify the longest river in Africa. From Text 1, we learn it’s the Nile.

\- Second Hop: Determine which city known for its many temples was situated along the Nile. From Texts 2 and Text 3, we can conclude that Thebes, known for its temples, was located along the Nile in Egypt.

**Answer:** Thebes

## Challenges of Creating a Multi-Hop LLM Agent

Creating a Large Language Model (LLM) agent for multi-hop question-answering is particularly challenging due to the necessary prompt engineering involved.

This complex process requires the model to engage in multiple rounds of prompting where the main question must be deconstructed into manageable sub-questions. Each sub-question is then sequentially addressed, gathering the essential information step-by-step.

This meticulous structuring of prompts is crucial as it guides the LLM to navigate through and gather information from various sources effectively, ensuring a coherent and accurate final answer based solely on the initial, complex inquiry.

Therefore, in order to create an efficient multi-hop LLM application, one needs to invest a significant amount of time and effort in prompt engineering.

This process of prompt engineering is often a hit-and-trial method, where the developer has to tweak their prompts iteratively until they are satisfied with the LLM’s responses. Moreover, prompt templates are LLM specific — meaning different LLMs respond correctly to different types of prompting templates.

All of this makes multi-hop question-answering a rather complicated process.

Enter [DSPy](<https://github.com/stanfordnlp/dspy>), a framework specially designed to do away with traditional prompt engineering methodologies.

## How DSPy Takes Care of Prompt Engineering

[DSPy](<https://github.com/stanfordnlp/dspy>) has out-of-the-box prompting modules especially designed for various use-cases of LLM question-answering. It prioritizes programming over manual prompting, aiming to streamline tasks that traditionally required intricate prompt crafting or intensive model tweaking.

The framework introduces structured components like Signatures, Modules, and Optimizers to automate prompting for arbitrary pipelines, making the development process more efficient and effective.

## Building a Multi-Hop RAG Pipeline with DSPy, Qdrant, and Ollama

DSPy has a readymade set of modules which can be used to construct a RAG pipeline that is capable of performing multi-hop question-answering.

In this tutorial, we’ll use [Qdrant ](<https://qdrant.tech/>)as our vector database to store the external information, and we’ll connect it to the LLM Llama3 using [Ollama](<https://ollama.com/>). Then we’ll use the tools provided by DSPy to build our multi-hop RAG.

Now configure the Qdrant Retriever and Llama3 into DSPy.

```python from dspy.retrieve.qdrant_rm import QdrantRMimport dspyqdrant_retriever_model = QdrantRM("leo_collection", client, k=10)ollama_model = dspy.OllamaLocal(model="llama3",model_type='text', max_tokens=350, temperature=0.1, top_p=0.8, frequency_penalty=1.17, top_k=40)dspy.settings.configure(lm= ollama_model, rm=qdrant_retriever_model) ```

You can refer to [this](<https://github.com/ollama/ollama>) to install Ollama. Make sure you have pulled llama3 br running ```ollama pull llama3```

We’ll first define a DSPy signature which will generate an answer given a context and a question.

```python class GenerateAnswer(dspy.Signature): """Answer questions with short factoid answers.""" context = dspy.InputField(desc="may contain relevant facts") question = dspy.InputField() answer = dspy.OutputField() ```

Then we’ll define another signature which will help define the intermediate query for the multi-hop.

```python class GenerateSearchQuery(dspy.Signature): """Write a simple search query that will help answer a complex question.""" context = dspy.InputField(desc="may contain relevant facts") question = dspy.InputField() query = dspy.OutputField() ```

Then we’ll construct a DSPy module that will generate intermediate queries to collect all the relevant context and then use that to answer the user’s questions.

```python from dsp.utils import deduplicateclass SimplifiedBaleen(dspy.Module): def __init__(self, passages_per_hop=3, max_hops=2): super().__init__() self.generate_query = [dspy.ChainOfThought(GenerateSearchQuery) for _ in range(max_hops)] self.retrieve = dspy.Retrieve(k=passages_per_hop) self.generate_answer = dspy.ChainOfThought(GenerateAnswer) self.max_hops = max_hops def forward(self, question): context = [] for hop in range(self.max_hops): query = self.generate_query[hop](context=context, question=question).query passages = self.retrieve(query).passages context = deduplicate(context + passages) pred = self.generate_answer(context=context, question=question) return dspy.Prediction(context=context, answer=pred.answer) ```

The `__init__` method in our code sets up several important components:

\- generate_query: For each step, or “hop,” in our process, this component uses a special tool called dspy.ChainOfThought with the GenerateSearchQuery setup to create a search query. dspy.ChainOfThought makes sure that the LLM reasons through the prompts in a step-by-step fashion.

\- retrieve: This component takes the search queries and finds relevant information from the Qdrant database using the dspy.Retrieve module.

\- generate_answer: After gathering all the required information, this dspy.Predict module, configured with the GenerateAnswer setup, is used to formulate the final response.

In the `forward` method, the process is laid out in a sequence of steps:

1\. We loop through a set number of times, defined by `self.max_hops`.

2\. In each cycle of the loop:

\- A search query is generated using the generate_query component for the current hop.

\- This query is used to fetch the top relevant pieces of information (top-k passages).

\- We collect these passages, ensuring there are no duplicates, and add them to our collection of context information.

3\. After completing all the hops, we use the generate_answer component to create the final answer based on the accumulated context.

4\. Finally, the process returns a prediction that includes both the gathered context and the generated answer.
