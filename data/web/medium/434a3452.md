![A cute cartoon robot and a cheerful duck high-five each other, surrounded by stacks of paper. The robot is holding a document, and both characters look happy and enthusiastic.](https://miro.medium.com/v2/resize:fit:700/0*L0rPmgEw_CjEEaoF)

Loading long documents into AI chatbots to ask specific questions of interest is a quite practical use case for large language models. I’m certain that this is a feature many of us can no longer imagine working without.

However, when it comes to providing sources for the information presented in their final answers, many chatbots simply reference the entire document rather than pinpointing the specific section relevant to the answer.

This approach is of limited use when the document contains over 100 pages, thousands of paragraphs, or numerous images.

But this doesn’t have to be the case.

Advanced document analysis during the offline indexing phase of a Retrieval-Augmented Generation (RAG) system enables answer grounding at the paragraph level.

This technique allows us to specify exactly where each piece of information originates.

Thus, sources can be verified in seconds, leading to faster fact-checking and greater interpretability of LLM outputs.

In this blog post, I will introduce a solution for visual answer grounding in advanced RAG systems, using Docling.

I will present the general processing pipeline for both the offline indexing and online retrieval phases, along with a detailed walkthrough of the scripts.

In this way, you can easily incorporate this feature into your next RAG application.

## Explanation of the general workflow

Like most RAG applications, this application is also split into two parts: the offline indexing part and the online retrieval part.

### Offline Indexing Part

In the offline indexing part, the input PDF documents are analyzed by Docling.

This process includes paragraph parsing, layout understanding, and image and table extraction.

Additionally, each image receives a detailed description generated by a vLM, which considers a document summary, the text paragraphs surrounding the image, and the image itself.
Adding this extra context significantly enhances the quality of the image descriptions.

Afterward, all extracted PDF items are serialized, including the image descriptions and tables, for the subsequent Docling chunking process.
In the end, these chunks are embedded and added to the Qdrant vector store for later retrieval.

### **Online Retrieval Part**

The embedded knowledge is used in the second part for answering questions by retrieving the K semantically most similar document chunks to the user query.

These K chunks are analyzed to determine which document they originate from, so the related JSON document representation (created by Docling during the offline indexing phase) can be loaded.

This JSON document representation includes all details from the previous document analysis, such as item type, position, page number, and annotations.
This metadata provides the basis for the subsequent grounding process.

However, a single document chunk often consists of several items, such as sections, equations, tables, or multiple paragraphs.
For answering a specific question, not all this information is necessarily relevant.

To ensure that only relevant information is considered in the final answer generation and visual grounding process, an additional LLM-based post-processing step has been added.

In this step, each document item in a chunk is passed to an LLM, which assesses the relevance of the item to the provided user query on a scale from 1 to 5, where 5 is highly relevant.

Only document items above a predefined threshold are passed to the LLM for generating the final answer and for the visual grounding process.

**Document Summarization with LangGraph
** In the next step, an iterative document summarization method is defined that allows for the generation of document summaries beyond the context window size of an LLM.

This approach involves dividing the document into large sections. The first section is summarized, and then this summary is expanded upon by the second section, and so on, until all sections are integrated into a cohesive summary.

```python def build_iterative_summary_graph( llm: ChatModel, config: Optional[RunnableConfig] = None) -> StateGraph: """Build a LangGraph for iterative document summarization.""" # Initial summary prompt and chain init_prompt = ChatPromptTemplate([ ("human", "Write a concise summary of the following:
{context}

" "The summary must be clear and informative. " "The summary of the document have to be between one and three sentences long.") ]) initial_chain = init_prompt | llm | StrOutputParser() # Refinement prompt and chain refine_prompt = ChatPromptTemplate([ ("human", "Produce a final summary.

" "Existing summary up to this point:
{existing_answer}

" "New context:
------------
{context}
------------
" "Given the new context, refine the original summary. " "The summary of the document have to be between one and three sentences long.") ]) refine_chain = refine_prompt | llm | StrOutputParser() # State type for the graph class State(TypedDict): contents: List[str] index: int summary: str def generate_initial_summary( state: State, cfg: Optional[RunnableConfig] = None ) -> dict: """Generate initial summary from first chunk.""" summary = initial_chain.invoke(state["contents"][0], cfg or config) return {"summary": summary, "index": 1} def refine_summary( state: State, cfg: Optional[RunnableConfig] = None ) -> dict: """Refine summary with additional context.""" context = state["contents"][state["index"]] summary = refine_chain.invoke( {"existing_answer": state["summary"], "context": context}, cfg or config ) return {"summary": summary, "index": state["index"] + 1} def should_refine(state: State) -> Literal["refine_summary", END]: """Determine if more refinement is needed.""" return ( END if state["index"] >= len(state["contents"]) else "refine_summary" ) # Build the state graph graph = StateGraph(State) graph.add_node("generate_initial_summary", generate_initial_summary) graph.add_node("refine_summary", refine_summary) graph.add_edge(START, "generate_initial_summary") graph.add_conditional_edges("generate_initial_summary", should_refine) graph.add_conditional_edges("refine_summary", should_refine) return graph.compile()def run_graph(app, documents: List[Document]) -> str: """Execute the summarization graph.""" final_summary: Optional[str] = None for step in app.stream( {"contents": [doc.page_content for doc in documents]}, stream_mode="values" ): if "summary" in step: final_summary = step["summary"] if final_summary is None: raise RuntimeError("Iterative summary failed: no summary produced.") return final_summarydef chunk_text( text: str = "", chunk_size: int = 500, chunk_overlap: int = 0) -> List[Document]: """Split text into chunks using RecursiveCharacterTextSplitter.""" doc = Document(page_content=text) text_splitter = RecursiveCharacterTextSplitter( chunk_size=chunk_size, chunk_overlap=chunk_overlap ) chunks: List[Document] = text_splitter.split_documents([doc]) return chunksdef iterative_summary( text: str, chunk_size: int = 50000, chunk_overlap: int = 200, config: Optional[RunnableConfig] = None) -> str: """Generate iterative summary of long text.""" docs = chunk_text(text, chunk_size, chunk_overlap) app = build_iterative_summary_graph(llm_client, config) return run_graph(app, docs) ```

### Online Retrieval Phase

Finally, only the most relevant information elements are included in the generation of the final answer, which is grounded in the exact document pages, paragraphs, and images.

**Defining Pydantic Assessment Models
** A structured output from a language model is achieved using Pydantic. Pydantic models help maintain cleanliness and verifiability, allowing for the parsing and validation of outputs from the language model to ensure consistency.

In total, three different Pydantic classes are needed:

1. `BatchHelpfulnessTextAssessment**` and `HelpfulnessTextAssessment**` for evaluating batches of paragraphs.
2. `HelpfulnessImageAssessment` for assessing a single image at a time, as many visual language models only support one input image.

```python class HelpfulnessTextAssessment(BaseModel): score: int = Field(..., description="Helpfulness score from 0 (not helpful at all) to 5 (includes direct answer)", ge=0, le=5) reasoning: str = Field(..., description="Brief explanation of why this score was assigned")class HelpfulnessImageAssessment(BaseModel): score: int = Field(..., description="Helpfulness score from 0 (not helpful at all) to 5 (includes direct answer)", ge=0, le=5) information: str = Field(..., description="Information extracted from the image for the generation of the final answer")class BatchHelpfulnessTextAssessment(BaseModel): assessments: List[HelpfulnessTextAssessment] = Field( ..., description="List of helpfulness assessments, one for each text item in order" ) ```

These endpoints are used later for retrieval, chunk assessment, and answer generation.

```python def initialize_llm_clients() -> Tuple[ChatOpenAI, ChatOpenAI]: vision_llm_client = ChatOpenAI( model_name="pixtral-12b-2409", openai_api_key=MISTRAL_API_KEY, openai_api_base="https://api.mistral.ai/v1", temperature=0.0, ) llm = ChatOpenAI( model_name="mistral-large-2407", openai_api_key=MISTRAL_API_KEY, openai_api_base="https://api.mistral.ai/v1", temperature=0.0, ) return vision_llm_client, llmdef initialize_vector_store() -> QdrantVectorStore: client = QdrantClient(path="langchain_qdrant") embeddings = HuggingFaceEmbeddings(model_name=EMBED_MODEL) try: vector_store = QdrantVectorStore( client=client, collection_name=COLLECTION_NAME, embedding=embeddings, ) return vector_store except Exception as e: raise ValueError( f"Failed to create vector store: {e}. " "Ensure the collection exists and the embedding model is correct." ) ```

**Document Loading
** The function `collect_json_paths()` locates the previously stored JSON files that were created by the offline indexing script.

These JSON files are essential for visually grounding the final answer, as they contain images of all pages, item positions, and associated metadata.

```python def collect_json_paths(base_dir: str) -> Dict[int, str]: json_map = {} for root, _, files in os.walk(base_dir): for filename in files: if filename.lower().endswith('.json'): name, _ = os.path.splitext(filename) if name.isdigit(): key = int(name) full_path = os.path.join(root, filename) json_map[key] = full_path return json_map ```

The `collect_json_paths()` function is utilized by the `load_and_process_documents()` function.

This function takes as input the retrieved documents from the Qdrant semantic similarity search and decomposes each document into its individual items.

Each item is sorted into the appropriate list for the subsequent assessment step, depending on its category: picture, text, or table.

This allows for a differentiated assessment of each type during the iteration process.

```python def load_and_process_documents( found_docs: List[Any], file_path: Dict[int, str]) -> Tuple[List[Dict], List[Dict], List[Dict], Dict]: TableItems = [] PictureItems = [] TextItems = [] dl_docs_pages = {} dl_docs_cache = {} processed_items_set = set() for doc in found_docs: try: doc_id = int(doc.metadata["doc_id"]) if doc_id in dl_docs_cache: dl_doc = dl_docs_cache[doc_id] print(f"Using cached document {doc_id}") else: file = file_path.get(doc_id, None) if file is None: print(f"File not found for doc_id: {doc_id}") continue dl_doc = DoclingDocument.load_from_json(file) dl_docs_cache[doc_id] = dl_doc print(f"Loaded and cached document {doc_id}") if dl_doc.origin.binary_hash not in dl_docs_pages: dl_docs_pages[dl_doc.origin.binary_hash] = dl_doc.pages except Exception as e: print(f"Error loading document {doc.metadata['doc_id']}: {e}") continue refs_set = set(doc.metadata["refs"]) items_index = {} for element, _level in dl_doc.iterate_items(): if element.self_ref in refs_set: items_index[element.self_ref] = element print( f"Built index with {len(items_index)} relevant items out of {refs_set} references") # Process only the items we need for ref in refs_set: if ref in processed_items_set: print(f"Skipping already processed item: {ref}") continue element = items_index.get(ref) if element is None: print(f"Reference {ref} not found in document") continue processed_items_set.add(ref) item = { "doc_name": dl_doc.name, "doc_hash": str(dl_doc.origin.binary_hash), "page_no": element.prov[0].page_no if element.prov else 0, "item": element, } print(f"Reference found: {type(element)}") if isinstance(element, PictureItem): PictureItems.append(item) elif isinstance(element, TableItem): item["table_image"] = element.get_image(dl_doc) TableItems.append(item) elif isinstance(element, TextItem): TextItems.append(item) else: print(f"Unknown item type: {type(element)}") return TableItems, PictureItems, TextItems, dl_docs_pages ```

**Helpfulness Assessment with LLMs
** The next step in the helpfulness assessment process is divided into three functions.

The function `get_assessment_template()` provides a reusable template for both text and image assessments.

```python def get_assessment_template() -> str: return """ You are an expert at assessing the relevance of {content_type} content for answering questions. Question: {query} {content_instruction} Please rate how relevant this {{content_type}} is for answering the question on a scale of 0-5: - 0: Not helpful at all - completely irrelevant - 1: Minimally helpful - tangentially related but doesn't contribute to answer - 2: Somewhat helpful - provides background context but no direct answer elements - 3: Moderately helpful - contains relevant information that supports answering - 4: Very helpful - contains key information needed for a comprehensive answer - 5: Extremely helpful - includes direct answer or critical information {additional_context} {format_instructions} """ ```

The function `assess_text_batch_helpfulness()` retrieves this template, fills in the gaps, and then calls a language model to structure the output, allowing for the assessment of all text items at once.

```python def assess_text_batch_helpfulness(text_items: List[Dict], question: str, llm: ChatOpenAI, format_instructions: str) -> List[HelpfulnessTextAssessment]: concatenated_text = "" for i, text_item in enumerate(text_items): text = text_item["item"].text self_ref = text_item["item"].self_ref concatenated_text += f"# {self_ref}
{text}

" batch_parser = PydanticOutputParser( pydantic_object=BatchHelpfulnessTextAssessment) batch_format_instructions = batch_parser.get_format_instructions() batch_template = """ You are an expert at assessing the relevance of text content for answering questions. Question: {query} Please analyze the following {num_items} text items for their relevance to the question. Each text item is marked with a # followed by its reference ID. Text Items: {concatenated_text} Please rate how relevant EACH text item is for answering the question on a scale of 0-5: - 0: Not helpful at all - completely irrelevant - 1: Minimally helpful - tangentially related but doesn't contribute to answer - 2: Somewhat helpful - provides background context but no direct answer elements - 3: Moderately helpful - contains relevant information that supports answering - 4: Very helpful - contains key information needed for a comprehensive answer - 5: Extremely helpful - includes direct answer or critical information Provide assessments for all {num_items} text items in the exact order they appear above. {format_instructions} """ prompt = PromptTemplate( input_variables=["query", "num_items", "concatenated_text"], template=batch_template, partial_variables={ "query": question, "num_items": len(text_items), "concatenated_text": concatenated_text, "format_instructions": batch_format_instructions, } ) structured_llm = llm.with_structured_output(BatchHelpfulnessTextAssessment) chain = prompt | structured_llm response = chain.invoke({}) return response.assessments ```

A similar process is applied in the `assess_images_helpfulness()` function; however, images are assessed separately rather than all at once.

```python def assess_image_helpfulness(image: str, question: str, llm: ChatOpenAI, format_instructions: str) -> HelpfulnessImageAssessment: print("Assessing image helpfulness...") template = get_assessment_template() prompt = template.format( content_type="image", query=question, content_instruction="Please analyze the provided image for its relevance to the question", additional_context="", format_instructions=format_instructions, ) messages = [ { "role": "user", "content": [ {"type": "text", "text": prompt}, { "type": "image", "source_type": "base64", "mime_type": "image/png", "data": image, } ] } ] response = llm.invoke(messages) try: image_parser = PydanticOutputParser( pydantic_object=HelpfulnessImageAssessment) parsed_response = image_parser.parse(response.content) return parsed_response except Exception as e: print(f"Failed to parse response: {e}") return HelpfulnessImageAssessment( score=0, information="Failed to assess image due to parsing error" ```

**Item Processing: Filtering for Relevance
** Afterwards, these assessment functions process each content type (text, image, table) separately, retaining only the most helpful items.

All items above a certain threshold are added to the `relevant_items` list in the end. This list is used for the generation of the final answer.

The function `process_text_items` uses the `HelpfulnessTextAssessment` Pydantic for structured output and the function `assess_text_batch_helpfulness` for evaluating the helpfulness of all paragraphs at once.

During the assessment of paragraph helpfulness, a related score was generated along with the reasoning to make the output more understandable for humans.

```python def process_text_items(text_items: List[Dict], query: str, llm: ChatOpenAI) -> Tuple[List[str], List[Dict]]: context = [] relevant_items = [] if not text_items: return context, relevant_items text_parser = PydanticOutputParser( pydantic_object=HelpfulnessTextAssessment) format_text_instructions = text_parser.get_format_instructions() print(f"Processing {len(text_items)} text items in batch...") batch_assessments = assess_text_batch_helpfulness( text_items, query, llm, format_text_instructions) for i, (text_item, assessment) in enumerate(zip(text_items, batch_assessments)): text = text_item["item"].text doc_name = text_item["doc_name"] doc_hash = text_item["doc_hash"] print(f"Text: {text[:50]}... from {doc_name} ({doc_hash})") print(f"score: {assessment.score}, reasoning: {assessment.reasoning}") text_items[i]["assessment"] = assessment.score if assessment.score >= HELPFULNESS_THRESHOLD: relevant_items.append(text_item) context.append(f""" [{len(context)}] Text Source {text_item["doc_name"]} {text_item["item"].self_ref} {text} """) return context, relevant_items ```

The `process_picture_items` function evaluates all pictures sequentially using the vLM and the `HelpfulnessImageAssessment` Pydantic class.

However, multiple images may be relevant for answering the user’s query. Instead of passing the relevant images directly to a LLM, we provide information about how these images contribute to the question, without delving into the reasoning behind their importance, as we do with text items.

This approach allows us to incorporate visual information beyond the vLM’s image input limit into the final answer.

```python def process_picture_items(picture_items: List[Dict], query: str, vision_llm: ChatOpenAI) -> Tuple[List[str], List[Dict]]: context = [] relevant_items = [] image_parser = PydanticOutputParser( pydantic_object=HelpfulnessImageAssessment) format_image_instructions = image_parser.get_format_instructions() for i, image_item in enumerate(picture_items): url = image_item["item"].image.uri.path image_base64 = url.split(',', 1)[1] assessment = assess_image_helpfulness( image_base64, query, vision_llm, format_image_instructions) picture_items[i]["assessment"] = assessment.score if assessment.score >= HELPFULNESS_THRESHOLD: relevant_items.append(image_item) context.append(f""" [{len(context)}] Image Source {image_item["doc_name"]} {image_item["item"].self_ref} {assessment.information} """) return context, relevant_items ```

The process of handling table items is similar to that of image items. The main difference lies in how Docling treats tables and how to obtain the image of the table from a Docling `TableItem`.

```python def process_table_items(table_items: List[Dict], query: str, vision_llm: ChatOpenAI) -> Tuple[List[str], List[Dict]]: context = [] relevant_items = [] image_parser = PydanticOutputParser( pydantic_object=HelpfulnessImageAssessment) format_image_instructions = image_parser.get_format_instructions() for i, table_item in enumerate(table_items): table_image = table_item["table_image"] buf = BytesIO() table_image.save(buf, format="PNG") b64_str = base64.b64encode(buf.getvalue()).decode() assessment = assess_image_helpfulness( b64_str, query, vision_llm, format_image_instructions) table_items[i]["assessment"] = assessment.score if assessment.score >= HELPFULNESS_THRESHOLD: relevant_items.append(table_item) context.append(f""" [{len(context)}] Table Source {table_item["doc_name"]} {table_item["item"].self_ref} {assessment.information} """) return context, relevant_items ```

**Annotation & Visualization
**After identifying the relevant items for generating the final answer, the location of these items should be visually grounded on the correct document pages. This grounding process is divided into three functions.

The `draw_box` function takes an image and an element as inputs and draws a bounding box around that element, such as a table, paragraph, or image.

```python def draw_box(page_image, image_size, element, color="blue", thickness=5, padding=None, text="Hello World"): if padding is None: padding = thickness + 2 if not element.prov: print(f"No provenance information for element: {element}") return None prov = element.prov[0] bbox = prov.bbox.to_top_left_origin(page_height=image_size.height) bbox = bbox.normalized(image_size) bbox.l = round(bbox.l * page_image.width - padding) bbox.r = round(bbox.r * page_image.width + padding) bbox.t = round(bbox.t * page_image.height - padding) bbox.b = round(bbox.b * page_image.height + padding) draw = ImageDraw.Draw(page_image) draw.rectangle( xy=bbox.as_tuple(), outline=color, width=thickness, ) font_size = 40 font = ImageFont.load_default(size=font_size) text_x = bbox.l + 5 text_y = bbox.t - 10 if font: bbox_text = draw.textbbox((text_x, text_y), text, font=font) else: bbox_text = draw.textbbox((text_x, text_y), text) bg_padding = 3 draw.rectangle( [bbox_text[0] - bg_padding, bbox_text[1] - bg_padding, bbox_text[2] + bg_padding, bbox_text[3] + bg_padding], fill="white" ) text_color = "red" if color == "blue" else "blue" if font: draw.text((text_x, text_y), text, fill=text_color, font=font) else: draw.text((text_x, text_y), text, fill=text_color) return page_image ```

The `draw_box` function is invoked within the `create_annotated_pages` function, which gathers the relevant items and creates annotated pages. This function allows for multiple bounding boxes to be drawn around several elements on the same page.

```python def create_annotated_pages(relevant_items: List[Dict], dl_docs_pages: Dict) -> List[Dict]: drawn_pages = [] for item in relevant_items: idx = next((i for i, p in enumerate(drawn_pages) if p["doc_hash"] == item['doc_hash'] and p["page_no"] == item['page_no']), None) if idx is None: drawn_pages.append({ "doc_hash": item["doc_hash"], "doc_name": item["doc_name"], "page_no": item["page_no"], "image": None, "image_name": f"{item['doc_name']}_{item['page_no']}.png" }) pages = dl_docs_pages[int(item["doc_hash"])] page = pages[int(item["page_no"])].image.pil_image print(f"page_type: {type(page)}") drawn_pages[-1]["image"] = draw_box( page, pages[int(item["page_no"])].size, item["item"], text=f"{item['item'].self_ref} ({item['assessment']})" ) else: pages = dl_docs_pages[int(item["doc_hash"])] drawn_pages[idx]["image"] = draw_box( drawn_pages[idx]["image"], pages[int(item["page_no"])].size, item["item"], text=f"{item['doc_name']} {item['item'].self_ref} {item['assessment']}" ) return drawn_pages ```

The final function, `save_annotated_pages`, performs exactly what its name suggests: it saves the annotated image for later inspection.

```python def save_annotated_pages(drawn_pages: List[Dict]) -> None: for page in drawn_pages: image_path = OUTPUT_DIR / page["image_name"] page["image"].save(image_path) print(f"Saved annotated page: {image_path}") ```

**Answer Synthesis with Inline Citations
** After completing all these steps, the final answer is generated based on all items with a relevance score above a certain threshold.

A few examples are included to guide the model in placing sources at appropriate positions for quick fact-checking.

However, the list of sources at the end is added manually to mitigate the risk of inaccuracies in source creation.

```python def generate_final_answer(context: str, question: str, llm: ChatOpenAI) -> str: prompt = PromptTemplate( input_variables=["context", "question"], template=""" You are an expert researcher tasked with answering questions based on provided sources. Question: {question} Sources: {context} Instructions: 1. Provide a comprehensive answer to the question using the provided sources 2. Use inline citations with numbers in square brackets [1], [2], etc. to reference specific sources 3. Only cite sources that you actually use in your answer 5. If multiple sources support the same point, you can cite multiple sources like [1], [3] 6. Place citations immediately after the relevant information, like this: "Information here [1]" or "More info [2], [3]" 7. There has to be a source at the end of every paragraph. 8. You are not allowed to add any paragraph without at least one source at the end. 9. If you cannot find any relevant information in the sources, say "I don't know" !! YOUR ARE NOT ALLOWED TO LEAVE OUT ANY SOURCES PROVIDED IN THE CONTEXT !! !! YOU MUST USE ALL SOURCES IN YOUR FINAL ANSWER !! !! DO NOT LIST SOURCES AT THE END OF YOUR ANSWER !! === Few-Shot Examples === ### Example 1 (2 sources, single paragraph) Question: What is a palindrome? Sources: [1] A palindrome is a word, number, phrase, or other sequence of characters which reads the same backward as forward. [2] Common examples include "racecar" and the number "121". Answer: A palindrome is a sequence of characters that reads identically forwards and backwards [1]. They can consist of letters (e.g., "racecar") or numbers (e.g., "121") and are recognized by their symmetry when reversed [2]. ### Example 2 (2 sources, two paragraphs) Question: How does photosynthesis work? Sources: [1] Photosynthesis is the process by which green plants and some other organisms use sunlight to synthesize foods from carbon dioxide and water. [2] The overall chemical equation is: 6CO₂ + 6H₂O → C₆H₁₂O₆ + 6O₂. Answer: Photosynthesis is the biochemical process in which green plants convert light energy into chemical energy by combining carbon dioxide and water to form glucose and oxygen [1], [2]. This process occurs in the chloroplasts of plant cells, where the pigment chlorophyll captures photons to drive both the light-dependent and light-independent reactions [1]. ### Example 3 (3 sources, two paragraphs) Question: What are the main benefits of electric vehicles? Sources: [1] Electric vehicles (EVs) produce zero tailpipe emissions, reducing local air pollution. [2] EVs generally have lower operating costs per mile compared to gasoline vehicles due to higher energy efficiency. [3] Government incentives and tax credits are often available to EV buyers in many countries. Answer: Electric vehicles offer significant environmental benefits by emitting no tailpipe pollutants, which helps improve urban air quality and public health [1], [2]. In addition to lower fuel costs—since electric motors convert over 85% of electrical energy to motion versus ~25% for combustion engines—EV owners often benefit from governmental incentives such as tax credits and rebates that further reduce total ownership costs [2], [3]. ### Example 4 (4 sources, three paragraphs) Question: Explain the stages of the water cycle. Sources: [1] Evaporation is the process where water changes from liquid to vapor due to heat. [2] Condensation occurs when water vapor cools and forms liquid droplets in the atmosphere. [3] Precipitation happens when those droplets become heavy enough to fall as rain, snow, sleet, or hail. [4] Collection refers to water gathering in bodies like rivers, lakes, and oceans. Answer: The first stage of the water cycle is evaporation, where sunlight heats surface water—especially from oceans and lakes—causing it to turn into vapor and rise into the air [1]. Once aloft, the water vapor cools and undergoes condensation, forming tiny droplets that cluster into clouds [2]. When these droplets grow large enough, they fall back to Earth as precipitation—rain, snow, sleet, or hail. The fallen water then collects in various reservoirs such as rivers, lakes, groundwater, and oceans, completing the cycle [3], [4]. """ ) chain = prompt | llm response = chain.invoke({ "question": question, "context": context }) return response.content ```

The function `create_sources_list` generate the list of the used relevant sources, which is appended to the final answer.

```python def create_sources_list(relevant_items: List[Dict]) -> str: """Create a formatted list of sources.""" sources_list = "

" for i, item in enumerate(relevant_items): doc_name = item["doc_name"] self_ref = item["item"].self_ref if isinstance(item["item"], TextItem): source_type = "Text Source" elif isinstance(item["item"], PictureItem): source_type = "Image Source" elif isinstance(item["item"], TableItem): source_type = "Table Source" else: source_type = "Unknown Source" sources_list += f"[{i}] {source_type}
{doc_name} {self_ref}

" return sources_list ```

**Main Execution Logic**

Ultimately, everything is combined in the main function, which sequentially calls the previously explained functions to generate the final answer, backed by sources and visual grounding features

```python def main(query: str = None) -> Dict[str, Any]: if query is None: query = "What is the BLEU score of transofmers?" print(f"Processing query: {query}") # Initialize components vision_llm_client, llm = initialize_llm_clients() vector_store = initialize_vector_store() file_path = collect_json_paths(str(OUTPUT_DIR)) # Search for relevant documents print("Searching for relevant documents...") found_docs = vector_store.similarity_search(query, k=4) # Load and process documents print("Loading and processing documents...") table_items, picture_items, text_items, dl_docs_pages = load_and_process_documents( found_docs, file_path ) # Process different types of items all_context = [] all_relevant_items = [] # Process text items text_context, text_relevant = process_text_items(text_items, query, llm) all_context.extend(text_context) all_relevant_items.extend(text_relevant) # Process picture items picture_context, picture_relevant = process_picture_items( picture_items, query, vision_llm_client) all_context.extend(picture_context) all_relevant_items.extend(picture_relevant) # Process table items table_context, table_relevant = process_table_items( table_items, query, vision_llm_client) all_context.extend(table_context) all_relevant_items.extend(table_relevant) # Create context string context_string = "

".join(all_context) print("Context gathered:") print(context_string) # Create and save annotated pages print("Creating annotated pages...") drawn_pages = create_annotated_pages(all_relevant_items, dl_docs_pages) save_annotated_pages(drawn_pages) # Generate final answer print("Generating final answer...") final_answer = generate_final_answer(context_string, query, llm) # Create sources list sources_list = create_sources_list(all_relevant_items) final_answer_with_sources = final_answer + sources_list print(f"
Final Answer:
{final_answer_with_sources}") return { "query": query, "answer": final_answer, "sources": sources_list, "relevant_items_count": len(all_relevant_items), "context": context_string, "annotated_pages": len(drawn_pages) }if __name__ == "__main__": if len(sys.argv) > 1: query = " ".join(sys.argv[1:]) result = main(query) else: result = main() print( f"
Processing complete. Found {result['relevant_items_count']} relevant items across {result['annotated_pages']} pages.") ```

## Limitations

Despite its benefits, this approach has also limitations, including:

* **Chunking and Context Windows:** Even with hierarchical chunking, relevant information may still be split across multiple chunks or overlooked due to chunk size and overlap constraints.
* **Performance and Latency:** The pipeline requires running several LLM and vLM calls per user query. These multiple calls can be slow or costly at scale without optimization or batching.
* **Complex Document Layouts:** Docling performs well on well-structured documents, such as manuals, research papers, or documentation. However, it struggles with more complex layouts and advanced designs.

## Conclusion

Multi-modal Retrieval-Augmented Generation (RAG) systems with visual answer grounding represent a significant step forward in the explainability and reliability of AI-driven question-answering pipelines.

Combining advanced document parsing with Docling, semantic search via Qdrant, and LLMs (Mistral, LangChain) it is not only possible to fact-check answers but also visually and contextually ground every output in its original source.

The workflow outlined in this post presents a transparent fact-checking mechanism and makes it possible for users to verify claims, fostering trust in AI-generated outputs quickly.
