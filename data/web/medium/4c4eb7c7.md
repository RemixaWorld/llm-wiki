## Introduction

In Singapore, the government is answerable to Parliament and Members of Parliament (MPs) may raise queries to any Minister on any matter in his portfolio. These questions can be answered orally during the Parliament sitting or through a written reply. Regardless of the medium, public servants in the ministries must gather materials to answer the question and prepare a response.

Generative AI and Large Language Models (LLMs) have already been applied to help public servants do this more effectively and efficiently. For example, [Pair Search](<https://search.pair.gov.sg/>) (publicly accessible) and the Hansard Analysis Tool (only accessible to public servants) help public servants search for relevant information in past Parliamentary Sittings relevant to the question and synthesise a response to it.

The existing systems draft the responses using prompt engineering and Retrieval Augmented Generation (RAG). To recap, RAG consists of two main parts:

* **Retriever** : A search engine that finds documents relevant to the question
* **Generator** : A text generation model (LLM) that takes in the instruction, the question, and the search results from the retriever to respond to the question

![A typical RAG system. Illustration by Hrishi Olickel, taken from here.](https://miro.medium.com/v2/resize:fit:700/0*QgyR-g9UfsbN6Lnb.png)

Using a pre-trained instruction-tuned LLM like GPT-4o, the generator can usually generate a good response. However, it might not be exactly what is desired in terms of verbosity, style and writing prose, and additional human post-processing might be needed. Extensive prompt engineering or few-shot learning can be done to mold the response at the expense of incurring higher costs from using additional tokens in the prompt.

An alternative to prompt engineering and few-shot learning is to **fine-tune** the generator by letting it see examples of how Parliamentary replies are written so that the model can learn from it. In this blog post, we show our fine-tuning experiment design and results. The experiment aims to answer the following question:

_Given the same context, would a fine-tuned model generate a more “Parliamentary-like” response compared to a pre-trained instruction-tuned model in terms of verbosity, writing style, prose, and factual correctness?_

## Experiment Set-up

The overall process, which I will explain in detail later, is as follows:

![image](https://miro.medium.com/v2/resize:fit:1000/1*rzC4bnUzwfoF40BcoGrSFQ.png)

It consists of three stages:

1. Data collection and preprocessing
2. Fine-tuning
3. Evaluation

### Data Collection

Parliamentary proceedings are recorded in the Hansard, which can be found [here](<https://sprs.parl.gov.sg/search/#/home>). As previously mentioned, Parliamentary questions can be answered either orally or in writing. For our experiment, we use the written responses as they are more structured. Each record consists of only one question and one answer, whereas the structure of oral answers can sometimes be non-deterministic, depending on the follow-up questions and conversation flow.

The written responses can be easily crawled from the Hansard website using the section headers _Written Answers to Questions_ and _Written Answers to Questions For Oral Answer Not Answered By End of Question Time_. The same response to the Parliamentary question can be found on the agency’s website.

We crawled data from _1 Jan 2020_ to _8 May 2024_ and obtained **7011** written question-response pairs.

![Finding written answers to questions on Hansard website](https://miro.medium.com/v2/resize:fit:700/1*i-5IClOcUUro7thEOKv9RA.png) ![Example of written answer to question](https://miro.medium.com/v2/resize:fit:700/1*4V-Ljp_cEd5P_fcUjq73cw.png) ![The same information is also posted on MCI’s website](https://miro.medium.com/v2/resize:fit:700/1*yftrI_YPZ-dTmEqgU6UNJg.png)

### Pre-processing

Unfortunately, not all 7011 pairs could be used as the questions were not always answered directly. On multiple occasions, the questions had previously been asked, and the ministers directed the MP to a previous answer. On other occasions, the answers were not ready, and the replies were deferred. Since our objective was to fine-tune the LLMs to answer the question given information that is available, we needed to remove such pairs from the dataset. We did this with an LLM (GPT-4o) using the following prompt to get a status for each pair which was one of _repeated, deferred_ , _answered_ , or _not answered_. In addition, if the question was answered, the LLM was asked to convert the answer into point form.

```json Given the following question and answer pair, do the following:1. Check if the answer addresses the question. If the answer says something like "This question has been asked before, please refer to another answer." The status will be "repeated" and the reference_answer will be the extracted answer link or document id.2. If the answer says something like "This will be addressed in future" or "Time is needed for investigation" or "The report will be released in future", the status will be "deferred".3. If the answer does not answer the question, the status will be "not_answered".4. If the answer addresses the question, the status will be "answered".5. If the answer addresses the question, summarise the answer in succint and concise point forms in relation to the question.Give your answer as a JSON output with the following keys:- "status": answered or not_answered or deferred or repeated,- "reference_answer": reference_link_or_id or "",- "summary_points": summarised points or ""This is the question:{question}And this is the answer:{answer} ```

Out of the 7011 pairs, 2089 had replies that directly answered the question, and these were used as our experiment data.

![Fine-tuning the LLM](https://miro.medium.com/v2/resize:fit:1000/1*jAQA_7NfunHl9mDXnHlw9A.png)

### Synthetically Generating Relevant Documents

Since we wanted to fine-tune our LLM to generate an answer given a question AND relevant documents, we needed documents pertinent to the question as additional input. These would be the documents the public servants in the various ministries used as references in their answers. Due to the sensitive nature of these documents, we could not collect all of them.

We could not use relevant past Hansard documents as the answers were not exclusively from past Parliamentary proceedings. Therefore, we generated reports from the answers using GPT-4o to represent the relevant documents for experiment purposes. Though the synthetically generated documents might not have the same characteristics as the actual documents used by the public servants, it was not so much of an issue for experimentation since we were comparing the fine-tuned model to the pre-trained models, which would receive the same inputs.

With the points previously generated from the written answer and the title of the parliamentary question as inputs, we used the following prompt template to create relevant documents:

``` Imagine that you are a public servant writing a report for your boss.Write a report using the following points. Be as elaborate as possible. You can create your own story but it must be around these points and the title:Title: {title}Points: {points} ```

For example, the relevant document generated for the above-mentioned Singpass facial verification example can be found [here](<https://gist.github.com/watsonchua/e232143a7dc54bc0332ba150ccdf14cc>).

## Fine-tuning

Fine-tuning in machine learning is the process of adapting a pre-trained model for specific tasks or use cases. Three common techniques of fine-tuning are:

* Full Fine-tuning
* Low-Rank Adaptation (LoRA), and
* Quantised LoRA (QLoRA)

For a detailed explanation of the differences between the three different techniques, I refer you to this [blog post](<https://towardsdatascience.com/qlora-fine-tune-a-large-language-model-on-your-gpu-27bed5a03e2b>) by [Benjamin Marie](</@bnjmn_marie>).

We chose LoRA for fine-tuning for the following reasons:

1. Lower GPU memory is needed than full fine-tuning
2. Faster than both full fine-tuning and Q-LoRA
3. It retains knowledge of what was previously learned during the pre-training phase better than full fine-tuning
4. We had enough GPU memory for 8-bit fine-tuning without having to quantise to 4-bit

![LoRA finetuning. Illustration from the original paper.](https://miro.medium.com/v2/resize:fit:1000/0*CNpXFD0wREbjmZZE.png)

In a nutshell, LoRA is a form of parameter-efficient fine-tuning. Instead of updating all the weights in the model, updates are done only on the weights of certain layers (usually the attention layers). The weight update matrix **W** of dimension**d**(e.g. 1000 x 1000 dimensions) is transformed into two lower ranked matrices **A** and **B** of rank**r**(e.g. 1000 x 16, 16 x 1000) through matrix decomposition to further reduce the number of weights to update (1 million parameters vs. 2 x 16 x 1000 = 32 000 parameters). Updates to the low-ranked matrices can be easily applied to the original weight update matrix through linear transformations.

We used the [Axolotl library](<https://github.com/axolotl-ai-cloud/axolotl/tree/main>) to do LoRA fine-tuning on two base models, [Llama-3–8B](<https://huggingface.co/meta-llama/Meta-Llama-3-8B>) and [Gemma-2–9B](<https://huggingface.co/google/gemma-2-9b>), using the following Axolotl configuration:

``` load_in_8bit: truelora_r: 32lora_alpha: 16lora_dropout: 0.05lora_target_linear: truesequence_len: 2500pad_to_sequence_len: truegradient_accumulation_steps: 4micro_batch_size: 1num_epochs: 4optimizer: adamw_bnb_8bitlr_scheduler: cosinelearning_rate: 0.0002 ```

Llama3–8B and Gemma2–9B were chosen because they were one of the best-performing base models. In addition, because they have less than 10B parameters, training could be done on a 40GB GPU, and inference could be done with less than 20GB of GPU RAM. Inference GPU RAM usage is important because the day-to-day operation cost would be substantial if we proceed to deploy the model.

The inputs were formatted using the Llama-3 prompt template as follows:

``` <|start_header_id|>system<|end_header_id|>You are a public servant. Your task is to reply to a parliamentary question given a list of supporting documents.<|eot_id|><|start_header_id|>user<|end_header_id|>Question:{question}Supporting Documents: {relevant_document}<|eot_id|><|start_header_id|>assistant<|end_header_id|>{answer}<|eot_id|><|end_of_text|> ```

At inference time, the input was passed in without the answer so that the models would generate it. Inference stopped when the special token **< |eot_id|>** was generated.

``` <|start_header_id|>system<|end_header_id|>You are a public servant. Your task is to reply to a parliamentary question given a list of supporting documents.<|eot_id|><|start_header_id|>user<|end_header_id|>Question:{question}Supporting Documents: {relevant_document}<|eot_id|><|start_header_id|>assistant<|end_header_id|> ```

Since we were fine-tuning base models which had not been instruction-tuned, which prompt template we used did not matter as long as we consistently used the same one.

We trained on the data from 2020 to 2023 and used the data for 2024 as the test data, giving us a train-test split of 1785–304, which is about 85%-15%.

Training was done on an A100 40GB GPU and took 3 hours for Llama-3–8B and 4 hours for Gemma-2–9B.

## Evaluation

Each data point in the test set, consisting of the title of the Parliamentary query, actual question asked, and synthetically generated relevant document was passed to each of the fine-tuned models to get an answer.

We then used the following prompt template to get GPT-4o’s responses:

``` Imagine that you are a public servant drafting a reply for a parliamentary question.Given the following title, question, and points, write a reply to the question.Respond with only the answer to the question.Title:{title}Question:{question}Relevant Documents:{relevant_documents}###########################################################################{example} ```

where _example_ was an empty string for zero-shot learning, and [this example](<https://gist.github.com/watsonchua/0b84b8db5ae4ef0b02fc69cb9e17e35d>) for one-shot learning.

### LLM-as-a-Judge

We first evaluated the models using LLM-as-a-Judge. We fed the question, relevant documents, ministers’ answer, and model generated answer for each data point to another pre-trained instruction-tuned LLM, _gemini-1.5-flash-001_ and asked it to pick the better answer and explain why, based on the following criteria:

1. Factual correctness according to the context
2. Similarity to model answer
3. Conciseness

Gemini-1.5-Flash was chosen to be our LLM-as-a-judge over the popular choice GPT-4o because GPT-4o was one of the models being assessed and [models often have biases towards their own generations](<https://arxiv.org/abs/2404.13076v1>). Besides, generation with Gemini-1.5-Flash was fast and cost-effective.

This was the prompt template used to ask the LLM to assess the responses:

```json Given the following question, context, and two different answers a) and b), assess the answer based on the following criteria:1) factual correctness according to the context2) similarity to model answer3) concisenessRespond in JSON whether answer a) or b) is the better answer and state your reason using the following schema:{{"winner": a or b,"reason": reason it is the better answer}}Here is the information,Question: {question}Context: {context}Model Answer: {ground_truth}Answer A: {answer_a}Answer B: {answer_b}Respond with only the JSON reply and nothing else. Use double quotes for the json schema and DO NOT use any double quotes in the values. ``` ![Choosing between two answers be like…](https://miro.medium.com/v2/resize:fit:700/1*dmMxu3p4exPvTHvh3ofVuQ.png)

### Ragas

We then evaluated the model outputs using [Ragas](<https://docs.ragas.io/en/latest/concepts/metrics/index.html>) metrics. Ragas is a framework that helps developers evaluate their RAG pipelines. It offers metrics tailored for evaluating each component of the pipeline in isolation. Since we were only fine-tuning the generator of the RAG pipeline, we used only the generator-relevant metrics which are:

* **Faithfulness** : Whether the information in the generated answer came from the context
* **Answer relevancy** : Whether the generated answer is relevant to the question
* **Answer similarity** : Whether the generated answer is semantically similar to the ground truth (ministers’ answer)
* **Answer correctness** : Whether the generated answer shares the same points as the ground truth

## Results

![image](https://miro.medium.com/v2/resize:fit:700/1*LeSCXojMBgTGdIaoBLk6-A.png)

The chart above shows the results using Gemini-1.5-Flash as a judge. The LLM judge picked the answer generated by the fine-tuned models over GPT-4o with zero-shot learning about 70% of the time. When one-shot learning was used with GPT-4o, this fell to about 60%. Between Gemma-2 and Llama-3, the LLM judge preferred Gemma-2’s answers 71% of the time.

Gemini-Flash performed fairly well as a judge. Here is an example of how Gemini-Flash judged the answers, generated with [this synthetically generated relevant document](<https://gist.github.com/watsonchua/0b00825ae3a61abac1bcb713e20a3e6a>) :

``` Question:Ms Denise Phua Lay Peng asked the Minister for National Development whether the senior-friendly fittings under the Housing and Development Board's (HDB's) Enhancement for Active Seniors (EASE) 2.0 programme, which is not applicable to private housing, can be partially or fully extended to eligible elderly retirees living in non-HDB estates.Minister's Answer:For senior-friendly features within homes, the Housing and Development Board's (HDB's) Home Improvement Programme (HIP) and Enhancement for Active Seniors (EASE) 2.0 programme cover a range of enhancements tailored for HDB flats, which are more standardised. In contrast, the designs and layouts of private homes vary greatly. As such, we will continue to study how seniors living in private homes can be better supported to age well within their homes.GPT-4o's Zero-Shot Answer:The Ministry acknowledges the importance of extending senior-friendly fittings to elderly retirees living in non-HDB estates. However, due to the diverse architectural designs and unique challenges associated with private homes, a one-size-fits-all approach is not feasible. The Ministry is committed to exploring viable strategies to address these challenges, including customised assessments, financial assistance, collaboration with industry experts, pilot programmes, and public awareness initiatives. These efforts aim to ensure that all elderly residents, regardless of their housing type, can access the necessary support to age well.Fine-tuned Gemma-2's Answer:As both HIP and EASE 2.0 improvements are carried out based on common designsacross many units within an HDB block, they cannot easily be extended to private homes where there is great diversity in architecture and layout. Nevertheless, my Ministry will continue to look at ways to better enable seniors living in private homes to age well.Gemini-Flash's Choice and Reason:Answer b) is more concise, factual, and aligns with the model answer. While answer a) provides additional details, it doesn't succinctly address the question posed, and lacks the clarity and conciseness of the model answer. Answer b) acknowledges the challenges of applying EASE 2.0 to private homes and reaffirms the Ministry's commitment to supporting seniors in all housing types, mirroring the model answer's approach. ``` ![image](https://miro.medium.com/v2/resize:fit:700/1*G7GgKzWR7THHJZyNgOWomQ.png)

The chart above shows the Ragas results. Compared to both the zero-shot and one-shot GPT-4o’s results, the fine-tuned models performed slightly better in faithfulness. Although their scores for answer relevancy were worse, they had significantly better answer correctness scores when compared to the ministers’ actual answers. However, the difference (around 10–12%) was not as huge as that for LLM-as-a-judge (20–30%). This was because many of the answers were quite similar and the fine-tuned models’ answer only had a slight edge over GPT-4o’s. They were chosen by the LLM judge as the better answer but GPT-4o’s were not very worse off. Lastly, we see that the difference in Ragas scores between Llama-3 and Gemma-2 was insignificant (<1%).

The experiment results showed that smaller fine-tuned models performed better than large pre-trained instruction-tuned models with zero-shot and one-shot learning, which is consistent with the findings of other practitioners in the industry.

## Conclusion

From this experiment, we can see that it is possible to fine-tune a smaller LLM on Hansard written answers to help public servants draft better replies that are consistent with the style and prose of past Parliamentary replies while maintaining factual accuracy.

However, we have to bear in mind that the objective of this experiment is to show such a potential and synthetically generated relevant documents were used. To fine-tune a model which public servants can really use for drafting replies in practice, we would need to use the actual documents they used for reference when drafting their replies.

For production systems, the decision to continue using pre-trained LLMs-as-a-service like GPT-4o or use your own fine-tuned models is not a trivial one that is solely dependent on accuracy. It is a balancing act between cost and benefits, and other factors influencing the decisions include:

* **Data availability** : Is there relevant data to fine-tune your model? How do you collect data for continuous training over time?
* **Cost** : How much does it cost to fine-tune AND host the model? Is it cheaper than LLMs-as-a-service?
* **Latency** : Are there enough GPU resources to make inference on the fine-tuned model as fast as the LLMs-as-service?

## Extension to Other Use Cases

The findings from this fine-tuning experiment are not limited only to drafting Parliamentary replies. They can be extended to many other use cases, like domain-specific summarisation, key point extraction, and report generation. The premise is that you need to have a set of input documents and a set of desired outputs (usually human-curated) you want to get from the input documents.
