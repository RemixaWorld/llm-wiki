_Vision Transformers are powerful but picky about image size. Enter ViTAR: a smarter, flexible upgrade that handles images of any shape or resolution._

Computer vision is evolving at an incredible pace, and one of the most exciting breakthroughs we've seen recently is the Vision Transformer, or (ViT). However, there’s a little hiccup — ViTs prefer everything to be neat and tidy, which means they require all images to be the same size. But we know that’s not how things work in the real world! Just think about satellite images, medical scans, or footage from security cameras — they come in all sorts of shapes and sizes. This is where ViTAR steps in to save the day: it's a Vision Transformer specially designed to handle images of any resolution.

In this article, I will explain how ViTAR differs from ViT using simple examples.

## **What is Vision Transformer with Any Resolution?**

It is a new transformer-based architecture that can handle images of different sizes without requiring resizing or cropping. This is a massive advantage in domains where resizing can lead to information loss.

Imagine working with satellite images that come in all sorts of shapes and sizes—some large, some small, some rectangular, and others square. While traditional ViTs must fit these images into a fixed shape, which may technically function, it risks overlooking important spatial details. Thankfully, ViTAR addresses this challenge by:

* Supporting **input of any resolution**
* Using an innovative **fuzzy positional encoding** method to understand where each patch is, even if the image size changes
* Delivering **robust performance** on real-world, high-resolution data

### Real-World Applications

* **Remote Sensing** : Process satellite images at various resolutions without compromising information quality.
* **Medical Imaging** : Analyze CT scans, MRIs, or X-rays in their original resolution.
* **Surveillance Systems** : Handle different frame sizes from various camera feeds.
* **Document Analysis** : Manage scanned documents with differing formats and aspect ratios.

### How Is ViTAR Trained?

ViTAR is trained using datasets with varying image sizes. During training, it learns how to generalize across resolutions. This makes it ideal for real-world datasets, unlike older ViTs that rely on neatly curated, fixed-size datasets like ImageNet.

### Structure of ViTAR:

Would you like a sneak peek at the engine? Here’s a friendly, simplified walkthrough of ViTAR’s pipeline:

1. **Patch Embedder with Any‑Resolution Flexibility**
• The input image — whether 200 × 300 or 4 K — is split into fixed‑size patches (e.g., 16 × 16).
• Because image sizes vary, the _number_ of patches is variable, not the patch size.
2. **Linear Projection**
• Each patch is flattened and passed through a small linear layer, turning raw pixels into a _patch embedding_ vector.
3. **Fuzzy Positional Encoding**
• To keep track of _where_ each patch came from, ViTAR adds a learned, interpolated positional vector that scales smoothly with resolution.
• This lets the model understand spatial layout even when image dimensions change.
4. **Transformer Encoder Blocks**
• Stacks of multi‑head self‑attention (MHSA) + MLP layers process all patch embeddings in parallel, sharing information across the entire image.
• LayerNorm and residual connections keep training stable.
5. **Adaptive Aggregation**
• For classification, a special [CLS] token or global average pooling gathers a single image representation.
• For dense tasks (segmentation, detection), patch outputs are reshaped back to spatial grids.
6. **Task‑Specific Head**
• A simple linear layer (classification), a small decoder (segmentation), or a detection head attaches here, depending on your goal.

### Why low-frequency channels change smoothly across the grid while high-frequency channels oscillate rapidly (capturing fine spatial detail).

The positional formula is

* `p` – patch (or token) index
* `d` – **channel** (embedding dimension)
* `D` – total embedding width (e.g., 768)

As `d` gets larger, the denominator 10000^(d/D) grows exponentially, making the angle—and therefore the sine/cosine value—change **more slowly** from one patch to the next.

Bottom line:

* **Low-index channels** (e.g., 0, 1) oscillate quickly ⇒ **high frequency**
* **High-index channels** (e.g,. 510, 511…) vary slowly ⇒ **low frequency**

## Hands‑On: Calculating Positional Embeddings in Vanilla ViT

Below is a _ground-up_ walkthrough that shows how classic ViT transforms 2D patch coordinates into learnable vectors — and how those vectors are combined with patch features.

1. **Indexing patches** — ViT flattens a 14 × 14 grid into a **196‑long sequence**.
2. **Parameter table** — A single tensor `pos_embed` stores a 768‑D vector for the `[CLS]` token **plus** one vector per patch.
3. **Simple addition** — The model literally **adds** the right row of `pos_embed` to each patch’s projected pixels, giving the transformer a _sense_ of spatial order before self‑attention.

> **_Key Limitation:_**_If the image isn’t 224 × 224 (so the grid isn’t 14 × 14) the table no longer matches — hence the need to resize images_ or _interpolate_` _pos_embed_` _(as ViTAR does)._

## Fuzzy Positional Encoding — ViTAR

### ViTAR introduces a flexible approach by replacing that rigid lookup table with **fuzzy positional encoding**.

A classic Vision Transformer (ViT) stores one row for **each patch in a 224 × 224 image**. If you suddenly give it a taller or wider picture, the spreadsheet no longer lines up — the model has no rows for the “extra” patches, so you have to crop or stretch the image first. That’s why we call the table **brittle**.

ViTAR swaps that rigid spreadsheet for a **“stretchy rubber sheet”** of numbers. It isn’t a fixed list of rows. Still, it’s a continuous mathematical surface, so if your image grows from 14 × 14 to 24 × 24 patches, ViTAR just **samples** new points on the same surface (using smooth bicubic interpolation).

### Instead of one‑hot positions, ViTAR learns a **continuous function** that can be _interpolated_ to any patch grid.

`**resample_abs_pos_embed**`Performs a bicubic interpolation on the 2‑D positional grid, just like resizing an image, but in the **embedding space**.

To illustrate this concept, we will use the same example that was applied earlier for ViT, but this time for ViTAR to highlight the differences. You can notice that the low-frequency channels remain smooth while the high-frequency channels display stripes. No new information is created; the pattern "stretches," allowing ViTAR to preserve positional meaning at a higher resolution.

```python # -----------------------------------------------------------# 0) CONFIG – ViT-Base (patch16, 224×224 ⇒ 14×14 grid)# -----------------------------------------------------------H0 = W0 = 14 # original gridD = 768 # embedding dims# Utility: index p (0…195) → sin/cos pair using Transformer formuladef build_sincos_table(H, W, D): p_flat = np.arange(H * W) # row-major patch index table = np.zeros((H * W, D), np.float32) for d in range(0, D, 2): angle = p_flat / 10000 ** (d / D) table[:, d] = np.sin(angle) table[:, d + 1] = np.cos(angle) return table.reshape(H, W, D) # (H, W, D)pos14 = build_sincos_table(H0, W0, D) # vanilla table# -----------------------------------------------------------# 1) VISUALISE PATCH INDICES (helps orientation)# -----------------------------------------------------------patch_idx = np.arange(H0*W0).reshape(H0, W0)plt.figure(figsize=(4,4))plt.imshow(patch_idx, cmap="viridis")for y in range(H0): for x in range(W0): plt.text(x, y, patch_idx[y,x], ha='center', va='center', color='white', fontsize=6)plt.title("Patch Indices 14×14"); plt.axis('off'); plt.tight_layout(); plt.show()# -----------------------------------------------------------# 2) INTERPOLATE → 24×24 (ViTAR-style fuzzy encoding)# We upsample EACH channel like an image (bicubic).# -----------------------------------------------------------H1 = W1 = 24 # new grid for 384×384 imagepos24 = np.zeros((H1, W1, D), np.float32)for d in range(D): # normalise channel to 0-255 → PIL → resize → back to float ch = pos14[..., d] # Replaced ch.ptp() with np.ptp(ch) ch_img = Image.fromarray(((ch - ch.min()) / np.ptp(ch) * 255).astype(np.uint8)) ch_up = ch_img.resize((W1, H1), Image.Resampling.BICUBIC) # Replaced ch.ptp() with np.ptp(ch) ch_up = np.asarray(ch_up).astype(np.float32) / 255 * np.ptp(ch) + ch.min() pos24[..., d] = ch_up# -----------------------------------------------------------# 3) COMPARE ONE (d=0) BEFORE vs AFTER# -----------------------------------------------------------fig, ax = plt.subplots(1,2, figsize=(7,3))ax[0].imshow(pos14[...,0], cmap="twilight");
