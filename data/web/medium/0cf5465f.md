The Diffusion community is cheering about the release of [Flux.1 Diffusion model](<https://huggingface.co/black-forest-labs/FLUX.1-dev>) from [Black Forest labs](<https://blackforestlabs.ai/>) [1], the original team behind Stable Diffusion. It is the largest open-source Diffusion model released when I write this. Is it good? Yes, this model is what I was expecting from Stable Diffusion 3.

Since it is an open-source model, I should be able to run it with my own RTX 4090 with Python, right? let’s find out.

### 1\. Load up Flux.1 model using Hugging Face Diffusers

Open Github Diffusers repository, and found that `diffusers` just released Flux.1 support hours ago. These are good people. Update the diffusers package from the latest main branch:

```python pip install -U git+https://github.com/huggingface/diffusers.git@main ```

Following the guideline looks like all I need to do is kick off the following code:

```python import torchfrom diffusers import FluxPipelinepipe = FluxPipeline.from_pretrained( "black-forest-labs/FLUX.1-schnell" , torch_dtype=torch.bfloat16)#save some VRAM by offloading the model to CPU. Remove this if you have enough GPU powerpipe.enable_model_cpu_offload() prompt = "A cat holding a sign that says hello world"image = pipe( prompt, guidance_scale = 3.5, output_type = "pil", num_inference_steps = 20, max_sequence_length = 512, generator = torch.Generator("cuda").manual_seed(0)).images[0]image.save("flux-schnell.png")image ```

Bump, what I saw is not “A cat holding a sign that says hello world”, instead, an error message — “CUDA out of memory …”. WHAT? I can’t run a model with RTX 4090?

There must be a way to load it up. I need to do some research work.

[Nov 28,2024 Update]

With the newest Diffusers `pip install -U diffusers` We can run without quant with a 24G VRAM GPU.

### 2\. Use FLUX by quantizing the model weights

The quantization technique works pretty well with the LLM neighbor, considering that the FLUX.1 is also using the Transformer architecture as its denoising backbone, I should be able to quantize the FLUX.1 model to float8 or maybe even int4.

We can quantize the Flux Transformer model using either `[optimum-quanto](<https://github.com/huggingface/optimum-quanto>)` or `quantize_` from `torchao` . I found torchao is a faster and better solution.

To install `torchao`, use the following command:

```python pip install torchao --extra-index-url https://download.pytorch.org/whl/cu121 # full options are cpu/cu118/cu121/cu124 ```

Here is the complete code to use FLUX.1 with torchao with only 14.1GB VRAM (1024 x 1024).

```python from diffusers import DiffusionPipeline, FluxTransformer2DModelfrom torchao.quantization import quantize_, int8_weight_onlyimport torchmodel_path = "/path/to/FLUX.1-schnell_main"# or # model_path = "black-forest-labs/FLUX.1-schnell"# load transformer model and quantize to int8transformer = FluxTransformer2DModel.from_pretrained( model_path , subfolder = "transformer" , torch_dtype = torch.bfloat16)quantize_(transformer, int8_weight_only())# load up pipepipe = DiffusionPipeline.from_pretrained( model_path , transformer = transformer , torch_dtype = torch.bfloat16)pipe.enable_model_cpu_offload()# generate imageimage = pipe( prompt = "cat" , guidance_scale = 0.0 , num_inference_steps = 6 , height = 1024 , width = 1024 , generator = torch.Generator('cuda:0').manual_seed(1)).images[0]display(image) ```

With the above code, we can use FLUX model in a GPU with about 16GB VRAM. But it takes a while to quantize the transformer model, is there a way to save the quantized transformer and load the int8 version directly?

### 3\. Save and load the quantized model

**Step 1** , load transformer sub model, quantize and then save to a local pt file.

```python import torchmodel_path = "path/to/FLUX.1-schnell_main"transformer = FluxTransformer2DModel.from_pretrained( model_path , subfolder = "transformer" , torch_dtype = torch.bfloat16)quantize_(transformer, int8_weight_only())save_file_path = "/path/to/flux_schnell_int8.pt"torch.save(transformer.state_dict(), save_file_path) ```

**Step 2** , load up the saved quantized file, so that we don’t need to quantize the weight file every time loading up the model.

``` dtype = torch.bfloat16with torch.device('meta'): config = FluxTransformer2DModel.load_config(model_path, subfolder = "transformer") model = FluxTransformer2DModel.from_config(config).to(dtype)state_dict = torch.load(save_file_path)model.load_state_dict(state_dict, assign = True)pipe = DiffusionPipeline.from_pretrained( model_path , transformer = model , torch_dtype = dtype)pipe.enable_model_cpu_offload() ```

Let me explain the above code by section.

* **Loading the model configuration**

``` with torch.device('meta'): config = FluxTransformer2DModel.load_config(model_path, subfolder="transformer") model = FluxTransformer2DModel.from_config(config).to(dtype) ```

This block loads the configuration of a `FluxTransformer2DModel` from a file located at `model_path` in the `transformer` subfolder. The `torch.device('meta')` context is used to indicate that the model is being loaded in a meta-device mode, which allows for loading the model without actually allocating memory.

The `load_config` method loads the configuration, and `from_config` creates a new instance of the model from that configuration. The `to(dtype)` method converts the model to the specified data type (`torch.bfloat16`).

* **Loading the model weights**

``` state_dict = torch.load(save_file_path)model.load_state_dict(state_dict, assign=True) ```

This block loads the model weights from a file located at `save_file_path` using `torch.load`. The `state_dict` variable holds the loaded weights. The `load_state_dict` method is then used to assign the loaded weights to the model. The `assign=True` argument ensures that the weights are assigned directly to the model's parameters.

In general, setting `assign=False` is useful when you want to inspect the loaded state dictionary and decide how to handle any mismatched or unused parameters. However, if you're sure that the loaded state dictionary matches the model's parameters, setting `assign=True` is usually the safer choice.

### 4\. Generate images

Now let’s generate some images from the quantized FLUX model.

``` prompt = """\A photo of fashion model on stage, she wear a navy blue blazer paired with a light blue dress shirt and khaki dress pants. wear a brown leather belt,wear brown leather dress shoes. raw photo, cannon, nikon,nikon f4, 50mm f1.2, Fujichrome Velvia 50, bokeh,8k, best quality, masterpiece, realistic, photo-realistic, ultra detailed"""image = pipe( prompt = prompt , guidance_scale = 0.0 , num_inference_steps = 6 , height = 1680 , width = 1024 , generator = torch.Generator('cuda:0').manual_seed(2)).images[0]display(image) ```
