## About Finetuning

In this section, you can find the motivation for the start of your finetuning journey by finding what it is, why is used, and when to finetune the LLM. Enjoy!

### What is finetuning?

Based on the Cambridge dictionary, finetuning is a process of making small changes to make some processes better:

Fine-tune general meaning (Image by: Author; Source: <https://dictionary.cambridge.org/dictionary/english/fine-tune>)

If we translate this definition into the AI language, the first finetuning approach is a process of training (changing/tuning) weights of a neural network on a new dataset where one can change all or a fraction of weights. The second one is training the so-called “adapter” for the specific task with far fewer parameters than an AI model that will be used together with the model to produce the result. But, what about LLMs? If you change the term “AI model” with the “LLM” in this paragraph, you will find the definition of finetuning the LLMs.

### Why finetuning is used?

T**heory** — to enhance the capability of pre-trained LLMs which often are not usable after full training using initial large text corpus.

P**ractice** —**theory** \+ you do not have the resources (GPUs, other infrastructure, data, …) to train the LLM from the start.

### When to finetune the LLM?

**If**[**In Context Learning (ICL)**](<https://towardsdatascience.com/all-you-need-to-know-about-in-context-learning-55bde1180610>)**doesn’t work or doesn’t make any sense:** ICL is a process of enhancing the LLM prompt with some context knowledge that can include examples, factual data, or similar. So, it has nothing to do with learning in the AI context, but this name has already become a standard in the LLM community. This process will help the model to “ground itself” and construct the output that is more prone to hallucinations. The main challenge here is to create a dataset that can be used for providing context to LLM prompts. In those cases, RAGs are implemented that try to retrieve relevant context based on a provided prompt. If you are interested in such a system, a good start can be found in [this article](<https://towardsdatascience.com/the-ins-and-outs-of-retrieval-augmented-generation-rag-56f470ccda4>). Here are some examples:

``` Prompt 1: Without ICL"""Create a new unseen banana bread recipe."""Prompt 2: With ICL"""Create a new unseen banana bread recipe based on the provided context. Context: Cream 140g softened butter and 140g caster sugar until light and fluffy, then slowly add 2 beaten large eggs with a little of the 140g flour. Fold in the remaining flour, 1 tsp baking powder, and 2 mashed bananas. Pourthe mixture into the prepared tin and bake for about 50 mins, or until cooked through.""" ```

**If you want to adapt the LLM to be an expert in a specific field:** Here, ICL will not exactly be your partner because it can “only” provide an output based on the context provided in the given prompt. This is why ICL is mostly used in Document QA applications where the user asks the system to answer a specific answer which is constructed based on the context retrieved from some document. Nevertheless, finetuning will help you to create a real expert in the field that you want or an expert for some company-specific knowledge.

**If you want to cut costs:** For a large portion of companies commercially available LLM APIs can represent a significant cost and overkill for their needs. Then, you can try to finetune open-source available LLMs, especially smaller versions that can inspire you to create an LLM army with many smaller experts in different fields required. Another good cutting-cost case would be running code testing or research activities that can generate a significant number of API calls.

## How to finetune?

In this section, you can find all the theoretical background needed to start your finetuning journey. Enjoy!

### Infrastructure requirements

It is not a coincidence that this is the first paragraph you encountered in the „How“ section! If you do not have a powerful GPU with a lot of VRAM, you probably will not finetune anything without leasing a GPU server at Amazon, Google, or your other favorite provider. Some [recent research](<https://kaitchup.substack.com/p/fine-tune-llms-on-your-cpu-with-qlora>) showed that it is possible to finetune the LLM using the CPU using the QLoRA technique, but training is still much faster on GPUs. For code examples in this article, the Nvidia RTX 2080 Super with 8GB of VRAM is used, with the small disclaimer that small LLMs are used for examples.

### Finetuning goal

The most important step in starting to finetune the base model is to understand and define your finetuning goal because it will heavily influence data preparation. Finetuning goals define the use case, model inputs, and model output. As mentioned before, it can include question answering, machine translation, chatbot, or similar. Every goal requires you to prepare a specific set of data that will be used for finetuning. You can see the examples in the _Use Cases_ section of this article.

### Data preparation

After defining the finetuning goal, the most exhausting task in the AI world can start! Data preparation! Of course, to start preparing the data, you have to have one. So, the first step is to get the finetuning data that is adaptable for the finetuning goal that you want to achieve. In an LLM context, a feature is a text used for “predicting” the LLM label, which is again, text. And of course, as we mentioned multiple times, this text-to-text dataset must be adapted based on the finetuning goal. If you do not have your finetuning dataset, you can find a variety of datasets at the [HuggingFace data hub](<https://huggingface.co/datasets>). Finetuning datasets should look like the below with at least 1000+ examples.

### Machine translation

> Shortcut to full code example at GitHub repo: <https://github.com/tisljaricleo/llm-finetuning/blob/main/translations-finetuning.ipynb>

The goal of this use case is to fine-tune the translation model to translate from English to French texts. The model will be fine-tuned on a set of data that consists of English-sentence -> French-sentence. Everything in the AI world starts with data, so …

**Get the data**

In this use case (and all others) we will use prepared datasets from HuggingFace. For machine translation, we will use [KDE4 dataset](<https://huggingface.co/datasets/kde4>) and load it in a notebook:

```python from datasets import load_datasetsource_lang = "en"target_lan = "fr"dataset = load_dataset( "kde4", lang1=source_lang, lang2=target_lan, trust_remote_code=True)print(f"DATASET TYPE: {type(dataset)}")print(f"DATASET INFO: {dataset.items()}")print(f"DATASET COL NAMES: {dataset.column_names}") ```

Dataset overview (Image by: Author)

Now we have 210173 data rows to train the model! Nets dive deeply to see what it actually looks like:

``` # Take three values at random indexes.dataset["train"][10:13] ```

Training dataset content (Image by: Author)

As we can see it is a dictionary with a list of indexes and a list of translation pairs. **At first, I did not take my time to browse through more dataset pairs to look for some error patterns… it was a great mistake! Let’s see why.**

The next step is preparing the dataset for training:

1. **Test/train split**

``` split_datasets = dataset["train"].train_test_split(train_size=0.9, seed=20)split_datasets["validation"] = split_datasets.pop("test")split_datasets ```

Dataset after splitting (Image by: Author)

2.**Tokenize training data**

```python model_checkpoint = "Helsinki-NLP/opus-mt-en-fr" # Model name from HuggingFacemax_length = 128 # Max. length of generated content.tokenizer = AutoTokenizer.from_pretrained( model_checkpoint, # Model name or path. return_tensors="pt" # Type of returned tokenized texts: pt - Pytorch -> NOT Portugeese like in some tutorials :))def preprocess_function(examples): inputs = [ex["en"] for ex in examples["translation"]] targets = [ex["fr"] for ex in examples["translation"]] model_inputs = tokenizer( inputs, # Define input text. text_target=targets, # Define "labels". max_length=max_length, truncation=True, # Truncate texts to the same size. ) return model_inputs# Map preprocess function to every dataset (train/validation)tokenized_datasets = split_datasets.map( preprocess_function, batched=True, remove_columns=split_datasets["train"].column_names, # Remove additional columns (try to run map function with and without remove_columns param to explore the results).)tokenized_datasets ```

Dataset after tokenization (Image by: Author)

Here you can observe different column names, but the same number of rows. This is a [result of the tokenization process](<https://huggingface.co/docs/transformers/main_classes/tokenizer>). It will return three lists (columns in this context):

* _input_ids_ — List of token ids to be fed to a model.
* _attention_mask_ — List of indices specifying which tokens should be attended to by the model.
* _labels_ — List of token ids that represent the model's expected response.

This is the last step in data preparation, now we can load the model and set the finetuning parameters:

``` model_checkpoint = "Helsinki-NLP/opus-mt-en-fr"model = AutoModelForSeq2SeqLM.from_pretrained(model_checkpoint) # Data collators are objects that will form a batch by using a list of dataset# elements as input. These elements are of the same type as the elements of # train_dataset or eval_dataset.data_collator = DataCollatorForSeq2Seq( tokenizer, model=model, return_tensors="pt")# Create an object for setting training arguments.model_args = Seq2SeqTrainingArguments( f"{model_checkpoint}-finetuned-{source_lang}-to-{target_lan}", # Finetuned model name. evaluation_strategy="epoch", # Defines when to run evaluation. learning_rate=2e-4, # Learning rate. per_device_train_batch_size=8, # Batch size per GPU for training if GPU is available, else per CPU core. per_device_eval_batch_size=8, # Same thing but for evaluation. weight_decay=0.02, # The weight decay to apply (if not zero) to all layers except all bias and LayerNorm weights in AdamW optimizer. save_total_limit=3, # Limits total amount of checkpoints. In this case, after training you will have only three checpoints. num_train_epochs=3, # Total number of training epochs. predict_with_generate=True # Whether to use generate to calculate generative metrics like ROUGE or BLEU.)# Create an object for training the LLM.trainer = Seq2SeqTrainer( model, model_args, train_dataset=tokenized_datasets["train"], eval_dataset=tokenized_datasets["validation"], data_collator=data_collator, tokenizer=tokenizer, compute_metrics=compute_metrics # This is a function that is used for computing metrics available at the github repo.)# This will start the training process. Be patient :)trainer.train() ```

Finetuning results for machine translation with LLMs (Image by: Author)

For the evaluation metric, we used the [BLEU score](<https://towardsdatascience.com/nlp-metrics-made-simple-the-bleu-score-b06b14fbdbc1>). This is a simple, standard evaluation metric for comparison of two translations. In our case, we want to compare the translation from the training dataset to the generated translation during the training.

If the training went well with increasing BLEU scores, we can use the model like this:

``` # Now model_checkpoint (name) is the path to the finetuned model.# Your model is probably saved to the same folder from which you ran the training.my_model_checkpoint = "Helsinki-NLP/opus-mt-en-fr-finetuned-en-to-fr_3/checkpoint-141500"my_model = AutoModelForSeq2SeqLM.from_pretrained(my_model_checkpoint)tokenizer = AutoTokenizer.from_pretrained(my_model_checkpoint, return_tensors="pt")text = "Hello, my name is Leo!"tokenized_text = tokenizer(text, return_tensors="pt")result = my_model.generate(**tokenized_text)print(tokenizer.decode(result[0], skip_special_tokens=True)) ```

And voila! We have successfully fine-tuned the translation model for eng->fra translations:

Finetuned model result (Image by: Author)

Well, the translation is good, BUT we have some unexpected behavior here. Model outputs were strange text in the form of “« & #160;”. If you encounter some strange words like this, make sure to investigate if this is a data problem or model problem.

* **Model problems** can be detected if the model has strong hallucinations or returns texts that have no sense. In this case, you can play with the model training arguments or prepare a larger, high-quality training dataset.
* **Data problems** are mostly related to data cleanliness level or some similar issues. In our case, the training dataset was full of « & #160;” which are [HTML tags for space](<https://homework.study.com/explanation/what-does-160-mean-in-html.html>). Because of many examples of those tags in the training examples, the model learned that this tag needs to be placed in the resulting text. So, data was not cleared properly as we can see:

Press enter or click to view image in full size

Data before cleaning (Image by: Author)

To solve this issue, we need to clear the data before tokenizing it:

```python # Function for ceanining the input texts for the training.def clean_text(text: str) -> str: return re.sub('«&#160;', '', text) # You can define your expression/s here.def preprocess_function(examples): inputs = [clean_text(ex["en"]) for ex in examples["translation"]] targets = [clean_text(ex["fr"]) for ex in examples["translation"]] model_inputs = tokenizer( inputs, text_target=targets, max_length=max_length, truncation=True, ) return model_inputs ```

And rerun the fine-tuning process :) Good luck!

This dataset consists of two parts, train and test. Every part has two columns, text, and labels. Here, the text represents the comment regarding some movie and the label is a number 0 or 1, where 0 represents negative content and 1 is positive.

As you can observe from the image above, once again we have a dataset with many HTML tags like “<br /><br>”. We will create a clear_text function to remove those tags and run the tokenization process:

```python def clear_text(text: str) -> str: return re.sub('<[^<]+?>', '', text)def preprocess_function(examples): inputs = [clear_text(ex) for ex in examples["text"]] model_inputs = tokenizer( inputs, truncation=True ) return model_inputsmodel_checkpoint = "distilbert-base-uncased"tokenizer = AutoTokenizer.from_pretrained(model_checkpoint, return_tensors="pt")tokenized_datasets = dataset.map( preprocess_function, batched=True,) ```

To explain the model’s users which class is represented by 0 and which by 1, we need to define id-to-label and label-to-id dictionaries like this:

```json id2label = {0: "NEGATIVE", 1: "POSITIVE"}label2id = {"NEGATIVE": 0, "POSITIVE": 1} ```

For this example, I’ve created a simple script for trying different model’s hyperparameters to determine the best for my use case:

``` # We will train 5 models with different parameters to find the best one.finetuned_ids = [0, 1, 2, 3, 4]learning_rates = [2e-3, 2e-4, 2e-5, 2e-7, 2e-9]n_epochs = [2, 3, 3, 5, 7]model_checkpoint = "distilbert-base-uncased"for f_id, lr, n_e in zip(finetuned_ids, learning_rates, n_epochs): print(f"ID: {f_id}, LEARNING_RATE: {lr}, N_EPOCHS: {n_e}") model = AutoModelForSequenceClassification.from_pretrained( model_checkpoint, num_labels=2, # We have only two labels, 0 and 1. id2label=id2label, label2id=label2id ) tokenizer = AutoTokenizer.from_pretrained(model_checkpoint, return_tensors="pt") data_collator = DataCollatorWithPadding(tokenizer=tokenizer) training_args = TrainingArguments( output_dir=f"{model_checkpoint}-finetuned-CLASSIFICATION-{f_id}", learning_rate=lr, per_device_train_batch_size=8, per_device_eval_batch_size=8, num_train_epochs=n_e, weight_decay=0.01, evaluation_strategy="epoch", save_strategy="epoch", load_best_model_at_end=True, ) trainer = Trainer( model=model, args=training_args, train_dataset=tokenized_datasets["train"], eval_dataset=tokenized_datasets["test"], tokenizer=tokenizer, data_collator=data_collator, compute_metrics=compute_metrics, ) trainer.train() ```

### Text generation/chatbot

> Shortcut to full code example at GitHub repo: <https://github.com/tisljaricleo/llm-finetuning/blob/main/text-generation-finetuning.ipynb>

The last example in this article is the text generation example. This is the use case where you want to fine-tune the base model for conversational-like tasks like chatbots or to inject new knowledge into existing LLM.

For this example, we will introduce two new terms:

**Quantization:** Process of simplifying model weights by reducing them from float to integer values. [Read more about quantization here.](<https://towardsdatascience.com/introduction-to-weight-quantization-2494701b9c0c>) This process will reduce the model size so it can fit into memory and increase the training/inference speed. Of course, you will lose some accuracy with quantization, but you need to decide if it is significant for your use case.

**PEFT (Performance Efficient Fine-Tunning):** Process of training a smaller model (not the whole original LLM) to be used as an adapter for the specific use case. For example, PEFT is used for creating different adapters for learning the LLM in different languages or to perform multiple tasks based on the input prompt. [To learn more about PEFT, check out this article.](<https://towardsdatascience.com/parameter-efficient-fine-tuning-peft-for-llms-a-comprehensive-introduction-e52d03117f95>)

> Why do you want to use quantization and PEFT? Because you do not have 300+ GB VRAM to train LLMs from the start.

**Get data**

``` dataset = load_dataset("gathnex/Gath_baize", split="train")print(dataset["chat_sample"][0]) ```

You can observe special [prompt tokens](<https://replicate.com/blog/how-to-prompt-llama#wrap-user-input-with-inst-inst-tags>) introduced with [Llama models](<https://huggingface.co/docs/transformers/main/model_doc/llama>) like [INST] and [/INST] that represent the beginning and the end of the instruction for the LLM. Before instruction we have context information and after the answer. If you encounter multiple questions and answers, every question for the LLM needs to be marked with [INST] and [/INST] tokens.

Next, we will load the model and the configuration for quantization:

``` # Configuration for quantization - you can choose 4-bit and 8-bit quantization.bnb_config = BitsAndBytesConfig( load_in_4bit= True, bnb_4bit_quant_type= "nf4", bnb_4bit_compute_dtype= torch.bfloat16, bnb_4bit_use_double_quant= False,)# Load base model(Mistral 7B)model = AutoModelForCausalLM.from_pretrained( base_model, quantization_config=bnb_config, device_map={"": 0})model.config.use_cache = False # silence the warnings. Now let’s initialize the tokenizer and set special tokens:

``` tokenizer = AutoTokenizer.from_pretrained(base_model, trust_remote_code=True)tokenizer.pad_token = tokenizer.eos_tokentokenizer.add_eos_token = Truetokenizer.padding_side = 'right'tokenizer.add_bos_token, tokenizer.add_eos_token ```

… and attach the PEFT to the base model:

``` model = prepare_model_for_kbit_training(model)peft_config = LoraConfig( r=16, lora_alpha=16, lora_dropout=0.05, bias="none", task_type="CAUSAL_LM", target_modules=["q_proj", "k_proj", "v_proj", "o_proj","gate_proj"] )model = get_peft_model(model, peft_config) ```

Before the training starts, it is always recommended to run some metrics logging so that you can stop the training process if your learning curve is not as it is supposed to be. This is very important because this fine-tuning procedure could last for 10+ hours, depending on your hardware! So, if the model is not performing well on training data, you want to stop the fine-tuning process, change something (data, hyperparameters, etc.), and run the training procedure again.

[Weights & Biases](<https://wandb.ai/site>) saved me there! It is a simple metrics monitoring platform that is of immense importance when dealing with training LLMs. Of course, you can write your code for this, but this is simpler and has a lot of useful features.
