## Our 1B LLM And Embedding Model

Almost all AI products that show hallucinations are based on two components:

* Text Generation LLM
* Embedding Model

OpenAI, Gemini, and Anthropic models are so good that, even in very complex situations, they hardly create hallucinations. However, they come at a cost. On the other hand, open-source LLMs, especially tiny ones are cheaper but not as good at producing quality answers.

## Factual Correction Using RAG

Let’s start with the basic issue with tiny LLMs, they often provide wrong answers to factual questions.

See this example:

``` # The system prompt sets the behavior or persona of the AIsystem_prompt = "You are an AI Chatbot!"# The user prompt is the actual question or input from the useruser_prompt = "Who discovered Penicillin in 1928?"# Generate a response from the AI using the system and user promptsresponse = generate_response(system_prompt, user_prompt)# Print the response returned by the AIprint(response) ```

The true answer to our query is **“Penicillin was discovered in 1928 by Alexander Fleming”** but the LLM response is:

``` Robert Withering, an English physician, is often credited with the discovery of penicillin in ```

Our tiny LLM gives credit to the wrong person (it might give the correct answer if you try multiple times), but in production, there’s no room for multiple attempts.

Our 1B LLaMA training data might or might not contain the true answer, but in either case, its first response wasn’t correct.

You might already know that **RAG** is one of the most common techniques to solve this issue. You can skip from here and move on to the next issue and its solution if you’re already familiar.

So, we normally have tons of documents, and somewhere among them lies the answer to our test query.

Otherwise, the LLM should respond that it has no relevant training data, instead of providing an incorrect answer. This way, the model’s quality remains trustworthy to the user.

Let’s define our knowledge base:

``` # Our Knowledge Base (5 Documents)documents = [ "Robert Withering, an English physician and botanist, is known for his study of the foxglove plant and its medicinal properties, particularly its use in treating dropsy (edema).", "The process of fermentation is a metabolic process that produces chemical changes in organic substrates through the action of enzymes. This discovery revolutionized medicine.", "The Eiffel Tower is a wrought-iron lattice tower on the Champ de Mars in Paris, France. It was named after the engineer Gustave Eiffel, whose company designed and built the tower."] ```

Our knowledge base contains five documents that will be used by our LLM to answer our query. So, let’s create that simple RAG pipeline and see if it improves our LLM.

``` # Embed the user queryuser_query = "Who discovered Penicillin in 1928?" # Our test queryuser_query_embedding = get_sentence_embedding(user_query)# Embed the Knowledge Basedocument_embeddings = [get_sentence_embedding(doc) for doc in documents]# Find the most relevant document based on embedding similarity (using dot product)similarity_scores = np.dot(document_embeddings, user_query_embedding)# Find the index of the document with the highest scoremost_relevant_doc_index = np.argmax(similarity_scores)# Retrieve the text of the most relevant documentretrieved_context = documents[most_relevant_doc_index] ```

In production, you typically retrieve and experiment with chunk size, overlap, and other parameters including the top relevant chunks.

But here, to keep things simple, we are retrieving only the highest similarity score document as a reference, which will be passed to our LLM input.

Let’s create that system and user prompt and see what the LLM response would be.

``` # We explicitly tell the AI to use the context providedrag_system_prompt = f"""You are an AI Chatbot!Use the following context to answer the user's question accurately.If the context does not contain enough information to answer the question, respond that you don't have sufficient information from the provided context.Context:{retrieved_context}"""# The user prompt remains the sameuser_prompt = "Who discovered Penicillin in 1928?"# Generate a response using the RAG system prompt and original user promptrag_response = generate_response(rag_system_prompt, user_prompt)# Print the RAG-enhanced responseprint(rag_response) ```

Our LLM response is:

``` Penicillin was actually discovered by Sir Alexander Fleming,a Scottish physician and microbiologist, ```

There is a clear correction in our LLM’s factual response; now it correctly answers our factual question.

## Temporal Correction Using Time-Aware Prompting

Temporal hallucinations arise when an LLM produces time-sensitive errors or outdated information.

Because LLMs have a fixed **“knowledge cutoff”** (they only know the world up to their training date).

See this example:

``` # The system prompt sets the behavior or persona of the AIsystem_prompt = "You are an AI Chatbot!"# The user prompt is the actual question or input from the useruser_prompt = "Who is the president of France today?"# Generate a response from the AI using the system and user promptsresponse = generate_response(system_prompt, user_prompt)# Print the response returned by the AIprint(response) ```

So, we are asking the LLM about the current president of France, and here is the output from our LLM:

``` The current President of France is Emmanuel Macron. ```

One way to solve this issue is to use RAG, but it’s not always necessary to have a relevant knowledge base available. So, how can we handle that case?

[Qian et al. propose **TimeR4**](<https://aclanthology.org/2024.emnlp-main.394/>), a framework that rewrites queries to include time constraints. We can use this **time-aware prompting** approach, which means we make the LLM aware of the time frame of the query being asked.

* today → 5 May 2025
* this year → 2025
* this month → May

…and so on. This way, we guide our LLM with a rephrased query that clearly specifies the time frame being referred to, allowing the LLM to respond more accurately based on its training data.

> This can also improve the RAG retrieval quality because we are including the time frame in it.

Let’s implement this time-aware prompting technique.

We can use Python datetime module for this, You can use LLM for it too. But for now, we will create a function or some simple code to rewrite the user query by replacing temporal keywords like “today” with the actual current date.

```python from datetime import datetimedef make_query_time_aware(user_prompt: str) -> str: """ Rewrites the user prompt to include the current date for temporal context. This is a simplified example targeting specific keywords. Parameters: - user_prompt (str): The original user query. Returns: - str: The rewritten, time-aware query. """ current_date_str = datetime.now().strftime("%d %B %Y") # e.g., "05 May 2025" # Simple replacements - expand this for more temporal keywords rewritten_prompt = user_prompt.replace("today", current_date_str) rewritten_prompt = rewritten_prompt.replace("this year", datetime.now().strftime("%Y")) rewritten_prompt = rewritten_prompt.replace("this month", datetime.now().strftime("%B %Y")) # You might add more complex logic or regex for different temporal phrases return rewritten_prompt ```

Let’s run this function on our query:

``` # Let's apply this to our original temporal queryuser_prompt = "Who is the president of France today?"time_aware_user_prompt = make_query_time_aware(user_prompt)print(f"Original Query: {user_prompt}")print(f"Time-Aware Query: {time_aware_user_prompt}") ```

Today is **05 May 2025** , the output of this snippet would be:

``` Original Query: Who is the president of France today?Time-Aware Query: Who is the president of France 05 May 2025? ```

Now, we use this **time_aware_user_prompt** with our original simple system prompt to generate the response.

The system prompt doesn’t need to be changed, as the temporal information is now embedded directly in the user query itself.

``` # The system prompt remains simplesystem_prompt = "You are an AI Chatbot!"# Generate a response using the simple system prompt and the time-aware user prompttemporal_response = generate_response(system_prompt, time_aware_user_prompt)# Print the time-aware responseprint(temporal_response) ```

Our 1B-size LLaMA response is:

``` I'm an AI chatbot, and my training datais up to December 2023 ```

This approach not only gives the LLM a strong reason for why not to answer this question, but when you include RAG, the time frame will definitely affect the information fetching process because **“today”** creates confusion to LLM but a date does not.

It will guarantee the retrieval of relevant documents if they are present in the knowledge base.

## Contextual Issue Using Lookback Lens

Contextual hallucinations happen when a language model gives incorrect or misleading answers, even though all the right information is available.

This occurs when the model doesn’t properly use or understand the provided details, leading to answers that might seem relevant but are actually wrong or incomplete.

See this example:

``` # Our source context (representing a document or retrieved chunk)source_context = """ByteBuilders Q3 profit: ~5.02% adj, 4.9% unadj, +502 bps margin, –0.1 ppt FX drag, vs. 4.5% est."""# The system prompt (Report + System prompt)system_prompt = f"""You are an AI Chatbot!Article Snippet:{source_context}"""# The user prompt is simply asking for the summaryuser_prompt = "Summarize the Q3 earnings."# Generate a response using the system prompt with contextresponse = generate_response(system_prompt, user_prompt)# Print the response returned by the AIprint(response) ```

Our source context (tricky one), which can be a retrieved chunk, document, or web search result is basically a financial report of ByteBuilders company.

Since the information is already available in the document, we are asking our LLM to summarize it.

This is the response we get:

``` ByteBuilders reported Q3 earnings (4th quarter) with a net profit of approximately 4. ```

It gives the net profit value incorrectly, even though the correct value is clearly present in the document. This is our ground truth:

* **Quarter mix‑up:** Q3 is the third quarter, not the fourth.
* **Wrong profit figure:** The profit increase wasn’t “approximately 4” (percent or otherwise). In our context, ByteBuilders actually reported **5.02 %** adjusted profit growth (versus 4.50 % expected).

We can use a method similar to [Lookback Lens](<https://arxiv.org/html/2407.07071v1#:~:text=To%20leverage%20signals%20from%20attention,The>) to make sure that any specific factual claim the model makes is actually _supported_ by the provided input context.

We can take critical pieces of information from the generated summary (like **“net profit of 4”**) and pose them as explicit verification questions to the LLM, giving it the original source_context again and asking it to act as a fact-checker.

The good part is, we can often use the _same_ tiny LLM we used for generation to perform this verification task!

``` # Our source context (representing a document or retrieved chunk)source_context = """ByteBuilders Q3 profit: ~5.02% adj, 4.9% unadj, +502 bps margin, –0.1 ppt FX drag, vs. 4.5% est."""# Fact checking system promptverification_system_prompt = f"""You are a fact-checking assistant. Your task is to determine if the following STATEMENT is fully and directly supported by the provided CONTEXT.Answer (only one option to select):1. Yes2. No3. Partially SupportedCONTEXT:{source_context}"""# Proper naming (Last summarized response = hallucinated summary)hallucinated_summary = response ```

We are defining the verification system prompt, which will be passed along with the hallucinated summarized information to see what our LLM’s response would be.

``` # Generate a response using the system prompt with contextverify = generate_response(source_context, hallucinated_summary)# Print the response returned by the AIprint(verify) ```

This is the response we get:

``` Based on the provided context,The statement is partially supported ```

We can use this verification information and, based on it, either ask the LLM to regenerate its summarized response or redirect the task to a more powerful LLM to generate a more accurate summary for the query. Let’s do that and see how it affects the response.

``` # Decide based on the verification outcomeif "No" in verify or "Partially" in verify: # Regenerate the summarized info response = generate_response(improved_system_prompt, user_prompt) # Show the new response print(response)else: pass ```

Let’s see the generated response:

``` ByteBuilders reported Q3 earnings of ~5.02% annualized growth ```

We can build this pipeline inside a for loop to reattempt in parallel, helping avoid making the user wait for the answer. But in our case, the second attempt already gives us an improved result.

## Linguistic Issue Using Semantic Coherence Filtering

Linguistic hallucinations happen when a language model creates sentences that sound correct and make sense grammatically, but the meaning is wrong, irrelevant, or doesn’t make sense.

The result looks good on the surface but lacks true or useful content.

Consider when a similar question is being asked to the LLM **by 10 different people at the same time or same prompt being pass multiple times** , there’s a real possibility that one or more of them may encounter this kind of issue.

See this example:

``` # The system prompt sets the behavior or persona of the AIsystem_prompt = "You are an AI Chatbot!"# The user prompt is the actual question or input from the useruser_prompt = "Explain how photosynthesis works in plants"# Initializing a list to store multiple generated responsesresponses = []# Loop to generate 10 different responsesfor i in range(10): # Generating Responses response = generate_response(system_prompt, user_prompt) # Append the generated response to the list responses.append(response) ```

We are using a very simple query that many LLMs’ training data likely includes.

Now that we have our responses generated, let’s generate a similarity score between the query and the generated responses to identify where the issue lies.

``` # Get the embedding for the user's queryuser_query_embedding = get_sentence_embedding(user_query)# Get embeddings for all responsesresponse_embeddings = [get_sentence_embedding(response) for response in responses]# Calculate similarity scores between the query and each response using dot productsimilarity_scores = np.dot(response_embeddings, user_query_embedding)# Printing sim scoreprint(similarity_scores) ```

our scores are:

``` array([68.78545 , 69.63894 , 67.53516 , 67.09607 , 32.15152, 67.746735, 67.09607 , 69.6586 , 28.45125, 69.6586 ], dtype=float32) ```

Two of the responses at indices (4, 8) have very low similarity scores. Let’s print one of the low score response and examine what issues it might have:

``` # Printing Response at index 4print(f"response[4]: {responses[4]}") ``` ``` "Photosynthesis is a process where plants turn sunlight into sound waves, which they use to create energy." ```

This is an incorrect description of photosynthesis, as sound waves are not involved in the process. The response sounds grammatically correct, but the meaning doesn’t make any sense here.

We can set a threshold for the similarity score (e.g., 20%). Any response with a similarity score below this threshold will be flagged for regeneration.

``` # Set a similarity score thresholdthreshold = 50# Iterate over the responses and regenerate if the score is below the thresholdfor i, score in enumerate(similarity_scores): if score < threshold: # Regenerate the response regenerated_response = generate_response(system_prompt, user_prompt) responses[i] = regenerated_response ```

After regenerating the responses at indices **4** and **8** , we will recheck the similarity scores to ensure that the new responses are more relevant and accurate.

Let’s recalculate the similarity scores:

``` # Get embeddings for the regenerated responsesresponse_embeddings = [get_sentence_embedding(response) for response in responses]# Recalculate similarity scores between the query and each regenerated responsenew_similarity_scores = np.dot(response_embeddings, user_query_embedding)# Printing the new similarity scoresprint("New similarity scores after regeneration:")print(new_similarity_scores) ```

Take a look at our newly generated SIM score:

Our index 4 and index 8 scores have improved and are getting closer to the user query, meaning they might now contain relevant information related to the query.

This technique is really useful and important when you need high-temperature responses from an LLM.

## Intrinsic Issue Using Contradiction Checking

Intrinsic hallucinations are cases where the LLM’s output contradicts or misinterprets the input source.

In other words, the model has twisted the given facts incorrectly.

You might find intrinsic and contextual hallucinations pretty much the same, but let’s understand it with a simple example first:

* Input: The dog is running in the park.
* (Contextual Hallucination): The dog is running on the beach.
* (Intrinsic Hallucination): The dog is flying in the park.

The Intrinsic output directly contradicts the input. A dog can’t fly, so it creates a fundamental inconsistency with the original statement, as compared to a contextual issue where the model stayed within the context of the dog running but changed the location (from park to beach).

Let’s generate an output that have this issue.

``` # Our source context (representing a document or retrieved chunk)source_context = """The Nile River originates from the Great Lakesregion in Africa."""# Our user promptuser_prompt = "Where does the Nile originate?"# Generate a response using the system prompt with contextresponse = generate_response(system_prompt, user_prompt)# Print the response returned by the AIprint(response) ```

Let’s see the output of our LLM:

``` The Nile River originates from Lake Hindia, in Tanzania. ```

Our llm output directly contradicts the input. To detect contradictions between the premise (source text) and hypothesis (Model Output), we can use a pre-trained **BERT-based model** fine-tuned for **Natural Language Inference (NLI)**.

## Extrinsic Issue Using Copy/Pointer Mechanism

Extrinsic hallucinations happen when a language model adds extra information that isn’t supported by the original input.

Unlike intrinsic hallucinations, which conflict with the provided data, extrinsic hallucinations create entirely new, made-up facts.

See this example:

``` # Meeting summary Reportdocument = """Meeting Summary – April 10, 2025- Discussion of Q1 2025 performance and upcoming product launch.- CFO presented the Q2 2025 budget proposal."""# User prompt to test for extrinsic hallucinationsuser_prompt = """Can you summarize the meeting that took place on April 10th, 2025, and include any decisions made about budget allocations or new project approvals?"""# Generating Responsesresponse = generate_response(document, user_prompt)# Print the generated responseprint(response) ```

In this prompt, we are specifically asking the LLM if there are any new project approvals that are not present in the document.

Let’s see if the LLM comes up with any made-up facts.

``` Meeting Summary – April 10, 2025**Introduction*** The meeting was attended by the Executive Team, led by the CEO.**Q1 2025 Performance Review*** The team reviewed the Q1 2025 performance,highlighting areas of success and challenges faced.**New Project Approvals*** The Executive Team approved several new projects, including: + A cloud-based CRM system for customer engagement and support ```

**When our LLM is set to a higher max new tokens (e.g., 500)** , our tiny 1B model starts generating a bunch of made-up facts just to fill the token space, which are not even present in the original document.

> A proven method to reduce extrinsic hallucinations is using [pointer/copy mechanisms](<https://arxiv.org/pdf/2005.00661#:~:text=and%20inference,intrinsic%20hallucination>).

These techniques make the model pull content directly from the source text instead of creating new information.

For example, the Pointer-Generator Network in summarization allows the model to either generate new words or copy them from the input.

One simple way to enforce copying in your LLM is to use a **system prompt** that guides the model to copy directly from the source text.

Here’s an example of how you can structure the prompt:

``` system_prompt = """Please summarize the following document, but make sure to only use information that is present in the text.Do not add any new facts or details that are not in the original document.""" ```

Let’s generate the response with this updated template and see what our llm output is:

``` # User prompt + documentcombined_info = document + user_prompt# Generating Responses with copying mechanismresponse_with_copy = generate_response(system_prompt, combined_info)print(response_with_copy) ```

The updated output is:

``` The meeting summary provided is as follows:- The Q1 2025 performance was discussed.- A product launch for the upcoming period was announced.- The CFO presented a Q2 2025 budget proposal. ```

Our LLM is not using its own brain to write but is only copying text from the original source.

This is a useful technique because, in most cases, our knowledge base is very large and contains the relevant information that only needs to be called, not rephrased.

## Conclusion

Alright, we grabbed a tiny LLM (LLaMA 1B) and a small embedding model (GTE Tiny), proving we can work with less.

* **Factual issues?** We grounded it with RAG. Simple, effective.
* **Temporal oopsies?** Made the queries “time-aware” injecting the date works wonders!
* **Contextual confusion?** Implemented a ‘Lookback Lens’ the LLM fact-checks itself against the source!
* **Linguistic weirdness?** Filtered nonsensical outputs using embedding similarity thresholds and regenerated.
* **Intrinsic contradictions?** Used an NLI model to detect if the output fought the source, regenerated when it did.
* **Extrinsic made-up stuff?** Forced a ‘Copy/Pointer’ style via prompting stick to the source text.

We can make tiny, cheaper LLMs a viable option by systematically tackling hallucinations with these techniques.
