Quantization is a technique that enables us to use larger Large Language Models (LLMs) with limited hardware by reducing the number of bits per parameter.

Most LLMs nowadays use 16-bit floating point formats (FP16 or BF16) to store their parameters. When using 4-bit quantization instead, we can achieve up to a 4x reduction in model size.

Quantization algorithms aim to minimize size while maintaining optimal performance.

In this article, we will explore the Activation-Aware Weight Quantization (AWQ) algorithm and apply it to a small local LLM in practice.

### Weight Matrices

Quantization typically involves weight matrices **W** consisting of multiple rows and columns of numbers. There are different ways to apply quantization to a matrix.

One option is to compute one scaling factor for the entire matrix. Another option is to compute multiple scaling factors. Scaling factors for matrices are usually computed in two ways:

* **Channel-Wise** : One scaling factor for each row or column of the weight matrix
* **Block-Wise** : Split the weight matrix into multiple 2D blocks and compute one scaling factor for each block.

## Activation-Aware Weight Quantization (AWQ)

Activation-Aware Weight Quantization (AWQ) is a relatively new technique that makes AI models smaller without hurting their performance by squeezing model weights down to 4 bits (INT4). This is important because smaller models run faster and use less memory, making them easier to deploy on limited hardware.

The key idea behind AWQ is simple: not all weights in a neural network are equally important. Some have a much bigger influence on the model’s predictions than others.

AWQ uses a small calibration dataset to identify these important weights by examining the activations (the values that move through the model during inference). Weights connected to large activations are likely more critical to the model’s accuracy.

AWQ visualization with toy data: The top 1% of the most important weights are marked with a white X and are the ones we want to preserve with the lowest quantization error.

One simple approach would be to maintain 16-bit floating-point precision for the most important weights and reduce the rest to INT4.

However, this mixed-precision approach results in poor hardware efficiency. That is why AWQ uses a different method to achieve the same goal.

First, AWQ identifies the most important weights, which are usually just 0.1% to 1% of the total weights. Then, AWQ applies per-channel scaling with scaling factors that protect these important weights before converting all the weights to 4-bit values. This reduces the error introduced by quantization for the important weights, helping the model remain accurate despite its smaller size [1].

## **Quantizing an LLM With AWQ In Python**

First, we install the latest `transformers` and `datasets` libraries:

```python pip install -U transformers datasets ```

Then, I installed the `llm-compressor` library directly from GitHub (I faced a bug with the current v0.5.1 release):

```python pip install -U git+https://github.com/vllm-project/llm-compressor.git ```

Now, we can load all the libraries and begin by instantiating the model and tokenizer:

```python import torchfrom datasets import load_datasetfrom transformers import AutoModelForCausalLM, AutoTokenizerfrom llmcompressor import oneshotfrom llmcompressor.modifiers.awq import AWQModifierdevice = torch.device("cuda" if torch.cuda.is_available() else "cpu")print(f"found device: {device}")# Select model and load it.MODEL_ID = "Qwen/Qwen3-0.6B"model = AutoModelForCausalLM.from_pretrained( MODEL_ID, device_map="auto", torch_dtype="auto")tokenizer = AutoTokenizer.from_pretrained(MODEL_ID, trust_remote_code=True) ```

Before quantizing, let’s inspect the model. AWQ will convert all the `Linear` weight layers to INT4. The `lm_head` is excluded for better performance:

``` Qwen3ForCausalLM( (model): Qwen3Model( (embed_tokens): Embedding(151936, 1024) (layers): ModuleList( (0-27): 28 x Qwen3DecoderLayer( (self_attn): Qwen3Attention( (q_proj): Linear(in_features=1024, out_features=2048, bias=False) (k_proj): Linear(in_features=1024, out_features=1024, bias=False) (v_proj): Linear(in_features=1024, out_features=1024, bias=False) (o_proj): Linear(in_features=2048, out_features=1024, bias=False) (q_norm): Qwen3RMSNorm((128,), eps=1e-06) (k_norm): Qwen3RMSNorm((128,), eps=1e-06) ) (mlp): Qwen3MLP( (gate_proj): Linear(in_features=1024, out_features=3072, bias=False) (up_proj): Linear(in_features=1024, out_features=3072, bias=False) (down_proj): Linear(in_features=3072, out_features=1024, bias=False) (act_fn): SiLU() ) (input_layernorm): Qwen3RMSNorm((1024,), eps=1e-06) (post_attention_layernorm): Qwen3RMSNorm((1024,), eps=1e-06) ) ) (norm): Qwen3RMSNorm((1024,), eps=1e-06) (rotary_emb): Qwen3RotaryEmbedding() ) (lm_head): Linear(in_features=1024, out_features=151936, bias=False)) ```

We can also print the model’s size in MB:

```python def print_model_size(model): total_bytes = 0 for p in model.parameters(): total_bytes += p.numel() * p.element_size() print(f"Model size: {total_bytes / (1000 ** 2):.2f} MB")print_model_size(model)>> Model size: 1192.10 MB ```

The original model uses 16-bit bfloat16 and is at 1.2 GB.

Now, let’s reduce that model size with AWQ quantization.

### AWQ Quantization

The following script uses a very small subset of the “The Pile” dataset, which was also used in the AWQ paper, as the calibration dataset. This dataset is used to identify the largest activations and select the most important weights to protect.

Then, the `oneshot` function will actually run the AWQ quantization.

```python # Select calibration dataset (The Pile)DATASET_ID = "ola13/small-the_pile"DATASET_SPLIT = "train"# Increasing the number of calib samples to 256 or higher can improve accuracy.NUM_CALIBRATION_SAMPLES = 64 MAX_SEQUENCE_LENGTH = 512# Load dataset and preprocess.ds = load_dataset(DATASET_ID, split=f"{DATASET_SPLIT}[:{NUM_CALIBRATION_SAMPLES}]")ds = ds.shuffle(seed=42)print(f"Dataset size: {len(ds)} samples")def preprocess(example): return { "text": tokenizer.apply_chat_template( [{"role": "user", "content": example["text"]}], tokenize=False, ) }ds = ds.map(preprocess)# Tokenize inputs.def tokenize(sample): return tokenizer( sample["text"], padding=False, max_length=MAX_SEQUENCE_LENGTH, truncation=True, add_special_tokens=False, )# Configure the AWQ quantization algorithm to runrecipe = [ AWQModifier(ignore=["lm_head"], scheme="W4A16_ASYM", targets=["Linear"]),]# Run quantization algorithmoneshot( model=model, dataset=ds, recipe=recipe, max_seq_length=MAX_SEQUENCE_LENGTH, num_calibration_samples=NUM_CALIBRATION_SAMPLES,) ```

Running the AWQ quantization might take a while. When it’s done, we save the new model to disk:

``` # Save to disk compressed.SAVE_DIR = "./" + MODEL_ID.split("/")[-1] + "-awq-asym"model.save_pretrained(SAVE_DIR, save_compressed=True)tokenizer.save_pretrained(SAVE_DIR) ```

And now we can check the new model’s size:

``` print_model_size(model)>> Model size: 540.10 MB ```

The model’s size was reduced from 1.2 GB to 540 MB!

If we print the new model, we can see that the `Linear` layers have been converted to `CompressedLinear` layers:

``` Qwen3ForCausalLM( (model): Qwen3Model( (embed_tokens): Embedding(151936, 1024) (layers): ModuleList( (0-27): 28 x Qwen3DecoderLayer( (self_attn): Qwen3Attention( (q_proj): CompressedLinear(in_features=1024, out_features=2048, bias=False) (k_proj): CompressedLinear(in_features=1024, out_features=1024, bias=False) (v_proj): CompressedLinear(in_features=1024, out_features=1024, bias=False) (o_proj): CompressedLinear(in_features=2048, out_features=1024, bias=False) (q_norm): Qwen3RMSNorm((128,), eps=1e-06) (k_norm): Qwen3RMSNorm((128,), eps=1e-06) ) (mlp): Qwen3MLP( (gate_proj): CompressedLinear(in_features=1024, out_features=3072, bias=False) (up_proj): CompressedLinear(in_features=1024, out_features=3072, bias=False) (down_proj): CompressedLinear(in_features=3072, out_features=1024, bias=False) (act_fn): SiLU() ) (input_layernorm): Qwen3RMSNorm((1024,), eps=1e-06) (post_attention_layernorm): Qwen3RMSNorm((1024,), eps=1e-06) ) ) (norm): Qwen3RMSNorm((1024,), eps=1e-06) (rotary_emb): Qwen3RotaryEmbedding() ) (lm_head): Linear(in_features=1024, out_features=151936, bias=False)) ```

This is according to the AWQModifier recipe variable that we defined earlier.

Currently, the LLM compressor includes AWQ mappings for the following architectures out-of-the-box:

* LlamaForCausalLM
* MistralForCausalLM
* Phi3ForCausalLM
* Phi3VForCausalLM
* Qwen2ForCausalLM
* Qwen2MoeForCausalLM
* Qwen3ForCausalLM
* Qwen3MoeForCausalLM

For other models, we would need to manually add AWQ mappings to indicate which layer names we want to convert to INT4 [2].

We can now use the quantized model with the vLLM inference engine, for example.

### Compression Rate

After AWQ quantization, the model was “only” 2.2 times smaller than the original. This is primarily because I started with a tiny 0.6B model.

AWQ targets the linear weight matrices inside the transformer block. For very large models, we can expect a maximum compression rate of just under 4x when converting from 16-bit floating-point to 4-bit integer.

However, for very small models, `embed_tokens` and `lm_head` comprise a larger portion of the overall parameter count, so AWQ is not the most efficient quantization method for these tiny models.

## Conclusion

AWQ is a smart quantization algorithm that targets linear weight matrices within transformer LLMs.

Using a small calibration dataset, AWQ identifies the most important weights and protects them before quantizing down to four bits.

We used the `llm-compressor` library to perform AWQ quantization on the tiny Qwen3–0.6B model. The compression rate achieved was 2.2x, but larger models should approach almost 4x.
