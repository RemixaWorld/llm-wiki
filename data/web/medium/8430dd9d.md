## Dify

[Dify](<https://github.com/langgenius/dify>) is a popular open-source LLM app development platform. Its intuitive interface combines AI workflows, RAG pipeline, agent capabilities, model management, observability features, and more. RAG pipeline is a fundamental module within Dify, as shown in Figure 1.

Press enter or click to view image in full size

Figure 1: Dify Beehive Architecture. Source: [Dify’s blog](<https://dify.ai/blog/dify-rolls-out-new-architecture>).

In Dify, file loading and parsing are implemented in the [class ExtractProcessor](<https://github.com/langgenius/dify/blob/0.9.1/api/core/rag/extractor/extract_processor.py#L40>). We focus particularly on the most complex PDF files among all file formats, which are handled in the [class PdfExtractor](<https://github.com/langgenius/dify/blob/0.9.1/api/core/rag/extractor/pdf_extractor.py#L12>), using [pypdfium2 library](<https://pypi.org/project/pypdfium2/>) for parsing.

```python def parse(self, blob: Blob) -> Iterator[Document]: """Lazily parse the blob.""" import pypdfium2 with blob.as_bytes_io() as file_path: pdf_reader = pypdfium2.PdfDocument(file_path, autoclose=True) try: for page_number, page in enumerate(pdf_reader): text_page = page.get_textpage() content = text_page.get_text_range() text_page.close() page.close() metadata = {"source": blob.source, "page": page_number} yield Document(page_content=content, metadata=metadata) finally: pdf_reader.close() ```

Additionally, Dify offers features to clean up content parsed from files by removing superfluous characters, correcting encoding errors, and more. These strategies are based on [unstructured cleaning](<https://github.com/langgenius/dify/tree/0.9.1/api/core/rag/cleaner/unstructured>). Dify encapsulates various cleaning strategies into interfaces, simplifying the selection process for the application layer.

### PDF Parser Server

The above code initially uses the [get_pdf_result_sync function](<https://github.com/netease-youdao/QAnything/blob/v2.0.0/qanything_kernel/core/retriever/general_document.py#L46>) to convert PDFs into Markdown format text. It utilizes a custom-built PDF parser server.

```python def get_pdf_result_sync(file_path): try: data = { 'filename': file_path, 'save_dir': os.path.dirname(file_path) } headers = {"content-type": "application/json"} response = requests.post(f"http://{LOCAL_PDF_PARSER_SERVICE_URL}/pdfparser", json=data, headers=headers, timeout=240) response.raise_for_status() response_json = response.json() markdown_file = response_json.get('markdown_file') return markdown_file except Exception as e: insert_logger.warning(f"pdf parser error: {traceback.format_exc()}") return None ```

```python @app.post("/pdfparser")async def pdf_parser(request: Request): filename = safe_get(request, 'filename') save_dir = safe_get(request, 'save_dir') pdf_parser_: PdfLoader = request.app.ctx.pdf_parser markdown_file = pdf_parser_.load_to_markdown(filename, save_dir) return json({"markdown_file": markdown_file})if __name__ == '__main__': app.run(host="0.0.0.0", port=9009, workers=args.workers) ```

### Two Branches

Subsequently, the process of PDF parsing mainly involves two branches:

1. If the Markdown format file (`markdown_file`) is successfully obtained, the code then proceeds to process this Markdown.
2. If there are issues during the conversion from PDF to Markdown (i.e., if `markdown_file` is empty), the code uses [class UnstructuredPaddlePDFLoader](<https://github.com/netease-youdao/QAnything/blob/v2.0.0/qanything_kernel/utils/loader/pdf_loader.py#L12>) to handle the PDF files.

The [UnstructuredPaddlePDFLoader](<https://github.com/netease-youdao/QAnything/blob/v2.0.0/qanything_kernel/utils/loader/pdf_loader.py#L12>) operates in 'fast' mode, utilizing the [PyMuPDF](<https://github.com/pymupdf/PyMuPDF>) and [unstructured](<https://pub.towardsai.net/advanced-rag-02-unveiling-pdf-parsing-b84ae866344e>) frameworks, but it does not perform OCR. This approach offers faster but potentially less accurate PDF parsing.

## Cognita

[Cognita](<https://github.com/truefoundry/cognita>) is a RAG framework designed for building modular, open-source applications for production. Its architecture is illustrated in Figure 7.

Press enter or click to view image in full size

Figure 7: The architecture of Cognita. Source: [Cognita](<https://github.com/truefoundry/cognita>).

We focus on its parser component. Cognita offers two methods for parsing PDF files.

* [class UnstructuredIoParser](<https://github.com/truefoundry/cognita/blob/60b5533768b3c302ded53d9ff242590c79e8471b/backend/modules/parsers/unstructured_io.py#L10>): Standard file types such as PDF, TXT, PNG, DOCX, and PPTX are parsed using APIs provided by Unstructured.
* [class MultiModalParser](<https://github.com/truefoundry/cognita/blob/60b5533768b3c302ded53d9ff242590c79e8471b/backend/modules/parsers/multimodalparser.py#L22>): For PDF files, it converts each page into an image and then transforms these images into base64 encoding. For each converted image, the parser sends the base64 encoded image along with a prompt to the configured LLM (such as GPT-4o-mini) for asynchronous data analysis based on the image content. The prompt is shown below.

```python class MultiModalParser(BaseParser): """ MultiModalParser is a multi-modal parser class for deep extraction of pdf documents. Your task is to analyze the image and provide insights based on the data it represents.Specifically, the information should include but not limited to:Title of the Image: Provide a title from the charts or image if any.Type of Chart: Determine the type of each chart (e.g., bar chart, line chart, pie chart, scatter plot, etc.) and its key features (e.g., labels, legends, data points).Data Trends: Describe any notable trends or patterns visible in the data. Highlight similarities, differences, or correlations between datasets.Conclude with a summary of the key findings from your analysis and any recommendations based on those findings.""" super().__init__(**kwargs) ... ... ```

## Kotaemon

[Kotaemon](<https://medium.com/ai-advances/kotaemon-unveiled-innovations-in-rag-framework-for-document-qa-0b6d67e4b9b7>) is an open-source clean & customizable RAG UI for chatting with your documents. Built with both end users and developers in mind.

Figure 8: A visualization of kotaemon. Source: [kotaemon](<https://github.com/Cinnamon/kotaemon/>)

When a PDF file is uploaded, the [load_data function](<https://github.com/Cinnamon/kotaemon/blob/cd85c4935c85afdd18416fd902e09c4a8b997d86/libs/kotaemon/kotaemon/loaders/pdf_loader.py#L65>) within the [class PDFThumbnailReader](<https://github.com/Cinnamon/kotaemon/blob/cd85c4935c85afdd18416fd902e09c4a8b997d86/libs/kotaemon/kotaemon/loaders/pdf_loader.py#L56>) is triggered. The main steps are as follows:

1. **Load PDF File** : PDF text extraction is carried out through the [load_data](<https://github.com/run-llama/llama_index/blob/v0.10.68/llama-index-integrations/readers/llama-index-readers-file/llama_index/readers/file/docs/base.py#L39>) function in [llama_index.readers.file.PDFReader](<https://github.com/run-llama/llama_index/blob/v0.10.68/llama-index-integrations/readers/llama-index-readers-file/llama_index/readers/file/docs/base.py#L27>). As noted in [my previous article](<https://pub.towardsai.net/advanced-rag-02-unveiling-pdf-parsing-b84ae866344e>), llama_index relies on [pypdf](<https://pypi.org/project/pypdf/>) for this task.
2. **Generate Thumbnails** : For each page, a thumbnail image is created using the [get_page_thumbnails](<https://github.com/Cinnamon/kotaemon/blob/cd85c4935c85afdd18416fd902e09c4a8b997d86/libs/kotaemon/kotaemon/loaders/pdf_loader.py#L13>) function, which utilizes [PyMuPDF (fitz)](<https://github.com/pymupdf/PyMuPDF>).
3. **Store Data** : The extracted text, generated thumbnails, and any relevant metadata (e.g., page numbers, sizes) are stored in a Python list called `documents`.
4. **Return the Data** : Finally, the `documents` list is returned.

### Insights

By analyzing industrial solutions, I have gained the following insights:

* **Balancing Performance and Speed:** RAGFlow excels in PDF parsing by leveraging a deep and comprehensive pipeline, achieving unrivaled performance in this domain. However, this high level of capability comes at the cost of slower parsing speeds. Additionally, the dual parsing modes in QAnything reflect the industry’s efforts to effectively meet varied business requirements. Developers can adjust the parsing mode to meet the specific demands of different business cases, optimizing either speed or precision as needed.
* [**Unstructured framework**](<https://pub.towardsai.net/advanced-rag-02-unveiling-pdf-parsing-b84ae866344e>): This framework has a wide range of applications, making it an important tool for PDF parsing.
* **User-Friendly Interface Design** : Kotaemon’s simplified interface and direct document interaction streamline complex parsing operations into a format that is easy to understand and use. This design offers a strong example of how to create high-availability user interfaces that maintain functionality without overwhelming the user.
* **Data Security and Privacy Requirements:** In the field of document parsing, particularly in industries involving sensitive data such as healthcare and finance, data security and privacy protection are crucial factors in the design of parsing tools. In the future, these tools could further integrate features like data encryption and access control to ensure compliance with privacy regulations when handling sensitive files**.**

Overall, the unique strengths of each method highlight ongoing innovation in document intelligence and PDF parsing. However, the choice of our specific approach depends heavily on the specific requirements of the situation.
