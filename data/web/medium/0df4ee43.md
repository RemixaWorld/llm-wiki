The world of information retrieval is constantly evolving, and a new paper called “ColPali: Efficient Document Retrieval with Vision Language Models” proposes a revolutionary approach that could redefine how we search for information in large document sets.

_This blog post explores the ColPali approach, highlighting its advantages, comparing it to existing methods, and delving into its technical details._

## The Challenges of Traditional RAG Systems

Retrieval Augmented Generation (RAG) systems, which combine information retrieval with language models for question answering, face several challenges:

* PDF Parsing: Extracting meaningful information from PDF files is a complex task, often requiring multiple steps like Optical Character Recognition (OCR), layout detection, and chunking.
* Limited Explainability: Existing embedding-based retrieval methods struggle to provide insights into why a particular document is retrieved, hindering user understanding and trust.
* Performance vs. Keyword-based Approaches: Keyword-based retrieval methods like BM25 can surprisingly perform as well as or even better than embedding-based methods for certain applications, highlighting the limitations of current embedding approaches.

## ColPali: A Vision-Based Solution

ColPali presents a novel solution that addresses these challenges by leveraging the power of vision language models. Instead of relying solely on text, ColPali directly processes images of PDF pages, allowing it to capture both textual and visual content.

![image](https://miro.medium.com/v2/resize:fit:700/1*nIseRHXaBzqpYW-ZmBzMpQ.png)

Here’s how ColPali works:

1\. Image Processing and Patch Embeddings:

* Each PDF page is converted into an image and divided into a grid of small patches (32x32 for ColPali).
* Each patch is then embedded into a higher-dimensional vector space using a linear projection, capturing initial visual features.
* These patch embeddings are further processed by a Vision Transformer, applying self-attention mechanisms to capture the relationships between different patches within the image.

2\. Vision-Language Fusion:

* The output from the Vision Transformer is fed into a vision language model like PolyGamma, which further processes the visual information and potentially aligns it with textual representations. This allows ColPali to understand the context of visual elements like plots, images, and tables without the need for separate parsers.

3\. Multi-Vector Representation and Retrieval:

* The output from the vision language model is projected into a lower-dimensional vector space, resulting in a multi-vector representation of each page (1024 patches x 128 dimensions each).
* Retrieval is performed by comparing query embeddings with the multi-vector representation of each page. The approach utilizes a similarity matrix and max pooling, similar to how Colbert works, to identify the most relevant pages.

## ColPali’s Advantages:

* Improved Retrieval Accuracy: ColPali significantly outperforms existing methods, including keyword-based approaches, text-based embeddings, and other vision-based retrieval methods.
* Efficient Indexing: ColPali’s indexing process, which involves creating the multi-vector representation, is remarkably efficient, taking only 0.4 seconds per page, compared to traditional methods that can take 7.22 seconds per page.
* Explainability: Since ColPali leverages a vision transformer, it can provide insights into which specific patches are most relevant to a given query, offering greater transparency and explainability.

**Usage**

```python import torchimport typerfrom torch.utils.data import DataLoaderfrom tqdm import tqdmfrom transformers import AutoProcessorfrom PIL import Imagefrom colpali_engine.models.paligemma_colbert_architecture import ColPalifrom colpali_engine.trainer.retrieval_evaluator import CustomEvaluatorfrom colpali_engine.utils.colpali_processing_utils import process_images, process_queriesfrom colpali_engine.utils.image_from_page_utils import load_from_datasetdef main() -> None: """Example script to run inference with ColPali""" # Load model model_name = "vidore/colpali" model = ColPali.from_pretrained("google/paligemma-3b-mix-448", torch_dtype=torch.bfloat16, device_map="cuda").eval() model.load_adapter(model_name) processor = AutoProcessor.from_pretrained(model_name) # select images -> load_from_pdf(<pdf_path>), load_from_image_urls(["<url_1>"]), load_from_dataset(<path>) images = load_from_dataset("vidore/docvqa_test_subsampled") queries = ["From which university does James V. Fiorca come ?", "Who is the japanese prime minister?"] # run inference - docs dataloader = DataLoader( images, batch_size=4, shuffle=False, collate_fn=lambda x: process_images(processor, x), ) ds = [] for batch_doc in tqdm(dataloader): with torch.no_grad(): batch_doc = {k: v.to(model.device) for k, v in batch_doc.items()} embeddings_doc = model(**batch_doc) ds.extend(list(torch.unbind(embeddings_doc.to("cpu")))) # run inference - queries dataloader = DataLoader( queries, batch_size=4, shuffle=False, collate_fn=lambda x: process_queries(processor, x, Image.new("RGB", (448, 448), (255, 255, 255))), ) qs = [] for batch_query in dataloader: with torch.no_grad(): batch_query = {k: v.to(model.device) for k, v in batch_query.items()} embeddings_query = model(**batch_query) qs.extend(list(torch.unbind(embeddings_query.to("cpu")))) # run evaluation retriever_evaluator = CustomEvaluator(is_multi_vector=True) scores = retriever_evaluator.evaluate(qs, ds) print(scores.argmax(axis=1))if __name__ == "__main__": typer.run(main) ```
