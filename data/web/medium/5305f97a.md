### **The origins of SAM**

LLMs pre-trained on a large corpus of text can generalize very well. That is, if you give tasks like text classification, sentimental analysis, etc… it can do them pretty well without the need for fine-tuning or training the model further via prompt engineering.

They want SAM to do the same thing but in the field of image segmentation i.e., they want their model to be able to generalize well for other relevant tasks. If you wonder what tasks comprise/correlate the image segmentation here are some of them.

Object Detection, Edge Detection, Instance Segmentation, Interactive Segmentation, etc…

So, What can SAM do?

Given a prompt and an image, SAM can identify the corresponding **valid object** present in the image and segment it even if the prompt is ambiguous. It can also identify and mask all the **valid objects** present in an image (See Figure 1 again).

You might wonder what exactly is “prompt” here. Typically one would think it is a text prompt. If you thought the same you were wrong. The “prompt” mentioned here is more than that.

**Prompt types**

You can provide prompts in the form of points and boxes:

* **Point prompt** : You select a point on the image, and SAM returns a segment around that point.

## **Feature Pipeline**

What is the data required to train this model? Let’s look at what one data sample comprises that is used to train SAM.

One data sample contains an image and a JSON file that stores the metadata of that image.

Let’s sneak a peek into what the JSON file consists of.

### Image Metadata:

```json "image": {"image_id": 223750,"width": 2254,"height": 1500,"file_name": "sa_223750.jpg"} ```

This describes the basic properties of the image — its unique ID, dimensions, and filename. There are also other properties along with this.

1. Annotations: Each image comes with multiple annotation objects in an array. Each annotation contains:

* `bbox`: _[x, y, width, height_] defining a bounding box
* `area`: number of pixels in the segmentation mask
* `segmentation`: Contains:
`size`: _[height, width]_ of the mask
`counts`: Run-length encoded (RLE) format of the binary mask
* `predicted_iou`: Model’s predicted Intersection over Union score (confidence)
* `point_coords`: Coordinates of the point prompt used to generate this mask
* `crop_box`: _[x, y, width, height]_ of the region used to process this segment
* `id`: Unique identifier for this specific mask
* `stability_score`: Score indicating mask prediction stability

You store a bunch of these (probably in millions) in your feature store and feed them to the model in batches.

## **Training Pipeline**

Remember the training objective of SAM? Given a prompt and an image, the model should be able to produce a valid segmentation mask even if the prompt is ambiguous.

To make this possible the model architecture is divided into three main components.

1. **Image Encoder:** Given an image this image encoder produces the corresponding embedding vector (image embeddings)
2. **Prompt Encoder:** Given any kind of prompt (point, or box) it produces the corresponding embedding vector (prompt embeddings).
3. **Mask Decoder:** Given prompt embeddings and image embedding as inputs it can output mask/s along with the respective IoU score.

### Image Encoder

SAM Image Encoder’s Input and Output ```python import torch# Create a sample image: batch_size=1, channels=3 (RGB), height=1024, width=1024image = torch.randn(1, 3, 1024, 1024)print(f"Input image shape: {image.shape}") # [1, 3, 1024, 1024]# Initialize the Image Encoder with default parametersencoder = ImageEncoderViT( img_size=1024, # Input image size patch_size=16, # Size of each patch in_chans=3, # RGB input embed_dim=768, # Embedding dimension depth=12, # Number of transformer blocks out_chans=256, # Output channels)# Step 1: Patch Embedding# The image is divided into patches of 16x16 and embeddedx = encoder.patch_embed(image)# New shape: [1, 64, 64, 768]# - 64 = 1024/16 (spatial dims divided by patch_size)# - 768 is the embedding dimensionprint(f"After patch embedding: {x.shape}")# Step 2: Add positional embeddingsif encoder.pos_embed is not None: x = x + encoder.pos_embed # Shape remains [1, 64, 64, 768]print(f"After position embedding: {x.shape}")# Step 3: Pass through transformer blocksfor block in encoder.blocks: # Each block contains self-attention and MLP # Shape remains constant through blocks: [1, 64, 64, 768] x = block(x)print(f"After transformer blocks: {x.shape}")# Step 4: Final neck processing# First permute to [1, 768, 64, 64]x = x.permute(0, 3, 1, 2)# Pass through neck (two conv layers with layer norm)x = encoder.neck(x)# Final output shape: [1, 256, 64, 64]print(f"Final output shape: {x.shape}")"""Shape transformation summary:1. Input: [1, 3, 1024, 1024] # Original image2. Patch Embedding: [1, 64, 64, 768] # Patched and embedded3. Transformer: [1, 64, 64, 768] # Through all blocks4. Output: [1, 256, 64, 64] # Final feature map""" ```

This script shows how a single image of size 1024x1024 is processed through the `ImageEncoderViT`. Here’s what happens at each step:

1. The input image (1024x1024) is divided into 16x16 patches, resulting in a 64x64 grid of patches (spatial compression).
2. Each patch is embedded into a 768-dimensional vector (channel expansion)
3. The embedded patches maintain their spatial relationship (64x64 grid) through the transformer blocks
4. Finally, the _neck module_ converts the 768-channel features to 256-channel features while maintaining the spatial dimensions (channel compression).

Now you know how the input image is processed and how it is transformed to the resultant vector shape `[256, 64, 64]`. Essentially we reduced the image size and increased the number of channels for computing efficiency while preserving the details for the model to learn from.

**Point Prompt
** How is a point represented in numbers in this scenario?

``` # 1. Initial Point Inputpoint_coord = torch.tensor([[[500, 300]]]) # [1, 1, 2] - (x, y) coordinatespoint_label = torch.tensor([[1]]) # [1, 1] - 1 for positive, 0 for negativeprint(f"Raw point coordinate: {point_coord}") # A point at (500, 300) ```

A point is represented using x and y coordinates and a label that indicates whether it is a foreground or background point.

Now how is this input transformed?
1\. The `point_coord` which is of shape `[1, 2]` is transformed into a vector of shape `[2, 256]` using **positional encoding**(simple explanation below).
2\. The `point_label` of vector shape `[1]` is transformed into a vector of shape `[256]` and this is a `learned embedding` i.e., the 256 values are altered during training.

So What do positional encoding and learned embedding mean in this scenario?

Our aim is to process input into vectors that neural networks can understand. Positional encoding makes the model understand where the point is located spatially and learned embedding represents what the point means.

``` # 2. Coordinate Normalization# Points are normalized to [0,1] range by dividing by image dimensionsnormalized_coord = point_coord.clone()normalized_coord[..., 0] = point_coord[..., 0] / 1024 # x coord / widthnormalized_coord[..., 1] = point_coord[..., 1] / 1024 # y coord / heightprint(f"Normalized coordinate: {normalized_coord}") # Approximately [0.49, 0.29]# 3. Positional Encoding# The normalized coordinates are transformed using the gaussian matrix# This creates a higher dimensional representation using sine and cosinepe_layer = PositionEmbeddingRandom(num_pos_feats=128) # 128 features = 256/2pos_encoding = pe_layer._pe_encoding(normalized_coord)print(f"Position encoding shape: {pos_encoding.shape}") # [1, 1, 256]# The 256 comes from concatenating sin and cos of 128 frequency components# 4. Final Point Embedding# The positional encoding is combined with a learned embedding # based on whether it's a positive or negative pointpoint_embedding = pos_encoding.clone()if point_label[0, 0] == 1: point_embedding += prompt_encoder.point_embeddings[0].weight # positive point embeddingelse: point_embedding += prompt_encoder.point_embeddings[1].weight # negative point embeddingprint(f"Final point embedding shape: {point_embedding.shape}") # [1, 1, 256] ```

The final representation of the point is the combined result of `positional encoding` and `learned embedding` as you can observe from the script.

It’s like saying: “This is a point at coordinates (500,300) AND it’s a positive point” but represented in a way that’s useful for the neural network to process.

**Box Prompt**

``` # 1. Initial Box Input# Box format: [x1, y1, x2, y2] where (x1,y1) is top-left, (x2,y2) is bottom-rightbox = torch.tensor([[[200, 300, 400, 500]]]) # [1, 1, 4]print(f"Raw box coordinates: {box}") # Box from (200,300) to (400,500)# 2. Reshape to corners# Convert [x1,y1,x2,y2] format to two corners [[x1,y1], [x2,y2]]corners = box.reshape(-1, 2, 2) # [1, 2, 2]print(f"Reshaped corners: {corners}") # [[200,300], [400,500]]# 3. Add 0.5 to center in pixelscorners = corners + 0.5print(f"Centered corners: {corners}") # [[200.5,300.5], [400.5,500.5]]# 4. Normalize coordinates to [0,1]image_size = (1024, 1024) # (H, W)normalized_corners = corners.clone()normalized_corners[..., 0] = corners[..., 0] / image_size[1] # x coords / widthnormalized_corners[..., 1] = corners[..., 1] / image_size[0] # y coords / heightprint(f"Normalized corners: {normalized_corners}") # Approximately [[0.196,0.293], [0.391,0.489]]# 5. Positional Encodingpe_layer = PositionEmbeddingRandom(num_pos_feats=128) # 128*2=256 featurescorner_encoding = pe_layer._pe_encoding(normalized_corners)print(f"Position encoding shape: {corner_encoding.shape}") # [1, 2, 256]# 6. Final Box Embedding# Each corner gets a different learned embedding added to itcorner_embedding = corner_encoding.clone()corner_embedding[:, 0, :] += prompt_encoder.point_embeddings[2].weight # first cornercorner_embedding[:, 1, :] += prompt_encoder.point_embeddings[3].weight # second cornerprint(f"Final box embedding shape: {corner_embedding.shape}") # [1, 2, 256] ```

So a box transforms as follows:
1\. Raw input: [200, 300, 400, 500] — four numbers defining box extent
2\. Reshaped: Two corners [[200,300], [400,500]] (top-left and bottom-right corners)
3\. Centered: Add 0.5 to each coordinate
4\. Normalized: Convert to [0,1] range by dividing by image dimensions
5\. Position encoded: Each corner becomes a 256-dimensional vector
6\. Final embedding: Add learned embeddings to distinguish corners

The final representation consists of:
\- Two 256-dimensional vectors (one for each corner) (Did you observe? Box uses two 256-D vectors (two corners) vs one for points)
\- Each vector encodes:
* Spatial information (where the corner is) from positional encoding
* Corner-type information (which corner it is) from learned embeddings

In simple words, the information about the two corners (top-left and bottom-right) is represented using the sum of its positional encoding (where the corner is) and learned embeddings (which corner it is) respectively.

**Mask Prompt**

``` # 1. Initial Mask Input# Binary mask: 1 for foreground, 0 for backgroundmask = torch.zeros((1, 1, 256, 256)) # [1, 1, 256, 256]mask[0, 0, 100:150, 100:150] = 1 # Example: square maskprint(f"Input mask shape: {mask.shape}") # [1, 1, 256, 256]# 2. Mask Downscaling through Conv Layers# The mask goes through 3 convolutional layers:# First conv + norm + activation# Conv2d: in_channels=1, out_channels=4 (mask_in_chans//4), kernel=2, stride=2conv1 = nn.Conv2d(1, 4, kernel_size=2, stride=2)x = conv1(mask)print(f"After first conv: {x.shape}") # [1, 4, 128, 128]# Spatial size halved, channels increased to 4# Second conv + norm + activation# Conv2d: in_channels=4, out_channels=16 (mask_in_chans), kernel=2, stride=2conv2 = nn.Conv2d(4, 16, kernel_size=2, stride=2)x = conv2(x)print(f"After second conv: {x.shape}") # [1, 16, 64, 64]# Spatial size halved again, channels increased to 16# Final 1x1 conv to get to embedding dimension# Conv2d: in_channels=16, out_channels=256 (embed_dim), kernel=1conv3 = nn.Conv2d(16, 256, kernel_size=1)mask_embedding = conv3(x)print(f"Final mask embedding: {mask_embedding.shape}") # [1, 256, 64, 64] ```

It’s quite obvious we need to keep the mask embedding shape the same as the encoded input image’s shape from the image encoder (see the architecture figure once again). You can imagine the mask as a white cutout on a black background.

It passes through three convolutional layers producing a vector of shape `[256, 64, 64]` matching the `image embedding` (image encoder’s output). _Did you observe? No positional encoding is needed in this case as the spatial information is preserved in the grid._

**Explanation**

1. **Inputs to MaskDecoder** :

* `image_embeddings`: [1, 256, 64, 64] - Image features from the encoder
* `sparse_prompt_embeddings`: [1, 2, 256] - Point/box prompts
* `dense_prompt_embeddings`: [1, 256, 64, 64] - Mask prompts

**2\. Step-by-Step Process** :

* Step 1: Create output tokens [5, 256] (1 IoU token + 4 mask tokens)
* Step 2: Combine with prompt embeddings [1, 7, 256]

_Why are these five extra tokens (each token is of [1, 256]) added to the prompt embeddings?_

`IoU Token`: This is for getting the IoU score for the predicted at the transformer’s output.

`3 tokens for ambiguous cases`: When the prompt given by you might contain multiple valid masks i.e., 3 masks are produced. These masks [3, 256] are reshaped to match the image’s shape and are overlayed onto them.

_Why just 3 why not any other number?
When you click on a point in an image, there are typically up to 3 valid “levels” of objects:
Level 1: The entire object (e.g., a whole person)
Level 2: A major part (e.g., the torso)
Level 3: A specific subpart (e.g., the shirt)_

`1 token for ambiguous cases`: If the prompt given by you contains only one valid mask this gets triggered and projected onto the image.

* Step 3: Process through transformer:
Output tokens: [1, 7, 256]
Image features: [1, 256, 64, 64]
* Step 4: Extract IoU [1, 256] and mask tokens [1, 4, 256]
* Step 5: Upscale image embeddings to [1, 32, 256, 256]
* Step 6: Generate outputs

**Final Outputs** :

* Masks: [1, 3, 256, 256] — Three predicted masks (for ambiguous cases)
* IoU Predictions: [1, 3] — Quality score for each mask

Now you know what goes into the mask decoder and what comes out of it.

### **Training Process of One Data Sample**

Let’s finish the training pipeline by understanding how the model is trained using one data sample.

```python import torchimport torch.nn as nnimport numpy as npfrom typing import Tuple, Listclass SAMTrainer: def __init__(self): # Initialize models self.image_encoder = None # MAE pretrained ViT-H self.prompt_encoder = None # Encodes points, boxes, and masks self.mask_decoder = None # Predicts masks from embeddings # Training params self.num_iterations = 11 # Number of prompt iterations per mask self.num_mask_outputs = 3 # Number of masks for ambiguous prompts def train_step(self, image: torch.Tensor, # [1, 3, 1024, 1024] ground_truth: torch.Tensor, # [1, 1024, 1024] ) -> float: """Single training step for one image and one ground truth mask""" # 1. Encode image (done once per image) # Output: [1, 256, 64, 64] - (batch, embedding_dim, H/16, W/16) image_embedding = self.image_encoder(image) # Current prediction starts as None current_mask = None total_loss = 0.0 # 2. Iterate through prompt rounds (11 rounds total) for prompt_idx in range(self.num_iterations): # 3. Generate prompt for this iteration if prompt_idx == 0: # First prompt: random box or point with 50% probability prompt = self.generate_first_prompt(ground_truth) # Box: [1, 2, 2] (batch, top_left/bottom_right, xy) # Point: [1, 1, 2] (batch, num_points, xy) else: # Subsequent prompts: sample points from error regions prompt = self.sample_points_from_error( current_mask, # [1, 1024, 1024] ground_truth # [1, 1024, 1024] ) # [1, 1, 2] (batch, num_points, xy) # 4. Encode prompt # Output: [1, num_prompts, 256] (batch, num_prompts, embedding_dim) prompt_embedding = self.prompt_encoder(prompt) if current_mask is not None: # Also encode previous mask prediction as additional prompt # Output: [1, 256, 64, 64] (same as image embedding) mask_embedding = self.prompt_encoder.encode_mask(current_mask) image_embedding = image_embedding + mask_embedding # 5. Decode masks - returns multiple masks for ambiguous prompts # Output: [1, num_mask_outputs, 256, 256] (batch, num_masks, H/4, W/4) mask_predictions = self.mask_decoder( image_embedding, # [1, 256, 64, 64] prompt_embedding, # [1, num_prompts, 256] ) # 6. Predict IoU scores for each mask # Output: [1, num_mask_outputs] (batch, num_masks) iou_predictions = self.mask_decoder.predict_iou( image_embedding, # [1, 256, 64, 64] prompt_embedding, # [1, num_prompts, 256] mask_predictions # [1, num_mask_outputs, 256, 256] ) # 7. Calculate losses # Compute loss for each predicted mask mask_losses = [] for i in range(self.num_mask_outputs): mask_loss = self.compute_mask_loss( mask_predictions[:, i], # [1, 256, 256] ground_truth # [1, 1024, 1024] ) mask_losses.append(mask_loss) # Only backpropagate through minimum loss prediction min_loss_idx = np.argmin(mask_losses) loss = mask_losses[min_loss_idx] # Add IoU prediction loss iou_loss = self.compute_iou_loss( iou_predictions, # [1, num_mask_outputs] ground_truth, # [1, 1024, 1024] mask_predictions # [1, num_mask_outputs, 256, 256] ) loss = loss + iou_loss total_loss += loss # Update current mask with highest confidence prediction current_mask = mask_predictions[ 0, # batch idx torch.argmax(iou_predictions) # mask with highest predicted IoU ] return total_loss / self.num_iterations def compute_mask_loss(self, pred_mask, gt_mask) -> float: """Combines focal loss and dice loss""" focal_loss = 20.0 * self.focal_loss(pred_mask, gt_mask) dice_loss = self.dice_loss(pred_mask, gt_mask) return focal_loss + dice_loss def compute_iou_loss(self, pred_ious, gt_mask, pred_masks) -> float: """Mean squared error between predicted and actual IoUs""" actual_ious = self.calculate_iou(pred_masks, gt_mask) return nn.MSELoss()(pred_ious, actual_ious) ```

Focus on the next few paragraphs carefully as they connect all the dots. You will know a lot of “why it is done the way it is”.

Initially, when they collected data to train this model the dataset contained an image and the corresponding masks (which can be visualized as a white cutout on a black background).

Here’s the training process of a single data sample.

1. Each training sample consists of an image (adjusted to 1024x1024) and a ground truth mask
2. Image Encoder (ViT) component produces image embedding (done once per image)
3. A foreground point is sampled from the ground truth mask region and a box is extracted from the same region. A prompt (box or point) is selected among them with 50% probability.
4. Our model trains on one data sample 11 times i.e., 11 prompt iterations per mask.
Round 1: A random box or point (50/50 probability) is fed and predictions are made.
In 8 other iterations, we feed **the point prompts** (foreground or background depends on false positives and false negatives) sampled from the error region the (mismatched region between the predicted mask and ground truth mask) and **predicted mask** as the mask input (both to the prompt encoder)
_Now you know that the mask prompt is included in the architecture so that we can have a feedback loop i.e., the model can learn and improve from its previous predictions._
5. In 2 other iterations, we feed no point prompts and only the predicted mask is fed as the prompt to the model. _Why? To make the model capable of predicting the masks intuitively even if there is no sparse prompt present._

Mask and points prompt act as the feedback loops during training

Key Tensor Shapes:

```yaml image: [1, 3, 1024, 1024] # Input imageimage_embedding: [1, 256, 64, 64] # Encoded imagepoint_prompt: [1, 1, 2] # Single point coordinatesbox_prompt: [1, 2, 2] # Box coordinatesprompt_embedding: [1, num_prompts, 256] # Encoded promptsmask_predictions: [1, 3, 256, 256] # 3 possible masksiou_predictions: [1, 3] # IoU score per mask ```

Loss Components:

* Mask Loss = 20 * Focal Loss + Dice Loss
* IoU Loss = MSE between predicted and actual IoUs
* Only backpropagates through the minimum loss among the 3 predicted masks

_The point is presenting the training pipeline in this way is to let you know why a particular design choice and algorithm is used. I hope it lets you use that knowledge when building similar models. The intention isn’t to walk you through the code._

You might wonder what happens inside the transformer. Here’s what happens. Essentially “image embedding” and “tokens” get to know each other through cross-attention in both ways. That’s why it is called a 2-way transformer.

If you’ve understood the training pipeline understanding the inference pipeline is icing on the cake.

1. You provide the model with a prompt and an image. Let’s assume you provided a point prompt.
2. Since there is no mask input and box input, the prompt embeddings contain only point embeddings.
3. These prompt embeddings along with image embeddings are fed to the mask decoder and the final mask/s are produced along with the IoU score.
Note that there is no 11-iteration sequence as in the training process.
4. The masks are transformed to the original shape of the input image and you see them overlayed over the image as you’ve seen in the [demo](<https://segment-anything.com/demo>).

### Summary

A foundational model has to satisfy two requirements:

1. It must be used useful for the downstream tasks.
2. It should also be used as an internal module or part of a system for building another deep-learning model.

In summary, SAM (Segment Anything Model) is a foundational model for the image segmentation task based on the transformers architecture. It is operated using three main components: image encoder that produces image embeddings, prompt encoder that produces prompt embeddings, and finally mask decoder which takes these embeddings as input and generates the masks.
