## 👀 Why Invoice Fraud Detection?

Imagine a company, big or small, drowning in hundreds of invoices each month 📑💼. Fraudsters know this and try to sneak in fake invoices or mess with real ones to get extra $$$. This is what we call **Invoice Fraud** — sneaky stuff like:

* **Duplicate Invoices** : Submitting the same invoice twice, hoping no one notices.
* **Altered Info** : Messing with details like the amount or vendor name.
* **Phishing** : Pretending to be someone they’re not, like a legit vendor.

Our mission is to build a nerd-powered system to spot these fake invoices before anyone pays up. 💰🛑

## 🔍 The Plan: How Our System Works

To catch the bad guys, we need a multi-step approach that will check an invoice and see if it’s hiding any suspicious clues. Here’s the high-level breakdown:

1. **Read the Invoice Image** : We’ll feed it a picture and process it.
2. **Analyze the Invoice Details** : Extract every bit of text and structure to see what’s there.
3. **Anomaly Detection** : Check if it looks odd compared to what we’ve seen before.
4. **Compare to Known Data** : Use historical and vendor data to make sure this isn’t a weird outlier.

Each step helps us build a case to detect fraud 🕵️‍♂️. Now let’s break it down further! 💡

## 📥 Step 1: Importing the Tools for the Job

Our toolkit includes some powerful libraries and APIs:

* **Transformers** (AutoProcessor, AutoModelForVisionText2Text): For analyzing the text in invoices. Think of this as our powerful **AI eyes** 👁️.
* **PIL (Python Imaging Library)** : To open and manage invoice images 📸.
* **Faiss** : This is our **data muscle** , a supercharged library for efficient similarity search, which helps us check if this invoice is like any others.
* **Numpy** and **Regex (Re)** : For number crunching and fancy text extraction.
* **Logging** : Because we need to keep track of errors and make sure we’re getting everything right. 📜🖊️

```python from transformers import AutoProcessor, AutoModelForVisionText2Textfrom PIL import Imageimport faissimport numpy as npimport reimport loggingimport osfrom langchain_ollama import OllamaEmbeddings ```

## 🛠️ Configuration: Setting Our System’s Sensitivity

We’re working with numbers and thresholds — things that help us tell _normal_ from _weird_. Here’s what we’re setting up:

* **UNUSUAL_CHARS_THRESHOLD** : If we see lots of weird symbols like `@#$%^&`, the invoice might be sketchy.
* **INCONSISTENT_CAPS_THRESHOLD** : If capitalization looks all over the place (think “Invoice Number” vs. “invoice NUMBER”), that’s strange.
* **VENDOR_SIMILARITY_THRESHOLD** : We want the vendor details to match _known_ vendor data by at least 70%.
* **HISTORICAL_SIMILARITY_THRESHOLD** : Similar invoices should be close to each other in structure, so we’ll set this at 60%.
* **HIGH_VALUE_THRESHOLD** : Any invoice over $10,000 needs extra scrutiny because large amounts are prime fraud targets. 💸

``` HISTORICAL_DATA_DIM = 768 # Nomic embedding dimensionVENDOR_DATA_DIM = 768 # Nomic embedding dimensionUNUSUAL_CHARS_THRESHOLD = 5INCONSISTENT_CAPS_THRESHOLD = 0.3VENDOR_SIMILARITY_THRESHOLD = 0.7HISTORICAL_SIMILARITY_THRESHOLD = 0.6HIGH_VALUE_THRESHOLD = 10000 ```

## 🧬 The Core System: Analyzing Invoices

Now that the setup is done, let’s talk about the **InvoiceFraudDetectionSystem** class. This is where the magic happens! ✨ Here’s the rundown:

### The Heart of the System (Initialization)

When we create an instance of this class, we load:

* A **model** to analyze text in invoices.
* A **processor** to help the model make sense of the image.
* **Indexes for historical and vendor data** : Imagine a big library of all past invoices and legit vendor information that our system can look up anytime.

```python class InvoiceFraudDetectionSystem: def __init__(self, historical_index_path, vendor_index_path): self.model = AutoModelForVisionText2Text.from_pretrained("microsoft/Phi-3-vision-128k-instruct") self.processor = AutoProcessor.from_pretrained("microsoft/Phi-3-vision-128k-instruct") self.historical_data = self.load_index(historical_index_path, HISTORICAL_DATA_DIM) self.vendor_details = self.load_index(vendor_index_path, VENDOR_DATA_DIM) self.embeddings = OllamaEmbeddings(model="nomic-embed-text") ```
* **model and processor** : Here, we load a pre-trained model and processor from the Microsoft repository. These help read and understand the invoice image.
* **historical_data and vendor_details** : These are indexes (collections of past data) loaded from file paths provided at initialization.
* **embeddings** : Sets up text embeddings from `OllamaEmbeddings`, allowing the system to convert text into vector representations that we can search for similar entries.

### Loading Historical and Vendor Data

Historical and vendor data are like our **reference libraries**. If an invoice doesn’t look like past invoices, or the vendor seems shady, we want to know. So, we load these libraries using Faiss.

```python def load_index(self, index_path, dimension): if not os.path.exists(index_path): raise FileNotFoundError(f"Index file not found: {index_path}") return {'index': faiss.read_index(index_path)} ```

This function loads an index file that contains pre-computed vectors for invoices and vendors, which are stored in the Faiss format. It checks if the file exists and, if so, loads it using `faiss.read_index`.

## 🔍 Analyzing the Invoice: Step by Step

### Opening the Invoice Image

The system loads the image file 📸. If it can’t open the image, it’ll log an error, so we know where the system’s struggling.

### Processing Text from the Image

Using the processor and model, we can extract the text from the image — names, numbers, dates — and make it usable. It’s like taking a messy photo and turning it into clear text so we can analyze it. 📜

```python def analyze_invoice(self, image_path): try: image = Image.open(image_path) except IOError: logging.error(f"Unable to open image file: {image_path}") return None, ["Error: Unable to process invoice image"] inputs = self.processor(images=image, return_tensors="pt") outputs = self.model.generate(**inputs, max_new_tokens=256) analysis = self.processor.decode(outputs[0], skip_special_tokens=True) anomalies = self.check_anomalies(analysis) return analysis, anomalies ```

* **Loading the Image** : Tries to open the invoice image using PIL. If unsuccessful, logs an error.
* **Text Processing** : Passes the image to `processor` and extracts the text from it.
* **Analyze the Text** : The extracted text is analyzed by `check_anomalies`, which identifies any potential fraud. The function returns both the text analysis and any detected anomalies.

### Checking for Anomalies

Now the fun starts! Here’s how we sniff out suspicious stuff:

1. **Altered Text** : We scan for unusual characters (`$%#@!`) and weird capitalization (like “Invoice Number” vs “Invoice nUmber”).
2. **Inconsistent Formatting** : Are dates formatted the same way? Are amounts written consistently? If it looks messy, it could be a red flag. 🚩
3. **Suspicious Vendor** : If the vendor details don’t look like they match known vendors, or if there are words like “urgent” or “confidential,” it could be a scam.
4. **Comparing with History** : Finally, we check if the invoice is too different from what we’ve seen before. If the amounts are very high or formatting is way off, it’s worth a second look.

```python def check_anomalies(self, analysis): anomalies = [] if self.detect_altered_text(analysis): anomalies.append("Possible altered text detected") if self.detect_inconsistent_formatting(analysis): anomalies.append("Inconsistent formatting detected") if self.detect_suspicious_vendor(analysis): anomalies.append("Suspicious vendor information detected") if self.compare_historical_patterns(analysis): anomalies.append("Deviates from historical patterns") return anomalies ```

## 📊 Creating the Detection Methods

### Detect Altered Text

This function checks for special characters and inconsistent capitalization. If an invoice has a lot of random characters or some weird capitalization, it’s probably worth flagging. Think of it as a mini-grammar check for suspicious formatting.

```python def detect_altered_text(self, analysis): unusual_chars = re.findall(r'[^\w\s,.$]', analysis) if len(unusual_chars) > UNUSUAL_CHARS_THRESHOLD: return True words = analysis.split() inconsistent_caps = sum(1 for word in words if word.istitle() != words[0].istitle()) if inconsistent_caps > len(words) * INCONSISTENT_CAPS_THRESHOLD: return True return False ```

* **Unusual Characters** : Searches for strange characters (not letters, digits, or punctuation).
* **Inconsistent Capitalization** : Flags entries where capitalization is inconsistent.

### Detect Inconsistent Formatting

Dates, amounts, and text alignment — if any of these are off, that’s a clue. Our system looks for common formats and flags any unusual ones. For instance, an invoice where some dates are `YYYY-MM-DD` while others are `MM/DD/YYYY` might be a red flag. 🚩

```python def detect_inconsistent_formatting(self, analysis): date_formats = re.findall(r'\d{1,4}[-/]\d{1,2}[-/]\d{1,4}', analysis) if len(set(date_formats)) > 1: return True number_formats = re.findall(r'\d{1,3}(?:,\d{3})*(?:\\.\d+)?', analysis) decimal_counts = [num.count('.') for num in number_formats] if len(set(decimal_counts)) > 1: return True lines = analysis.split('
') left_aligned = sum(1 for line in lines if line.lstrip() == line) if left_aligned != 0 and left_aligned != len(lines): return True return False ```

This function checks:

* **Date Formats** : Finds and verifies consistency in date formatting.
* **Number Formats** : Checks if amounts use the same formatting.
* **Text Alignment** : Ensures all lines are consistently aligned (either left or right).

### Detect Suspicious Vendor

We match the vendor’s details with our vendor data. If it doesn’t match well or uses keywords like “urgent payment,” there’s a good chance something fishy is going on. 🐠

```python def detect_suspicious_vendor(self, analysis): vector = self.get_embedding(analysis) D, I = self.vendor_details['index'].search(np.array([vector]), k=1) if D[0][0] > VENDOR_SIMILARITY_THRESHOLD: return True suspicious_keywords = ['urgent', 'confidential', 'immediate payment', 'offshore'] if any(keyword in analysis.lower() for keyword in suspicious_keywords): return True return False ```

* **Similarity Check** : Compares invoice text with vendor data to detect mismatches.
* **Keyword Search** : Flags invoices with keywords associated with fraud (e.g., “urgent payment”).

### Compare with Historical Patterns

The final check! Here we compare the invoice’s details (like amount) to past invoices. If it’s a lot higher than usual or very different in format, it could be fraud. Any big number, like `$15,000`, might get flagged for review. 📈

```python def compare_historical_patterns(self, analysis): vector = self.get_embedding(analysis) D, I = self.historical_data['index'].search(np.array([vector]), k=5) if np.mean(D[0]) > HISTORICAL_SIMILARITY_THRESHOLD: return True amounts = re.findall(r'\$\s*(\d{1,3}(?:,\d{3})*(?:\\.\d+)?)', analysis) if amounts: max_amount = max(float(amount.replace(',', '')) for amount in amounts) if max_amount > HIGH_VALUE_THRESHOLD: return True return False ```

## 🧠 Embedding the Text for Comparison

To make sure the invoice text matches our data libraries, we transform it into **embeddings**. This fancy term means turning the text into numerical data so we can make mathematical comparisons. If the comparison score is too low, it’s worth investigating further. 🤔

```python def get_embedding(self, text): return self.embeddings.embed_query(text) ```
