## Simplest RL Algorithm

We begin with the most fundamental concept in RL, the interaction loop between an agent and its environment. Even the most basic approach follows this cycle.

Let’s visualize how an RL agent works and then we will understand it’s process.

Press enter or click to view image in full size

Simplest RL (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

Let’s understand this flow. The agent observes the current situation (the state `s`) from the environment. Based on this state, the agent decides on an action `a` to take, following its current strategy (policy). It performs the action, which influences the environment.

The environment then responds by transitioning to a new state `s'` and providing a numerical reward `r` to the agent.

This reward signals how good the immediate outcome of the action was. The agent uses this feedback (`s, a, r, s'`) to learn or adapt its strategy for the future, and the cycle repeats from the new state `s`.

This first agent doesn’t truly “learn” in the sophisticated way later algorithms do. It simply _remembers_ the immediate rewards it received for taking specific actions in specific states.

Its goal is naive: **pick the action that yielded the best _average immediate reward_ from this state in the past.** It has no concept of long-term consequences.

First, we need a way for the agent to store its memories. A dictionary mapping (state, action) pairs to a list of rewards received works well.

``` # Memory Structure: memory[(state_tuple)][action_index] -> [list_of_rewards]agent_memory: DefaultDict[Tuple[int, int], DefaultDict[int, List[float]]] = \ defaultdict(lambda: defaultdict(list))# Example: Store reward for taking action 1 in state (0,0)# agent_memory[(0,0)][1].append(-0.1) ```

This simple dictionary structure stores every immediate reward encountered for each state-action pair.

Next, the agent needs a strategy (policy) to choose its next action. We’ll use an epsilon-greedy approach based on the _average immediate reward_ stored in memory.

```python def choose_simple_action(state: Tuple[int, int], memory: DefaultDict[Tuple[int, int], DefaultDict[int, List[float]]], epsilon: float, n_actions: int) -> int: """ Chooses action epsilon-greedily based on average immediate reward. """ if random.random() < epsilon: return random.randrange(n_actions) # Explore else: # Exploit: Find action with best average immediate reward state_action_memory = memory[state] best_avg_reward = -float('inf') best_actions = [] for action_idx in range(n_actions): rewards = state_action_memory[action_idx] # If action never tried from this state, consider its avg reward 0 or very low avg_reward = np.mean(rewards) if rewards else 0.0 if avg_reward > best_avg_reward: best_avg_reward = avg_reward best_actions = [action_idx] elif avg_reward == best_avg_reward: best_actions.append(action_idx) # If no actions have positive rewards or state unvisited, choose randomly if not best_actions: return random.randrange(n_actions) # Break ties randomly return random.choice(best_actions) ```

This function allows the agent to either explore randomly (with probability epsilon) or exploit its memory by choosing the action that, on average, gave the best _single-step_ reward from the current state previously.

Finally, the “learning” step is just updating the memory after taking an action.

```python def update_simple_memory(memory: DefaultDict[Tuple[int, int], DefaultDict[int, List[float]]], state: Tuple[int, int], action: int, reward: float) -> None: """ Adds the received reward to the memory for the state-action pair. """ memory[state][action].append(reward) ```

This agent simply records the immediate consequence. It doesn’t look ahead or consider the cumulative reward, which is the main limitation we’ll address with subsequent algorithms.

## Q Learning

The simple MemoryBot was limited because it only considered immediate rewards. Q-Learning takes a significant step forward by learning the **quality** (or Q-value) of taking an action in a state, considering not just the immediate reward but the _total discounted future reward_ it expects to get afterward.

It aims to learn the optimal action-value function = _Q∗(s,a)_

Press enter or click to view image in full size

Q Learning (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

When the agent takes action `a` in state `s`, it receives reward `r` and transitions to state `s'`. To update the value of the original (`s, a`) pair, Q-learning considers the best possible Q-value from the next state `s'` across all possible next actions `a'`, represented by `Max Q(s', a')`.

This maximum future value is discounted by gamma (γ) and added to the immediate reward `r` to form the **target value**. The Q-value of the original (`s, a`) pair, `Q(s, a)`, is then updated by moving it slightly toward this target value, controlled by the learning rate alpha (α).

The learning happens via the update rule:

Press enter or click to view image in full size

Q Learning Equation

This means:

* We get a new estimate of the value: reward + discount_factor * best_future_value.
* We calculate the difference between this new estimate and the old Q-value (this is the _Temporal Difference error_).
* We update the old Q-value by adding a fraction (determined by the learning rate.

First, we initialize the Q-table. We can again use defaultdict for simplicity, initializing unknown Q-values to 0.

``` # Q-Table: q_table[(state_tuple)][action_index] -> q_valueq_table: DefaultDict[Tuple[int, int], Dict[int, float]] = \ defaultdict(lambda: defaultdict(float))# Example: Accessing Q((0,0), 0=Up) will return 0.0 initially# print(q_table[(0,0)][0]) ```

This structure stores the estimated Q-value for each action within each state.

Action selection still uses epsilon-greedy, but now it exploits based on the learned Q-values, not just immediate rewards.

```python # Epsilon-Greedy Action Selection based on Q-valuesdef choose_q_learning_action(state: Tuple[int, int], q_table: DefaultDict[Tuple[int, int], Dict[int, float]], epsilon: float, n_actions: int) -> int: """ Chooses action epsilon-greedily based on Q-table values. """ if random.random() < epsilon: return random.randrange(n_actions) # Explore else: # Exploit: Choose action with highest Q-value for this state q_values_for_state = q_table[state] if not q_values_for_state: # If state hasn't been visited/updated return random.randrange(n_actions) max_q = -float('inf') best_actions = [] # Iterate through available actions (0 to n_actions-1) for action_idx in range(n_actions): q_val = q_values_for_state[action_idx] # defaultdict returns 0 if key missing if q_val > max_q: max_q = q_val best_actions = [action_idx] elif q_val == max_q: best_actions.append(action_idx) return random.choice(best_actions) # Break ties randomly ```

The agent explores randomly with probability epsilon, otherwise it picks the action currently estimated to yield the best _long-term_ return from the current state.

The core Q-Learning update function implements the Bellman update.

```python # Q-Learning Update Ruledef update_q_value(q_table: DefaultDict[Tuple[int, int], Dict[int, float]], state: Tuple[int, int], action: int, reward: float, next_state: Tuple[int, int], alpha: float, # Learning Rate gamma: float, # Discount Factor n_actions: int, is_done: bool) -> None: """ Performs a single Q-Learning update step. """ # Get the current Q-value estimate current_q = q_table[state][action] # Find the maximum Q-value for the next state (Q-Learning specific) # This represents the best possible value achievable from the next state. max_next_q = -float('inf') if not is_done and q_table[next_state]: # Check if next_state has entries max_next_q = max(q_table[next_state].values()) elif is_done: max_next_q = 0.0 # No future reward if episode is done else: max_next_q = 0.0 # If next_state has no entries yet # Calculate the TD Target: R + gamma * max(Q(s', a')) td_target = reward + gamma * max_next_q # Calculate the TD Error: TD Target - Q(s, a) td_error = td_target - current_q # Update the Q-value: Q(s, a) <\- Q(s, a) + alpha * TD_Error q_table[state][action] = current_q + alpha * td_error ```

This function calculates the target value based on the reward and the _maximum_ Q-value achievable from the next state (the off-policy aspect) and updates the Q-value for the state-action pair that was actually taken.

## Sarsa

SARSA (State-Action-Reward-State-Action) is another value-based algorithm similar to Q-Learning, but with a key difference: it’s **on-policy**.

This means it learns the value of the _policy it is currently following_ , including any exploratory actions. Q-Learning, being off-policy, learns the optimal policy regardless of the exploration strategy.

Press enter or click to view image in full size

Sarsa (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

The agent starts in state `s`, chooses action `a` using its policy, receives reward `r`, and transitions to state `s'`. Crucially, before updating the value of the original (`s, a`) pair, the agent determines the next action `a'` it will take from state `s'` using the same policy.

The Q-value of this specific next state-action pair, `Q(s', a')`, is discounted by gamma (γ) and added to the immediate reward `r` to form the **SARSA target**. The original `Q(s, a)` is then updated toward this target, influenced by the learning rate alpha (α). This process follows the full quintuple (`s, a, r, s', a'`).

SARSA uses the same Q-table structure as Q-Learning to store state-action values. The structure remains the same, mapping state-action pairs to estimated values.

Action selection also typically uses epsilon-greedy, identical to Q-Learning, to balance exploration and exploitation.

```python # Epsilon-Greedy Action Selection (Same function as Q-Learning)def choose_sarsa_action(state: Tuple[int, int], q_table: DefaultDict[Tuple[int, int], Dict[int, float]], epsilon: float, n_actions: int) -> int: """ Chooses action epsilon-greedily based on Q-table values. """ if random.random() < epsilon: return random.randrange(n_actions) # Explore else: # Exploit: Choose action with highest Q-value q_values_for_state = q_table[state] if not q_values_for_state: return random.randrange(n_actions) max_q = -float('inf') best_actions = [] for action_idx in range(n_actions): q_val = q_values_for_state[action_idx] # Defaults to 0.0 if q_val > max_q: max_q = q_val best_actions = [action_idx] elif q_val == max_q: best_actions.append(action_idx) return random.choice(best_actions) if best_actions else random.randrange(n_actions) ```

The key difference lies in the update rule, which uses the Q-value of the _next action actually chosen_ (a′) instead of the maximum possible Q-value in the next state.

```python # SARSA Update Ruledef update_sarsa_value(q_table: DefaultDict[Tuple[int, int], Dict[int, float]], state: Tuple[int, int], action: int, reward: float, next_state: Tuple[int, int], next_action: int, # The action ACTUALLY chosen for the next step alpha: float, gamma: float, is_done: bool) -> None: """ Performs a single SARSA update step. """ # Get the current Q-value estimate current_q = q_table[state][action] # Get the Q-value for the *next state and the next action chosen by the policy* # This is the core difference from Q-Learning q_next_state_action = 0.0 if not is_done: q_next_state_action = q_table[next_state][next_action] # Use Q(s', a') # Calculate the TD Target: R + gamma * Q(s', a') td_target = reward + gamma * q_next_state_action # Calculate the TD Error: TD Target - Q(s, a) td_error = td_target - current_q # Update the Q-value: Q(s, a) <\- Q(s, a) + alpha * TD_Error q_table[state][action] = current_q + alpha * td_error ```

Because SARSA uses Q(s′,a′) (the value of the _next action chosen_ , which might be exploratory) in its update, it tends to learn a more conservative policy compared to Q-Learning, especially in environments with potential risks (like cliffs). It evaluates the policy being actively followed.

## Expected Sarsa

Expected SARSA builds directly on SARSA, maintaining the **on-policy** nature (learning based on the actions taken by the current policy).

However, instead of updating based on the single _next action_ (a′) chosen by the policy, Expected SARSA calculates the **expected** value of the next state by considering _all possible actions_ from that next state and weighting their Q-values by the probability of taking each action according to the current policy (π(a′∣s′).

This averaging process tends to **reduce the variance** in the updates compared to standard SARSA, which relies on a single, potentially exploratory (and thus noisy), next action sample. This often leads to smoother and sometimes faster learning.

Press enter or click to view image in full size

Expected Sarsa (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

Similar to SARSA, the agent takes action ‘a’ in state ‘s’, gets reward ‘r’, and moves to ‘s’’.

However, to calculate the target value, Expected SARSA looks at _all_ actions (‘a’₁, ‘a’₂, …) possible from ‘s’’. It gets the probability of choosing each action from its current policy (π(a′∣s′) and the corresponding Q-value Q(s′,a′).

It then computes the _expected_ Q-value for state ‘s’’ by summing the product of each action’s probability and its Q-value:

Press enter or click to view image in full size

Expected value sarsa Equation

This expected value is discounted (γ) and added to the reward ‘r’ to form the target. Finally, Q(s,a) is updated towards this averaged target using the learning rate (α).

The Q-Table initialization function and Action selection uses the same old epsilon-greedy policy based on current Q-values which we see earlier in sarsa section.

The main difference is in the update rule, which now computes the expectation over the next actions based on the epsilon-greedy policy probabilities.

```python # Expected SARSA Update Ruledef update_expected_sarsa_value( q_table: DefaultDict[Tuple[int, int], Dict[str, float]], state: Tuple[int, int], action: int, # Use integer action index now reward: float, next_state: Tuple[int, int], alpha: float, gamma: float, epsilon: float, # Current epsilon needed for expectation n_actions: int, is_done: bool) -> None: """ Performs a single Expected SARSA update step. """ # Get the current Q-value estimate current_q = q_table[state][action] # Calculate the expected Q-value for the next state expected_q_next = 0.0 if not is_done and q_table[next_state]: # Check if next state exists and has entries q_values_next_state = q_table[next_state] if q_values_next_state: # Check if dictionary is not empty max_q_next = max(q_values_next_state.values()) # Find all best actions (handle ties) best_actions = [a for a, q in q_values_next_state.items() if q == max_q_next] # Calculate probabilities under epsilon-greedy prob_greedy = (1.0 - epsilon) / len(best_actions) # Split greedy prob among best actions prob_explore = epsilon / n_actions # Calculate expected value E[Q(s', A')] = sum[ pi(a'|s') * Q(s', a') ] for a_prime in range(n_actions): prob_a_prime = 0.0 if a_prime in best_actions: prob_a_prime += prob_greedy # Add greedy probability prob_a_prime += prob_explore # Add exploration probability (applies to all actions) expected_q_next += prob_a_prime * q_values_next_state.get(a_prime, 0.0) # Default to 0 if action unseen # TD Target: R + gamma * E[Q(s', A')] td_target = reward + gamma * expected_q_next # TD Error: TD Target - Q(s, a) td_error = td_target - current_q # Update Q-value q_table[state][action] = current_q + alpha * td_error ```

This update considers the probabilistic nature of the epsilon-greedy policy when calculating the future value, making the update less sensitive to the single (potentially random) action chosen in the next step, compared to SARSA.

## Dyna Q

Previous methods learned solely from _direct_ interaction with the environment (model-free).

Dyna-Q introduces a simple form of **model-based** RL by simultaneously learning a model of the environment _and_ using that model for additional “planning” steps (simulated experience) to accelerate learning.

The core idea is to make better use of each real experience: use it once for direct Q-learning, once to update the internal model, and then use the model multiple times to simulate potential futures and perform extra Q-learning updates.

This often leads to significantly better **sample efficiency** means learning faster from fewer real-world interactions.

Press enter or click to view image in full size

Dyna Q (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

After taking a real action `a` in state `s` and observing reward `r` and next state `s'`, the **Dyna-Q agent** performs three tasks in parallel:

1. **Direct Reinforcement Learning (RL):** Updates the Q-value `Q(s, a)` using the real experience `(s, a, r, s')`, just like standard Q-learning.
2. **Model Learning:** Updates its internal world model to record that taking action `a` in state `s` resulted in reward `r` and next state `s'`.
3. **Planning:** Performs `k` additional updates using simulated experience: Randomly selects a previously encountered state-action pair `(s_p, a_p)`. ## Reinforce

We now shift from **value-based methods** (Q-Learning, SARSA) to **policy-based methods**.

Instead of learning action values, **REINFORCE** directly learns and optimizes a policy `π(a ∣ s; θ)`, which maps states to action probabilities, parameterized by `θ`. The policy is adjusted to make **good** actions, those leading to **high total reward** more likely.

REINFORCE follows a **Monte Carlo approach** , meaning it collects rewards over a **full episode** before updating the policy.

The agent uses its current **policy network** (`π_θ`) to generate a **complete episode**. At each step, it:

* Samples an action `a` based on the current state `s`.
* Stores the **log probability** (`log π(a | s)`) of the action.
* Records the received **reward** `r`.

Once the episode finishes, the agent **looks back** at the entire sequence of rewards. It calculates the **total discounted return** (`G_t`) starting from each time step `t`.

Finally, the policy parameters (`θ`) are updated using **gradient ascent** :

* The update **increases** the log probability (`log π(a | s)`) for actions followed by **high returns** (`G_t`).
* It **decreases** the log probability for actions followed by **low returns**.

First, we define the policy network. It’s similar to the Actor network in outputting probabilities via Softmax.

```python # Define the Policy Network architectureclass PolicyNetwork(nn.Module): def __init__(self, n_observations: int, n_actions: int): super(PolicyNetwork, self).__init__() self.layer1 = nn.Linear(n_observations, 128) self.layer2 = nn.Linear(128, 128) self.layer3 = nn.Linear(128, n_actions) # Outputs logits def forward(self, x: torch.Tensor) -> Categorical: """ Forward pass, returns a Categorical distribution over actions. """ if not isinstance(x, torch.Tensor): x = torch.tensor(x, dtype=torch.float32, device=device) # Assuming 'device' is defined elif x.dtype != torch.float32: x = x.to(dtype=torch.float32) if x.dim() == 1: x = x.unsqueeze(0) x = F.relu(self.layer1(x)) x = F.relu(self.layer2(x)) action_logits = self.layer3(x) # Use Categorical distribution directly from logits return Categorical(logits=action_logits) ```

This network takes a state and gives us a way to sample actions and calculate their log probabilities.

Next, the action selection function uses this network to _sample_ an action and record its log probability.

```python # Action Selection by Samplingdef select_action_reinforce(state: torch.Tensor, policy_net: PolicyNetwork) -> Tuple[int, torch.Tensor]: """ Selects action by sampling from the policy network's output distribution. """ action_dist = policy_net(state) action = action_dist.sample() # Sample action log_prob = action_dist.log_prob(action) # Get log probability of the chosen action return action.item(), log_prob ```

Unlike epsilon-greedy, exploration is inherent in the sampling process based on the action probabilities output by the network.

After an episode finishes, we need to calculate the discounted returns Gt​ for each step.

```python # Calculate Discounted Returnsdef calculate_discounted_returns(rewards: List[float], gamma: float, standardize: bool = True) -> torch.Tensor: """ Calculates discounted returns G_t for each step t, optionally standardizes. """ n_steps = len(rewards) returns = torch.zeros(n_steps, dtype=torch.float32) # Keep on CPU for calculation discounted_return = 0.0 # Iterate backwards for t in reversed(range(n_steps)): discounted_return = rewards[t] + gamma * discounted_return returns[t] = discounted_return if standardize: mean_return = torch.mean(returns) std_return = torch.std(returns) + 1e-8 # Add epsilon for stability returns = (returns - mean_return) / std_return return returns.to(device) # Move to appropriate device at the end ```

This function computes the actual outcome (Gt​) following each action taken in the episode. Standardizing often helps stabilize training.

Finally, the policy update uses the collected log probabilities and returns to adjust the network weights.

```python # Policy Update Stepdef optimize_policy(log_probs: List[torch.Tensor], returns: torch.Tensor, optimizer: optim.Optimizer) -> float: """ Performs one REINFORCE policy gradient update. """ # Stack log probabilities and ensure returns have correct shape log_probs_tensor = torch.stack(log_probs) returns = returns.detach() # Treat returns as fixed targets for this update # Calculate loss: - Sum(G_t * log_pi(a_t|s_t)) # We minimize the negative objective loss = -torch.sum(returns * log_probs_tensor) # Perform optimization optimizer.zero_grad() loss.backward() optimizer.step() return loss.item() ```

This function computes the REINFORCE loss and uses an optimizer (like Adam) to update the policy network parameters θ, making good action sequences more likely.

## PPO (Proximal Policy Optimization)

Policy gradient methods like REINFORCE can be unstable because a single update based on noisy returns might drastically change the policy for the worse.

Trust Region Policy Optimization (TRPO) addressed this with complex constraints. Proximal Policy Optimization (PPO) offers a simpler way to achieve similar stability by using a **clipped surrogate objective function**.

PPO is an **actor-critic, on-policy** algorithm that aims to keep the new policy close to the old policy during updates, preventing destructive large changes while still allowing for efficient learning, often over multiple passes (epochs) on the same batch of data.

PPO Simplified (Created by

)

Like **REINFORCE** and **A2C** , **PPO** starts by collecting experience `(s, a, r, s')` using the current **old policy** (`π_old`). It also stores the **log probability** of each action under that policy. A **critic** (`V_old`) provides **state value estimates**.

After gathering a batch of experience, **advantages** (`Â`) are computed—often using **Generalized Advantage Estimation (GAE)**.

The **core PPO update** happens over **multiple epochs** using this collected data:

1. The current **new policy** (`π_new`) is evaluated on the batch states to obtain new **log probabilities**.
2. The **probability ratio** `r` is computed between the new and old policies.
3. PPO then applies a **clipped objective** (`L_CLIP`), restricting how much `r` can influence updates, based on a **clipping parameter** (ϵ).

The **total loss** is formed by combining:

* The **clipped policy loss** (`L_CLIP`), ensuring stable updates.
* A **value loss** (`L_VF`), improving the critic.
* An **entropy bonus** (`S`), encouraging exploration.

Both the **actor (policy) and critic (value function)** are updated via **gradient descent** using this total loss.

PPO uses the same Actor (Policy Network) and Critic (Value Network) architectures as A2C and TRPO.

It also typically uses the same Generalized Advantage Estimation (GAE) function. The unique part is the PPO update function which incorporates the clipping.

The main difference lies in the **update logic** , specifically in how the **policy loss** (`L_CLIP`) is computed.

Update logic Equation

```python # PPO Update Step (Simplified view, assumes data is batched)def update_ppo(actor: PolicyNetwork, critic: ValueNetwork, actor_optimizer: optim.Optimizer, critic_optimizer: optim.Optimizer, states: torch.Tensor, actions: torch.Tensor, log_probs_old: torch.Tensor, # Log probs from the policy used for rollout advantages: torch.Tensor, # Calculated GAE advantages returns_to_go: torch.Tensor, # Target for value function (Adv + V_old) ppo_epochs: int, # Number of updates per batch ppo_clip_epsilon: float, # Clipping parameter ε value_loss_coeff: float, # Weight for critic loss entropy_coeff: float) -> Tuple[float, float, float]: # Avg losses total_policy_loss = 0.0 total_value_loss = 0.0 total_entropy = 0.0 # Data should be detached before entering the loop advantages = advantages.detach() log_probs_old = log_probs_old.detach() returns_to_go = returns_to_go.detach() # Perform multiple epochs of updates on the same batch for _ in range(ppo_epochs): # --- Actor (Policy) Update --- policy_dist = actor(states) # Get current policy distribution log_probs_new = policy_dist.log_prob(actions) # Log prob of actions under *new* policy entropy = policy_dist.entropy().mean() # Encourage exploration # Calculate the ratio r(θ) = π_new / π_old ratio = torch.exp(log_probs_new - log_probs_old) # Calculate clipped surrogate objective parts surr1 = ratio * advantages surr2 = torch.clamp(ratio, 1.0 - ppo_clip_epsilon, 1.0 + ppo_clip_epsilon) * advantages # Policy Loss: -(min(surr1, surr2)) - entropy_bonus policy_loss = -torch.min(surr1, surr2).mean() - entropy_coeff * entropy # Optimize actor actor_optimizer.zero_grad() policy_loss.backward() actor_optimizer.step() # --- Critic (Value) Update --- values_pred = critic(states).squeeze() # Predict V(s) with current critic value_loss = F.mse_loss(values_pred, returns_to_go) # Compare to calculated returns # Optimize critic critic_optimizer.zero_grad() (value_loss_coeff * value_loss).backward() # Scale loss before backward critic_optimizer.step() # Accumulate stats total_policy_loss += policy_loss.item() total_value_loss += value_loss.item() total_entropy += entropy.item() # Return average losses over the epochs return total_policy_loss / ppo_epochs, total_value_loss / ppo_epochs, total_entropy / ppo_epochs ```

This update function iterates over the collected data multiple times (epochs).

In each pass, it calculates the policy ratio, applies the clipping mechanism to limit the policy change, computes the value loss, and updates both networks. This combination allows for stable and efficient learning.

## A2C (Synchronous Advantage Actor-Critic)

Advantage Actor-Critic (A2C) is a synchronous, simpler variant within the actor-critic family.

Like other actor-critic methods, it uses two networks: an **Actor** to choose actions and a **Critic** to evaluate states. A2C specifically utilizes the **Advantage** estimate:

It guides the Actor’s updates, leading to lower variance compared to REINFORCE.

Unlike its asynchronous sibling A3C, A2C performs updates **synchronously**.

It typically waits for a batch of experiences (often collected from parallel environments, though simulated sequentially here) before computing and applying gradients to both the actor and critic networks simultaneously.

During the **rollout phase** , the **Actor** (`π_θ`) selects actions (`a`) based on the current state (`s`), while the **Critic** (`V_ϕ`) estimates the value of that state (`V(s)`).

The action leads to a **reward** (`r`) and **next state** (`s'`). This process repeats for `N` steps, collecting a batch of data.

In the **update phase** , the collected **rewards** and **value estimates** are used to calculate the **target returns** (`R_t`) and **advantage estimates** (`Â`). The **policy loss** is calculated using the **advantages** and **action log probabilities** , encouraging actions with **positive advantages**.

The **value loss** is calculated as the difference between the predicted values (`V(s_t)`) and the **target returns** (`R_t`).

Finally, gradients from **both losses** are computed and used to update the **Actor (**`**θ**`**) and Critic (**`**ϕ**`**)** parameters **synchronously**.

* **Actor:** The policy network `π(a ∣ s; θ)`, outputs action probabilities.
* **Critic:** The value network `V(s; ϕ)`, estimates the value of being in a state.
* **Advantage:** Calculated as `Â_t ≈ R_t − V(s_t)`, where `R_t` is often an **n-step return** or calculated using **GAE**. It measures how much better an action was than the average expected return from that state.
* **Synchronous Updates:** Gradients are calculated **over a batch of experience** and applied **simultaneously** to the actor and critic.

A2C uses the same Actor (Policy Network) and Critic (Value Network) architectures as PPO and TRPO.

It also typically uses Generalized Advantage Estimation (GAE) to get good advantage estimates and target returns for the critic.

The A2C update function calculates the combined loss and applies gradients synchronously.

```python # A2C Update Stepdef update_a2c(actor: PolicyNetwork, critic: ValueNetwork, actor_optimizer: optim.Optimizer, critic_optimizer: optim.Optimizer, states: torch.Tensor, actions: torch.Tensor, advantages: torch.Tensor, # Calculated GAE advantages returns_to_go: torch.Tensor, # Target for value function (Adv + V_old) value_loss_coeff: float, # Weight for critic loss entropy_coeff: float # Weight for entropy bonus ) -> Tuple[float, float, float]: # Avg losses # --- Evaluate current networks --- policy_dist = actor(states) log_probs = policy_dist.log_prob(actions) # Log prob of actions taken entropy = policy_dist.entropy().mean() # Average entropy values_pred = critic(states).squeeze() # Critic's value prediction # --- Calculate Losses --- # Policy Loss (Actor): - E[log_pi * A_detached] - entropy_bonus policy_loss = -(log_probs * advantages.detach()).mean() - entropy_coeff * entropy # Value Loss (Critic): MSE(V_pred, Returns_detached) value_loss = F.mse_loss(values_pred, returns_to_go.detach()) # --- Optimize Actor --- actor_optimizer.zero_grad() policy_loss.backward() # Calculate actor gradients actor_optimizer.step() # Update actor weights # --- Optimize Critic --- critic_optimizer.zero_grad() # Backward pass for critic loss (scaled) (value_loss_coeff * value_loss).backward() critic_optimizer.step() # Update critic weights # Return losses for logging (policy objective part, value loss, entropy) return policy_loss.item() + entropy_coeff * entropy.item(), value_loss.item(), entropy.item() ```

This function takes a batch of transitions, computes policy and value losses based on calculated advantages and returns, and then performs separate, synchronous gradient updates for the actor and critic networks.

## A3C (Asynchronous Advantage Actor-Critic)

Asynchronous Advantage Actor-Critic (A3C) was a groundbreaking algorithm that demonstrated how **parallelism** could stabilize actor-critic learning _without_ relying on experience replay buffers like DQN.

It uses multiple “worker” agents running in parallel, each interacting with its own copy of the environment.

The core idea is **asynchronicity** : workers compute updates independently based on their local experience and apply them to a shared global network without waiting for each other.

This constant stream of diverse updates helps to decorrelate the data and stabilize training.

)

Multiple independent ‘Workers’ exist. Each worker first copies the parameters from the ‘Global Network’.

Then, using its local network copy, it interacts with its own separate environment instance for a small number of steps (‘Rollout n steps’).

Based on this short trajectory, the worker calculates gradients for both the actor and critic parts of its local network.

Finally, it sends these gradients asynchronously to update the ‘Global Network’ using a shared optimizer.

Because workers operate independently and update at different times, the global network receives a diverse and less correlated stream of updates.

* **Asynchronous Updates:** Workers don’t wait for each other, reducing idle time and decorrelating updates.
* **Global & Local Networks:** Workers sync with a **central global network** but compute gradients **locally**.
* **N-Step Returns:** Updates are typically based on rewards collected over a small number of steps (`n`), plus a bootstrapped value estimate from the **critic** for the state reached after `n` steps. This balances the **bias** of 1-step **TD** and the **variance** of full **Monte Carlo** returns.
* **Advantage Estimation:** Advantages are calculated as `Â_t = R_t − V(s_t)`, using these **n-step returns** (`R_t`).

A3C often uses a combined Actor-Critic network where initial layers are shared.

## DDPG (Actor-Critic for Continuous Actions)

Deep Deterministic Policy Gradient (DDPG) extends the actor-critic idea to environments with **continuous action spaces** (e.g., applying a specific torque, setting a velocity).

It cleverly combines ideas from DQN (like replay buffers and target networks) with a deterministic actor policy.

The core idea is:

* **Deterministic Actor:** Unlike `REINFORCE`/`A2C`/`PPO`, which output **action probabilities** , the `DDPG` actor network outputs a **specific, deterministic action** for a given state.
* **Q-Critic:** The critic network learns a Q-function `Q(s, a)`, similar to **Q-learning** , evaluating the value of taking the actor's chosen **continuous action** (`a`) in state (`s`).
* **Off-Policy:** Uses a **replay buffer** to store experiences and samples **mini-batches** , allowing **stable learning** from past data, similar to `DQN`.
* **Target Networks:** Employs **separate target networks** for both the **actor** and the **critic** to stabilize the learning of the critic’s **target values**.
* **Exploration:** Since the **policy is deterministic** , exploration is added **manually** , typically by adding **noise** (e.g., **Gaussian** or **Ornstein-Uhlenbeck noise**) to the actor’s output action during training.

During **interaction** , the **Actor** network produces a **deterministic action** based on the current state (`s`).

**Noise** is added to this action for **exploration** before executing it in the **environment**. The resulting transition (`s, a, r, s', done`) is stored in the **Replay Buffer**.

During **training** , a **batch** is sampled from the buffer.

* **Critic Update:** A target **Q-value** (`TD Target y`) is calculated using the **reward** (`r`) and the **target actor** and **target critic networks** evaluated at the **next state** (`s'`). The main **Critic** network computes `Q(s, a)` for the **sampled states and actions**. The difference (**MSE loss**) between the **target** (`y`) and `Q(s, a)` is used to update the main **Critic** parameters (`ϕ`).
* **Actor Update:** The **Actor** network computes **actions** for the **sampled states** (`s`). These **actions** are fed into the **main Critic** network to get their **Q-values**. The **Actor** is updated to **produce actions** that **maximize this Q-value** (typically by minimizing the **negative Q-value** , `L_θ = −Q`).
* **Target Updates:** The **target actor** and **target critic networks** (`θ'`, `ϕ'`) are **slowly updated** towards the **main network parameters** using **soft updates**.

DDPG requires separate Actor and Critic networks. The Actor outputs a specific continuous action, often scaled using tanh.

The Critic takes both state and action as input.

```python # Simplified Actor Network for DDPG (outputs continuous action)class ActorNetworkDDPG(nn.Module): def __init__(self, state_dim: int, action_dim: int, max_action: float): super(ActorNetworkDDPG, self).__init__() self.layer1 = nn.Linear(state_dim, 256) self.layer2 = nn.Linear(256, 256) self.layer3 = nn.Linear(256, action_dim) self.max_action = max_action # To scale the output def forward(self, state: torch.Tensor) -> torch.Tensor: x = F.relu(self.layer1(state)) x = F.relu(self.layer2(x)) # Use tanh to output values between -1 and 1, then scale action = self.max_action * torch.tanh(self.layer3(x)) return action# Simplified Critic Network for DDPG (takes state and action)class CriticNetworkDDPG(nn.Module): def __init__(self, state_dim: int, action_dim: int): super(CriticNetworkDDPG, self).__init__() # Process state and action separately or together self.layer1 = nn.Linear(state_dim + action_dim, 256) self.layer2 = nn.Linear(256, 256) self.layer3 = nn.Linear(256, 1) # Outputs a single Q-value def forward(self, state: torch.Tensor, action: torch.Tensor) -> torch.Tensor: # Concatenate state and action x = torch.cat([state, action], dim=1) x = F.relu(self.layer1(x)) x = F.relu(self.layer2(x)) q_value = self.layer3(x) return q_value ```

## SAC (Maximum Entropy Actor-Critic)

Soft Actor-Critic (SAC) is another advanced actor-critic algorithm designed for **continuous action spaces** , building upon DDPG and TD3. Its defining feature is the incorporation of a **maximum entropy reinforcement learning** framework.

This means the agent is incentivized not only to maximize rewards but also to act as randomly as possible (maximize policy entropy) while doing so.

This entropy maximization encourages broader exploration, improves robustness, and often leads to faster and more stable learning compared to DDPG. SAC is also **off-policy** , using a replay buffer like DDPG.

SAC (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

**Interaction** is similar to other **actor-critics** , but the **Actor** (`π_θ`) is **stochastic** – it outputs a **distribution** from which **actions** are **sampled**. The experience (`s, a, r, s', done`) is stored in a **replay buffer**.

During **training** (sampling a **batch**):

* **Critic Update:** The target **Q-value** calculation is **unique**. It uses **target networks** to get the **minimum Q-value estimate** (`Min Q'`) for the **next action** (`a'`) sampled from the **current policy** (evaluated at the **next state** `s'`).
* It then **subtracts** the **entropy term** (`α * log π(a'|s')`) from this **minimum Q-value** to get the **"soft target"**. The **TD target** (`y`) is formed using the **reward** and this **soft target**. The main **critics** (`Q_ϕ`, usually **twin critics** `Q1, Q2`) are **updated** to minimize the **MSE loss** against `y`.
* **Actor Update:** The **Actor** **samples** an **action** (`a_π`) for the **current batch state** `s`. The **loss** encourages **actions** that lead to **high Q-values** (estimated by the **main critics**) and have **high entropy** (**high** `log π`). The **loss** is approximately

``` (α * log π − min(Q1, Q2)).mean() ```
* **Alpha Update (Optional):** The **entropy temperature** (`α`) can be **automatically tuned** by defining a **target entropy level** and updating `α` to **encourage** the **policy's actual entropy** to match the **target**.
* **Target Updates:** **Soft updates** are applied to the **target critic networks**. **SAC** often **doesn’t use a target actor** , using the **current actor** for **target action sampling**.

So the core concept is this:

* **Maximum Entropy:** Adds the policy’s entropy `H(π(⋅∣s))_H_(_π_(⋅∣ _s_)) `to the standard reward objective.
* **Stochastic Actor:** Outputs parameters (e.g., mean, std dev) for a probability distribution (like Gaussian) over continuous actions. Actions are sampled.
* **Twin Critics:** Uses two Q-networks and takes the minimum of their target values to combat Q-value overestimation (similar to TD3).
* **Entropy Temperature:** Balances the reward and entropy objectives. Can be fixed or automatically tuned.

```python LOG_STD_MAX = 2LOG_STD_MIN = -20EPSILON = 1e-6 # For numerical stability in log_prob calculationclass ActorNetworkSAC(nn.Module): """ Stochastic Gaussian Actor for SAC. """ def __init__(self, state_dim: int, action_dim: int, max_action: float): super(ActorNetworkSAC, self).__init__() self.layer1 = nn.Linear(state_dim, 256) self.layer2 = nn.Linear(256, 256) self.mean_layer = nn.Linear(256, action_dim) # Output mean self.log_std_layer = nn.Linear(256, action_dim) # Output log std dev self.max_action = max_action def forward(self, state: torch.Tensor) -> Tuple[torch.Tensor, torch.Tensor]: """ Outputs squashed action and its log probability. """ x = F.relu(self.layer1(state)) x = F.relu(self.layer2(x)) mean = self.mean_layer(x) log_std = self.log_std_layer(x) log_std = torch.clamp(log_std, LOG_STD_MIN, LOG_STD_MAX) # Clamp for stability std = torch.exp(log_std) # Create distribution and sample using reparameterization trick normal_dist = Normal(mean, std) z = normal_dist.rsample() # Differentiable sample (pre-squashing) action_squashed = torch.tanh(z) # Apply tanh squashing # Calculate log_prob with correction for tanh # log_prob = log_normal(z) - log(1 - tanh(z)^2 + eps) log_prob = normal_dist.log_prob(z) - torch.log(1 - action_squashed.pow(2) + EPSILON) # Sum log_prob across action dimensions if action_dim > 1 log_prob = log_prob.sum(dim=-1, keepdim=True) # Scale action to environment bounds action_scaled = action_squashed * self.max_action return action_scaled, log_prob ```

The Critic network typically uses a Twin Q structure, similar to TD3, taking state and action as input.

```python # Critic Network (Twin Q) for SACclass CriticNetworkSAC(nn.Module): def __init__(self, state_dim: int, action_dim: int): super(CriticNetworkSAC, self).__init__() # Q1 architecture self.l1_q1 = nn.Linear(state_dim + action_dim, 256) self.l2_q1 = nn.Linear(256, 256) self.l3_q1 = nn.Linear(256, 1) # Q2 architecture self.l1_q2 = nn.Linear(state_dim + action_dim, 256) self.l2_q2 = nn.Linear(256, 256) self.l3_q2 = nn.Linear(256, 1) def forward(self, state: torch.Tensor, action: torch.Tensor) -> Tuple[torch.Tensor, torch.Tensor]: sa = torch.cat([state, action], 1) q1 = F.relu(self.l1_q1(sa)) q1 = F.relu(self.l2_q1(q1)) q1 = self.l3_q1(q1) q2 = F.relu(self.l1_q2(sa)) q2 = F.relu(self.l2_q2(q2)) q2 = self.l3_q2(q2) return q1, q2 ```

The update logic combines the losses for actor, critics, and optionally alpha. This outline captures the key calculations for SAC, emphasizing the entropy term in the target Q-value and the actor loss, alongside the use of twin critics and optional alpha tuning.

## TRPO (Constrained Policy Updates)

Trust Region Policy Optimization (TRPO) is an earlier policy gradient algorithm focused on achieving **monotonic policy improvement,** ensuring (with high probability) that each policy update step does _not_ decrease performance.

It achieves this stability by constraining how much the policy can change in a single update, measured by the KL divergence between the old and new policies.

TRPO is an **on-policy, actor-critic** algorithm (though the critic is primarily used for advantage estimation, not updated within the core TRPO constraint).

Its main challenge lies in solving the constrained optimization problem efficiently.

TRPO (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

Like other on-policy methods, TRPO collects a batch of experience using the current policy (πold​) and calculates advantages (A). It then computes the standard policy gradient (‘g’).

The core of TRPO lies in finding the update step. Instead of just stepping along ‘g’, it aims to solve a constrained problem: maximize the policy improvement subject to keeping the KL divergence between the old and new policy below a threshold (δ).

This is approximately solved by finding a step direction ‘s’ that satisfies Fs≈g, where F is the Fisher Information Matrix (approximating the KL constraint curvature).

TRPO uses the **Conjugate Gradient (CG)** algorithm to efficiently find ‘s’ _without_ explicitly forming or inverting F. CG only requires computing **Fisher-Vector Products (FVP)**.

Once ‘s’ is found, a **backtracking line search** determines the largest step size (α) such that the actual KL constraint and a surrogate advantage improvement condition are met for the update

TRPO Update Equation

* **Trust Region:** Limiting policy updates to a region where the approximation of performance improvement holds, ensuring stability.
* **KL Divergence Constraint:** Uses the average Kullback-Leibler divergence `DKL(πold∣∣πnew)≤δ _DKL_ ​(_πold_ ​∣∣ _πnew_ ​)≤ _δ_`as the measure of policy change.
* **Fisher Information Matrix (FIM):** Represents the curvature of the policy distribution space. TRPO approximates the KL constraint using a quadratic form involving the FIM
* **Fisher-Vector Product (FVP):** A technique to compute the product of the FIM and an arbitrary vector efficiently using automatic differentiation, avoiding the need to compute and store the full FIM.
* **Conjugate Gradient (CG):** An iterative algorithm to solve the linear system`Fs≈g `to find the update direction using only FVPs.
* **Line Search:** Ensures the final step taken actually satisfies the KL constraint and improves performance according to the surrogate objective.

TRPO requires Actor (Policy Network) and Critic (Value Network) definitions (same as A2C/PPO).

The complex parts are the FVP, CG, and line search. Here are conceptual outlines (refer to **12_trpo.ipynb** or **a3c_training.py** for more detailed, runnable but complex code).

```python # Computes the Fisher vector product using Hessian-vector product approximation# This is used in the conjugate gradient method for computing the search direction# in the TRPO update step.def fisher_vector_product(actor, states, vector, cg_damping): log_probs = actor.get_log_probs(states).detach() kl = (log_probs.exp() * (log_probs - log_probs.detach())).sum() grads = torch.autograd.grad(kl, actor.parameters(), create_graph=True) flat_grads = torch.cat([g.view(-1) for g in grads]) gv = torch.dot(flat_grads, vector) hv = torch.autograd.grad(gv, actor.parameters()) flat_hv = torch.cat([h.view(-1) for h in hv]) # Adds a damping term to improve numerical stability return flat_hv + cg_damping * vector# Implements the conjugate gradient method to solve Ax = b# This is used to approximate the natural gradient direction# in the TRPO update step.def conjugate_gradient(fvp_func, b, cg_iters=10, tol=1e-10): x = torch.zeros_like(b) # Initialize solution vector r = b.clone() # Residual p = b.clone() # Search direction rs_old = torch.dot(r, r) for _ in range(cg_iters): Ap = fvp_func(p) alpha = rs_old / torch.dot(p, Ap) x += alpha * p r -= alpha * Ap rs_new = torch.dot(r, r) if rs_new < tol: break p = r + (rs_new / rs_old) * p rs_old = rs_new return x# Performs backtracking line search to find an acceptable step size# Ensures that the KL divergence constraint is satisfied# and that the new policy improves the surrogate loss.def backtracking_line_search(actor, states, actions, advantages, old_log_probs, step_direction, initial_step_size, max_kl, decay=0.8, max_iters=10): theta_old = {name: param.clone() for name, param in actor.named_parameters()} # Store old parameters for i in range(max_iters): step_size = initial_step_size * (decay ** i) # Reduce step size progressively # Apply the step to actor parameters for param, step in zip(actor.parameters(), step_size * step_direction): param.data.add_(step) # Compute KL divergence and surrogate loss kl = actor.kl_divergence(states, old_log_probs) surrogate = actor.surrogate_loss(states, actions, advantages, old_log_probs) # Check if KL is within constraint and surrogate loss has improved if kl <= max_kl and surrogate >= 0: return step_size * step_direction, True # Restore old parameters if step is not successful for name, param in actor.named_parameters(): param.data.copy_(theta_old[name]) return None, False # Return failure if no valid step found# Updates the actor (policy) and critic (value function) using TRPO algorithm.def update_trpo(actor, critic, actor_optimizer, critic_optimizer, states, actions, advantages, returns_to_go, log_probs_old, max_kl=0.01, cg_iters=10, cg_damping=0.1, line_search_decay=0.8, value_loss_coeff=0.5, entropy_coeff=0.01): # Compute policy gradient policy_loss = actor.surrogate_loss(states, actions, advantages, log_probs_old) grads = torch.autograd.grad(policy_loss, actor.parameters()) g = torch.cat([grad.view(-1) for grad in grads]) # Compute the natural gradient direction using conjugate gradient fvp_func = lambda v: fisher_vector_product(actor, states, v, cg_damping) step_direction = conjugate_gradient(fvp_func, g, cg_iters) # Compute step size based on KL constraint sAs = torch.dot(step_direction, fvp_func(step_direction)) step_size = torch.sqrt(2 * max_kl / (sAs + 1e-8)) # Perform backtracking line search to ensure KL constraint is satisfied step, success = backtracking_line_search(actor, states, actions, advantages, log_probs_old, step_direction, step_size, max_kl, line_search_decay) # Apply the step if successful if success: with torch.no_grad(): for param, step_val in zip(actor.parameters(), step): param.data.add_(step_val) # Compute and update value function using MSE loss value_loss = nn.MSELoss()(critic(states), returns_to_go) critic_optimizer.zero_grad() value_loss.backward() critic_optimizer.step() return policy_loss.item(), value_loss.item() # Return loss values for monitoring ```

TRPO ensures stability by explicitly constraining the policy update size using second-order information (approximated by the FIM), calculated efficiently via CG and FVPs, and verified with a line search.

## DQN (Deep Q-Learning)

Q-Learning works well for environments with a small, manageable number of discrete states.

However, it struggles when the state space becomes very large or continuous (like processing game pixels or robot sensor data).

Deep Q-Network (DQN) solves this by replacing the Q-table with a **deep neural network** that _approximates_ the Q-values, Q(s,a;θ) represents the network’s parameters.

DQN introduces two key innovations to stabilize learning when using neural networks with Q-learning: **Experience Replay** and **Target Networks**.

Press enter or click to view image in full size

DQN (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

The agent interacts with the environment using an epsilon-greedy policy based on its main Q-network (`Q_θ`).

Each experience tuple `(s, a, r, s', done)` is stored in a **Replay Buffer**.

For training, the agent **samples a mini-batch** of these experiences from the buffer. For each experience in the batch, a **target Q-value** (‘TD Target `y`') is calculated using the observed reward `r` and the maximum Q-value achievable from the next state `s'`, estimated by a separate, **slowly updated Target Network** (`Q_θ⁻`).

The **main Q-network** predicts the Q-value for the action `a` actually taken in state `s`. The **difference** (MSE or **Huber loss**) between the **target** `y` and the **predicted Q-value** is calculated, and **gradient descent** is used to update the main Q-network's parameters (`θ`).

Periodically, the weights of the **main network** are copied to the **target network** : θ⁻ ← θ.

The core concept of DQN contains:

* A **neural network** (e.g., MLP, CNN) that approximates `Q(s, a)`. It typically takes the state `s` as input and outputs **Q-values** for all discrete actions.
* A **buffer** storing past transitions `(s, a, r, s', done)`. Sampling **random mini-batches** breaks **data correlations** and improves **stability and efficiency**.
* A **separate copy** of the **Q-network** whose weights (`θ⁻`) are updated **less frequently** (e.g., every `C` steps or via slow "soft" updates). It provides **stable targets** :

DQN Update Equation

It provides stable targets for training the main Q-network, preventing oscillations.

First, define the Q-Network. For simple vector states (like our grid world’s normalized coordinates), an MLP is sufficient.

```python # DQN Network (MLP)class DQN(nn.Module): def __init__(self, n_observations: int, n_actions: int): super(DQN, self).__init__() self.layer1 = nn.Linear(n_observations, 128) self.layer2 = nn.Linear(128, 128) self.layer3 = nn.Linear(128, n_actions) # Outputs Q-value for each action def forward(self, x: torch.Tensor) -> torch.Tensor: """ Forward pass to get Q-values. """ # Ensure input is float tensor on correct device if not isinstance(x, torch.Tensor): x = torch.tensor(x, dtype=torch.float32, device=x.device) elif x.dtype != torch.float32: x = x.to(dtype=torch.float32) x = F.relu(self.layer1(x)) x = F.relu(self.layer2(x)) return self.layer3(x) # Raw Q-values ```

This network learns the mapping from state to action-values.

Next, the Replay Memory stores experiences.

```python # Structure for storing transitionsTransition = namedtuple('Transition', ('state', 'action', 'next_state', 'reward', 'done'))# Replay Memory Bufferclass ReplayMemory: def __init__(self, capacity: int): self.memory = deque([], maxlen=capacity) def push(self, *args: Any) -> None: """ Saves a transition tuple (s, a, s', r, done). """ # Ensure tensors are stored on CPU to avoid GPU memory issues with buffer processed_args = [] for arg in args: if isinstance(arg, torch.Tensor): processed_args.append(arg.cpu()) elif isinstance(arg, bool): # Store done flag as tensor for consistency processed_args.append(torch.tensor([arg], dtype=torch.bool)) else: processed_args.append(arg) self.memory.append(Transition(*processed_args)) def sample(self, batch_size: int) -> Optional[List[Transition]]: """ Samples a random batch of transitions. """ if len(self.memory) < batch_size: return None return random.sample(self.memory, batch_size) def __len__(self) -> int: return len(self.memory) ```

This buffer allows sampling uncorrelated batches for training updates. Action selection uses epsilon-greedy based on the main Q-network’s output.

```python # Action Selection (Epsilon-Greedy using DQN)def select_action_dqn(state: torch.Tensor, policy_net: nn.Module, epsilon: float, n_actions: int, device: torch.device) -> torch.Tensor: """ Selects action epsilon-greedily using the policy Q-network. """ if random.random() < epsilon: # Explore: choose a random action action = torch.tensor([[random.randrange(n_actions)]], device=device, dtype=torch.long) else: # Exploit: choose the best action based on Q-network with torch.no_grad(): # Add batch dim if needed, ensure tensor is on correct device state = state.unsqueeze(0) if state.dim() == 1 else state state = state.to(device) # Get Q-values and select action with max Q action = policy_net(state).max(1)[1].view(1, 1) return action ```

The optimization step calculates the TD target using the _target network_ and updates the _main policy network_.

```python # DQN Optimization Step Outlinedef optimize_model_dqn(memory: ReplayMemory, policy_net: DQN, target_net: DQN, optimizer: optim.Optimizer, batch_size: int, gamma: float, device: torch.device): """ Performs one step of optimization on the DQN policy network. ## MADDPG (Multi-Agent Settings)

Handling multiple agents learning simultaneously presents a unique challenge: **non-stationarity**.

From any single agent’s perspective, the environment keeps changing as other agents update their policies. Multi-Agent Deep Deterministic Policy Gradient (MADDPG) extends DDPG to address this by using **centralized training with decentralized execution**.

Each agent learns its own Actor network based on local observations, but training involves a centralized Critic for each agent that receives information (observations and actions) from _all_ agents.

This shared information during training helps stabilize learning.

MADDPG (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

Each agent `(1, 2, ...N)` acts in the environment using **only its local observation** (`o1, o2`) and its own **Actor network** (`μ_θ1`, `μ_θ2`) to produce an action (`a1, a2`), adding **noise** for exploration. The **joint experience** (all **observations, actions, rewards, next observations**) is stored in a **shared replay buffer**.

1. **Critic Update (Agent i):**
The **Critic** for agent `i` (`Q_ϕi`) is updated using a **target value**. This target depends on: The **reward** for agent `i` (`r_i`). The output of the **target centralized critic** (`Q_ϕi′`), which takes as input: The **joint next observations.** The **next actions** predicted by **all target actors** (`μ_θj′(o_j′)`)
2. The **Actor** for agent `i` (`μ_θi`) is updated to produce **actions** that maximize the **Q-value** estimated by its **main centralized critic** (`Q_ϕi`), while considering the **current actions** of all actors.
3. All **target networks** are updated **slowly via soft updates** from their **main network** counterparts.

The core concept behind this MADDPG is:

* **Decentralized Actors:** Each agent `i` has its own policy network `μ_i(o_i)` that only uses its **local observation** `o_i` to choose an action `a_i`.
* **Centralized Critic:** Each agent `i` has a corresponding **critic network** `Q_i(x, a_1, ..., a_N)` that takes the **joint state/observations** `x` and **all agents' actions** `(a_1, ..., a_N)` as input to estimate the **value** for agent `i`.
* **Off-Policy:** Uses a **replay buffer** storing **joint transitions** , allowing learning from **past experiences**.

The Actor network for each agent is typically similar to the DDPG actor, outputting a deterministic action (or probabilities if adapted for discrete actions).

```python # Actor Network (similar to DDPG's, one per agent)class ActorNetworkMADDPG(nn.Module): def __init__(self, obs_dim: int, action_dim: int, max_action: float): super(ActorNetworkMADDPG, self).__init__() self.layer1 = nn.Linear(obs_dim, 128) self.layer2 = nn.Linear(128, 128) self.layer3 = nn.Linear(128, action_dim) self.max_action = max_action def forward(self, obs: torch.Tensor) -> torch.Tensor: x = F.relu(self.layer1(obs)) x = F.relu(self.layer2(x)) action = self.max_action * torch.tanh(self.layer3(x)) # Scaled continuous action return action ```

The crucial difference is the Centralized Critic, which takes _all_ information as input.

```python # Centralized Critic Network (one per agent)class CentralizedCriticMADDPG(nn.Module): def __init__(self, joint_obs_dim: int, joint_action_dim: int): super(CentralizedCriticMADDPG, self).__init__() # Input size = combined dimension of all observations + all actions self.layer1 = nn.Linear(joint_obs_dim + joint_action_dim, 256) self.layer2 = nn.Linear(256, 256) self.layer3 = nn.Linear(256, 1) # Outputs single Q-value for this agent def forward(self, joint_obs: torch.Tensor, joint_actions: torch.Tensor) -> torch.Tensor: # Concatenate all observations and all actions x = torch.cat([joint_obs, joint_actions], dim=1) x = F.relu(self.layer1(x)) x = F.relu(self.layer2(x)) q_value = self.layer3(x) return q_value ```

This critic learns agent i’s expected return given what _everyone_ is doing and observing.

The replay buffer needs to store the joint experience (o_list, a_list, r_list, o_next_list, done_list).

``` # --- MADDPG Update Logic Outline (for agent i) ---# Assumes optimizers, targets, batch sampling are handled# 1. Sample batch of joint transitions from buffer:batch_obs, batch_actions, batch_rewards, batch_next_obs, batch_dones# --- Critic_i Update ---with torch.no_grad(): target_next_actions = [target_actor_j(batch_next_obs_j) for j in range(num_agents)] target_next_actions_cat = torch.cat(target_next_actions, dim=1) joint_next_obs_cat = batch_next_obs.view(batch_size, -1) q_target_next = target_critic_i(joint_next_obs_cat, target_next_actions_cat) td_target_i = batch_rewards_i + gamma * (1 - batch_dones_i) * q_target_nextjoint_obs_cat = batch_obs.view(batch_size, -1)joint_actions_cat = batch_actions.view(batch_size, -1)q_current_i = critic_i(joint_obs_cat, joint_actions_cat)critic_loss_i = F.mse_loss(q_current_i, td_target_i.detach())# Optimize critic_i# --- Actor_i Update ---# Freeze critic gradientscurrent_actions = [actor_j(batch_obs_j) for j in range(num_agents)]current_actions[i] = actor_i(batch_obs_i)current_actions_cat = torch.cat(current_actions, dim=1)actor_loss_i = -critic_i(joint_obs_cat, current_actions_cat).mean()# Optimize actor_i# Unfreeze critic gradients# --- Soft Update Target Networks ---soft_update(target_critic_i, critic_i, tau)soft_update(target_actor_i, actor_i, tau) ```

The update logic involves coordinated use of these components. By using the centralized critic during training, MADDPG provides each actor with a stable learning signal that accounts for the actions of other agents, mitigating the non-stationarity problem while still allowing for decentralized execution.

## QMIX (Value Decomposition for Cooperation)

QMIX (`Q-value Mixing`) is specifically designed for cooperative multi-agent reinforcement learning tasks where agents share a common team reward. Like `MADDPG`, it uses centralized training and decentralized execution.

However, instead of learning a separate centralized critic for each agent, QMIX learns individual agent `Q-functions` (`Q_i`) based on local observations and combines them through a special `Mixing Network` to estimate the joint action-value function (`Q_tot`).

The key insight is that for many cooperative tasks, if an agent takes an action that increases its local utility (`Q_i`), it should also increase (or at least not decrease) the overall team's utility (`Q_tot`). QMIX enforces this `monotonicity constraint` structurally within its `Mixing Network`.

This ensures that `decentralized greedy action selection` based on individual `Q_i` values corresponds to selecting the greedy joint action based on `Q_tot`.

The `Mixing Network` itself takes the `global state` as input (via `hypernetworks`) to allow the way individual utilities combine to depend on the overall context.

QMIX (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

During execution, each agent `i` uses its local observation `o_i` and its network `Q_i(θ_i)` to choose an action `a_i` (typically epsilon-greedily). The joint experience, including the `global state x`, is stored.

### Target `Q_tot'` Calculation:

* For each agent `i`, the target agent network `Q_i'(θ_i')` is used to find the `Q-value` corresponding to the best possible action from the next observation `o_i'`.
* These individual maximum `Q-values` are fed into the target `Mixing Network` `f_mix'(ϕ_mix')`, which also takes the next `global state x'` as input, to produce the target joint value `Q_tot'`.
* The standard TD target `y` is then calculated: `y = r + γQ_tot'`.

### Current `Q_tot` Calculation & Loss:

* For each agent `i`, the main agent network `Q_i(θ_i)` computes the `Q-value` for the action `a_i` actually taken in the batch.
* These `Q-values` are fed into the main `Mixing Network` `f_mix(ϕ_mix)`, along with the current `global state x`, to produce the current `Q_tot`.
* The `MSE loss` between `y` and `Q_tot` is calculated.

### Optimization:

A single `optimizer` updates the parameters of all agent networks (`θ_i`) and the `Mixing Network` (`ϕ_mix`) based on the computed loss. `Target networks` are updated via `soft updates`.

First, the individual agent network. It’s a standard Q-network taking local observation and outputting Q-values for each action.

```python # Agent Network (similar to DQN's Q-network)class AgentQNetwork(nn.Module): def __init__(self, obs_dim: int, action_dim: int): super(AgentQNetwork, self).__init__() # Could be MLP or RNN (DRQN) depending on observability needs self.fc1 = nn.Linear(obs_dim, 64) self.fc2 = nn.Linear(64, 64) self.fc3 = nn.Linear(64, action_dim) # Q-values for each action def forward(self, obs: torch.Tensor) -> torch.Tensor: x = F.relu(self.fc1(obs)) x = F.relu(self.fc2(x)) q_values = self.fc3(x) return q_values ```

The Mixing Network is the novel part, using hypernetworks.

```python # Simplified QMIX Mixing Networkclass QMixer(nn.Module): def __init__(self, num_agents: int, global_state_dim: int, mixing_embed_dim: int = 32): super(QMixer, self).__init__() self.num_agents = num_agents self.state_dim = global_state_dim self.embed_dim = mixing_embed_dim # Hypernetwork for W1 (generates positive weights) self.hyper_w1 = nn.Sequential( nn.Linear(self.state_dim, 64), nn.ReLU(), nn.Linear(64, self.num_agents * self.embed_dim) ) # Hypernetwork for b1 self.hyper_b1 = nn.Linear(self.state_dim, self.embed_dim) # Hypernetwork for W2 (generates positive weights) self.hyper_w2 = nn.Sequential( nn.Linear(self.state_dim, 64), nn.ReLU(), nn.Linear(64, self.embed_dim) # Output size embed_dim -> reshape to (embed_dim, 1) ) # Hypernetwork for b2 (scalar bias) self.hyper_b2 = nn.Sequential( nn.Linear(self.state_dim, 32), nn.ReLU(), nn.Linear(32, 1) ) def forward(self, agent_qs: torch.Tensor, global_state: torch.Tensor) -> torch.Tensor: # agent_qs shape: (batch_size, num_agents) # global_state shape: (batch_size, global_state_dim) batch_size = agent_qs.size(0) agent_qs_reshaped = agent_qs.view(batch_size, 1, self.num_agents) # Generate weights/biases from global state w1 = torch.abs(self.hyper_w1(global_state)).view(batch_size, self.num_agents, self.embed_dim) b1 = self.hyper_b1(global_state).view(batch_size, 1, self.embed_dim) w2 = torch.abs(self.hyper_w2(global_state)).view(batch_size, self.embed_dim, 1) b2 = self.hyper_b2(global_state).view(batch_size, 1, 1) # Mixing layers (ensure non-linearity like ELU/ReLU after first layer) hidden = F.elu(torch.bmm(agent_qs_reshaped, w1) + b1) # (batch, 1, embed_dim) q_tot = torch.bmm(hidden, w2) + b2 # (batch, 1, 1) return q_tot.view(batch_size, 1) # Return shape (batch, 1) ```

The update logic involves getting Qi ​values for the relevant actions, passing them through the mixer, calculating the TD target using target networks, and backpropagating the loss through both the mixer and all agent networks.

QMIX provides a structured way to learn cooperative policies by factorizing the team value function while ensuring individual contributions align with the global goal through the monotonicity constraint.

## HAC (Hierarchy for Long-Horizon Tasks)

Flat RL agents often struggle with tasks requiring long sequences of actions or where rewards are very sparse.

Hierarchical Reinforcement Learning (HRL) addresses this by learning policies at multiple levels of abstraction.

Higher levels set goals (subgoals) for lower levels, breaking down the complex task. Hierarchical Actor-Critic (HAC) is one such approach using goal-conditioned policies and hindsight learning.

Press enter or click to view image in full size

HAC (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

HAC (`Hierarchical Actor-Critic`) uses multiple levels:

* **High Level (Level 1):** Observes the state `s` and the final goal `G`, and its policy (`π_1`) chooses a subgoal `g₀` for the level below it.
* **Low Level (Level 0):** Receives the current state `s` and the subgoal `g₀`. Its policy (`π_0`) selects primitive actions `a` to try and reach `g₀` within a fixed time limit `H`. It receives an `intrinsic reward` based on whether it successfully achieved `g₀`, which is used to update its policy.
* **High Level Update:** The high level receives the total `environment reward` accumulated while the low level was active. It updates its policy based on the state transition (from where the subgoal was set to where the low level ended up).

Both levels may use `critics (V_0, V_1)` to estimate values or advantages. `Hindsight experience replay` (relabeling transitions with achieved goals) is crucial for efficient learning, especially for the low level.

We need goal-conditioned networks. For our discrete grid world, we can adapt the DQN Q-network structure. The input dimension will be state_dim + goal_dim.

```python # Goal-Conditioned Q-Network (Can be used for Actor/Critic proxy in HAC)# Assumes state and goal are concatenated as inputclass GoalConditionedQNetwork(nn.Module): def __init__(self, input_dim: int, action_dim: int): super(GoalConditionedQNetwork, self).__init__() self.fc1 = nn.Linear(input_dim, 128) self.fc2 = nn.Linear(128, 128) # Output depends on level: # L0: Q-values for primitive actions # L1: Q-values for selecting discrete subgoals self.fc3 = nn.Linear(128, action_dim) def forward(self, state_goal_concat: torch.Tensor) -> torch.Tensor: x = F.relu(self.fc1(state_goal_concat)) x = F.relu(self.fc2(x)) q_values = self.fc3(x) return q_values# --- Network Dimensions ---# state_dim = env.state_dim# goal_dim = env.goal_dim # Usually same as state_dim if goals are states# primitive_action_dim = env.action_dim# subgoal_action_dim = env.rows * env.cols # If subgoals are discrete grid cells# low_level_net = GoalConditionedQNetwork(state_dim + goal_dim, primitive_action_dim)# high_level_net = GoalConditionedQNetwork(state_dim + goal_dim, subgoal_action_dim) ```

This network structure takes both the current state and the target goal to output Q-values for the level-specific actions (primitive actions for L0, subgoal selections for L1).

A crucial component is the Hindsight Replay Buffer, which stores transitions and relabels goals.

```python # Simplified Hindsight Replay Buffer Conceptclass HindsightReplayBuffer: def __init__(self, capacity: int, hindsight_prob: float = 0.8): self.memory = deque([], maxlen=capacity) self.hindsight_prob = hindsight_prob def push(self, state, action, reward, next_state, goal, done, level, achieved_goal): # Store the full transition including the intended goal and what was achieved self.memory.append({ 'state': state, 'action': action, 'reward': reward, 'next_state': next_state, 'goal': goal, 'done': done, 'level': level, 'achieved_goal': achieved_goal }) def sample(self, batch_size: int, level: int): # 1. Filter buffer for transitions of the correct 'level' # 2. Sample a batch of these transitions # 3. For each transition in the batch: # - Keep the original transition (state, action, reward, next_state, goal, done) # - With probability 'hindsight_prob': # - Create a *new* hindsight transition: # - Use the same state, action, next_state. # - Replace 'goal' with 'achieved_goal'. # - Recalculate 'reward' based on whether next_state matches the *new* hindsight goal # (e.g., 0 if matched, -1 if not for L0 intrinsic reward). # - Recalculate 'done' based on whether the hindsight goal was achieved. # - Add this hindsight transition to the batch being prepared. # 4. Convert the final batch (originals + hindsight) into tensors. ```

HAC combines these components hierarchically: the high level proposes subgoals, the low level attempts to achieve them within a time limit, and both levels learn from their experiences (including hindsight relabeling) using off-policy updates.

## MCTS (Planning via Simulated Exploration)

Monte Carlo Tree Search (MCTS) shifts focus from learning value/policy functions covering the _entire_ state space to performing focused **online planning** from the _current_ state.

Given a state, MCTS simulates many possible future trajectories using a known model (or simulator) of the environment, building a search tree to identify the most promising immediate action.

MCTS (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

Each MCTS iteration performs four steps starting from the root node (current state):

1. **Selection:** Traverse the existing tree by repeatedly choosing child nodes based on a selection strategy (like UCB1) that balances exploration (visiting less-explored nodes) and exploitation (visiting nodes with high average rewards from past simulations). This continues until a leaf node (one not fully expanded) is reached.
2. **Expansion:** If the leaf node isn’t terminal, expand it by choosing one previously untried action, simulating it to get the next state, and adding a new child node representing that state to the tree.
3. **Simulation (Rollout):** From the newly expanded node (or the selected leaf if it couldn’t be expanded), run a simulation using a simple, fast “rollout policy” (often random actions) until the end of the episode (or a depth limit). Record the total reward obtained during this simulation.
4. **Backpropagation:** Update the statistics (visit count ’N’ and total reward ‘W’) of all nodes visited during the Selection and Expansion phases with the result ‘R’ from the simulation.

First, we need a structure to represent the nodes in the tree.

Following are some core concept of MCTS:

1. Search Tree: Nodes represent states, edges represent actions.
2. Node Statistics: Each node stores visit count `N(s)` and total value `W(s)` (sum of rollout rewards passing through it). The average value is `Q(s) = W(s) / N(s)`. Edge statistics (`N(s,a)`, `W(s,a)`) are also common.
3. UCT (`UCB1` for Trees): The selection strategy, balancing exploitation (`Q(s,a)`) and exploration (`ln N(s) / N(s,a)`).
4. Rollout Policy: A simple policy (e.g., random) used during the Simulation phase. Its quality affects the accuracy of value estimates.
5. Model/Simulator: `MCTS` requires a way to predict the next state and reward given a state and action (either a known model or access to a simulator).

First, we need a structure to represent the nodes in the tree.

```python class MCTSNode: """ Represents a node in the Monte Carlo Tree Search. """ def __init__(self, state: Tuple[int, int], parent: Optional['MCTSNode'] = None, action: Optional[int] = None): self.state = state self.parent = parent self.action_that_led_here = action # Action parent took to get here self.children: Dict[int, MCTSNode] = {} # map action -> child node # Function to get possible actions (depends on the environment) self.untried_actions: List[int] = self._get_possible_actions(state) self.visit_count: int = 0 self.total_value: float = 0.0 # Sum of rewards from rollouts def _get_possible_actions(self, state): # Placeholder: Replace with actual environment call # Example for grid world (assuming env is accessible or passed): if env.is_terminal(state): return [] return list(range(env.get_action_space_size())) # Or env.get_valid_actions(state) def is_fully_expanded(self) -> bool: return not self.untried_actions def is_terminal(self) -> bool: # Placeholder: Replace with actual environment call return env.is_terminal(self.state) def get_average_value(self) -> float: return self.total_value / self.visit_count if self.visit_count > 0 else 0.0 def select_best_child_uct(self, exploration_constant: float) -> 'MCTSNode': """ Selects child node with the highest UCT score. """ best_score = -float('inf') best_child = None for action, child in self.children.items(): if child.visit_count == 0: score = float('inf') # Prioritize unvisited nodes else: exploit = child.get_average_value() explore = exploration_constant * math.sqrt(math.log(self.visit_count) / child.visit_count) score = exploit + explore if score > best_score: best_score = score best_child = child if best_child is None: # Should only happen if node has no children yet return self # Should ideally not be called on a node with no children return best_child ```

This node stores state, parent/child links, and the crucial visit count (N) and total value (W) statistics.

The main MCTS search function orchestrates the four steps (Selection, Expansion, Simulation, Backpropagation).

MCTS performs an online search using simulated rollouts from the current state to determine the best immediate action, leveraging statistical information gathered in the tree to guide exploration.

## PlaNet (Planning in Learned Latent Space)

PlaNet (Deep Planning Network) represents a sophisticated **model-based** approach, particularly effective for learning from high-dimensional observations like images.

Its core innovation is learning a **world model** (dynamics model) not in the complex observation space, but in a compact, learned **latent space**. Planning is then performed efficiently within this latent space.

Press enter or click to view image in full size

PlaNet (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--714ec2f581e5--------------------------------------->)

)

The agent observes the environment (`o_t`). An encoder maps this (potentially along with past context) to a latent state (`s_t`).

The planner (`CEM`), using the current latent state and the learned World Model, searches for the best action sequence over a future horizon.

Only the first action (`a_t*`) from the best sequence is taken in the real environment. The resulting observation (`o_{t+1}`), action (`a_t*`), reward (`r_t`), and done flag are stored as part of a sequence in the replay buffer.

Separately (often in parallel or interleaved), batches of sequences are sampled from the buffer to train and improve the World Model (which includes the encoder, transition predictor, reward predictor, etc.).

Implementing a full PlaNet with image processing and RSSMs is complex. For illustration with vector states (like Pendulum), we simplify:

1. The “latent state” can be approximated by the environment’s state vector (or a simple MLP encoding of it).
2. The world model becomes MLPs predicting the next state vector and reward.

```python # Simplified Dynamics Model (Predicts next state vector and reward)class DynamicsModel(nn.Module): def __init__(self, state_dim: int, action_dim: int, hidden_dim: int = 200): super(DynamicsModel, self).__init__() self.fc1 = nn.Linear(state_dim + action_dim, hidden_dim) self.fc2 = nn.Linear(hidden_dim, hidden_dim) self.fc_next_state = nn.Linear(hidden_dim, state_dim) self.fc_reward = nn.Linear(hidden_dim, 1) def forward(self, state: torch.Tensor, action: torch.Tensor) -> Tuple[torch.Tensor, torch.Tensor]: # Concatenate state and action x = torch.cat([state, action], dim=-1) x = F.relu(self.fc1(x)) x = F.relu(self.fc2(x)) pred_next_state = self.fc_next_state(x) pred_reward = self.fc_reward(x) return pred_next_state, pred_reward ```

This network learns to predict the immediate future based on the current state and action.

The planner uses this model to find the best action sequence. CEM is a common choice.

```python # CEM Planner Outlinedef cem_planner(model: DynamicsModel, initial_state: torch.Tensor, horizon: int, num_candidates: int, num_elites: int, num_iterations: int, gamma: float, action_low, action_high, action_dim, device) -> torch.Tensor: # Initialize action distribution (e.g., Gaussian mean=0, std=high) action_mean = torch.zeros(horizon, action_dim, device=device) action_std = torch.ones(horizon, action_dim, device=device) # Start with high variance for _ in range(num_iterations): # 1. Sample candidate action sequences (batch, horizon, action_dim) action_dist = Normal(action_mean, action_std) candidate_actions = action_dist.sample((num_candidates,)) candidate_actions = torch.clamp(candidate_actions, torch.tensor(action_low, device=device), torch.tensor(action_high, device=device)) # 2. Evaluate sequences using the model total_rewards = torch.zeros(num_candidates, device=device) current_states = initial_state.repeat(num_candidates, 1) with torch.no_grad(): for t in range(horizon): actions_t = candidate_actions[:, t, :] next_states, rewards = model(current_states, actions_t) total_rewards += (gamma ** t) * rewards.squeeze(-1) # Ensure reward is squeezed current_states = next_states # 3. Select elite action sequences _, elite_indices = torch.topk(total_rewards, num_elites) elite_actions = candidate_actions[elite_indices] # 4. Refit the action distribution action_mean = elite_actions.mean(dim=0) action_std = elite_actions.std(dim=0) + 1e-6 # Add epsilon for stability # Return the first action of the final mean sequence return action_mean[0] ```

The CEM planner iteratively refines a distribution over action sequences by simulating trajectories with the learned model and focusing the distribution on high-performing sequences.

The training involves collecting sequences, storing them in a sequence-aware buffer, and training the dynamics model to minimize prediction errors (e.g., MSE for next state and reward).

``` # --- Model Training Outline ---# (Assumes model, optimizer, sequence_buffer are defined) for _ in range(num_train_steps): 1. Sample batch of sequences from sequence_buffer 2. For each step in the sequence (or a subset): - Get state_t, action_t, reward_t, next_state_t from batch - Predict next_state_pred, reward_pred = model(state_t, action_t) - Calculate loss = MSE(next_state_pred, next_state_t) + MSE(reward_pred, reward_t) 3. Average loss over batch/steps 4. optimizer.zero_grad() 5. loss.backward() 6. optimizer.step() ```

## Which Algorithm to Use?

For simple tasks with discrete actions, Q-Learning or SARSA are great starting points. If stability and sample efficiency are crucial, especially in complex environments, PPO often proves robust and effective.

For continuous control problems like robotics, SAC and DDPG are strong contenders, with SAC often showing better stability and exploration. If you can simulate the environment cheaply, model-based methods like PlaNet or planning like MCTS can be extremely powerful.

While there’s no single winner, PPO and SAC stand out as popular, good choices for many modern RL challenges. Start there, but remember the best fit truly depends on your specific environment and goals.
