## What’s This Article About?

This article is about building an AI-powered drive-through voice assistant for a restaurant chain called AniDonald’s. The voice assistant is designed to interact with customers at the drive-through window, take their orders, provide information about the menu, and assist with the ordering process. The article walks through the implementation of the voice assistant using various technologies, including LLM for natural language processing, speech recognition, and vector databases.

## Let’s Design

So my goal is to have an architecture that ensures a seamless interaction at the drive-thru, powered by local AI and efficient data handling, all maintained without reliance on cloud services.

![image](https://miro.medium.com/v2/resize:fit:700/1*TvVioDpss1k9mzILbt-CMA.png)

### **Admin** :

* **Role** : The Admin is responsible for setting up and maintaining the menu.
* **Interaction** : The Admin interacts with the `Menu_DB` to add, update, or delete menu items.

### **Menu_DB** :

* **Role** : This database stores the menu items and their details.
* **Interaction** : It receives updates from the Admin and provides menu data to the `AniBot` via the `Menu DB Handler`.

### **Customer at Drive-Thru** :

* **Role** : The customer interacts with the drive-thru interface to place their order.
* **Interaction** : The customer uses the `Drive Thru UI` to communicate their order.

### **Drive Thru UI** :

* **_Role_** : This user interface facilitates the interaction between the customer and the AI system.
* **_Interaction_** _:_
* **Voice to Text** : Converts the customer’s spoken order into text.
* **Text to Voice** : Converts the AI’s textual response back into speech for the customer.

### **AniBot** :

**_Role_** : The central AI bot that manages the interaction and processing of orders.

**_Interaction_** :

* **_Voice to Text_** _:_ Receives voice input from the `Drive Thru UI` and converts it to text.
* **Text to Voice** : Sends text output to the `Drive Thru UI` to be converted into speech.
* **_Handlers and Components_** _:_
* **Audio Handler** : Manages audio processing tasks, such as converting text to speech and vice versa.
* **Menu DB Handler** : Interfaces with the `Menu_DB` to fetch and update menu data.
* **Response** : Generates appropriate responses based on user queries and menu data.
* **Reasoning** : Handles logical processing and decision-making tasks to provide intelligent responses.
* **User Session Memory** : Stores information about the current user session to maintain context and continuity in interactions.

### **Configuration Files** :

* **config.json** and **model_config.json** : These files contain configuration settings and model parameters necessary for the AI system to function properly.
* **Role** : They provide the `AniBot` with essential configurations for various components and functionalities.

## Interaction Flow:

**Menu Management** :

* The Admin updates the menu in the `Menu_DB`.
* The `Menu DB Handler` retrieves updated menu information for `AniBot`.

**Order Placement** :

* The customer speaks their order into the `Drive Thru UI`.
* The `Drive Thru UI` converts the voice input into text.
* The text input is sent to `AniBot`.

**AI Processing** :

* `AniBot` processes the text input using the `Reasoning` component to understand the order.
* `AniBot` may interact with the `Menu_DB` via the `Menu DB Handler` to validate or fetch additional details about the order.
* `AniBot` generates a textual response using the `Response` component.

**Order Confirmation** :

* The textual response is sent back to the `Drive Thru UI`.
* The `Drive Thru UI` converts the text response into voice.
* The customer hears the response and can confirm or modify their order.

```python def check_call_pause(data, max_amplitude_threshold=3000): """ Check if audio data contains silence based on a maximum amplitude threshold. Args: data (numpy.ndarray): The audio data to be analyzed. max_amplitude_threshold (int, optional): The amplitude threshold below which the audio is considered silent. Defaults to 3000. Returns: bool: True if the maximum amplitude is below or equal to the threshold, indicating silence. False otherwise. """ max_amplitude = np.max(np.abs(data)) return max_amplitude <= max_amplitude_threshold ```

Now, this is an important function I wrote to detect if a given audio data contains silence or not. I named it `check_call_pause` because its purpose is to check if there's a pause or silence in the audio data. The function takes two arguments: `data`, which is the actual audio data as a NumPy array, and `max_amplitude_threshold`, which is the threshold value for determining silence.

I set the default value for `max_amplitude_threshold` to 3000 because, based on my testing and research, this seemed to work well for distinguishing between silence and actual audio. However, I made it an optional argument so that the caller can override this value if needed.

Inside the function, I calculate the maximum absolute value of the audio data using `np.max(np.abs(data))`. This gives me the maximum amplitude of the audio signal. If this maximum amplitude is less than or equal to the `max_amplitude_threshold`, I consider the audio data to be silent, and the function returns `True`. Otherwise, it returns `False`.

I wrote this function because, in many audio applications, it’s important to detect silence or pauses in the audio stream. This can be useful for things like voice activity detection, automatic speech recognition, and other audio processing tasks.

```python def embedd_audio(audio, stream, chunk_length=DEFAULT_CHUNK_LENGTH): """ Record a chunk of audio, save it to a temporary file, and check if it contains silence. Args: audio (pyaudio.PyAudio): The PyAudio instance used to get sample size. stream (pyaudio.Stream): The audio stream from which to read data. chunk_length (int, optional): The length of the audio chunk to record in seconds. Defaults to DEFAULT_CHUNK_LENGTH. Returns: bool: True if the recorded chunk contains silence, False otherwise. """ frames = [] # Read audio data in chunks and append to frames for _ in range(0, int(16000 / 1024 * chunk_length)): data = stream.read(1024) frames.append(data) temp_file_path = 'inflight_audio.wav' # Save the recorded frames to a temporary WAV file with wave.open(temp_file_path, 'wb') as wf: wf.setnchannels(1) wf.setsampwidth(audio.get_sample_size(pyaudio.paInt16)) wf.setframerate(16000) wf.writeframes(b''.join(frames)) # Check if the recorded chunk contains silence try: samplerate, data = wavfile.read(temp_file_path) if check_call_pause(data): os.remove(temp_file_path) return True else: return False except Exception as e: print(f"Error while reading audio file: {e}") return False ```

This is a crucial function I wrote for recording audio chunks and checking if they contain silence. Let me walk you through it.

The function takes three arguments: `audio`, which is an instance of the PyAudio class used for audio input/output, `stream`, which is an audio stream object from which we'll read the audio data, and `chunk_length`, which is the length of the audio chunk to be recorded in seconds. If `chunk_length` is not provided, the function uses the `DEFAULT_CHUNK_LENGTH` constant we defined earlier.

Inside the function, I first initialize an empty list called `frames` to store the audio data frames.

Then, I use a `for` loop to read audio data from the `stream` in chunks of 1024 bytes. The number of iterations in the loop is calculated based on the desired `chunk_length` and the sample rate of 16000 Hz. For each iteration, I read 1024 bytes of audio data from the stream and append it to the `frames` list.

After reading all the audio data for the desired chunk length, I create a temporary WAV file called `inflight_audio.wav` and write the recorded frames to this file using the `wave` module.

Once the audio data is written to the temporary file, I use the `wavfile.read` function from the `scipy.io` module to read the audio data back from the file. This gives me the sample rate and the audio data as a NumPy array.

Next, I call the `check_call_pause` function we defined earlier, passing the audio data as an argument. If `check_call_pause` returns `True`, indicating that the audio chunk contains silence, I remove the temporary file and return `True` from the `embedd_audio` function.

If `check_call_pause` returns `False`, meaning the audio chunk does not contain silence, I simply return `False` from the `embedd_audio` function.

I also included a `try`-`except` block to handle any exceptions that might occur while reading the audio file. If an exception is raised, I print an error message and return `False` from the function.

I wrote this function because it’s a handy utility for recording audio chunks and checking if they contain silence. This can be useful in various audio processing applications, such as voice activity detection, speech recognition, and audio recording.

```python def transcribe_audio(model, file_path): """ Transcribe the audio file using a provided transcription model. Args: model: The transcription model to use. file_path (str): The path to the audio file to transcribe. Returns: str: The transcription of the audio file. """ segments, info = model.transcribe(file_path, beam_size=7) transcription = ' '.join(segment.text for segment in segments) return transcription ```

Finally, we have the `transcribe_audio` function, which is responsible for transcribing an audio file using a provided transcription model.

The function takes two arguments: `model`, which is the transcription model to be used, and `file_path`, which is the path to the audio file that needs to be transcribed.

Inside the function, I call the `transcribe` method of the provided `model`, passing the `file_path` and `beam_size=7` as arguments. The `beam_size` parameter is specific to the transcription model I'm using and determines the number of hypotheses considered during the transcription process.

The `model.transcribe` method returns two values: `segments`, which is a list of transcribed segments, and `info`, which contains additional information about the transcription process.

To obtain the final transcription, I join the text of all the transcribed segments using a space character as the separator. I do this using a list comprehension and the `join` method: `' '.join(segment.text for segment in segments)`. This gives me a single string containing the complete transcription of the audio file.

Finally, I return this transcription string from the function.

I wrote this function to abstract away the details of the transcription process and provide a simple interface for transcribing audio files. By separating the transcription logic into its own function, I can easily swap out the transcription model or modify the transcription process without affecting the rest of the code.
