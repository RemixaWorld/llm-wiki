## Adding Representation Models

Representation models refine the extracted keywords to ensure they align with the semantic meaning of the documents in each cluster.

### 1\. KeyBERTInspired Representation

This representation block from the BERTopic library allows us to compute an **average embedding vector** for all documents in a cluster and rank keywords based on their **cosine similarity** to the keyword vectors. Keywords that are more semantically aligned with the documents appear higher in the **ranking**. The following diagram gives us a big picture of how KeyBERTInspired performs this process.

KeyBERTInspired representation model procedure

### 2\. Maximum Marginal Relevance (MMR)

MMR diversifies the selected keywords, ensuring that each contributes unique information. This reduces redundancy, such as repetitive terms like

The topic representations generated through c-TF-IDF and KeyBERTInspired methods often contain redundant terms. A clear example is when semantically similar words like `summary`, `summarization`, and `summarized` appear in the same topic representation.

To address this redundancy, we can leverage maximal marginal relevance (MMR). This approach helps create more diverse topic representations while maintaining relevance to the source documents. MMR works by first creating embeddings of potential keywords, then selecting them one by one based on a diversity parameter that controls how different the chosen keywords should be from each other.

## Final Pipeline

To ensure everyone can follow along, let’s start fresh and walk through the complete code implementation from start to finish.

### Step 1: Install Dependencies

```python pip install sentence-transformers xformers bertopic datasets openai datamapplot plotly ```

### Step 2: Load Dataset

```python # Load data from huggingfacefrom datasets import load_datasetdataset = load_dataset("maartengr/arxiv_nlp")["train"]# Extract metadataabstracts = dataset["Abstracts"]titles = dataset["Titles"] ```

### Step 3: Generate Embeddings

Use `stella_en_400M_v5` from `sentence-transformers` library.

```python from sentence_transformers import SentenceTransformer# Create an embedding for each abstractembedding_model = SentenceTransformer('dunzhang/stella_en_400M_v5', trust_remote_code=True)embeddings = embedding_model.encode(abstracts, show_progress_bar=True) ```

### Step 4: Dimensionality Reduction

Reduce high-dimensional embeddings to 10D using **UMAP**.

```python from umap import UMAP# We reduce the input embeddings from 1024 dimenions to 10 dimenionsumap_model = UMAP( n_components=10, min_dist=0.0, metric='cosine', random_state=42)reduced_embeddings = umap_model.fit_transform(embeddings) ```

### Step 5: Clustering

Using the obtained reduced embeddings from previous step, form clusters using **HDBSCAN**.

```python from hdbscan import HDBSCAN# We fit the model and extract the clustershdbscan_model = HDBSCAN( min_cluster_size=50, metric='euclidean', cluster_selection_method='eom').fit(reduced_embeddings)clusters = hdbscan_model.labels_ ```

### Step 6: Topic Modeling with BERTopic

Combine embedding, dimensionality reduction, and clustering in BERTopic.

```python from bertopic import BERTopic# Train our model with our previously defined modelstopic_model = BERTopic( embedding_model=embedding_model, umap_model=umap_model, hdbscan_model=hdbscan_model, verbose=True).fit(abstracts, embeddings) ```

### Step 7: Integrate Representation Models — Fine-Tuning Representations

**Explanation for both GPT-4o and Llama3.1:8b — Key Insights:**

**1\. Scope of Terminology** :

* `gpt-4o` uses more specific and technical phrases like “Open-Domain,” “Neural,” and “Offensive Language.”
* `llama3.1:8b` opts for broader and more generalized terminology.

**2\. Contextual Focus** :

* `gpt-4o` often emphasizes domain-specific nuances (e.g., “Deep Learning,” “Offensive Language”).
* `llama3.1:8b` generalizes concepts, making the topics potentially more accessible to non-specialists.

**3\. Stylistic Differences** :

* `gpt-4o` provides slightly longer and more descriptive titles, offering clarity for niche audiences.

**4\. Audience Alignment** :

* `gpt-4o` is better suited for technical or academic audiences who prefer specificity.

Both models serve different niches. The choice boils down to **trade-offs between cost, data privacy, technical detail, and audience expectations**. If you already have `llama3.1:8b` set up locally, it’s an excellent tool for prototyping and general usage. However, for edge cases needing extreme precision or domain-specific language, `gpt-4o` still has the upper hand.

## Conclusion: Final Thoughts

This series of articles has equipped us with hands-on techniques to perform **text clustering** and**topic modeling**. We have explored the use of **LLMs (generative and representative)** in unsupervised learning. Unlike supervised methods, text clustering enables grouping texts by semantic content without prior labeling.

The pipeline involves converting text into **embeddings** , applying **dimensionality reduction** , and clustering the reduced embeddings. While manual inspection of clusters aids interpretation, **BERTopic** automates this process with topic modeling. It uses a **bag-of-words approach enhanced by c-TF-IDF** to weigh words based on their relevance to clusters.

Topic representations have been further fine-tuned using **KeyBERTInspired** and **Maximal Marginal Relevance (MMR)**. Additionally, generative LLMs using both `llama3.1:8b` and `gpt-4o`, enhance interpretability by generating descriptive topic labels. This combination of techniques improves automation, clarity, and usability in analyzing large text datasets.

The real power of these methods lies in their ability to uncover hidden patterns and provide actionable insights from large text datasets. Whether you’re a researcher, data scientist, or NLP enthusiast, these tools open doors to endless possibilities.
