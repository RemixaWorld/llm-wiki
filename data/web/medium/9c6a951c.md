Retrieval-Augmented Generation (RAG) is a popular approach that incorporates external knowledge into Large Language Models (LLMs) by retrieving relevant documents from a vector database.

RECOMP is a strategy that summarizes the retrieved documents before passing them to the LLM.

Since RECOMP can improve the performance and efficiency of RAG [1, 2], let’s examine how we can use it in practice.

## The Needle in a Haystack Problem

Why should we summarize the retrieved documents instead of putting them directly into the LLM’s prompt?

A RAG input prompt that includes a user question and additional context from the retrieved documents looks like this:

``` prompt = f"""You are a helpful assistant. Use the following context to answer the user's question. Context: {context}Question: {query}Answer:""" ```

It turns out that if important information is buried in a very long context, it can get “lost in the middle”, leading to degraded overall system performance [3].

Passing this prompt to a cloud-based LLM via an API also leads to a lot of tokens, which increases response time and costs extra money.

Therefore, it makes sense to compress the context to be as concise and relevant as possible before passing the prompt to an LLM.

## RECOMP

RECOMP stands for “Retrieve, Compress, Prepend”. The basic idea is simple: summarize the retrieved documents and add them to the LLM’s context [1].

The RECOMP paper tested two approaches for compressing a set of retrieved documents:

* **Extractive Compressor** : extract the most helpful sentences from the retrieved documents and discard the rest.
* **Abstractive Compressor** : summarize the retrieved documents into shorter text.

Since the results showed that the abstractive compressor performed better, we will focus on this approach.

### Abstractive Compressor

The easiest way to generate a summary is to use an LLM. However, using a large model like ChatGPT via an API is slow, and the cost adds up over time. In RECOMP, they fine-tuned a smaller LLM based on Google’s T5-large model (738M parameters) that can run locally and summarize input documents.

They used a GPT model to generate summarization training data with the following prompt:

> Compress the information in the retrieved documents into a 2-sentence summary that could be used to answer the question: Question: {query} Retrieved documents: {docs} Compressed documents:

This prompt shows that our goal is not just to summarize text, but to create a focused summary relevant to the given question.

Three fine-tuned abstractive compressor models are available on Hugging Face, depending on the training dataset:

* fangyuan/nq_abstractive_compressor (Natural Questions)
* fangyuan/tqa_abstractive (TriviaQA)
* fangyuan/hotpotqa_abstractive (HotpotQA)

Of these three question-answer datasets, the Natural Questions (NQ) dataset is arguably the most relevant for most RAG applications.

The NQ dataset contains questions submitted by real users to Google Search, and the answers must be retrieved from Wikipedia. A natural query looks like this: “where did yellowstone national park get its name”.

## Using the Abstractive Compressor

Now, let’s use the abstractive compressor from RECOMP to summarize documents.

To do so, we must first install the `torch` and `transformers` libraries.

First, we load the model and tokenizer:

```python import torchfrom transformers import AutoTokenizer, AutoModelForSeq2SeqLMdevice = "cuda" if torch.cuda.is_available() else "cpu" # use GPU if availableprint(f"Using device: {device}")compressor_tokenizer = AutoTokenizer.from_pretrained( "fangyuan/nq_abstractive_compressor")compressor_model = AutoModelForSeq2SeqLM.from_pretrained( "fangyuan/nq_abstractive_compressor", device_map="auto", torch_dtype=torch.bfloat16) ```

Using the RECOMP summarization model, a user query, and a list of documents, we can create a `summarize` function:

```python def summarize(query: str, docs: list[str], model, tokenizer, device): prompts = [ f"summarize: Question: {query}
Document: {doc}
Summary: " for doc in docs ] inputs = tokenizer( prompts, return_tensors="pt", max_length=512, padding=True, truncation=True ).to(device) outputs = model.generate(**inputs, max_new_tokens=200) summaries = tokenizer.batch_decode(outputs, skip_special_tokens=True) return summaries ```

The “summarize:” prefix is important because this model is based on Google’s T5.

One limitation of this model is its maximum input length of 512 tokens. Any input larger than that gets truncated (removed). For best results, ensure your document chunk size is smaller than 512. Based on the results from [2], a chunk size of 256 is a good choice.

### Example Usage

Let’s assume that we have a user query `query` and that our vector database search returned the top 3 document chunks `docs`. We can then use the new summarize function to compress these chunks:

``` query = "Who invented Python?"docs = ["Python was conceived in the late 1980s[42] by Guido van Rossum at Centrum Wiskunde & Informatica (CWI) in the Netherlands; it was conceived as a successor to the ABC programming language, which was inspired by SETL,[43] capable of exception handling and interfacing with the Amoeba operating system.[12] ", "Guido van Rossum began working on Python in the late 1980s as a successor to the ABC programming language, and he first released it in 1991 as Python 0.9.0.[36] Python 2.0 was released in 2000. Python 3.0, released in 2008, was a major revision not completely backward-compatible with earlier versions. Python 2.7.18, released in 2020, was the last release of Python 2.[37] ", "As of 8 April 2025, Python 3.13.3 is the latest stable release (it's highly recommended to upgrade to it, or upgrade any other older 3.x release). "]summaries = summarize( query=query, docs=docs, model=compressor_model, tokenizer=compressor_tokenizer, device=device,) ```

And here is the result:

``` print(summaries)['Guido van Rossum invented Python in the late 1980s as a successor to the ABC programming language, which was inspired by SETL. The project was implemented in December 1989 and Van Rossum assumed sole responsibility for the project until his retirement in 2018.', 'Guido van Rossum invented Python in the late 1980s as a successor to the ABC programming language. He first released it in 1991 as Python 0.9.0.', ''] ```

These summaries are shorter and more relevant to the query.

The third summary is an empty string because the compressor model considered the retrieved document irrelevant. This has the added benefit of the compressor acting as an additional quality gate that filters out irrelevant documents.

We then concatenate these summaries and use them in a RAG prompt to generate an answer from the LLM:

``` context = " ".join(summaries)prompt = f"""You are a helpful assistant. Use the following context to answer the user's question. Context: {context}Question: {query}Answer:""" ```

This gives us the following RAG prompt with a compressed context for the LLM to handle:

``` You are a helpful assistant. Use the following documents to answer the user's question. ## Conclusion

RECOMP summarizes the retrieved documents to compress them. This reduces the number of tokens in the subsequent RAG prompt, helping the LLM focus on the most relevant information.

The concept behind RECOMP is simple. To implement it, we only need a model that produces summaries. However, there are a few hyperparameters worth experimenting with:

* Which model should we use to produce these summaries?
* How long should the summaries be?
* What is the chunk size of the retrieved documents, and how many documents should be retrieved (Top-k)?
* Should we summarize each document separately or multiple documents together?

RECOMP is another tool to improve your RAG system. So give it a try!
