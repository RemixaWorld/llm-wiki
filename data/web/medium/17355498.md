If you’re lucky enough to have access to an Nvidia GPU at work or home, Nvidia and the team behind Polars, the high-performance dataframe library, have just given you an early Xmas gift.

That’s because Polars has just released a new GPU engine powered by RAPIDS cuDF that accelerates Polars workflows up to 13x on NVIDIA GPUs. Thus, data scientists can process hundreds of millions of rows of data in seconds on a single machine.

Polars believe there is a gap in the market for tools that process data efficiently for tens of millions up to a few hundred million rows of data. Such workloads are common for model development, demand forecasting, and logistics in finance, retail, and manufacturing industries.

The Polars library was developed to plug this gap. It’s one of the fastest-growing Python libraries for data scientists and engineers and was designed from the ground up to address these challenges. It uses advanced query optimizations to reduce unnecessary data movement and processing, allowing data scientists to smoothly handle workloads of hundreds of millions of rows in scale on a single machine.

Polars bridges the gap where single-threaded solutions like Pandas are too slow and distributed systems add unnecessary complexity, offering an appealing “medium-scale” data processing solution.

### Polars + Nvidia

Out of the box, Polars leverages multithreaded execution, advanced memory optimizations, and lazy evaluation to deliver significant acceleration compared to most CPU-only data manipulation tools.

However, as organisations' data processing demands grow—from analyzing hundreds of millions or even billions of records—even higher performance is required. This is where accelerated computing comes into play.

cuDF is part of the NVIDIA RAPIDS suite of CUDA-X libraries. Originally targeted at the Pandas library, cuDF is a GPU-accelerated DataFrame library that harnesses GPUs' massive parallelism to significantly enhance data processing performance.

The Polars team partnered with NVIDIA to add the speed of cuDF to the efficiency of Polars for an additional performance boost, up to 13x compared to Polars on CPU. This allows users to maintain an interactive experience as their data processing workloads grow to hundreds of millions and even billions of rows of data.

The Polars team makes an impressive claim, and they back it up with graphs of Polars running some PDS-H benchmarks with and without GPU acceleration.

OK, so that was a surprise. Polars enabled with the GPU did **_not_** accelerate data processing in my CSV file. In fact, the very opposite — it was taking approximately 4–5 times longer using the GPU.

I raised this point on the Polars Discord channel and was told that using the GPU **_should_** accelerate CSV data processing. Anyway, I raised an issue (#18832) with the support team over at GitHub, and they will investigate further.

It was time for a new approach. I suspected that the GPU would kick in properly if I used Parquet data, so the next task was to convert my CSV file to Parquet.

Polars can do that! I reverted to the 500 million record input CSV and converted it to Parquet with this code.

``` df=pl.scan_csv("/mnt/d/sales_data/sales_data_500m.csv", has_header=True)df.sink_parquet("/mnt/d/sales_data/sales_data_500m.parquet") ```

This reduced the input file size from 38 GB to around 7 GB. Let’s check the timings again.

### Summary

The Polars GPU engine powered by RAPIDS cuDF is now available in open beta, offering data scientists and engineers in every industry a powerful tool for medium-scale data processing. In my tests, it accelerated **_some_** Polars workflows up to 17x on NVIDIA GPUs, efficiently handling datasets of hundreds of millions of rows without the overhead of distributed systems. The Polars GPU engine is built directly into the Polars API, making it easily accessible to every user.

The only disappointing aspect was the CSV processing speed. But, again, it’s no big deal to convert your CSV data to a more modern alternative such as Parquet. It’s probably something you should be doing as a matter of course.

**[Note: I received a reply to the issue I raised with Polars regarding CSV processing. An analyst over there tried a similar operation on his (non-WSL) Linux machine, and his processing of the CSV was around twice as fast on the CPU as it was on the GPU.]**

The support team is unsure why there is such a big discrepancy between my timings on WSL Linux and theirs. I’m unsure how much testing the Polars team have done using the GPU on WSL for Windows.

So, overall, I think this is a great development for the Polars team and Nvidia. It doesn’t harm to try the GPU changes out on your own system and see what works for you. The change to go from CPU to GPU is relatively straightforward. And if changing to the GPU doesn’t work for you, flip it back. You know you’re still going to get blistering speed.
