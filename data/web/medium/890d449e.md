To streamline this process, we can create a function that takes all of our cleaned documents and converts them into embeddings:

```python def embed_corpus_with_api(df, client, model_name, batch_size=50): """Generates embeddings for the 'Text' column using the specified API client.""" # Prepare data all_embeddings = [] text_corpus = df["Text"].tolist() # Batch processing for i in tqdm(range(0, len(text_corpus), batch_size)): batch = text_corpus[i:i + batch_size] # API call response = client.embeddings.create( model=model_name, input=batch ) # Extract embeddings embeddings = [np.array(item.embedding) for item in response.data] all_embeddings.extend(embeddings) # Add embeddings to DataFrame df["Embeddings"] = all_embeddings df.dropna(subset=["Embeddings"], inplace=True) return df ```

## Why Euclidean Distance Approach never works

In real-world data, we rarely find perfectly shaped clusters where a Euclidean approach works.

Baseline Approach (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--ba77cb5bf01e--------------------------------------->)

)

To demonstrate this, we are implementing a simple baseline approach. Before we code it and explore the actual problem, let’s first understand and visualize how it works.

Press enter or click to view image in full size

Flow of Euclidean Distance (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--ba77cb5bf01e--------------------------------------->)

)

1. First, we turn every document into a high-dimensional embedding vector (already done in the previous section).
2. After that, we calculate the centroid of each category by averaging its embeddings.
3. Next, we determine how far each document is from its category’s centroid using Euclidean distance.
4. At the end, we set a distance threshold and mark any document past that boundary as an outlier.

We need to code a function that can give us the centroids for each of our science categories.

```python def get_embedding_centroids(df): """Calculates the centroid of the embeddings for each class.""" emb_centroids = {} grouped = df.groupby("Class Name") for class_name, group in grouped: emb_centroids[class_name] = np.mean(np.vstack(group['Embeddings']), axis=0) return emb_centroids ```

So, in this function, we are basically grouping our DataFrame by category and then calculating the mean vector for each group to find its **“center of gravity”** in the 4096-dimensional space.

Next, we need to apply the Euclidean formula to measure the straight-line distance between a document and its category’s center.

Press enter or click to view image in full size

sEuclidean formula

```python # Distance Calculationdef calculate_euclidean_distance(p1, p2): """Calculates the Euclidean distance between two vectors.""" return np.sqrt(np.sum((p1 - p2) ** 2)) ```

We have our two main components ready. Now we can code the third component, which detects outliers based on a predefined radius.

```python # Outlier Detection (Euclidean Distance)def detect_outliers_euclidean(df, emb_centroids, radius): """Flags outliers based on Euclidean distance from the class centroid.""" outlier_indices = [] # Compute distances for each sample for idx, row in df.iterrows(): class_name = row["Class Name"] dist = calculate_euclidean_distance(row["Embeddings"], emb_centroids[class_name]) if dist > radius: outlier_indices.append(idx) # Flag outliers in DataFrame df["Outlier_Euclidean"] = False df.loc[outlier_indices, "Outlier_Euclidean"] = True return df ```

Let’s run this baseline approach. We will be setting an arbitrary radius of **0.55** which means that anything above 55% we are calling it an outlier.

```python # Baseline Method (Euclidean Distance)RADIUS = 0.55# Compute class centroidsbaseline_centroids = get_embedding_centroids(df_train)# Detect outliersdf_train = detect_outliers_euclidean(df_train, baseline_centroids, RADIUS)# Report resultsnum_outliers_baseline = df_train["Outlier_Euclidean"].sum()print(f"Found {num_outliers_baseline} outliers with Euclidean method at radius {RADIUS}") ```

By running our eculidean distance pipeline we get the following output.

``` ######### OUTPUT ##########Found 506 outliers with Euclidean method at radius 0.55 ```

**506 outliers** out of our 600 documents, this simple method has flagged over 84% as anomalies. This is our first major clue that this approach is too naive.

It fails for two key reasons:

1. **The Arbitrary Radius:** How did we pick 0.55? A radius of 0.6 would find fewer outliers, and 0.5 would find even more. This single, hardcoded value isn’t statistically robust.
2. **The Spherical Assumption:** The method assumes each category forms a perfect sphere of data points. In reality, text embeddings create complex, elongated shapes. A single radius just can’t capture this nuance.

To visually see how outliers are representing in our clusters, we first need to map the high dimenstional data to 2d which can be done using UMAP, so let’s code that function first.

```python # Dimensionality Reduction (UMAP)def project_with_umap(df, n_neighbors=15, min_dist=0.1, random_state=42): """Projects high-dimensional embeddings into 2D using UMAP.""" print("Projecting embeddings to 2D using UMAP...") # Prepare embeddings embeddings = np.vstack(df["Embeddings"]) # Initialize UMAP reducer reducer = umap.UMAP( n_neighbors=n_neighbors, min_dist=min_dist, random_state=random_state, metric="cosine" ) # Fit and transform umap_results = reducer.fit_transform(embeddings) # Build UMAP DataFrame df_umap = pd.DataFrame(umap_results, columns=["UMAP1", "UMAP2"]) df_umap = pd.concat([df_umap, df.reset_index(drop=True)], axis=1) print("UMAP projection complete.") return df_umap ```

We are using cosine similarity as the metric in UMAP to preserve the angular relationships between high-dimensional embeddings, which is more meaningful for text data than straight-line distances.

This helps maintain the semantic structure of our documents when projecting into 2D. Let’s run this function and transform our data into a 2D representation.

``` # Project Embeddings to 2D (UMAP)df_umap = project_with_umap(df_train) ```

## Statistically Outlier with Mahalanobis Distance

The failure of the Euclidean method teaches us that real-world data clusters are rarely perfect spheres. We need a method that understands the shape and spread of the data. This is where Mahalanobis Distance comes in.

Press enter or click to view image in full size

Statistical approach (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--ba77cb5bf01e--------------------------------------->)

)

Instead of drawing a simple circle (like Euclidean distance), the Mahalanobis approach draws a custom-fit ellipse around the data, accounting for its unique shape. It works like this:

Press enter or click to view image in full size

Mahalanobis Distance Flow (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--ba77cb5bf01e--------------------------------------->)

)

1. **First** , it finds the center of each category’s data cloud (the centroid), just like the Euclidean method.
2. **Second** , it analyzes the _shape_ of that cloud by calculating its covariance matrix. This tells us how the data is spread out and whether it’s stretched more in certain directions than others.
3. **Third** , it measures the distance of each point from the centroid relative to the shape of the cloud. A point far away along a direction where the data is already very spread out is considered less of an anomaly than a point that is only slightly off in a direction where the data is normally very tightly packed.
4. **Finally** , instead of using an arbitrary radius, it compares this calculated distance to a statistical threshold derived from the chi-squared distribution. This allows us to say with a specific level of confidence (e.g., 99%) whether a point is a true outlier.

Press enter or click to view image in full size

Inverse Covariance Matrix

To understand how this works, we need to look at the core formula and, most importantly, the role of each notatin of it’s formula.

* **D²** is the Mahalanobis distance, a way of measuring how far a point is from the center while accounting for the cluster’s shape.
* **x** is the embedding of a single document, the point we’re measuring.
* **μ (mu)** is the mean embedding, the center of the cluster.
* **(x — μ)** is the difference vector, showing how far the document is from the center.
* **Σ (Sigma)** is the covariance matrix, which describes how the data is spread in different directions.
* **Σ⁻¹ (Sigma-Inverse)** is the inverse covariance matrix, which re-weights distances by giving less importance to spread-out directions and more importance to tight ones.
* **ᵀ (Transpose)** is just a math step to make the multiplication work correctly.

Now we need to code a function that implements this logic. We will calculate the centroid and covariance for each category, compute the Mahalanobis distance for every document within that category, and then flag anything that exceeds our 99% confidence threshold.

```python # Outlier Detection (Mahalanobis Distance)def detect_outliers_mahalanobis(df, confidence=0.99): """Flags outliers based on Mahalanobis distance for each class.""" outlier_indices = [] grouped = df.groupby("Class Name") for class_name, group in grouped: # Prepare embeddings and calculate centroid/covariance embeddings = np.vstack(group["Embeddings"]) centroid = np.mean(embeddings, axis=0) # This is μ cov = np.cov(embeddings.T) # This is Σ # Invert covariance matrix (with regularization for stability) inv_cov = np.linalg.inv(cov + np.identity(cov.shape[0]) * 1e-6) # This is Σ⁻¹ # Calculate Mahalanobis distance for each point distances = [mahalanobis(emb, centroid, inv_cov) for emb in embeddings] # Determine statistical threshold from chi-squared distribution threshold = chi2.ppf(confidence, df=embeddings.shape[1]) print(f"Mahalanobis threshold for '{class_name}': {threshold:.2f}") # Identify outliers exceeding the threshold group_outlier_indices = group.index[np.array(distances) > threshold].tolist() outlier_indices.extend(group_outlier_indices) # Flag outliers in DataFrame df["Outlier_Mahalanobis"] = False df.loc[outlier_indices, "Outlier_Mahalanobis"] = True return df ```

Let’s run this more sophisticated approach on our data.

``` # Detect Outliers (Mahalanobis Distance Method)df_umap = detect_outliers_mahalanobis(df_umap, confidence=0.99)# Report resultsnum_outliers = df_umap["Outlier_Mahalanobis"].sum()print(f"Found {num_outliers} outliers with Mahalanobis Distance method.") ```

## Density-Based Outliers with Local Outlier Factor (LOF)

This brings up a new question …

> what if an outlier isn’t a point that’s statistically far from the center, but is instead a point that’s just… lonely?

What if it’s in a sparse, isolated part of the embedding space, far from its immediate neighbors?

LOF Detection (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--ba77cb5bf01e--------------------------------------->)

)

This is a problem of **local density** , not global distance. And for that, we have the perfect approach, **Local Outlier Factor (LOF)** algorithm.

The core idea behind LOF is brilliantly simple and can be explained with a party analogy:

Press enter or click to view image in full size

Local Outlier Factor (LOF) (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--ba77cb5bf01e--------------------------------------->)

)

1. **First** , to check if someone is an outlier, you look at their closest group of friends (their nearest neighbors).
2. **Second** , you measure how tightly packed that group is. Are they in a close-knit conversation, or are they spread out? This is the person’s _local density_.
3. **Third** , and this is the key step, you ask their friends about _their_ own groups. You find out what the local density is for each of the neighbors.
4. **Finally** , you compare. If the person you’re checking is in a much more spread-out, sparse group than their friends are, they are an outlier. They are the person standing awkwardly alone, while their nearest “friends” are all part of much tighter, denser conversation circles.

LOF excels at finding these isolated points that other methods might miss. Let’s code it up.

```python # Outlier Detection (Local Outlier Factor)def detect_outliers_lof(df, n_neighbors=20, contamination="auto"): """Flags outliers using the Local Outlier Factor algorithm.""" # Prepare the embeddings embeddings = np.vstack(df["Embeddings"]) # Initialize the LOF model # 'n_neighbors' defines the size of the local neighborhood # 'contamination="auto"' lets the algorithm determine the outlier threshold lof = LocalOutlierFactor(n_neighbors=n_neighbors, contamination=contamination) # Get predictions (-1 for outliers, 1 for inliers) predictions = lof.fit_predict(embeddings) # Add a new boolean column to the DataFrame df["Outlier_LOF"] = (predictions == -1) return df ```

We will set `contamination` to `'auto'`, which is a robust way to let the algorithm decide the proportion of outliers based on its internal scoring, rather than us guessing a fixed percentage.

Let’s run this density-based check.

``` # Detect Outliers (LOF Method)df_umap = detect_outliers_lof(df_umap)# Report resultsnum_outliers = df_umap["Outlier_LOF"].sum()print(f"Found {num_outliers} outliers with Local Outlier Factor method.") ```

And once again, the result is same.

``` ##### OUTPUT #####Found 0 outliers with Local Outlier Factor method. ```

Zero outliers, again! This tells us something very important about our data. Not only are the clusters statistically consistent (as Mahalanobis showed), but they are also quite uniformly dense. There are no lone data points sitting in sparse regions. The documents within each category are semantically close and well-distributed.

Let’s quickly visualize this to be sure.

## Isolation-Based Outliers with Isolation Forest

So far, our implementations has taught us to see things differently. The Euclidean method saw outliers everywhere. The Mahalanobis and LOF methods, with their strict statistical and density-based rules, saw outliers nowhere. This tells us that our data clusters are well-formed and uniformly dense.

Isolation Forest (Created by

)

But this brings us to our third and final advanced technique, one that doesn’t rely on distance or density at all. Instead, it works on a fundamentally different and brilliant principle:

> **Anomalies are few and different, which makes them easier to _isolate_ than normal points.**

This is the core idea behind the **Isolation Forest** algorithm. Let’s use another analogy to understand it:

Press enter or click to view image in full size

Isolation Forest (Created by

[Fareed Khan](<https://medium.com/u/b856005e5ecd?source=post_page---user_mention--ba77cb5bf01e--------------------------------------->)

)

Imagine you are playing a “Guess Who?” game with our 600 documents. You start asking random questions to single out a specific document.

* To isolate a **normal document** , which is deep inside a dense cluster (e.g., a typical “sci.space” article about a shuttle launch), you’d need a lot of questions: “Is it about space?” (Yes), “Is it about NASA?” (Yes), “Is it about the shuttle?” (Yes), “Is it about the Columbia?” (Yes)… It takes many splits to get to that one specific, normal point.
* Now, imagine an **outlier document**. Perhaps it’s a “sci.space” article that is actually a long poem about the stars. To isolate it, you might only need one or two questions: “Is the text formatted like a poem?” (Yes). **Boom. Isolated.**

Isolation Forest builds hundreds of random decision trees (a “forest”) to play this game. It calculates the average number of questions (splits) needed to isolate each document. The documents that are consistently isolated with the fewest questions are flagged as anomalies.

Crucially, with this method, we have to give the algorithm a hint. We use a parameter called `contamination`, which is our best guess for the percentage of outliers in the data. This is different from our previous methods; here, we are explicitly telling the model, "I expect to find about 5% of my data to be anomalous. Please show me which points best fit that description."

Let’s code this powerful approach.

```python # Outlier Detection (Isolation Forest)def detect_outliers_isoforest(df, contamination=0.05, random_state=42): """Flags outliers using the Isolation Forest algorithm.""" # Prepare the embeddings embeddings = np.vstack(df['Embeddings']) # Initialize the Isolation Forest model # 'contamination' is our estimate of the outlier proportion iso_forest = IsolationForest(contamination=contamination, random_state=random_state) # Get predictions (-1 for outliers, 1 for inliers) predictions = iso_forest.fit_predict(embeddings) # Add a new boolean column to the DataFrame df['Outlier_ISO'] = (predictions == -1) return df ```

We will set `contamination=0.05`, telling the model to find the top 5% of the most easily isolated points. Now, let's see what it discovers.

``` # Detect Outliers (Isolation Forest Method)df_umap = detect_outliers_isoforest(df_umap, contamination=0.05)# Report resultsnum_outliers = df_umap["Outlier_ISO"].sum()print(f"Found {num_outliers} outliers with Isolation Forest method.") ```

And this time, we get a breakthrough.

``` ##### OUTPUT #####Found 30 outliers with Isolation Forest method. ```

We have a reasonable and actionable number of potential outliers. 5% of our 600 documents is exactly 30, and the algorithm has successfully identified them. These are the documents that are structurally **“different”** enough to be consistently separated from their peers with very few decision splits.

We now have results from our baseline and three advanced methods. The next logical step is to combine these results to identify the most suspicious, **“high-confidence”** outliers and, most importantly, understand why they were flagged (Explanable AI).

For this task, we will use one of the most well-known clustering algorithms: **K-Means**.

The logic behind K-Means is very intuitive:

1. It starts by randomly placing four “centroids” (cluster centers) in our high-dimensional embedding space.
2. It then assigns each of our 600 documents to the nearest centroid.
3. Next, it recalculates the position of each centroid to be the new center of all the documents assigned to it.
4. It repeats steps 2 and 3 over and over again until the cluster assignments stop changing.

Let’s write a function to apply K-Means to our embeddings. We will set `n_clusters=4` because we know from our initial data sampling that there are four distinct science categories we are trying to rediscover.

```python # Function to apply K-Means clusteringdef apply_kmeans(df, n_clusters=4, random_state=42): """Applies K-Means clustering to the embeddings and adds cluster labels to the DataFrame.""" # Prepare the embeddings embeddings = np.vstack(df['Embeddings']) # Initialize and fit the K-Means model kmeans = KMeans(n_clusters=n_clusters, random_state=random_state, n_init=10) df['KMeans_Cluster'] = kmeans.fit_predict(embeddings) print("K-Means clustering complete. Cluster labels added to the DataFrame.") return df ```

Now, let’s run the clustering and see how well the algorithm performs.

``` # Apply K-Means clustering to our datadf_umap = apply_kmeans(df_umap, n_clusters=4) ```

The `df_umap` DataFrame now has a new column, `KMeans_Cluster`, containing the cluster ID (0, 1, 2, or 3) that the algorithm assigned to each document.

The most powerful way to judge the result is to visualize it. We’ll create a side-by-side comparison:
