As a beginner in Python and ML, I frequently relied on scikit-learn for almost all of my projects. Its simplicity and versatility made implementing various algorithms a fascinating experience. Now, it’s exciting to see that scikit-learn has evolved even further with the introduction of LLM capabilities through **‘Scikit-LLM’**. This integration brings the power of large language models, such as GPT, Vertex, Gemma, Mistral, Llama, etc into the scikit-learn ecosystem, making it an even more powerful tool for machine learning enthusiasts and professionals alike. According to the library’s documentation, _‘Scikit-LLM allows you to seamlessly integrate powerful language models into scikit-learn for enhanced text analysis tasks.’_

**NOTE:** All the code examples in this article are taken form the documentation of [Scikit-LLM](<https://skllm.beastbyte.ai/>)

## About the Library

In Scikit-LLM, the estimators are grouped based on the type of language model API they use, which is called the “backend family”. This grouping is based on the **API format** rather than the actual architecture of the language model. For example, any model that follows the OpenAI API format is classified under the GPT family, regardless of which provider or model architecture is used. Each family has its own set of estimators located in specific sub-modules.

For instance, the Zero-Shot Classifier is available under different backend families: as `ZeroShotGPTClassifier` in the GPT family and as `ZeroShotVertexClassifier` in the Vertex family. Separating these backend families allows flexibility when different providers add unique features to their models that other providers might not support. Despite this, the number of families is kept minimal to ensure ease of use.

The default backend for a family is used unless otherwise specified. For example, the OpenAI backend is the default for the GPT family, but users can switch to the Azure backend by specifying it in the model settings. However, not all models support every backend.

## The GPT Family

The GPT family includes all backends using the OpenAI API format, with the OpenAI backend as the default. If no specific backend is mentioned, the OpenAI backend is used. To enable it, simply set your OpenAI API key and organization ID.

```python from skllm.config import SKLLMConfigSKLLMConfig.set_openai_key("<YOUR_KEY>")SKLLMConfig.set_openai_org("<YOUR_ORGANIZATION_ID>") ```

OpenAI models can also be accessed through the Azure OpenAI service. To use the Azure backend, provide your Azure API key and endpoint.

```python from skllm.config import SKLLMConfig# Found under: Resource Management (Left Sidebar) -> Keys and Endpoint -> KEY 1SKLLMConfig.set_gpt_key("<YOUR_KEY>")# Found under: Resource Management (Left Sidebar) -> Keys and Endpoint -> EndpointSKLLMConfig.set_azure_api_base("<API_BASE>") # e.g. https://<YOUR_PROJECT_NAME>.openai.azure.com/ ```

When using the Azure backend, the model should be specified as `model = "azure::<model_deployment_name>"`. For example, if we created a _gpt-3.5_ deployment under the name _my-model_ , we should use `model = "azure::my-model"`.

### GGUF

GGUF is an open-source format for storing quantized model weights and configurations. It’s mainly used with the Llama CPP project but can be loaded by other runtimes as well. To use GGUF models with scikit-llm, install the llama-cpp library and its Python bindings, with installation commands varying by hardware.

![From Documentation](https://miro.medium.com/v2/resize:fit:700/1*B7GX87iQqZSHt14FL9J21A.png)

All models use quantized versions, with precision indicated by suffixes (e.g., q4 for 4-bit). By default, 4-bit quantized models are used, but models with different precisions may be available. When choosing a model, consider the following rule of thumb:
q < 4 : Substantial performance loss, low size
q = 4 : Optimal trade-off between the loss and the size
4 < q < 8 : Minimal performance loss, large size
q = 8 : Almost no performance loss, very large size

### GPU acceleration

GGUF models can be offloaded to a GPU, either fully or partially, with a command to set the maximum GPU layers.

```python from skllm.config import SKLLMConfigSKLLMConfig.set_gguf_max_gpu_layers(-1) ```

0 : all layers on the CPU
-1 : all layers on the GPU
n>0 : n layers on the GPU, remaining on the CPU

Note that changing this setting doesn’t automatically reload the model. To unload models from memory, use the following command.

```python from skllm.llm.gpt.clients.llama_cpp.handler import ModelCacheModelCache.clear() ```

This is useful in interactive environments like Jupyter Notebook, as models stay in memory until the process ends.

### Custom URL

The custom URL backend enables use of any GPT estimator with OpenAI-compatible providers, whether local or cloud-based. Set a global custom URL to use this backend.

```python from skllm.config import SKLLMConfigSKLLMConfig.set_gpt_url("http://localhost:8000/")clf = ZeroShotGPTClassifier(model="custom_url::<custom_model_name>") ```

Note, If using both custom URL and OpenAI backends in the same script, reset the custom URL configuration with `SKLLMConfig.reset_gpt_url()`.

## The Vertex Family

The Vertex family has one backend, **Google Vertex AI**. To use it, configure your Google Cloud credentials:

1. Create a Google Cloud project in the Google Cloud Console.
2. Select the project from the list.
3. Search for and select Vertex AI.
4. Install Google Cloud CLI and set default credentials using the command from the official documentation.

``` gcloud auth application-default login ```

5\. Configure Scikit-LLM with your project ID:

```python from skllm.config import SKLLMConfigSKLLMConfig.set_google_project("<YOUR_PROJECT_ID>") ```

To tune LLMs in Vertex, you need 64 TPU v3 pod cores, which defaults to 0. To increase this quota:

1. Go to Quotas and filter for “Restricted image training TPU V3 pod cores per region.”
2. Select the “europe-west4” region.
3. Click “Edit Quotas,” set the limit to 64, and submit the request. Approval may take a few hours to several days.

## Text Classification

### 1\. Zero-Shot Text Classification

One key feature of LLMs is their ability to classify text without retraining, as long as the labels are descriptive. For example, to classify text into categories like [positive, negative, neutral], we can use the `ZeroShotGPTClassifier` with the regular scikit-learn API.

```python from skllm.models.gpt.classification.zero_shot import ZeroShotGPTClassifierfrom skllm.datasets import get_classification_dataset# demo sentiment analysis dataset# labels: positive, negative, neutralX, y = get_classification_dataset()clf = ZeroShotGPTClassifier(model="gpt-3.5-turbo")clf.fit(X,y)labels = clf.predict(X) ```

In a zero-shot setting, no training data is needed; you simply provide a list of candidate labels.

```python from skllm.models.gpt.classification.zero_shot import ZeroShotGPTClassifierfrom skllm.datasets import get_classification_datasetX, _ = get_classification_dataset()clf = ZeroShotGPTClassifier()clf.fit(None, ["positive", "negative", "neutral"])labels = clf.predict(X) ```

You can also perform multi-label classification, assigning multiple labels to a single text.

```python from skllm.models.gpt.classification.zero_shot import MultiLabelZeroShotGPTClassifierfrom skllm.datasets import get_multilabel_classification_datasetX, _ = get_multilabel_classification_dataset()candidate_labels = [ "Quality", "Price", "Delivery", "Service", "Product Variety", "Customer Support", "Packaging", "User Experience", "Return Policy", "Product Information",]clf = MultiLabelZeroShotGPTClassifier(max_labels=3)clf.fit(None, [candidate_labels])labels = clf.predict(X) ```

**Note:** The performance of a zero-shot classifier depends heavily on how descriptive and clear the labels are. For example, instead of using “SEMANTICS,” use a more natural phrase like “the semantics of the provided text is <<SEMANTICS>>.”

### 2\. Few-Shot Text Classification

Few-shot text classification involves categorizing text into pre-defined classes based on a few examples per class (e.g., positive, negative, neutral). Scikit-LLM estimators use the entire training set to create examples, so if your dataset is large, consider splitting it into smaller training and validation sets. It’s recommended to keep no more than 10 examples per class and shuffle the data to avoid recency bias.

``` from skllm.models.gpt.classification.few_shot import (FewShotGPTClassifier,MultiLabelFewShotGPTClassifier,)from skllm.datasets import ( get_classification_dataset, get_multilabel_classification_dataset,)# single labelX, y = get_classification_dataset()clf = FewShotGPTClassifier(model="gpt-4o")clf.fit(X,y)labels = clf.predict(X)# multi-labelX, y = get_multilabel_classification_dataset()clf = MultiLabelFewShotGPTClassifier(max_labels=2, model="gpt-4o")clf.fit(X,y)labels = clf.predict(X) ```

**API Reference**

```python # Few Shot GPT Classifierfrom skllm.models.gpt.classification.few_shot import FewShotGPTClassifier# Multi Label Few Shot GPT from skllm.models.gpt.classification.few_shot import MultiLabelFewShotGPTClassifier ```

### 3\. Dynamic Few-Shot Text Classification

Dynamic Few-Shot Classification extends Few-Shot Text Classification, making it better for larger datasets. Instead of using a fixed set of examples, it dynamically selects a subset for each sample, optimizing the model’s context window and saving tokens.

For example, if the goal is to classify reviews as about a book or a movie, the training set might consist of 6 samples, 3 for each class.

``` X = [ "I love reading science fiction novels, they transport me to other worlds.", # example 1 - book - sci-fi "A good mystery novel keeps me guessing until the very end.", # example 2 - book - mystery "Historical novels give me a sense of different times and places.", # example 3 - book - historical "I love watching science fiction movies, they transport me to other galaxies.", # example 4 - movie - sci-fi "A good mystery movie keeps me on the edge of my seat.", # example 5 - movie - mystery "Historical movies offer a glimpse into the past.", # example 6 - movie - historical]y = ["books", "books", "books", "movies", "movies", "movies"] ```

Now we need to classify this review, “I have fallen deeply in love with this sci-fi book; its unique blend of science and fiction has me spellbound.” Since the query is about a sci-fi book, we want examples 1 and 4, the most relevant, to be used for classification. When using the dynamic few-shot classifier with 1 example per class, the model correctly selects examples 1 and 4 as the most relevant.

```python from skllm.models.gpt.classification.few_shot import DynamicFewShotGPTClassifierquery = "I have fallen deeply in love with this sci-fi book; its unique blend of science and fiction has me spellbound."clf = DynamicFewShotGPTClassifier(n_examples=1).fit(X,y)prompt = clf._get_prompt(query)print(prompt) ``` ``` ...Sample input:"I love reading science fiction novels, they transport me to other worlds."Sample target: booksSample input:"I love watching science fiction movies, they transport me to other galaxies."Sample target: movies... ```

This process uses a KNN search algorithm as a preprocessor. First, the training set is vectorized with an embedding model. Then, a nearest neighbors index is built using algorithms like Scikit-Learn KNN or Annoy to efficiently find relevant examples. To ensure class balance, the training data is split by class, allowing equal sampling of N examples from each class during few-shot prompting.

**API Reference**

```python # Dynamic Few Shot GPT Classifierfrom skllm.models.gpt.classification.few_shot import DynamicFewShotGPTClassifier ```

### 4\. Chain-of-Thought Text Classification

CoT text classification is similar to zero-shot classification, but the model also generates reasoning behind its label choice. This can improve performance but increases token consumption.

```python from skllm.models.gpt.classification.zero_shot import CoTGPTClassifierfrom skllm.datasets import get_classification_dataset# demo sentiment analysis dataset# labels: positive, negative, neutralX, y = get_classification_dataset()clf = CoTGPTClassifier(model="gpt-4o")clf.fit(X,y)predictions = clf.predict(X)labels, reasoning = predictions[:, 0], predictions[:, 1] ```

### 5\. Tunable Text Classification

Tunable estimators let you fine-tune the underlying LLM for classification tasks, typically performed in the cloud (like OpenAI or Vertex), so no local GPU is needed. However, tuning can be expensive and time-consuming. It’s advisable to first try in-context learning estimators and only use tunable ones if necessary.

```python from skllm.models.gpt.classification.tunable import GPTClassifierX, y = get_classification_dataset()clf = GPTClassifier(n_epochs=1)clf.fit(X,y)clf.predict(X) ```

LLMs are excellent at summarization tasks. Scikit-LLM offers a summarizer that can be used either as a stand-alone estimator or as a preprocessor, similar to dimensionality reduction.

```python from skllm.models.gpt.text2text.summarization import GPTSummarizerfrom skllm.datasets import get_summarization_datasetX = get_summarization_dataset()summarizer = GPTSummarizer(model="gpt-3.5-turbo", max_words=15)X_summarized = summarizer.fit_transform(X) ```

The `max_words` hyperparameter sets a soft limit on word count, but the actual number may slightly exceed this. You can also generate a summary focused on a specific concept by using the optional `focus` parameter.

``` summarizer = GPTSummarizer(model="gpt-3.5-turbo", max_words=15, focus="apples") ```

### 2\. Tagging

Tagging in Scikit-LLM can be an arbitrary task that takes a raw text and returns the same text with inserted XML-like tags.

``` # InputI love my new phone, but I am disappointed with the battery life.# Output<positive>I love my new phone,</positive> <negative>but I am disappointed with the battery life.</negative> ```

In an ideal scenario, such tagging process should be invertible, so the original text can always be reconstructed from the tagged one. However, this is not always feasible and hence not considered to be a mandatory requirement.

### 3\. Named Entity Recognition

NER is an experimental feature in Scikit-LLM and may be unstable. NER involves locating and classifying named entities in text. Currently, Scikit-LLM offers one NER estimator, “Explainable NER,” which works only with the GPT family.

```python from skllm.models.gpt.tagging.ner import GPTExplainableNER as NERentities = { "PERSON": "A name of an individual.", "ORGANIZATION": "A name of a company.", "DATE": "A specific time reference."}data = [ "Tim Cook announced new Apple products in San Francisco on June 3, 2022.", "Elon Musk visited the Tesla factory in Austin on January 10, 2021.", "Mark Zuckerberg introduced Facebook Metaverse in Silicon Valley on May 5, 2023."]ner = NER(entities=entities, display_predictions=True)tagged = ner.fit_transform(data) ```

The model tags entities and provides brief reasoning for each. If `display_predictions` is set to True, the output is automatically parsed and shown in a readable format: entities are highlighted, and explanations appear when hovering over them.

**Sparse vs Dense NER
** There are two modes for generating NER predictions: sparse and dense.

**Dense Mode:** Produces a fully tagged output immediately. It’s useful when using larger models (e.g., GPT-4) or when the text has multiple instances of lexically ambiguous words. For example, distinguishing between different instances of “Apple” in the sentence “Apple is the favorite fruit of the CEO of Apple.”

**Sparse Mode:** Produces a list of entities mapped to the text via regex. It is often preferable due to:
\- Fewer output tokens (cost-effective).
\- Guaranteed invertibility and entity-specific output.
\- Higher accuracy with smaller models.
Sparse mode is generally recommended unless dense mode is necessary for specific conditions.

**API Reference**

```python # GPT ExplainableNERfrom skllm.models.gpt.tagging.ner import GPTExplainableNER ```

## **Conclusion**

Scikit-LLM enhances scikit-learn by integrating advanced language models for various NLP tasks, including text classification, summarization, and translation. It supports zero-shot and few-shot learning, dynamic example selection, and customizable backends. While it offers flexibility and efficiency, users should consider potential costs and performance impacts, especially with dynamic and tunable features. Overall, Scikit-LLM is a powerful tool for incorporating state-of-the-art language models into machine learning workflows.
