If you’re an _ML Engineer_ and your mental model of a Transformer is:

> _“You stack some encoder–decoder blocks, wire attention, train with Adam — done.”_

…you’re missing the _actual_ mechanism that makes modern AI work.

Transformers are not just an architecture pattern.

They’re better understood as a **math engine** — a system that accepts vectors, processes them through a learned vector field, and produces something meaningful (text, code, images, etc.).

In this article, I’ll explain that idea simply, using code and intuition instead of proofs.

![image](https://miro.medium.com/v2/resize:fit:700/1*Oe3KoqOFMI_LhgG_mXK4SQ.png)

## 1\. The Core Idea: Transformers = Vector Field Manipulation

Let’s strip away the buzzwords.

Inside a Transformer, each layer essentially performs three actions on your token representations:

1. **Projection** — map input vectors into query, key, and value spaces.
2. **Attention** — use similarities between tokens to mix information.
3. **Residual update** — add a small change (correction) to the current representation.

Each token is represented as a vector in a high-dimensional space. Each layer moves these vectors around — like particles flowing through a vector field.

That’s why it’s more accurate to say:

> _A Transformer is a_** _learned vector field processor_** _, not just a “sequence model.”_

It maps token representations through a series of controlled linear (matrix multiplies) and nonlinear (softmax, activations, norms) transformations.

Here’s a small PyTorch-style outline of a _single_ Transformer block:

```python import torchimport torch.nn as nnimport torch.nn.functional as Fclass TinyTransformerBlock(nn.Module): def __init__(self, d_model, n_heads, d_ff): super().__init__() self.attn = nn.MultiheadAttention(d_model, n_heads, batch_first=True) self.ffn = nn.Sequential( nn.Linear(d_model, d_ff), nn.ReLU(), nn.Linear(d_ff, d_model), ) self.norm1 = nn.LayerNorm(d_model) self.norm2 = nn.LayerNorm(d_model) def forward(self, x): # x: (batch, seq_len, d_model) # 1. Self-attention with residual + norm attn_out, _ = self.attn(x, x, x) # Q=K=V=x x = x + attn_out # residual connection x = self.norm1(x) # LayerNorm # 2. Feedforward with residual + norm ff_out = self.ffn(x) x = x + ff_out # residual connection x = self.norm2(x) # LayerNorm return x ```

This is the “block” everyone wires up.
But _why_ does it work so effectively? That’s where the math points to.

## 2\. Attention Is Not Magic — It’s a Quadratic Form

The self-attention formula you’ve seen countless times:

![image](https://miro.medium.com/v2/resize:fit:700/1*57ku7zjlZhPL664RD7mNWA.png)

Let’s unpack this in plain language:

* `Q` (queries): “What I’m looking for.”
* `K` (keys): “What I contain.”
* `V` (values): “What I’ll share if I’m relevant.”

Step-by-step:

1. **Similarity matrix:**
`QKᵀ` gives you a matrix of dot products.
Each entry `(i, j)` says: _“How similar is token i to token j?”_
2. **Softmax:**
`softmax(QKᵀ / √d)` turns each row into a probability distribution.
For token _i_ , the row is: “How much attention should I pay to each token j?”
3. **Weighted sum:**
Multiplying by `V` is just:
_“Take a weighted average of other tokens’ value vectors, using these attention weights.”_

So attention is basically:

> **_A learnable, data-dependent kernel smoother._**_
> It’s kernel regression happening inside your neural network._

Here’s a simple, almost “from scratch” implementation of single-head attention:

```python class SimpleSelfAttention(nn.Module): def __init__(self, d_model): super().__init__() self.W_q = nn.Linear(d_model, d_model) self.W_k = nn.Linear(d_model, d_model) self.W_v = nn.Linear(d_model, d_model) self.scale = d_model ** 0.5def forward(self, x): # x: (batch, seq_len, d_model) Q = self.W_q(x) # (batch, seq_len, d_model) K = self.W_k(x) V = self.W_v(x) # Similarity scores scores = torch.matmul(Q, K.transpose(-2, -1)) / self.scale # scores: (batch, seq_len, seq_len) # Probability weights attn_weights = F.softmax(scores, dim=-1) # Weighted sum of values out = torch.matmul(attn_weights, V) # (batch, seq_len, d_model) return out ```

## 3\. Multi-Head Attention = Multiple Kernels in Parallel

Single-head attention relies _on_ a single concept of similarity. However, language (and most data) encompasses many different “kinds” of relationships.

* Local vs. long-range dependencies
* Syntax vs. semantics
* Entity tracking vs. structure, etc.

Multi-head attention allows the model to learn **multiple geometries** simultaneously.

Each head:

* Projects into its own query/key/value subspace.
* Computes its own QKᵀ, softmax, and weighted sum.
* Learns to focus on a different pattern.

In code:

```python class SimpleMultiHeadAttention(nn.Module): def __init__(self, d_model, n_heads): super().__init__() assert d_model % n_heads == 0 self.d_model = d_model self.n_heads = n_heads self.d_head = d_model // n_headsself.W_q = nn.Linear(d_model, d_model) self.W_k = nn.Linear(d_model, d_model) self.W_v = nn.Linear(d_model, d_model) self.W_o = nn.Linear(d_model, d_model) def forward(self, x): batch_size, seq_len, _ = x.size() # Linear projections Q = self.W_q(x) # (batch, seq_len, d_model) K = self.W_k(x) V = self.W_v(x) # Split into heads def split_heads(t): return t.view(batch_size, seq_len, self.n_heads, self.d_head).transpose(1, 2) # -> (batch, n_heads, seq_len, d_head) Q, K, V = split_heads(Q), split_heads(K), split_heads(V) # Scaled dot-product attention for each head scores = torch.matmul(Q, K.transpose(-2, -1)) / (self.d_head ** 0.5) attn_weights = F.softmax(scores, dim=-1) head_out = torch.matmul(attn_weights, V) # (batch, n_heads, seq_len, d_head) # Concatenate heads head_out = head_out.transpose(1, 2).contiguous().view(batch_size, seq_len, self.d_model) # Final linear projection out = self.W_o(head_out) return out ```

Conceptually:

> _Multi-head attention =_**_an ensemble of kernel machines_** _over your sequence._

When people say “Transformers understand context,” what they truly mean is:
each head learns to attend based on its own learned notion of similarity.

## 4\. Residual Connections: The Real Backbone

If you had to choose _one_ thing that makes deep Transformers trainable, it’s not attention.

It’s **residual connections**.

The basic rule per layer:

xt+1=xt+f(xt)x_{t+1} = x_t + f(x_t)xt+1​=xt​+f(xt​)

Where:

* `x_t` is the current representation,
* `f(x_t)` is a small learned change (from attention + FFN).

This has two huge benefits:

1. **Stable gradients**
Gradients can flow directly through the “identity path” (`x_t`) even if `f(x_t)` is messy.
2. **Smooth representation updates**
Each layer is encouraged to learn _corrections_ , not completely new representations.

In pseudo-code:

```python def transformer_layer(x): # Self-attention block attn_out = attention(x) x = x + attn_out # residual x = layer_norm1(x)# Feedforward block ff_out = feed_forward(x) x = x + ff_out # residual x = layer_norm2(x) return x ```

If you remove the residuals and stack many layers, you usually get:

* Vanishing / exploding gradients,
* Training instability,
* Poor performance.

Residuals cause a deep Transformer to act more like numerically integrating a dynamical system — performing many small, stable updates to a state.

## 5\. LayerNorm: Curvature & Stability Control

Layer normalization often appears as a minor detail:

``` x = x + sublayer(...)x = layer_norm(x) ```

But mathematically, it’s critical.

LayerNorm:

* Normalizes activations for each token across the feature dimension.
* Keeps the **scale** of representations under control.
* Indirectly affects the **Jacobian** (how changes spread through layers).

If you allow activations to blow up or collapse, the singular values of your layer mappings become unstable — and your gradients may become erratic.

In code, it’s simply:

``` norm = nn.LayerNorm(d_model)x = norm(x) ```

But conceptually:

_LayerNorm is_** _curvature control_** _for your function. It prevents the Transformer from exploding internally as you stack many layers._

## 6\. Feedforward Network: Feature Expansion & Contraction

Each Transformer block includes a feedforward network (FFN / MLP):

![image](https://miro.medium.com/v2/resize:fit:700/1*Eb-ciI1pJXzH3slPkq6Mxg.png)

Where:

* `W1` maps from `d_model → d_ff` (higher dimension)
* `σ` is a nonlinearity (ReLU, GELU, etc.)
* `W2` maps back `d_ff → d_model`

This does three things:

1. **Expands** the feature space (more dimensions).
2. **Applies nonlinearity** to create complex interactions.
3. **Compresses** back to the original size.

Attention on its own is mostly linear mixing of values. The FFN is where the model synthesizes richer features — it’s a little **universal approximator** inside each layer.

Example:

```python class PositionwiseFFN(nn.Module): def __init__(self, d_model, d_ff): super().__init__() self.net = nn.Sequential( nn.Linear(d_model, d_ff), nn.GELU(), nn.Linear(d_ff, d_model), )def forward(self, x): # x: (batch, seq_len, d_model) return self.net(x) ```

You apply this pointwise to each position in the sequence.

``` x = x + ffn(x)x = layer_norm(x) ```

## 7\. Positional Encodings: Giving the Model a Sense of Order

By default, attention is **permutation invariant** :
if you shuffle your tokens, `QKᵀ` doesn’t know which order they came in.

That’s a problem for sequences.

So, Transformers incorporate **positional information.**

## Option 1: Sinusoidal encodings (as in the original paper)

You create a vector for each position using sine and cosine functions at different frequencies.

```python def positional_encoding(seq_len, d_model): pos = torch.arange(seq_len).unsqueeze(1) # (seq_len, 1) i = torch.arange(d_model).unsqueeze(0) # (1, d_model)angles = pos / torch.pow(10000, (2 * (i // 2)) / d_model) pe = torch.zeros(seq_len, d_model) pe[:, 0::2] = torch.sin(angles[:, 0::2]) # even indices pe[:, 1::2] = torch.cos(angles[:, 1::2]) # odd indices return pe # (seq_len, d_model) ```

Then you do:

``` x = token_embeddings + positional_encoding(seq_len, d_model) ```

## Option 2: Learned positional embeddings

Even simpler: treat positions as tokens and learn embeddings.

``` self.pos_embed = nn.Embedding(max_seq_len, d_model)positions = torch.arange(seq_len, device=x.device)pos_vecs = self.pos_embed(positions) # (seq_len, d_model)x = token_embeddings + pos_vecs ```

Intuition:

> _Positional encodings are_** _geometric priors_** _— they tell the model how to interpret “distance” and “order” in the sequence._

Without them, your Transformer perceives the input as a unordered collection of tokens.

## 8\. Putting It All Together: A Tiny Transformer Encoder

Let’s connect the components into a small, educational Transformer encoder.

```python class TinyTransformerEncoder(nn.Module): def __init__(self, vocab_size, d_model=128, n_heads=4, d_ff=512, n_layers=4, max_seq_len=256): super().__init__()self.token_embed = nn.Embedding(vocab_size, d_model) self.pos_embed = nn.Embedding(max_seq_len, d_model) self.layers = nn.ModuleList([ TinyTransformerBlock(d_model, n_heads, d_ff) for _ in range(n_layers) ]) self.ln_f = nn.LayerNorm(d_model) def forward(self, input_ids): # input_ids: (batch, seq_len) batch_size, seq_len = input_ids.size() # Token + positional embeddings token_vecs = self.token_embed(input_ids) # (batch, seq_len, d_model) positions = torch.arange(seq_len, device=input_ids.device) pos_vecs = self.pos_embed(positions)[None, :, :] # (1, seq_len, d_model) x = token_vecs + pos_vecs # Pass through transformer layers for layer in self.layers: x = layer(x) # Final norm x = self.ln_f(x) return x # (batch, seq_len, d_model) ```

If you add:

* A language modeling head (linear → vocab size),
* A training loop with cross-entropy loss,

…you get a basic language model. But beneath the surface, what you’ve truly built is:

> _A deep stack of residual, normalized vector-field updates driven by attention and local feature synthesis._

## 9\. Why So Many People Can Code Transformers but Struggle to Explain Them

It’s easy to wire together blocks:

* Import `nn.MultiheadAttention`.
* Add `LayerNorm` and an MLP.
* Copy a training script.

And still not really know what’s going on.

To truly _understand_ a Transformer, you need to see how the parts work together as a mathematical system.

* **Attention as kernel regression**
`softmax(QKᵀ)V` ≈ data-dependent kernel smoothing over your sequence.
* **Softmax as probability normalization**
Converts similarities into attention weights.
* **LayerNorm as Jacobian / curvature control**
Keeps representation scales and gradients stable.
* **Residuals as stable integration**
Each layer: `x ← x + f(x)` = small, safe update → deep stacks remain trainable.
* **FFN as feature synthesis**
Local, position-wise networks that expand and recompress features.
* **Positional encodings as geometric priors**
Inject structure (order, distance) into an otherwise permutation-invariant system.
* **Multi-head structure as an ensemble of kernels**
Multiple geometries of similarity learned in parallel.

Most people stop at “I can implement it.”
The true leverage appears when you view the Transformer as:

_A numerical method for learning complex functions over structured data such as sequences and graphs, not just a collection of layers._

## 10\. Big Picture: The Transformer as a Numerical Method

Here’s the TL;DR in plain language:

* A Transformer is **not** just an “architecture pattern.”
* It’s more like a **discrete dynamical system** that:
* stabilizes gradients,
* amplifies useful structure,
* and integrates information across tokens over many small steps.

You start with raw token embeddings.
Each layer does:

1. **Look around** (attention / kernel regression),
2. **Adjust features** (FFN),
3. **Apply a small update** (residual),
4. **Keep everything stable** (LayerNorm).

Stack this 24, 48, 100+ times and you create the kind of powerful function approximator that forms the foundation of modern LLMs.
