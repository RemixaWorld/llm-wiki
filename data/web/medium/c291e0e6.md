## 💻 Architecture Overview

![image](https://miro.medium.com/v2/resize:fit:700/1*LpkGh8uru8e65S9MSU79cQ.png)

The architecture of our application integrates Streamlit with the HayStack framework to create an interactive document-based question-answering system. Here’s how it works:

### 1\. User Interaction and Input Handling

* Users interact with the Streamlit app to upload PDF documents or ask questions via _text_ or _voice_.

### 2\. Document Processing and Indexing

* Uploaded PDFs are processed to extract text, which is then cleaned and split into meaningful chunks.
* Each chunk is converted into vector embeddings using Cohere’s model, capturing the semantic meaning of the text.
* These vectors are stored in the Qdrant database, enabling efficient retrieval later on.

### 3\. Query Handling and Retrieval

* When users submit a query, either by typing or speaking, it is embedded into a vector representation.
* The Qdrant database finds the most relevant document chunks based on the query, ensuring fast and accurate retrieval.

### 4\. Response Generation

* The retrieved chunks are passed to the Gemma 7B model, which generates a coherent and contextually relevant answer.

### 5\. Output Display and Interaction

* The generated response is shown as text, and, if desired, converted to speech, providing a seamless and interactive experience.

This streamlined process efficiently combines NLP models and vector databases, making it easy for users to interact with and gain insights from their documents in a few simple steps.

### Create a document Store

A Document Store is an object designed for storing documents. In Haystack, it differs from a component because it lacks a run() method. You can consider it as an interface to your database, where you can either input information or search through it. This means that a Document Store is not part of a pipeline but rather a resource that pipeline components can access and interact with. For more information, please refer to the [Haystack documentation (document stores)](<https://docs.haystack.deepset.ai/docs/document-store>).

``` document_store = QdrantDocumentStore( api_key=Secret.from_token(qdrant_key), url=qdrant_api, recreate_index=False, return_embedding=True, wait_result_from_api=True, embedding_dim=1024, index="RAG", # you can change this name similarity="cosine" ) ```

### Data Indexing Pipeline

In Haystack, a pipeline is a directed multigraph comprising various components and integrations, designed for building modern search systems with large language models (LLMs). It provides the flexibility to connect components in diverse ways, allowing for simultaneous flows, standalone components, loops, and non-linear connections, enabling scalable and dynamic interactions with LLMs. For more information, please refer to the [Haystack documentation(pipelines)](<https://docs.haystack.deepset.ai/docs/pipelines>).

As illustrated in the architecture above, when users upload PDF documents through the app, these documents are processed and indexed by Haystack components. This includes document cleaners, splitters, and embedders that transform the documents into vector representations using the Cohere model, which are then stored in the Qdrant vector database.

```json # Add components to the indexing pipeline## Create pipeline componentsconverter = PyPDFToDocument()cleaner = DocumentCleaner()splitter = DocumentSplitter(split_by="sentence", split_length=10, split_overlap=2)embedder = CohereDocumentEmbedder(api_key=Secret.from_token(cohere_api_key),model="embed-multilingual-v3.0")writer = DocumentWriter(document_store=document_store, policy=DuplicatePolicy.SKIP)# Add components to the indexing pipelineindexing_pipeline = Pipeline()indexing_pipeline.add_component("converter", converter)indexing_pipeline.add_component("cleaner", cleaner)indexing_pipeline.add_component("splitter", splitter)indexing_pipeline.add_component("embedder", embedder )indexing_pipeline.add_component("writer", writer)# Connect the components to each otherindexing_pipeline.connect("converter", "cleaner")indexing_pipeline.connect("cleaner", "splitter")indexing_pipeline.connect("splitter", "embedder")indexing_pipeline.connect("embedder", "writer")#Run the pipeline# The files_path variable represents the path to the PDF files that you need to index.indexing_pipeline.run({"converter": {"sources": files_path}}) ```

### Data Retrieval and Generation Pipeline

In this section, we will explain how the system handles user queries and generates responses. As illustrated in the architecture above, users can ask questions by typing or by using their voice. In the latter case, we need to convert their voice to text in order to input their questions into the retrieval pipeline and obtain the corresponding answers.

* **Audio transcription** 🎙️

Another advantage that **Haystack** offers is a component that converts audio to text. To utilize this feature, you need to use GroqCloud, which provides a model called **‘whisper-large-v3’** specifically designed for transcribing audio. This integration allows for accurate and efficient transcription of audio recordings, enhancing the overall functionality and user experience of your application. For more information, please refer to the [Haystack documentation(audio)](<https://docs.haystack.deepset.ai/docs/audio>).

First, we utilize the `audio_recorder()` function to capture audio input from the user. If the recording is successful, we proceed to save the audio as an MP3 file named "record.mp3". This is done by opening a new file in write-binary mode (`"wb"`) and writing the recorded audio data to it.

```python from audio_recorder_streamlit import audio_recorderrecorded_audio = audio_recorder()if recorded_audio: audio_file = "reocord.mp3" with open(audio_file, "wb") as f: f.write(recorded_audio) ```

Next, we focus on transcribing the recorded audio into text. We achieve this by calling the **RemoteWhisperTranscriber** function, passing in the necessary parameters. This function processes the audio file and returns the transcribed text, allowing users to interact with the system using their voice seamlessly.

``` # Create an instance of RemoteWhisperTranscriber, which connects to a remote Whisper transcription servicewhisper = RemoteWhisperTranscriber(api_base_url=groq_api, api_key=Secret.from_token(groq_key), model="whisper-large-v3")# Run the transcription process on the audio source file that we saved.transcription = whisper.run(sources=[audio_path])# Extract the transcription contenttranscribed_text = transcription['documents'][0].content ```

* **Building the Prompt ✍️**

The `PromptBuilder`compenent in haystack lets you create dynamic prompts using a `Jinja2`template.please refer to the [Haystack documentation(PromptBuilder).](<https://docs.haystack.deepset.ai/docs/promptbuilder>)

You initialize it with a template containing placeholders for variables. These placeholders are filled with values passed through keyword arguments (`kwargs`) when rendering the prompt. This allows you to customize the prompt with different values as needed. The template follows the Jinja2 syntax for flexible prompt creation.

``` template = """Role: You are an AI designed to answer questions strictly based on the information contained in the provided documents. \ Your task is to analyze the available content and generate a relevant response.Guidelines: * Greetings: If the input is a greeting, respond with a brief, friendly message, such as: "Hello! How can I assist you today?" * No Documents Available: If no documents are provided or they are empty, respond with: "I don't have the necessary information to answer your question." * Token Limit for Greetings/No Documents/ general question: Keep your response under 30 tokens if no documents are available or if the input is a greeting or the question is not explicitly covered by the documents. * Document-Based Answers: For questions, base your response only on the content from the provided documents. Avoid using any external knowledge. If the question is not explicitly covered by the documents, respond with: "I don't have the information." * Insufficient Information: If the documents don't contain the necessary information to answer the question, respond with: "I don't have the information."Example Scenarios: * Greeting Example: Input: "Hi there!" Output: "Hello! How can I assist you today?" * No Documents Example: Input: "What is the capital of France?" Output: "I don't have the necessary information to answer your question." * Document-Based Answer Example: Input: "What is the main ingredient in a Caesar salad?" Output: (Based on the content of the provided documents) * General Question Example: Input: "What is the difference between euro and dollar?" Output: "I don't have the information."Important Notes: * Ensure that all responses are accurate and relevant to the content provided in the documents. * Do not use any external knowledge unless explicitly stated in the provided documents. * If multiple documents are provided, loop through them to formulate the answer based on the combined content.
Documents:{% for document in documents %} {{ document.content }}{% endfor %}
Question: {{ question }}?"""prompt_builder = PromptBuilder(template=template) ```

* **Configuring the Text Embedder**

After receiving the user’s query, we need an embedding component to convert the text into a vector. For this, we use `CohereTextEmbedder`, a component that transforms the string into a vector representation, capturing its semantic meaning through a Cohere embedding model. Please refer to the[ Haystack documentation(CohereTextEmbedder).](<https://docs.haystack.deepset.ai/docs/coheretextembedder>)

``` embedder = CohereTextEmbedder(api_key=Secret.from_token(cohere_api_key),model="embed-multilingual-v3.0") ```

* **Configuring the Retriever**

Now we need to define te retriever to get the similar documents from the Vector database, for this we used the `QdrantEmbeddingRetriever` which is an embedding-based retrieval component designed to work with the `QdrantDocumentStore`. It evaluates the embeddings of both the query and the documents, retrieving the most relevant documents from the `QdrantDocumentStore` based on their similarity to the query embedding. Please refer to the [Haystack documentation(QdrantEmbeddingRetriever).](<https://docs.haystack.deepset.ai/docs/qdrantembeddingretriever>)

``` retriever = QdrantEmbeddingRetriever(document_store=document_store) ```

* **Setting Up the Generative Model 🤖**

```json llm = OpenAIGenerator( api_key=Secret.from_token(groq_key), api_base_url=groq_api, # Specify the model name. In this case, we're using "gemma 7b", # but you can choose a different one, as GroqCloud offers multiple models. model="gemma-7b-it", generation_kwargs = {"max_tokens": 512, "temperature": 0}) ```
* **Define & execute the generation pipeline**

Now that we have defined all the components, it’s time to create the pipeline for the data retrieval and generation parts based on the architecture presented above.

``` # Add components to the RAG pipelinerag_pipeline = Pipeline()rag_pipeline.add_component("text_embedder", embedder)rag_pipeline.add_component("retriever", retriever)rag_pipeline.add_component("prompt_builder", prompt_builder)rag_pipeline.add_component("llm", llm)## Connect the components to each otherrag_pipeline.connect("text_embedder.embedding", "retriever.query_embedding")rag_pipeline.connect("retriever", "prompt_builder.documents")rag_pipeline.connect("prompt_builder", "llm") ```

Since our solution supports both voice and text input from the user, we have defined a component to transcribe voice. Therefore, we will create two scenarios to execute the `rag_pipeline`: one for voice input and the other for text input.

```json # Text input response = retriever_pipeline.run({"text_embedder":{"text": user_query}, "prompt_builder": {"question": user_query}})#voice inputresponse = retriever_pipeline.run({"text_embedder":{"text": transcribed_text}, "prompt_builder": {"question": transcribed_text}}) ```
