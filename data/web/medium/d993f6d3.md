## What is NuExtract?

I learned of it from an article by [Stefano Fiorucci](<https://github.com/anakin87>) on Hugging Face: you can read here 👨‍🍳📓 <https://lnkd.in/dpm4p_RM>

🎯 The Goal is to automatically extract structured information from any document, in my case CVs, and create a database with structured data.

The guys at [NuMind](<https://huggingface.co/numind>), are pioneers. As clearly stated on their [official website](<https://numind.ai/>), they aim to create high-quality lightweight models tailored to your needs:

* Automate classification
* entity recognition
* structured extraction

Press enter or click to view image in full size

NuMind official website

They are aware of the main issue here: it is all about computational resources! You need many GPUs to use complex models….

So they pushed further and created a model family of different sizes, so that anyone can run information extraction tasks. Here is the smart strategy:

### NuExtract (3.8 Billion parameters)

NuExtract is a version of [phi-3-mini](<https://huggingface.co/microsoft/Phi-3-mini-4k-instruct>), fine-tuned on a private high-quality synthetic dataset for information extraction. To use the model, provide an input text (less than 2000 tokens) and a JSON template describing the information you need to extract.

Note: This model is purely extractive, so all text output by the model is present as is in the original text. You can also provide an example of output formatting to help the model understand your task more precisely.

You can also try it at [Hugging Face spaces, here](<https://huggingface.co/spaces/numind/NuExtract>).

### NuExtract-tiny (0.5 Billion parameters)

NuExtract_tiny is a version of [Qwen1.5–0.5](<https://huggingface.co/Qwen/Qwen1.5-0.5B>), fine-tuned on a private high-quality synthetic dataset for information extraction. To use the model, provide an input text (less than 2000 tokens) and a JSON template describing the information you need to extract.

Note: While this model provides good 0 shot performance, it is intended to be fine-tuned on a specific task (>=30 examples). And it is quite easy, considering Qwen-1.5 has a context lenght of 32k tokens.

### NuExtract-large (7 Billion parameters)

NuExtract-large is a version of [phi-3-small](<https://huggingface.co/microsoft/Phi-3-small-8k-instruct>), fine-tuned on a private high-quality synthetic dataset for information extraction. To use the model, provide an input text (less than 2000 tokens) and a JSON template describing the information you need to extract.

## Smart strategies and Quantization

The fact that [NuMind ](<https://numind.ai/>)decided to proceed with different model sizes is amazing.

They are really taking into consideration the resources and the individual or Company needs. In fact, even with no GPU computation you can easily run the `NuExtract-tiny`, basically on any computer.

With a proper GPU, on a consumer hardware (for example an Nvidia GTX or AMD GPU with 6 Gb of VRAM) you can also run very fast inference with the `NuExtract `(3.8B), and with decent speed also the` NuExtract-large` (7B).

Quantization, in these scenarios, is the key. you may not be able to run the models (except for the tiny version) if you don’t use a quantized version of the model.

The easiest way to evaluate if you have enough computational power is a simple math:

> 1 Billion parameters = 1GB * 4 VRAM

Press enter or click to view image in full size

infographic by the author

If we take as an example a good laptop, without dedicated GPU card, but with 16 Gb of RAM, we cannot even run the 3.8B version of the model in full precision (FP32) or even the 7B model in half precision (FP16)

In this article we will use the Quantized versions of `NuExtract-tiny` at FP16 quantization. Extensive studies have demonstrated that at Q8 the model precision degradation is almost irrelevant, at FP16 you cannot even see it.

Ok, but where can we find these quantized versions?

Easy, Hugging Face is our friend. You can filter the models by Libraries (GGUF) and by tasks and also by name. Here below an example for `NuExtract`. You may notice that we do not have any quantized version for the `NuExtract-large.`

## The minimum python required

In the HF model card page we have quite the good tips. We want to learn how to extract easily data from a text.

First we import the libraries and load the model

```python import jsonfrom llama_cpp import Llamaimport warningswarnings.filterwarnings(action='ignore')import datetimefrom rich.console import Consoleconsole = Console(width=90) ```

I am using rich because is able to print structured JSON data in a way you can see it in the terminal too.

``` print('loading NuExtract-tiny.gguf with LlamaCPP...')nCTX = 12000sTOPS = ['<|end-output|>']client = Llama( model_path='model/NuExtract-tiny.gguf', #n_gpu_layers=0, temperature=0.24, n_ctx=nCTX, max_tokens=600, repeat_penalty=1.176, stop=sTOPS, verbose=False, )print('Done...') ```

Since this model (the tiny version) comes from [Qwen1.5–0.5](<https://huggingface.co/Qwen/Qwen1.5-0.5B>), fine-tuned on a private high-quality synthetic dataset for information extraction, it has a huge context window of 32k tokens. To save memory I set the `nCTX `to 12k tokens… but you can increase it.

> NOTE: if you set the parameter `verbose=True` you get all the metadata of the model, a sort of Model Card hidden in the GGUF.

This option is quite useful, because we can also understand if a model does have a `chat_template` (this means we can also call the `chat_completion` method…).

The prompt and the generation call comes next:

```json prompt = """<|input|>
### Template:{ "Car": { "Name": "", "Manufacturer": "", "Designers": [], "Number of units produced": "", }}### Text:The Fiat Panda is a city car manufactured and marketed by Fiat since 1980, currently in its third generation. The first generation Panda, introduced in 1980, was a two-box, three-door hatchback designed by Giorgetto Giugiaro and Aldo Mantovani of Italdesign and was manufactured through 2003 — receiving an all-wheel drive variant in 1983. SEAT of Spain marketed a variation of the first generation Panda under license to Fiat, initially as the Panda and subsequently as the Marbella (1986–1998).The second-generation Panda, launched in 2003 as a 5-door hatchback, was designed by Giuliano Biasio of Bertone, and won the European Car of the Year in 2004. The third-generation Panda debuted at the Frankfurt Motor Show in September 2011, was designed at Fiat Centro Stilo under the direction of Roberto Giolito and remains in production in Italy at Pomigliano d'Arco.[1] The fourth-generation Panda is marketed as Grande Panda, to differentiate it with the third-generation that is sold alongside it. Developed under Stellantis, the Grande Panda is produced in Serbia.In 40 years, Panda production has reached over 7.8 million,[2] of those, approximately 4.5 million were the first generation.[3] In early 2020, its 23-year production was counted as the twenty-ninth most long-lived single generation car in history by Autocar.[4] During its initial design phase, Italdesign referred to the car as il Zero. Fiat later proposed the name Rustica. Ultimately, the Panda was named after Empanda, the Roman goddess and patroness of travelers.<|output|>""" ```

The prompt must follow the format shown above: we declare after the the keywords `### Template:` our JSON format expected, and after `### Text:` the context from where we want the information to be retrieved.

We can now call the generation: here I am using `create_completion` (without the `chat_format`) method.

``` start = datetime.datetime.now()output = client.create_completion( prompt =prompt, temperature=0.1, repeat_penalty= 1.11, stop=sTOPS, max_tokens=500, stream=False)delta = datetime.datetime.now() - startresult = output['choices'][0]['text']console.print(result)console.print('---')console.print(f'Completed in {delta}') ```

The call to the model is quite straight forward, but remember that the `temperature `and `repeat_penalty` parameters requires special care. Small models are really sensitive to those values, and the results may be not complete 100%, changing them.

Finally we also convert the model output (a string) into a JSON, easy to be used in following database pipelines.

``` # convert the stringo into JSON and printreplies = [result]adapter = result.replace("'",'"')final = json.loads(adapter)console.print('---')console.print(final) ```

You can save the python file (mine is called `singleExtract.py`) and from the terminal, with the `venv `activated, run

## Future problems…

A [recent pape](<https://arxiv.org/abs/2408.02442v1>)r titled _Let Me Speak Freely? A Study on the Impact of Format Restrictions on Performance of Large Language Models_ , highlights potential quality degradation when LLM are forced to have format restrictions in the prompt.

Press enter or click to view image in full size

Here an example from the paper

Large Language Models (LLMs) have demonstrated remarkable capabilities in generating human-like text, but their application in real-world scenarios often requires the output to be in structured formats like JSON or XML. This is particularly important for extracting key information from the generated content and facilitating easy integration with other systems. However, the impact of imposing such structural constraints on the reasoning abilities and domain knowledge comprehension of LLMs has not been thoroughly investigated.

**The mentioned above paper** addresses the problem by conducting a comprehensive evaluation of LLMs’ performance when generating structured output compared to free-form responses across various common tasks. The findings suggest that enforcing structured output formats can lead to a significant decline in LLMs’ reasoning abilities, with stricter constraints resulting in greater performance degradation.

**But we are safe! In fact our, our NuExtract model is not forcing a strange output, but is already trained to generate JSON outputs. So the model output is enhanced by the fine-tuning and there is no model quality degradation.**

You can use the bigger models with the same approach, but do not expect fast inference (unless you have a GPU). It will work like a charm.
