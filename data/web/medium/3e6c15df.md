First, we will build our own 3D first-person shooting game using the Ursina engine. This environment is where our agent will operate.

1. **So the very first step is we are going to let our agent perceive the game world.** We do this by constantly taking screenshots for visual information and simultaneously saving critical data like player health, enemy location, and aiming details into a json file.
2. **Then, we are going to capture the game’s state.** This means taking a screenshot to see the visual environment and reading a data file to get precise info like player health and enemy location.
3. **afterwards, our high-level ‘Commander’ AI (the vision model) analyzes that screenshot and data.** Based on the big picture, it decides on an overall strategy, like whether to ENGAGE_AGGRESSIVELY or REPOSITION_DEFENSIVELY.
4. **After that, the ‘Lieutenant’ AI (the text model) receives the Commander’s strategy.** It looks at the most current, real-time data and chooses the best immediate action to follow that strategy, such as AIM at the enemy or ATTACK.
5. **Next, that simple command is translated into actual keyboard presses and mouse movements.** This allows the agent to physically interact with the game and control the player character.
6. **Finally, this entire process repeats in a continuous, fast loop.** By constantly perceiving, thinking, and acting, the agent can react to what’s happening and play the game autonomously.

## Creating Logical Enemies and Health Status

Now we are very close to completing our gaming environment, and soon we will move to the **agent phase** , where the AI will play the game. Enemies are one of the most important components of our game.

We want our enemies to **not have weapons** , but instead, their ability will be to **hunt the player by moving toward them** and reducing the player’s health on contact.

So, first, we need to create an **enemy structure** that continuously tries to reach the player, no matter where the player moves.

```python class Enemy(Entity): # Enemy entity class def __init__(self, **kwargs): # Initialize enemy super().__init__( parent=shootables_parent, # Set parent to shootables model='cube', # Use cube model scale_y=2, # Set vertical scale origin_y=-.5, # Set origin color=color.light_gray, # Set color collider='box', # Set collider **kwargs # Additional arguments ) self.health_bar = Entity( # Create health bar entity parent=self, # Set parent to enemy y=1.2, # Position above enemy model='cube', # Use cube model color=color.red, # Set color to red world_scale=(1.5, .1, .1) # Set scale ) self.max_hp = 100 # Set max HP self.hp = self.max_hp # Initialize HP def update(self): # Update enemy each frame dist = distance_xz(player.position, self.position) # Calculate distance to player if dist > 40: # Skip if too far return self.health_bar.alpha = max(0, self.health_bar.alpha - time.dt) # Fade health bar self.look_at_2d(player.position, 'y') # Face player hit_info = raycast( # Raycast forward self.world_position + Vec3(0, 1, 0), # Start above enemy self.forward, # Direction forward 30, # Ray length ignore=(self,) # Ignore self ) if hit_info.entity == player: # If player is hit if dist > 2: # If not close self.position += self.forward * time.dt * 5 # Move towards player @property def hp(self): # HP property getter return self._hp @hp.setter def hp(self, value): # HP property setter self._hp = value # Set HP if value <= 0: # If HP depleted destroy(self) # Destroy enemy return self.health_bar.world_scale_x = self.hp / self.max_hp * 1.5 # Update health bar scale self.health_bar.alpha = 1 # Show health bar ```

So, there’s a lot happening in our enemy code, but let’s simplify it for easier understanding. Our enemy is created and functions in a **simple yet effective way**.

Here’s a breakdown:

* The enemy is a cube entity with a light gray color, box collider, and slightly stretched vertical scale to resemble a character.
* A red health bar is attached above the enemy to show its current health.
* The enemy starts with **100 HP** , and when HP reaches **0** , it is destroyed.
* In the `update` function, the enemy first checks its distance from the player, if the player is more than **40 units away** , it does nothing to save performance.
* The health bar slowly fades out when not recently hit to keep the screen clean.
* The enemy always rotates to face the player using `**look_at_2d**`.
* A **raycast** is used to detect if there’s a clear line of sight to the player.
* If the player is detected and is more than **2 units away** , the enemy moves toward the player at a steady speed, chasing the player naturally.
* The HP property updates the health bar size according to the remaining health and makes it fully visible for a short time when hit.
* When HP drops to **0 or below** , the enemy is destroyed and removed from the game.

This is just for a single enemy. Now, we can easily create **multiple enemies** by simply using a loop to spawn several of them in the environment.

## Capturing the Game State

As discussed earlier, our agent will be composed of two components/models:

1. **Vision model** to “see” the screen.
2. **Text-based reasoning model** to understand textual information such as enemy positions, player position, health status, etc.

To make this work, we need to maintain a **dictionary that stores the game state** , which will include all necessary textual information for the agent to make decisions and take the next step accordingly.

First, let’s **capture the player’s position and aiming direction**. This will allow our agent to aim directly at the enemy if it’s visible on the screen. We will store these values in variables that can later be added to our game state dictionary.

```python import math # Import the math module for mathematical functions.# Get the player's current rotation on the y-axis (in degrees)player_y_rotation = player.rotation_y# Calculate the direction vector from the player to the enemydirection_vector = enemy.position - player.position# Calculate the angle to the enemy using atan2 for accuracy, in radiansangle_to_enemy_rad = math.atan2(direction_vector.x, direction_vector.z)# Convert the angle from radians to degreesangle_to_enemy_deg = math.degrees(angle_to_enemy_rad)# Calculate the difference between the player's view angle and the angle to the enemyaiming_error = angle_to_enemy_deg - player_y_rotation# Normalize the aiming error to be between -180 and 180 degrees for easier interpretationif aiming_error > 180: aiming_error -= 360if aiming_error < -180: aiming_error += 360 ```

So, we are basically calculating how accurately the player is aiming at the enemy by comparing the player’s current viewing angle with the enemy’s position.

* We first get the **player’s rotation on the y-axis** (horizontal view direction).
* We then find the **direction vector** from the player to the enemy by subtracting their positions.
* Using `**math.atan2**`, we calculate the precise angle (in radians) from the player to the enemy.
* This angle is converted to **degrees** for easier interpretation.
* We calculate the **aiming error** by subtracting the player’s current view angle from the angle to the enemy.
* Finally, we **normalize the aiming error** to stay within **-180 to 180 degrees** , making it easier for the agent to interpret whether it needs to aim left or right to target the enemy.

Next, based on this calculation and the default information from the Ursina engine, we need to determine **hitting information** while the game is being played. Specifically, we need to know whether a shot **hits an enemy** or **misses**.

For this, we can use the `**raycast**` element, which we have already used earlier for building some entities. The raycast will project a line from the player's weapon (or camera direction) and detect whether it collides with an enemy entity or not.

This hitting info will then be stored in our **game state dictionary** , so the agent can understand whether its shooting action was successful or not.

``` # Use a raycast from the player's camera to check for line of sight to the enemy.hit_info = raycast(player.world_position + player.camera_pivot.up, camera.forward, distance=100, ignore=(player,))# The enemy is visible if the raycast hits the enemy entity.is_enemy_visible = True if hit_info.entity == enemy else False ```

This way, we are determining whether the enemy is directly visible to the player or blocked by any obstacles.

* We use a **raycast** starting from the player’s camera position, slightly adjusted upward (`player.camera_pivot.up`).
* The raycast shoots forward in the **same direction the camera is facing** (`camera.forward`).
* We set the **maximum distance** to 100 units, enough to cover long-range visibility.
* The raycast **ignores the player itself** to prevent false detection.
* If the raycast **directly hits the enemy entity** , we set `is_enemy_visible` to `True` otherwise, it’s `False`.

This information will help our agent decide:

* If the enemy is in sight and hit detection is positive → aim and shoot.
* If the enemy is not in sight → move closer or adjust position until the enemy becomes visible.

Now, we can store all the relevant information such as player position, aiming direction, hit detection, enemy positions, and health statuses into a single dictionary.

We are storing key important details from our game state into a structured dictionary so our agent (DeepSeek Model) can make better decisions.

* `player_health` stores the player’s current HP to decide defensive or aggressive actions.
* `player_rotation_y` keeps track of the player’s view direction to help with aiming decisions.
* `enemy_health` tracks the enemy’s HP to decide whether to continue attacking or switch targets.

* `is_enemy_visible` indicates if the enemy is currently in the player’s line of sight.
* `angle_to_enemy_error` measures how much the player’s aim needs to adjust to target the enemy.
* `game_status` holds the current game phase or state (e.g., fighting, exploring, paused).

## Building Action Decider Component

We need to make our agent **actionable** based on the given environment status through the text information that we stored earlier in a JSON file. To take actions, we must give our DeepSeek component access to the **keyboard** and **mouse**.

So, let’s first **import those modules** and correctly **initialize them**.

```python # Import keyboard control classes from pynputfrom pynput.keyboard import Key, Controller as KeyboardController# Import mouse control classes from pynputfrom pynput.mouse import Button, Controller as MouseController# Create an instance of the keyboard controller to simulate key presseskeyboard = KeyboardController()# Create an instance of the mouse controller to simulate mouse movements and clicksmouse = MouseController()# Set the model ID for the "Lieutenant" agent, a faster text-only model for quick tactical decisions.text_model_id = "deepseek-ai/DeepSeek-V3" ```

We are initializing the basic components through which our agent will control the **mouse** and **keyboard**.

Next, we need to initialize the **execution strategy** for our agent basically defining what possible actions the agent can perform. For that, we need to create a function as well.

```python def execute_command(command, game_state): """(The Muscle) Translates low-level commands from the AI into actual keyboard and mouse actions.""" # Get the current aiming error from the game state, defaulting to 0 if it's not available. aim_error = game_state.get('angle_to_enemy_error', 0) # If the command is to AIM or ATTACK and an enemy is currently visible... if command in ['AIM', 'ATTACK'] and game_state.get('is_enemy_visible', False): # Calculate the necessary mouse movement to correct the aim. mouse_movement = -int(aim_error * 2.5) # A multiplier acts as sensitivity. # Move the mouse horizontally to adjust the aim. mouse.move(mouse_movement, 0) # If the command is ATTACK and the aim is already accurate (error is small)... if command == "ATTACK" and abs(aim_error) < 5: # Press and hold the left mouse button to fire. mouse.press(Button.left) else: # Otherwise, release the left mouse button to stop firing. mouse.release(Button.left) # If the command is to perform a defensive maneuver... if command == "DEFENSIVE_MANEUVER": # Press 's' and 'a' keys to move backward and left. keyboard.press('s'); keyboard.press('a') # Hold the keys for a short duration. time.sleep(0.5) # Release the keys. keyboard.release('s'); keyboard.release('a') # If the command is to search for the enemy... if command == "SEARCH": # Move the mouse horizontally to look around. mouse.move(80, 0) # If the command is to advance... if command == "ADVANCE": # Press 'w' to move forward briefly. keyboard.press('w'); time.sleep(0.3); keyboard.release('w') ```

We are defining **five possible actions** that our agent can take based on the game state stored in the JSON file:

* **AIM** → Adjusts the aim towards the enemy by moving the mouse horizontally based on the aiming error.
* **ATTACK** → Fires at the enemy by holding the left mouse button when the aim is accurate (aiming error < 5).
* **DEFENSIVE_MANEUVER** → Moves backward and left (`S` \+ `A` keys) to dodge or take cover.
* **SEARCH** → Moves the mouse around to look for enemies when they are not visible.
* **ADVANCE** → Moves forward (`W` key) briefly to get closer to the enemy or objective.

Each of these actions directly manipulates the mouse and keyboard through the **Pynput** controllers, allowing the **DeepSeek** agent to interact with the game environment just like a human player.

## Creating Main Action Logic of Our AI Agent

We need to create a **loop** that will continuously re-apply the logic functions we coded earlier. This loop should also **store each action state** , allowing the agent to decide whether the next step should be different or remain the same based on its **past knowledge**. Let’s code that loop logic.

```python # importing the necessary librariesimport time# Start the main control loop that runs continuously.while True: # Read the latest game state from the JSON file. game_state = read_game_state() # If the game state is missing or indicates the game has ended, stop the agent. if not game_state or game_state.get('game_status') in ['won', 'lost']: print(f"Game over or state unreadable.") break # --- COMMANDER'S TURN (Strategic Thinking) --- # Check if enough time has passed since the last strategic update. if time.time() - last_strategic_update_time > strategic_update_interval: # If so, capture a new screenshot. screenshot = capture_screen_as_base64() # Ask the Commander (VLM) for a new strategic goal. current_strategic_goal = get_strategic_goal_from_vlm(game_state, screenshot) # Update the timestamp for the last strategic update. last_strategic_update_time = time.time() # --- LIEUTENANT'S TURN (Tactical Execution) --- # Ensure the Commander has provided an initial strategy. if current_strategic_goal != "INITIALIZING": # Ask the Lieutenant (LLM) for a specific tactical action based on the current strategy. tactical_action = get_tactical_action_from_llm(current_strategic_goal, game_state) # Execute the chosen action. execute_command(tactical_action, game_state) else: # If still initializing, just print a waiting message. print("Waiting for initial strategy from Commander...") # Pause briefly before the next loop iteration to control the action frequency. time.sleep(0.3) # Tactical loop speed ```

It first continuously runs in a loop until the game ends or the state becomes unreadable.

* It starts by **reading the latest game state** from the JSON file to ensure updated information.
* If the game is over (either **won** or **lost**), the loop **breaks immediately**.
* The **Commander (Strategic Model)** is responsible for making high-level decisions. Every few seconds (based on `strategic_update_interval`), it:
* Captures a **new screenshot** of the game.
* Calls the **VLM (Vision-Language Model)** to get a **new strategic goal** based on the game state and visual input.
* Updates the last time a strategic decision was made.
* The **Lieutenant (Tactical Model)** handles immediate actions.
* If the Commander has already set a valid strategy (not “INITIALIZING”), the Lieutenant asks the **LLM (Language Model)** for the **next tactical action**.
* That action is **executed immediately** in the game using `execute_command()`.
* If still initializing, it simply waits and prints a message.
* A **short delay (**`**time.sleep(0.3)**`**)** ensures the loop runs smoothly without overloading the system, giving time for processing actions.

This loop allows the agent to make **dynamic decisions** ,**** the Commander updates strategy at longer intervals, while the Lieutenant executes rapid actions based on real-time game state.
