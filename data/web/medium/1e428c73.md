## Embedding

Let’s take a closer look at the “Embedding” section in the Transformer Explainer. This part will show us how tokens are transformed. So, what’s happening in embedding? Well, when you input text, it’s converted into the final embedding through four steps. First off, a token is any chunk of text the model handles — it could be a whole word, a part of a word, a single character, or even a punctuation mark.

For example, let’s take the sentence “Data visualization empowers users to.” When it gets tokenized, it’s split into tokens like [“Data”, “visualization”, “empowers”, “users”,” to”]. Each token is then given a unique identifier, like a special tag, that the model uses during its processing. This way, the model knows exactly how to handle each piece of the sentence as it works its magic.

Then, the token embedding step kicks in. This converts each word into numerical data, kind of like turning words into numbers. This allows the model to understand and capture how similar different tokens are in meaning. For example, tokens that mean similar things will have similar embedding vectors. It’s like the model’s way of grouping words that share vibes!

Next up, we have positional encoding. This step injects a bit of magic, adding information about word order into the model.

Think about it like this:’

‘T**he cat sat on the mat** ’ versus ‘**The mat sat on the cat.** ’ They sound similar but mean totally different things, right? That’s where positional encoding comes into play.”

We add a special vector to each word’s embedding that indicates its position in the sentence. These vectors are designed smartly so that the model can learn from them to understand the sequence of words. It’s like giving the model hints to figure out which word comes first, second, and so on, helping it understand the overall meaning

## Multi-head Self Attention

Then, this embedding is used in something called Multi-head Self Attention, which helps the model to pick up on complex relationships and dependencies between tokens, no matter how far apart they are in the sentence. From this vector, we calculate three important inputs: Query, Key, and Value. These allow the model to focus on different parts of the input sentence based on the context provided by the Query of the current token. This means the model can pay more attention to what’s most important at any given moment in the sentence.

The attention scores decide how much influence each token’s Value has on the final output representation for “Data.” This process is repeated for each token in the sequence, allowing the model to capture complex relationships and dependencies within the input data.

The attention score is calculated by taking the dot product of the Query for “data” with the Keys of all tokens. After calculating the dot products, we apply the softmax function to these scores to convert them into attention weights. This step ensures that the weights sum to one, allowing them to be interpreted as probabilities. Finally, we compute the output for “data” by taking the weighted sum of the Values (V) of all tokens, using the attention weights obtained from the softmax step.
