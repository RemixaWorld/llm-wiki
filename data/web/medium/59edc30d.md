Large Language Models (LLMs) with its exceptional generation capabilities are finding ways into various products, and we are seeing novel applications popping up like mushrooms. These are general-purpose tools, and often lack domain-specific knowledge reducing their impact somewhat. Such useful domain knowledge may be hidden away in disparate enterprise repositories.

Fine-tuning a custom LLM with your domain data may help bridge this gap. A key step toward this process is data preparation. This is a crucial step, as the quality of this data will significantly effect the fine-tuned model’s performance. Attempting to manually curate such a dataset can be an expensive and a very time-consuming exercise.

In this article, we will explore a cost-efficient alternative to automate the creation of instruction as well as training datasets from internal documents using the Mistral 7B Instruct model. We will pursue a novel approach to instruction generation that ensures a comprehensive coverage of your domain. Mistral 7B will also be used in a Retrieval-Augmented Generation (RAG) setup to generate the training dataset. Once we have the training dataset, we will call upon the MLX framework library to help with the actual fine-tuning of Mistral 7B with this dataset to enrich it with our local domain knowledge.

As we will explore the end-to-end workflow from instruction generation to fine-tuning of the model, there is quite a bit to cover here. Let’s get started!

## 1.0 Key Enabling Technology Overview

This work will be undertaken on a MacBook Air M1 with only 8GB RAM. Due to its rather limited compute and memory resources, we are adopting a 4-bit quantized version of Mistral 7B Instruct v0.1 model. To load such a quantized model in the GGUF format, we will be using the `llama-cpp-python` library, which is a Python bindings for the `llama.cpp` library.

`faiss-cpu` is a library for efficient similarity search and clustering of dense vectors using CPU. For training data generation, we will adopt the RAG technique. A RAG application consists of a retriever system to fetch relevant document snippets from the FAISS vectorstore, and an LLM to generate responses using the retrieved snippets as context. We have previously shown in an [earlier work](<https://medium.com/@heelara/querying-internal-documents-using-mistral-7b-with-context-of-ensemble-retrievers-f40aadaf8a6e>) that the `EnsembleRetriever` is a great choice for it [1]. It ensembles and reranks the results from a chosen list of retrievers based on the _Reciprocal Rank Fusion_ algorithm. We will combine a BM25 retriever and a FAISS retriever at ratio 0.3:0.7 for our ensemble.

The final key piece of technology is related to fine-tuning. Both `llama.cpp` and MLX framework [2] libraries provide tools to assist with fine-tuning. The latter takes advantage of Apple silicon to provide hardware acceleration, which makes fine-tuning a breeze on Mac. As such, we will be adopting MLX here.

We are now ready to prepare our dev environment. Let’s create a virtual environment to manage this project. To create and activate the environment, let’s run the followings:

``` python3.10 -m venv llm_tuningsource llm_tuning/bin/activate ```

Module `LoadVectorize` involves loading a 440-page IT vendor deployment guide that was released recently (Dec 2023). Let’s now take a look at the second module in depth.

### 2.1 Instruction Generation

For this end-to-end workflow, we are using a sample 400+-page pdf document about Riverbed SteelHead, an application acceleration solution, as the domain knowledge for the language model to acquire. As the first step, we will generate instructions (or prompts) related to this document using Mistral 7B as the language model.

The key design challenge here is how would the LLM know what instructions to generate for an area where it is not well-versed yet. This would be a common challenge for any internal documents. As part of the vectorization step, FAISS vectorstore has reference to the document chunks, which collectively form the domain knowledge. The main idea of this instruction generation function is to use LLM to generate instructions with each chunk individually serving as its context. To ensure these instructions provide a comprehensive coverage of the knowledge in a chunk, we should ideally generate instructions against every single document chunk. The number of instructions should be proportional to the adopted document chunk size. For our demonstration purposes, we will generate two questions for 100 random document chunks here due to time and platform resource constraints.

To gain access to the document chunks, get the `docstore` object from the FAISS object and the list of `docstore_id` representing all the document chunks. During each iteration, we find the relevant document chunk and use it as context for querying the QA chain.

The prompt for this instruction generation is:

> Please generate two questions about SteelHead based on the provided context. The question should be around SteelHead WAN acceleration and its related concepts only. The questions should start with any of the following: “What”, “How’, “Is there a”, “What are the”, “How do I”, “When is it”, “Does SteelHead have”, “How to”, “What is the difference”, “Which”, “List”. You do not need to provide an answer or category to each question.

By iterating through each selected document chunk, we invoke the QA chain with the chunk as the context and the above prompt. To serve as progress, the generated instructions are displayed on the console with with the time spent. The resulting instructions are saved to file `instructions.txt`. To serve as the generation progress, the current question number and time spent will be displayed at each iteration. With this understanding, the following listing captures code for function `generate_instructions`.

```python def generate_instructions(db,QA_PROMPT,llm) -> None: output_parser = StrOutputParser() # Custom QA Chain chain = ( {"context": RunnablePassthrough() , "question": RunnablePassthrough()} | QA_PROMPT | llm | output_parser ) # access docstore and docstore id for 100 random chunks vs = db.__dict__.get("docstore") docstore_id_list = list(db.__dict__.get("index_to_docstore_id").values()) rand_doc_id_list = random.choices(docstore_id_list, k=200) query = ''' Please generate two questions about SteelHead based on the provided context. The question should be around SteelHead WAN acceleration and its related concepts only. The questions should start with any of the following: "What", "How', "Is there a", "What are the", "How do I", "When is it", "Does SteelHead have", "How to", "What is the difference", "Which", "List". You do not need to provide an answer or category to each question. ''' qfile = open("instructions.txt", "w") start_gen = timeit.default_timer() for i,doc_id in enumerate(rand_doc_id_list): start = timeit.default_timer() a_doc = vs.search(doc_id) result = chain.invoke({"question": query, "context": a_doc.page_content}) resp_time = timeit.default_timer() - start # seconds print(f'{"-"*50}
Q #{i}: {result}
Time: {resp_time}
{"-"*50}
') qfile.write(result) qfile.close() # total time for generation gen_time = timeit.default_timer() - start_gen # seconds print(f'Total generation time => {timedelta(seconds=gen_time)}') ```

### 2.2 Training Dataset Generation

Once we have the instructions, we can now proceed with the training dataset generation. As before Mistral 7B is used as the LLM, however this time in a RAG setup. We will be using an `EnsembleRetriever` of FAISS maximum marginal relevance (MMR) and BM25 retrievers. We have previously shown that a ratio of 0.3:0.7 achieved the best accuracy performance for this retriever list.

Iterating through the instructions, we query the LLM for the answer and use it to generate a JSON string of the following format:

`<s>[INST] {instruction}[/INST] {answer}</s>`

Once we have the training dataset, 80% of this dataset is used for training and stored in `train.jsonl`. The remaining 20% of dataset will be used for validation and stored as `valid.jsonl`. The following listing captures the above procedure as function `generate_training`.

```python def generate_training(db,bm25_r,QA_PROMPT,llm) -> None: # create retrievers faiss_retriever = db.as_retriever(search_type="mmr", search_kwargs={'fetch_k': 3}, max_tokens_limit=1000) ensemble_retriever = EnsembleRetriever(retrievers=[bm25_r,faiss_retriever],weights=[0.3,0.7]) output_parser = StrOutputParser() # Custom QA Chain chain = ( {"context": ensemble_retriever | format_docs, "question": RunnablePassthrough()} | QA_PROMPT | llm | output_parser ) with open('instructions.txt') as tfile: instructions = tfile.readlines() start_t_gen = timeit.default_timer() train_lines = list() for i, instruction in enumerate(instructions, start=1): print(f"Handling ({i}/{len(instructions)}):") start = timeit.default_timer() try: answer = chain.invoke(instruction) except Exception as e: # skip questions that can't be answered by LLM print(f'FAILED for => {e}') continue resp_time = timeit.default_timer() - start # seconds print(f'{"-"*50}
Q #{i}: {instruction}
A:{answer}
Time: {resp_time}
{"-"*50}
') result = json.dumps({ 'text': f'<s>[INST] {instruction}[/INST] {answer}</s>' }) + "
" # write to a temp file with open('train_valid.jsonl', 'a') as file: file.write(result) train_lines.append(result) gen_time = timeit.default_timer() - start_t_gen # seconds with open('train.jsonl', 'w') as file: file.writelines(train_lines[:int(len(train_lines) * 0.2)]) with open('valid.jsonl', 'w') as file: file.writelines(train_lines[int(len(train_lines) * 0.2):]) print(f'Total training generation time => {timedelta(seconds=gen_time)}') ```

To invoke either of the above key functions, we will use function `main` as described next.

### 2.3 Function `main`

In this function, a number of common objects used by both functions are instantiated. Firstly, the prompt template is defined. The quantized 4-bit Mistral 7B Instruct model in the GGUF format is then loaded using `LlamaCpp`. Next, the pdf document is vectorized and a reference to its FAISS object is obtained along with a BM25 retriever.

To allow easy invocation of either generation function, let’s make use of the command-line options. Function `main` will accept up to two boolean arguments, which will be controlled by the supplied command-line options. To decide either instruction or training dataset generation task to be launched, command line option `-i` or `-t` will be used, respectively, with library `argparse`.

The following listing captures these command-line option handling as well as function `main`.

```python def main(is_gen_instruct=False,is_gen_training=False): # Prompt template qa_template = """<s>[INST] You are a helpful assistant. Use the following context to answer the question below accurately and concisely: {context} [/INST] </s>{question} """ # Create a prompt instance QA_PROMPT = PromptTemplate.from_template(qa_template) llm = LlamaCpp( model_path="./models/mistral_7b_gguf/mistral-7b-instruct-v0.1.Q2_K.gguf", temperature=0.01, max_tokens=2000, top_p=1, verbose=False, n_ctx=3000 ) db,bm25_r = LoadVectorize.load_db() if is_gen_instruct: generate_instructions(db,QA_PROMPT,llm) elif is_gen_training: generate_training(db,bm25_r,QA_PROMPT,llm) if __name__ == "__main__": # Initialize parser parser = argparse.ArgumentParser("Script to generate instruction or training data for LLM fine-tuning") group = parser.add_mutually_exclusive_group() # Adding optional mutually-exclusive arguments group.add_argument("-i", "--instructions", action='store_true', help = "Generate Instructions") group.add_argument("-t", "--training", action='store_true', help = "Generate Training and Validation Data") # Read arguments from command line args = parser.parse_args() if args.instructions: main(is_gen_instruct=args.instructions) elif args.training: main(is_gen_training=args.training) ```

We are now ready to fine-tune the model with the training dataset from the previous section. MLX supports Parameter Efficient Fine-Tuning (PEFT) through LoRA, which focuses on updating a subset of the model’s parameters. It often involves freezing certain layers or parts of the model. This approach naturally results in faster fine-tuning. In addition, MLX uses QLoRA on quantized models.

Script `lora.py` will help us here. When it detects the model is quantized, this script automatically switches to use QLoRA. Option `--data` is used to specify the directory containing our training and validation datasets. Option `--lora-layers` is used to set the number of layers to fine-tune. And option `--iters` specifies the number of iterations to train for. There are other optional settings, such as learning rate and sampling temperature, that can be used to control your fine-tuning. Simply run the script with option `-h` to get the full help listing.
