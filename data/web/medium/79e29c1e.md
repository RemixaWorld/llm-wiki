## Background Of AI Interpretability

DL models can learn human-comprehensible algorithms. These models can be understood, but by default, they have no incentive to make themselves legible to us.

Mechanistic interpretability in the context of DL involves delving into the inner workings of these models to understand how individual components contribute to overall behavior. To put it technically, we want to elucidate the function of**each neuron, layer, and pathway within the network with respect to how they process inputs and affect the final output.**

**But how are we making these claims that DL models can be broken down and interpreted?** The hunch is that in the end, DL models are just a bunch of neurons performing linear algebra, so theoretically, it should be possible to break it down in a human-understandable form.

> **“Mechanistic Interpretability” seeks to reverse engineer neural networks, similar to how one might reverse engineer a compiled binary computer program. After all, neural network parameters are in some sense a binary computer program which runs on one of the exotic virtual machines we call a neural network architecture.**

## What Is Monosemanticity?

Monosemanticity in mechanistic interpretability means that each component or mechanism within the model should have a single, clear, and unambiguous function or meaning.

Monosemanticity tries to create a dictionary in which we can look up each set of features that corresponds to what concept they represent. This is what they call **_“dictionary learning”_** and in this case, they use a Sparse Autoencoder to create the “dictionary”.

I wish life would have been so easy, but it’s not.

Concepts in DL architectures are superpositioned and that’s what makes interpretability so hard. So before we go deep into how Anthropic uses these autoencoders to achieve Monosemanticity, let’s understand the problem in more detail.

### Superposition in DL models

It would be very convenient if the individual neurons of artificial neural networks corresponded to cleanly interpretable features of the input. For example, in an “ideal” ImageNet classifier, each neuron would fire only in the presence of a specific visual feature, such as the color red, a left-facing curve, or a dog snout.

Empirically, in models we have studied, some of the neurons do cleanly map to features. But it isn’t always the case that features correspond so cleanly to neurons, especially in large language models where it actually seems rare for neurons to correspond to clean features. This brings up many questions. Why is it that neurons sometimes align with features and sometimes don’t? Why do some models and tasks have many of these clean neurons, while they’re vanishingly rare in others?

To answer that researchers found that not only can models store additional features in superposition by tolerating some interference, but they also showed that, at least in certain limited cases, models can perform computation while in superposition. (In particular, they showed that models can put simple circuits computing the absolute value function in superposition.)

This leads them to hypothesize that the neural networks we observe in practice are, in some sense, noisily simulating larger, highly sparse networks. In other words, it’s possible that models we train can be thought of as doing “the same thing as” an imagined much larger model, representing the exact same features but with no interference.

### Using Sparse Autoencoders

Autoencoders simply take an input, map it to a new set of values, and then reconstruct the original set from the new one. Usually, Autoencoders are used to compress information from a high-dimensional space to a lower-dimensional one. For example, go from a layer with 1024 values to one with 32 then back up to 1024.

**To extract monosemantic features they flip the Autoencoder on its head and encode the information into a larger dimensional space.**

They call this a Sparse Autoencoder. Since there are multiple concepts represented in each neuron, they decompose into _more features than there are neurons._

## Sparse Autoencoders (SAE)

The SAE consists of two layers. The first layer (“encoder”) maps the activity to a higher-dimensional layer via a learned linear transformation followed by a ReLU nonlinearity. We refer to the units of this high-dimensional layer as “features.”

The second layer (“decoder”) attempts to reconstruct the model activations via a linear transformation of the feature activations. The model is trained to minimize a combination of (1) reconstruction error and (2) an L1 regularization penalty on the feature activations, which incentivizes sparsity.

Once the SAE is trained, it provides us with an approximate decomposition of the model’s activations into a linear combination of “feature directions” (SAE decoder weights) with coefficients equal to the feature activations.

The sparsity penalty ensures that, for many given inputs to the model, a very small fraction of features will have nonzero activations. Thus, for any given token in any given context, the model activations are “explained” by a small set of active features (out of a large pool of possible features).

They apply the Sparse Autoencoder to the residual stream halfway through the model. At the “middle layer”.

The residual stream is much smaller than the MLP layer, making training the SAE cheaper. It is also where the model is passing information through and has a reasonable level of abstraction being in the middle.

### Local Replacement Model

The local replacement model is specific to a prompt of interest. An error adjustment term is added, and attention patterns froze to be what they were in the original model on the given prompt. It produces the exact same output as the original model but replaces as much computation as possible with features.

### Attribution Graph

Tracing from input to output through active features, pruning paths that don’t influence the output.

Press enter or click to view image in full size

By studying the interactions between features in the local replacement model, we can trace its intermediate steps as it produces responses. More concretely, we produce **attribution graphs** _,_ a graphical representation of the computational steps the model uses to determine its output for a particular input, in which nodes represent features and edges represent the causal interactions between them. As attribution graphs can be quite complex, we _prune_ them to their most important components by removing nodes and edges that do not contribute significantly to the model’s output.

With a pruned attribution graph in hand, we often observe groups of features with related meanings that play a similar role in the graph. By manually grouping these related graph nodes together into **supernodes,** we can obtain a simplified depiction of the computational steps performed by the model.

## Multi-Step Reasoning

Let’s consider the prompt Fact:

**_“the capital of the state containing Dallas is?”_**

For LLMs to complete this, it needs two steps — first, inferring that the state containing Dallas is Texas, and second, that the capital of Texas is Austin. But the real question is whether LLMs can actually perform these two steps internally. Or does it rely on some “shortcut” (e.g. perhaps it has observed a similar sentence in the training data and simply memorized the completion)?

We can answer this question by computing the [attribution graph](<https://transformer-circuits.pub/2025/attribution-graphs/static_js/attribution_graphs/index.html?slug=capital-state-dallas>) for this prompt, which describes the features the model used to produce its answer, and the interactions between them. First, we examine the features’ visualizations to interpret them, and group them into categories (“supernodes”).

Language models recognize capital cities through different connected features, let’s take a look at those:

**1\. Word-specific features:** Find exact words like “capital” in our case.

**2\. Concept features** : Recognize “capital” across different contexts, because the same word can be used in several different forms:

* maybe in questions related to state capitals
* in multilingual contexts (Turkish “başkenti”, Hindi “राजधानी”, etc.)

**3\. Output features:** Force the model to generate specific capital names:

* Some features activate specifically to output “Austin”
* Others activate to output various US state capitals
* Some activate to output country capitals

**4\. Context feature:** Identify locations like Texas generally, without being tied to specific cities or places.

The system groups related features into “**supernodes** ” that collectively represent concepts like **_“say a capital”_** or** _“Texas”_** even when individual features might represent slightly different aspects of those concepts.

After creating these supernodes, we can see in our attribution graph interface that, for example, the “** _capital_** ” supernode promotes the “s** _ay a capital_** ” supernode, which promotes the “** _say Austin_** ” supernode. To represent this, we draw a diagram where each supernode is connected to the next with a brown arrow, as in the below graph snippet:

The attribution graph contains multiple interesting paths, summarized below:

* The Dallas features (with some contribution from state features) activate the feature group representing the state of Texas.
* In parallel, we also see that the features activated by the word capital activate another cluster of output features that cause the model to _say_ the name of capital.

* There also exists a “** _shortcut_** ” edge directly from Dallas to say Austin. See, this type of thing directly comes from memorization. This shortcut is a direct result of memorization.

The above graph clearly shows that the replacement model does in fact perform “ _multi-hop reasoning_ ” — its decision to say Austin hinges on a chain of several intermediate computational steps (Dallas → Texas, and Texas + capital → Austin).

## Planning In Poem

Press enter or click to view image in full size

We all know that LLMs can write good rhyming poetry, but how does it do that, it is hard for even the best of human writers. So, let’s dive deeper into this.

When LLMs write rhyming poetry, they don’t just improvise line-by-line. Instead, it uses a **planning mechanism** :

1. **Planning ahead** : After writing the first line ending with a word like “grab it,” LLM immediately activates features representing potential rhyming words for the end of the next line (like “rabbit” or “habit”). Now this is easy for LLMs because it basically knows the entire dictionary.
2. **Working backward** : Once LLMs have these potential ending words in mind, they construct a line that naturally leads to that planned ending. Working backward is something that definitely needs some planning, but this is still likely to come out of pattern matching rather than creating concepts as we see in the above case of answering a capital of Texas.
3. **Multiple options** : LLMs consider several possible ending words simultaneously and select the most appropriate one.

So, to probe the LLMs further, we started blocking certain words:

* When we blocked the word related to “rabbit” features, llm switched to ending with “habit”.
* When all the rhyming words were blocked, llm struggled to complete the poem properly. This shows that LLMs are not thinking in terms of creating long concepts to tell a story and then writing the words, but rather finding some similar-looking sentences to rhyme.
* When they injected new word features like “green,” LLM restructured entire lines to end with that word.

People who have not written poetry were very impressed initially by seeing AI-generated poetry. LLMs are good style-matching machines, but poetry is both style and story. So, poetry written by LLMs often lacks coherency.

## Addition In LLMs

Btw, do you know that LLMs use totally different concepts to do simple mathematical operations? So, let’s see what is happening inside these beautiful machines.

Let’s understand this from a simple example, when LLM solves math problems like 36+59=95, it uses parallel pathways:

1. **Approximate pathway** : Roughly estimates that ~36 + ~60 is about 92. Why it uses this method, we don’t know precisely. But if I have to guess, while compressing the internet during its train time, it found doing this as the best option.
2. **Precise pathway** : Uses “lookup table” features that know specific digit combinations (like 6+9=15, so the final digit is 5). But note here, it is looking at some specific digits, not the whole number in one go and we can’t control this at all, what it is going to look at while doing these calculations.
3. **Combination** : Finally, it merges these pathways to get the exact answer (95)

This differs significantly from how most humans solve math problems — LLMs have memorized digit combinations but process them differently than standard human algorithms.

### Feature Types

LLM internal features show distinct patterns when visualized:

* **Diagonal patterns** : Features that detect the sum. There are certain nodes that activate to do multiplication and some others for other operations.
* **Horizontal/vertical patterns** : Features sensitive to individual input numbers. They are associated with the specific number given in the input prompt.
* **Point patterns** : “Lookup tables” that recognize specific number combinations. No one created these tables, it just created one out of all the numbers it saw. And that’s why the results are not consistent across all the numbers.
* **Repeating patterns** : Features that track modular information (like last digits).

### Generalizing to Other Contexts

These same addition features work in surprising contexts:

* Calculating publication years in academic citations. And that’s why LLM citations are often wrong in some ways.
* Predicting times in astronomical data. I won’t trust LLM-generated numbers when talking about astronomy, a point here and there will totally change the calculation.
* Computing sequential values in financial tables. Same, as trust problems like astronomy.
* Using addition as an intermediate step in complex expressions.

When the addition is part of a multi-step problem (like (4+5)×3), LLM activates features that mark “9” as an intermediate result rather than the final answer.

Interestingly, LLM can perform these calculations accurately (for a set of numbers) but can’t explain how it does so — when asked, it gives a standard human algorithm explanation rather than describing its actual internal process. Because LLM doesn’t know what it does to reach the answer. So, whenever it says let me think more, don’t get swayed away next time.

LLM-based calculations are so much based on memorization, that it can easily falter on with some simple maths, and you won’t even know. Especially when it starts seeing big numbers, these calculations go wrong very easily.

## Chain-of-Thought Unfaithfulness and Hidden Goals In Language Models

CoT is another fancy way of vibing with LLMs.

It has been well established now that (chain-of-thought or CoT) can be unfaithful to their actual internal processing. Using attribution graphs to analyze model behavior, researchers identified three distinct patterns:

### Types of Reasoning Observed

1. **Faithful Reasoning** : When solving sqrt(0.64), the model genuinely computes the square root and multiplies it by 5. There are times when a model can actually learn a true generalization. It has been shown by zeroing out all the irrelevant weights, and the model still worked.
2. **Bullshitting** : When asked to compute cos(23423), the model might claim to use a calculator (which it doesn’t have) and produces a guess without actually calculating. It might say that it is using a calculator even if doesn’t have access to the calculator.
3. **Motivated Reasoning** : When given hints about the expected answer (e.g., “I got 4”), the model works backward from that answer, computing what intermediate values would lead to that result rather than performing the calculation correctly. This is more like you trying to guide the model to the correct answer. But this only works when you know the correct answer already.

### Behind Hidden Machinery of LLMs

Let’s ask ourselves: “What’s really happening when an AI responds to us?”

These models don’t rely on a single approach to solve problems — they activate multiple pathways simultaneously. Let’s say, if asked about Michael Jordan’s sport, the model might trigger both basketball-specific neurons connected to Jordan AND general “sports category” pathways. These parallel processes sometimes work together and sometimes compete against each other. And we as the researchers have no control over what happens when.

> **This is a direct result of the model compressing the internet and generating some form of generalization. The correctness of that generalization is something we have no control of, we just hope that with more and more data it will reach the correct generalization.**

This isn’t just theoretical — it’s visible now, how models solve even basic math. When calculating something like 36+59, separate neural pathways handle different parts: some determine the ones digit while others estimate the overall magnitude of the answer.

### Abstraction Abilities

These models develop genuinely abstract concepts that work across totally different contexts. The same internal features that activate when adding numbers also fire when the model needs to:

* Calculate publication years in academic citations
* Predict time periods in astronomical measurements
* Compute sequential values in financial tables

This suggests that models develop a kind of “universal mental language” in their internal representations — something that gets stronger in more advanced systems. But here’s a big caveat, there are times when we want models to have more freedom,m and in some cases, we want to have very precise control. This is something we lack today, and maybe even in the future.

Hallucinations are not a problem for LLMs, but that’s precisely the reason why they are able to do what they do good. Hallucinations are inherent property of LLMs.

### Planning Rather Than Improvising

AI is not predicting just one word at a time. When writing poetry that needs to rhyme with “grab it,” models don’t just improvise — they activate features representing potential endings like “rabbit” and “habit” before even starting the line.

By manipulating these planning features, researchers can push the model to rewrite entire lines to naturally end with different rhyming words. This isn’t simple word prediction — it’s sophisticated planning of some form. Or better an approximate retrieval and then use that to write the next word that will be coherent.

These systems also demonstrate “backward chaining” — working backward from goals to determine intermediate steps. When showing their reasoning, they sometimes decide on their final answer first, then create calculations that would logically lead to that answer rather than performing actual step-by-step math.

Step-by-step reasoning is something we should take with a bit of salt, there are recent papers that showed that reasoning traces might be completely off, and the model will still produce the correct answer. Most research just assumed that because the final answers are correct thus the traces might be actually right.

### Are LLMs Building Self-Knowledge?

Some neural features represent concepts like “** _knowing the answer_** ” versus “** _being unable to answer_**.” These connect to specific entities the model recognizes. When researchers manipulated these features, they could make models act confident about things they don’t actually know, suggesting their “meta-cognition” remains fairly primitive.

### Why This Matters Beyond Academia

These aren’t just interesting discoveries — they have serious implications. Researchers already knew about a lot of these problems and the internal workings of LLMs. But now this coming out from a prominent AI lab is significant, especially in a shared socio-economic world where AI is playing a big role.

As these models get more integrated into society, understanding their internal workings becomes crucial for safety. Current methods might catch some problems but miss others. However, these investigations provide a foundation for better auditing tools.

The bottom-up exploration approach has revealed unexpected details that targeted hypotheses would have missed, like:

* How models juggle multiple word possibilities when generating text.
* The specific pathways that inhibit harmful responses. If we can identify these harmful pathways, it is easy to zero out the specific neurons and make these models safer to use.
* How broadly certain features generalize across contexts.

As language models grow more and more in size, understanding how they work will become increasingly difficult. Both exploratory tools and focused testing will be essential for understanding these systems.

> Understanding AI isn’t just a technical challenge — it’s an endeavor with high stakes.

These findings show that despite the complexity of these systems, we can develop tools to see inside these systems. Ultimately they are still a byproduct of human reasoning and ingenuity.
