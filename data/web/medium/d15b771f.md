## First Off, What is a U-Net? 🤔

U-Net is a type of **convolutional neural network (CNN)** designed for image segmentation tasks. Originally developed for biomedical image segmentation, U-Net’s architecture is made up of an encoder and a decoder, which give it its fun-looking U-shape.

* **Encoder (Contracting Path):** The encoder is a series of convolutional layers (these find features like edges and patterns) followed by max-pooling layers (these help reduce image size to help the model really tune in on the most important features)🔎.
* **Decoder (Expanding Path):** The decoder is made up of upsampling layers (these restore the original image size) and more convolutional layers. The decoder basically refines and rebuilds the output to create a nice segmentation map🛠.
* **Skip Connections:** U-Net uses skip connections that link corresponding layers in the encoder and decoder, helping to keep fine details and improving segmentation accuracy. **Think of skip connections as bullet trains that zooms straight from one side of the U-net to the other, skipping all of the traffic and making sure the important passengers (details) arrive safely at the other end** 🚄.

### Handling the Class Imbalance

There are tons of methods to address class imbalance, such as oversampling, undersampling, and data augmentation, I played around with some of these techniques but the one thing that helped my model the most was creating a special loss function which combined **Binary Cross-Entropy (BCE)** and **Dice Loss.**

**How Does this Address the Class Imbalance?**

So basically the loss function works by measuring how far off your model predictions are from the ground truth — and the goal of any model is to minimize this loss.

Given that we are only looking at a binary segmentation (differentiating between building and background), a strong choice of a loss function would be the BCE because it measures the pixel-wise loss, essentially it looks at every single little predicted pixel and how far it is from the true pixel. The problem with only using this type of loss is that the loss will be dominated by the majority class (the background pixels).

That’s where the Dice Loss comes in — the Dice Loss measures the loss by looking at the overlap between the predicted and ground truth masks

To understand the Dice Loss, first, let’s understand how the predictions are judged:

1. True Positives (TP):🏢✅ Buildings correctly identify as buildings.
2. False Positives (FP):🌄❌ Background pixels mistakenly marked as buildings.
3. False Negatives (FN): 🏢❌Buildings misidentified as background.
4. True Negatives (TN): 🌄✅Background correctly marked as background.

The Dice Coefficient (essentially the F1 Score for image segmentation) balances **precision** (how accurate the model was in marking building pixels) and **recall** (how many actual building pixels the model identified).

Basically it’s like saying — “Let’s focus on the buildings, how many did we correctly identify without making too many mistakes?”

While the Dice Coefficient (F1 Score) is a measure of model performance (higher is better), Dice Loss is used to **minimize the error** during training (lower is better).

**Combining BCE and Dice Loss**

By combining the two loss functions we benefit from both the pixel-wise supervision and the Dice’s focus on the overlap, making sure to balance sensitivity to both classes.

## Assembling the Model 🧱👷‍♀️

Before I jump into the model architecture, I want to quickly go over two key methods significantly improved my model’s performance — methods that are often overlooked during training.

### Spatial Dropout

As a way to help prevent the model from overfitting (learning the train data too well to the point where is can’t predict well on new data), I included a spatial dropout layer to the model. During training, it randomly hides a percentage of the pixels in each image. This basically forces the model to stop relying on individual pixels and instead pay attention to the **bigger picture** , learning the context and patterns around buildings.

This is a pretty cool method, dropout isn’t just limited to spatial layers in image models — you can use it for other types of neural networks too!

### Kernel Initializer

I think when building neural networks, one of the most overlooked components is the kernel initializer. This was probably one of the hardest concepts to wrap my head around during my master’s program, but once I finally did grasp the concept, I understood how critical it is in neural networks.

So, what is it exactly? In simple terms, it decides how the weights of the network’s layers are set **before training begins.** You can think of it like laying the foundation for a house. If your foundation is weak or uneven, it doesn’t matter how amazing the house design is — the structure won’t be stable.

For my U-Net model, the best initializer turned out to be **LeCun Normal**. It scales weights proportionally to the size of the input layer which in turn helps minimize the risk of gradients becoming too small (vanishing gradients) or too large (exploding gradients) as they flow through the network.

### Keras Functional API

Okay, now we get to the nitty-gritty of building our U-Net model. Using the **Keras API** , I defined a simplified U-Net model.

* **Keras Functional API:** A super flexible way to build deep learning models in Python, it allows you to define custom architectures by connecting different layers like building blocks🏗️.

### Encoder Block

Remember from earlier, this is the contracting path of the U-Net — it takes the input images, captures the features and shrinks the spatial information (reduces image size).

Each block is made up of the following:

* **Two Convolutional Layers:** Each with a `relu` activation and `lecun_normal` kernel initialization.
* **Spatial Dropout** : Regularization added after each convolutional layer with a dropout rate of 10%.
* **Max Pooling** : Downsamples the spatial dimensions by a factor of 2, reducing the image size, but making sure to keep the key features.

```python def encoder_block(filters, inputs, dropout_rate=0.1, kernel_initializer='lecun_normal'): x = Conv2D(filters, kernel_size=(3, 3), padding='same', strides=1, activation='relu', kernel_initializer=kernel_initializer)(inputs) x = SpatialDropout2D(dropout_rate)(x) s = Conv2D(filters, kernel_size=(3, 3), padding='same', strides=1, activation='relu', kernel_initializer=kernel_initializer)(x) s = SpatialDropout2D(dropout_rate)(s) p = MaxPooling2D(pool_size=(2, 2), padding='same')(s) return s, p ```

I used four blocks in my model (when I tried using more than this, or more filters, the model did worse):

* Block 1: 32 filters
* Block 2: 64 filters
* Block 3: 128 filters
* Block 4: 256 filters

### Bottleneck Layer

This part of the model acts as the bottleneck of the U-Net, laying between the encoder and decoder. It’s able to capture the deepest features while operating on the smallest spatial dimensions (super cool). It is built with:

* **Two convolutional layers**
* **Spatial Dropout**

The base helps to set the stage for the decoder to reconstruct high-resolution images from these abstract features.

```python def baseline_layer(filters, inputs, dropout_rate=0.1, kernel_initializer='lecun_normal'): x = Conv2D(filters, kernel_size=(3, 3), padding='same', strides=1, activation='relu', kernel_initializer=kernel_initializer)(inputs) x = SpatialDropout2D(dropout_rate)(x) x = Conv2D(filters, kernel_size=(3, 3), padding='same', strides=1, activation='relu', kernel_initializer=kernel_initializer)(x) x = SpatialDropout2D(dropout_rate)(x) return x ```

### Decoder Block

If you recall from earlier, the decoder is the expansive path of the U-Net, which rebuilds the image by upsampling and combining features. Each decoder block consists of:

* **Upsampling** : Using a transposed convolution layer with `relu` activation to double the spatial dimensions.
* **Skip Connections** : These combines features from the corresponding encoder block, making sure that the network keeps all of the fine-grained details lost during downsampling.
_Remember this these are like the bullet trains going from one end of the model to the other._
* **Two convolutional layers** : To refine the upsampled features.
* **Spatial Dropout** : Helps the model learn to generalize (even at this phase of the model).

```python def decoder_block(filters, connections, inputs, dropout_rate=0.1, kernel_initializer='lecun_normal'): x = Conv2DTranspose(filters, kernel_size=(2, 2), padding='same', activation='relu', strides=2, kernel_initializer=kernel_initializer)(inputs) skip_connections = concatenate([x, connections], axis=-1) x = Conv2D(filters, kernel_size=(3, 3), padding='same', activation='relu', kernel_initializer=kernel_initializer)(skip_connections) x = SpatialDropout2D(dropout_rate)(x) x = Conv2D(filters, kernel_size=(3, 3), padding='same', activation='relu', kernel_initializer=kernel_initializer)(x) x = SpatialDropout2D(dropout_rate)(x) return x ```

### Final Output Layer

And last but not least, the final layer of the model is a **1x1 convolutional layer** with a single output channel and a `sigmoid` activation function. This layer predicts the probability of each pixel belonging to the target class (buildings) or the background.

``` outputs = Conv2D(1, 1, activation = 'sigmoid')(d4) ```

### Putting all of the Pieces Together 🧩

Here we have our final masterpiece:

```python def unet(): inputs = Input(shape = (256, 256, 3)) #defines the input layer and shape of images #encoder s1, p1 = encoder_block(32, inputs = inputs) s2, p2 = encoder_block(64, inputs = p1) s3, p3 = encoder_block(128, inputs = p2) s4, p4 = encoder_block(256, inputs = p3) #bottleneck baseline = baseline_layer(512, p4) #decoder d1 = decoder_block(256, s4, baseline) d2 = decoder_block(128, s3, d1) d3 = decoder_block(64, s2, d2) d4 = decoder_block(32, s1, d3) #output function for binary classification of pixels outputs = Conv2D(1, 1, activation = 'sigmoid')(d4) #finalizing the model model = Model(inputs = inputs, outputs = outputs, name = 'Unet') return model ```

## Evaluating the Model 🧪

While accuracy shows the percentage of overall correct predictions, it does not account for the class imbalance in our dataset. For example, if the background pixels greatly outnumber the building pixels, the model could achieve high accuracy simply by predicting “background” most of the time. So this means a high accuracy doesn’t always necessarily indicate that the model performed well at identifying buildings.

**So, how can we really assess the model’s ability to segment buildings?**

That’s where the Dice Metric comes in again! Unlike accuracy, the Dice Metric measures how well the predicted mask overlaps with the ground truth mask. A higher Dice score means better performance, meaning the model accurately captured more of the intersection between the predicted and actual building areas.

Here’s the code I used to calculate the Dice Metric:

```python def dice_metric(y_true, y_pred): """Calculate Dice Coefficient for ground truth and predicted masks.""" y_pred = tf.cast(y_pred > 0.5, tf.float32) #threshold set to 0.5 intersection = tf.reduce_sum(y_true * y_pred) total_sum = tf.reduce_sum(y_true) + tf.reduce_sum(y_pred) dice = tf.math.divide_no_nan(2 * intersection, total_sum) return dice ```

### Test Set Results:

Evaluating the model on the test set, I achieved the following metrics:

* **Accuracy:** 94.7% (Overall correctness of predictions)
* **Precision:** 75.2% (Percentage of predicted buildings that were actual buildings)
* **Recall:** 78.9% (Percentage of actual buildings correctly identified by the model)
* **Dice Metric:** 76.7% (Measures the overlap between predicted and ground truth masks)

### What Does This Mean?

In a research paper, the authors highlighted that a Dice score above 0.7 indicates good performance in image segmentation tasks ([source](<https://pmc.ncbi.nlm.nih.gov/articles/PMC10449747/#:~:text=The%20threshold%20of%200.7%20was,a%20good%20overlap%20%5B31%5D>)). With a Dice score of 76.7%, the model performs well at segmenting buildings from the background.

So, while accuracy gives a general sense of performance, metrics like Dice, Precision, and Recall provide a way better understanding of how well the model handles the specific task of segmenting buildings. Based on these results, it looks like we have a winner! 🎉

## So What Did We Learn from All of This? 🧠

You made it to the end! So, here’s what we can take away from this experience:

1. **Model Architecture Matters** : The U-Net architecture proved to be a pretty strong choice for image segmentation, especially for tasks like identifying building footprints.
2. **Loss Functions Make the Difference** : Combining Binary Cross-Entropy and Dice loss ensured that the model balanced overall accuracy with a focus on correctly segmenting minority classes (the buildings in our case). This is really important when we’re dealing with class imbalance.
3. **Regularization** : Spatial dropout not only helped prevent overfitting but also improved the model’s ability to generalize to unseen data. This step made the training process more robust.
4. **Evaluation Beyond Accuracy** : Metrics like Dice provide better insights into the model’s performance, especially for tasks where class imbalance skews simple accuracy measures.

**Next Steps** ✨📈: There’s always room for improvement, and I believe the next logical step would be to implement data augmentation. This involves generating slightly altered copies of existing images, such as flipping, rotating, or adjusting brightness. By diversifying the training data, the model could learn even finer details and better differentiate between buildings and the background.
