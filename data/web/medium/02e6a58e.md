Classification models are widely used, particularly in business applications. These models answer the question: “What is the probability that this will happen?”

Predicting probabilities is incredibly valuable because they can be multiplied by monetary amounts, making them useful in decision-making processes.

However, **just because a model outputs scores between 0 and 1 doesn’t mean those scores represent true probabilities**. This distinction is critical in many real-world applications.

Consider this example. Your company sells two mugs — one plain white and one featuring a kitten. You need to decide which mug to show to a customer by predicting the probability that they will buy each. You train two models and get these results:

![Models with the same ROC score but different calibration. [Image by Author]](https://miro.medium.com/v2/resize:fit:700/1*9QRpqyNnga5EDyWKr1On7Q.png)

Now, which mug would you recommend?

Both models agree that the user is more likely to buy the plain mug (so, model A and model B have the same ROC score since this metric only evaluates the sorting).

However, according to model A, recommending the plain mug maximizes the expected profit, whereas model B suggests the kitten mug would yield the highest profit.

In applications like this one, it’s crucial to ensure that our model predicts actual probabilities, not just ranking scores. In jargon, a model that satisfies this property is said to be “calibrated”.

In this article, we will see how to find a reasonable baseline for your model’s calibration error. Using a clever trick, we’ll calculate the p-value so that you can be confident you’re working with true probabilities.

## Getting the model’s probabilities (or scores)

Throughout the article, I will analyze the results using a synthetic dataset. Let’s start by generating a training, validation, and test set.

```python from sklearn.datasets import make_classificationn = 15_000X, y = make_classification( n_samples=n, n_features=20, n_informative=10, n_redundant=10, weights=[.9,.1], random_state=0)X_train, X_valid, X_test = X[:int(n/3)], X[int(n/3):int(n*2/3)], X[int(n*2/3):]y_train, y_valid, y_test = y[:int(n/3)], y[int(n/3):int(n*2/3)], y[int(n*2/3):] ```

As usual, we want to train a model on this training set and have the same model predict probabilities on the test set.

```python from sklearn.tree import DecisionTreeClassifiermodel = DecisionTreeClassifier(max_depth=5).fit(X=X_train, y=y_train)proba_test = model.predict_proba(X_test)[:, 1] ```

Let’s see the distribution of the predicted probabilities (actually, I should call them, more generally, the “scores”) from the model.

![Histogram of the scores predicted by the model on the test set. [Image by Author]](https://miro.medium.com/v2/resize:fit:700/1*OxEAU00voTU0Gs993GdS_g.png)

A challenge in classification problems is that we aim to predict probabilities but we never get to observe them, because what we observe is just a binary outcome: 1 or 0. This means that, **contrary to regression problems, we don’t have the actual distribution of the thing we want to predict**.

In classification, all we can rely on is the expected value (average) of the predicted probabilities. For example, in our case, the fraction of positive samples is 10%, so the predicted probabilities should, on average, be around 10%.

However, this is only a necessary, not sufficient, condition for calibrated scores. Indeed, there are an infinite number of distributions that can satisfy this condition. For example, here are some distributions, all with an expected value of 10%

![Different distributions, all with an expected value of 10%. [Image by Author]](https://miro.medium.com/v2/resize:fit:700/1*5W77gUFMl7tyRh5iGap3VQ.png)

Unfortunately, there’s no way around this: we’ll never know the exact distribution of the probabilities we want to predict.

However, this isn’t a problem, because what truly matters to us is proving (or disproving) that the scores predicted by our model can be treated as true probabilities, not just ranking scores.

## From the probabilities to the calibration curve

Let’s take a look at some rows from our test dataset. The first column shows the scores predicted by the model, and the second column shows the observed target variable.

![First column: scores predicted by the model. Second column: observed target variable. [Image by Author]](https://miro.medium.com/v2/resize:fit:700/1*noezBfwys64ebIiLoL2aHA.png)

Theoretically, **a score coincides with the true probability if, repeating the observation in multiple parallel universes, the rate of positives matches the score**. For example, if the score is 25%, it would reflect the true probability if the observation were positive in one out of four “universes.”

Unfortunately, we can’t observe multiple universes, so we must make the most of the single one we can see.

However, we can still leverage the fact that we have many observations in our test set. To do this, we can **group observations with similar predicted probabilities and check if the observed fraction of positives in the target variable matches these predicted values**.

We can facilitate this process by grouping the observations into “bins” based on the distribution quantiles. For each bin, we will calculate:

* Mean of the predicted probabilities from the model.
* Mean of the target variable.
* Number of observations in each bin.

In this case, this is the result:

![Bin edges, average predicted probability, fraction of positives, and number of observations for each bin. [Image by Author]](https://miro.medium.com/v2/resize:fit:700/1*eHtUGdThgWwvSYNKeTLTeA.png)

Let’s now plot the average predicted probability and the observed fraction of positives for each bin, which gives us the so-called “calibration curve.”

![Calibration curve. [Image by Author]](https://miro.medium.com/v2/resize:fit:700/1*XFHRjINn4dXV1rf4nVQWnw.png)

I’ve added a dashed 45-degree line to the plot to help with interpretation. Ideally, if the predicted scores are accurate probabilities, they should be very close to this line.

This plot is qualitatively useful, but of course, we cannot base our decisions — such as selecting the best model— solely on the observation of a plot. We need a quantitative measure: a proper metric.

## Plots are cool, but metrics are useful

If our model is capable of predicting accurate probabilities, we would expect that:

1. The average probability of each bin is very close to the observed fraction of positives within the same bin.
2. If the two values differ significantly, it likely indicates that the number of observations in the bin is small, making the results more affected by random fluctuations.

These observations lead us to define a metric that penalizes the discrepancy between the average probability and the observed fraction of positives, with the penalty weighted by the number of observations in the bin. This metric is called Expected Calibration Error (ECE) in the literature.

Translating what we just said into a math formula:

![Expected Calibration Error (ECE) formula. [Image by Author]](https://miro.medium.com/v2/resize:fit:409/1*x7aIb14QYgY9ORScF-3pKQ.png)

We can compute the ECE using the statistics from the summary table above, where each row corresponds to a bin:

``` ece = ( ((summary["proba mean"] - summary["y mean"]).abs() * summary["count"]).sum() / summary["count"].sum()) ```

In this case, the resulting ECE is 2.1%.

The advantage of ECE is its simplicity — it directly tells us how far our model’s predicted probabilities are, on average, from being actual probabilities.

However, there are a couple of issues with this metric:

1. **The choice of the number of bins is arbitrary: varying the number of bins will yield different ECE values**.
2. **It’s difficult to determine when an ECE is considered “good enough.”** While a lower ECE is better, there’s no clear threshold for what an acceptable value is. In our case, is 2.1% good or bad?

To answer this question, we need a sensible baseline against which to compare our ECE. In the next paragraph, we will see how to get such a baseline.

## A more reasonable baseline for ECE

We already know that the ideal ECE would be 0. However, we also know that this scenario is practically impossible because some amount of randomness will always be involved, even if the model is perfectly calibrated.

Here is a smart trick that we will use to reach a good baseline.

**Instead of starting from the target variable and looking for perfectly calibrated probabilities that are compatible with it, we will reverse the logic**.

Indeed, we will **pretend that the probabilities predicted by our model are perfectly calibrated, and we will simulate many possible target variables that may have been generated by those probabilities**.

This process of simulating a target variable based on the assumption that the predicted probabilities are true is straightforward in Python

``` y_test_simul = np.random.uniform(0, 1, size=n) < proba_test ```

We will repeat this procedure multiple times (for example, 1,000 times). Let’s take a look at the first three simulated outcomes:

![Generating many simulated target variables that are compatible with the probabilities predicted by the model. [Image by Author]](https://miro.medium.com/v2/resize:fit:700/1*26_GymgCupHXB1NjDAiyBg.png)

Since we have many new target variables, and we know they are all perfectly calibrated (apart from random fluctuations), we can repeat what we did before (i.e., plotting the calibration curve, computing the ECE) for each of them.

For instance, let’s plot the calibration curves of the first 5 simulated target variables.

![Calibration curves of perfectly calibrated target variables. [Image by Author]](https://miro.medium.com/v2/resize:fit:700/1*NNDtYYnpTJmJ_J2cu0DiTw.png)

From the plot, we can see that even the perfectly calibrated target variables produce a calibration curve that does not perfectly align with the 45-degree line.

This is especially evident in the points where there are few observations (in our case when the probabilities are higher than 30%). This makes a lot of sense because in those points the impact of random fluctuations is higher.

This is also reflected in the ECE. In fact, even for the perfectly calibrated target variables, the ECE isn’t zero — it’s around 0.8% on average. This provides a useful baseline for comparison.

In fact, we already know that our model’s ECE is 2.1%. The next question is: how many of the perfectly calibrated simulations have an ECE equal to or greater than 2.1%?

This is similar to the reasoning behind computing a p-value. First, we have calculated the ECE on a large number of random simulations, and then we have to check how many times the ECE is greater than or equal to the observed ECE.

Note that, in our case, the null hypothesis is that the model is perfectly calibrated (and so any deviance from the 45-degree line is just due to randomness). So the higher the p-value, the more indistinguishable our probabilities are from perfectly calibrated probabilities. Thus, a **high p-value would mean that the probabilities predicted by our model are good**.

Let’s calculate the p-value:

``` p_value = np.mean(simulated_eces >= actual_ece) ```

In this case, the result I get is 0.0%, meaning that none of the simulated ECEs is higher than the observed ECE. This means that it’s hard to assume that our model’s probabilities reflect the true underlying probabilities.

Let’s summarize all the information we’ve seen so far in a single plot.

![Grey lines: calibration curves of the perfectly calibrated target variables. Red line: calibration curve of the actual target variable. [Image by Author]](https://miro.medium.com/v2/resize:fit:700/1*LqgmLPyHgBN0ICN3oMkgTQ.png)

So these probabilities are not good. Can we improve them?

## Checking if a calibrator can help us

In a [previous article on calibration](</towards-data-science/pythons-predict-proba-doesn-t-actually-predict-probabilities-and-how-to-fix-it-f582c21d63fc>), I have explained how we can use a second model (named a “calibrator”) to try and improve the scores predicted by our original model.

There are many choices, but maybe the most common calibrator is a model called isotonic regression. Luckily, this model is available in Scikit-learn. All we have to do is to train our calibrator on a validation set:

```python from sklearn.isotonic import IsotonicRegressioncalibrator = IsotonicRegression(y_min = 0, y_max = 1, out_of_bounds = "clip")proba_valid = model.predict_proba(X_valid)[:, 1]calibrator = calibrator.fit(X=proba_valid, y=y_valid) ```

Now, we can ask the original model to predict the scores on the test set and use the calibrator to try and correct them.

``` proba_test = model.predict_proba(X_test)[:, 1]cal_proba_test = calibrator.predict(proba_test) ```

Let’s see what are the resulting ECE and p-value now.

![Calibration plot and histogram of the probabilities after correcting them through the calibrator. [Image by Author]](https://miro.medium.com/v2/resize:fit:700/1*vR3SreWGupSOwzRIfz8tSg.png)

The results look much better now!

This time, the p-value is 6.1%, meaning that 61 out of 1,000 perfectly calibrated target variables have an ECE that is greater than or equal to 1.1%. This is an indication that we can be quite confident that using this new model we get the true underlying probabilities.
