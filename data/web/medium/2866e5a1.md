### Project Overview

Our project teaches an AI agent to control traffic lights, making decisions about when to change signals based on actual traffic conditions. It will use a **_Deep Q-Learning (DQN)_** to learn optimal patterns through trial and error.

![Image By Shutterstock](https://miro.medium.com/v2/resize:fit:325/1*LYkSb0XlNsqgrqwbnvw6dw.jpeg)

The system simulates traffic at a single intersection with flows in two directions **(east-west and north-south)** , but the approach can scale to entire networks of intersections (which we will cover in subsequent parts).

We compare three different approaches to compare the advantage of our model:

* Fixed-cycle timing (traditional method)
* Optimal threshold policy (based on queue differences)
* DQN-learned policy (our AI approach)

But before moving forward, let’s list all the tools we will use!

### The Environment: SUMO Traffic Simulator

We will use **_SUMO (Simulation of Urban MObility)_** to create a realistic traffic simulation environment. Our Python wrapper interfaces with SUMO to control the simulation and extract traffic data.

```python def _get_state(self): """Get the current state of the environment.""" # Get number of vehicles in each direction x1 = sum(traci.lane.getLastStepVehicleNumber(lane) for lane in self.we_lanes) x2 = sum(traci.lane.getLastStepVehicleNumber(lane) for lane in self.ns_lanes) # Get current traffic light phase tls_phase = traci.trafficlight.getPhase(self.tls_id) return (x1, x2, tls_phase) ```

This code shows how our system “sees” the current state of traffic — **_counting vehicles in each direction and checking the traffic light phase_**.

![Image By ResearchGate](https://miro.medium.com/v2/resize:fit:700/1*pyjIi2iToR5_TxG8nOmhew.png)

### The Reward Function

The reward function is like a report card for our AI. We designed it to prioritize minimizing queue lengths:

```python def _compute_reward(self, state): """Compute reward based on the current state.""" x1, x2, _ = state # Negative of sum of squared queue lengths reward = -(x1**2 + x2**2) return reward ```

> Why use squared queue lengths? This clever mathematical trick encourages the AI to balance traffic in both directions. The negative sign means larger queues create a more negative reward — the AI learns to avoid letting long lines form in any direction.

### Our DQN Model

The heart of our system is the Deep Q-Network implemented in PyTorch:

```python class QNetwork(nn.Module): def __init__(self, state_size, action_size, hidden_size=400): super(QNetwork, self).__init__() self.fc1 = nn.Linear(state_size, hidden_size) self.fc2 = nn.Linear(hidden_size, hidden_size) self.fc3 = nn.Linear(hidden_size, action_size) def forward(self, state): x = torch.tanh(self.fc1(state)) x = torch.tanh(self.fc2(x)) return self.fc3(x) ```

This neural network processes the current traffic state and decides whether to keep the current light phase or switch to the next one. Through training, it develops intuition about traffic patterns and optimal timing.

### The Complete Learning Process

The magic happens during training. Initially, the AI knows nothing about traffic management.

_It’s like a new driver education student_. Through thousands of simulated traffic scenarios, it develops an understanding of effective traffic control.

During training, the AI starts by exploring random actions (exploration phase) and gradually shifts to using what it’s learned (exploitation phase). This exploration-exploitation balance is controlled by a parameter called **_epsilon_** :

```python def get_action(self, state, training=True): """Select an action using epsilon-greedy policy.""" # Exploration: select random action if training and np.random.rand() < self.epsilon: return np.random.choice(self.action_size) # Exploitation: select best action based on learned Q-values # Convert state to tensor state_tensor = torch.FloatTensor(state).unsqueeze(0).to(self.device) with torch.no_grad(): q_values = self.q_network(state_tensor) return q_values.argmax().item() ```

I’ll never forget watching the training progress — seeing the AI evolve from making seemingly random decisions to developing sophisticated patterns that resembled what human traffic engineers might do.

### Practical Implementation

Ready to try implementing this yourself? Here’s what you’ll need (Refer to my repo for any additional guidance):

1. **Install SUMO** : Get the traffic simulator up and running
2. **Set up Python environment** : Install PyTorch and other dependencies
3. **Clone the repository** : All code is available at [GitHub Repository](<https://github.com/RSD-Studio/Intelligent-Traffic-Light-Control-System>)
4. **Train the model** : Start with a small number of episodes to see progress

The project structure is like this:

``` traffic_light_dqn/├── env/│ ├── __init__.py│ ├── sumo_env.py # SUMO environment wrapper│ └── sumo_files/ # SUMO configuration files├── models/│ ├── __init__.py│ └── dqn.py # DQN implementation with PyTorch├── utils/│ ├── __init__.py│ └── visualization.py # Visualization utilities├── scripts/│ ├── train.py # Training script│ └── test.py # Testing script├── saved_models/ # Directory for trained models├── results/ # Results and visualizations├── main.py # Main entry point└── README.md # This file ```

The trickiest part of my implementation journey was setting up the SUMO environment correctly. Make sure your PATH variable includes the SUMO_HOME directory:

``` # For Windows PowerShell$env:SUMO_HOME = "C:\Program Files (x86)\Eclipse\Sumo" ```

Once everything’s set up, you can train the model with:

``` python main.py --mode=train --episodes=200 --arrival_rate=0.25 ```

You can use following variables to alter the training as per desire:

* `--episodes`: Number of training episodes (default: 200)
* `--arrival_rate`: Probability of vehicle arrival per time step (default: 0.25)
* `--hidden_size`: Neural network hidden layer size (default: 400)
* `--learning_rate`: Learning rate for optimization (default: 0.001)
* `--render`: Add this flag to visualize the training in SUMO GUI
* `--device`: Specify "cuda" or "cpu" for computation

The training process will save models periodically in the `saved_models` directory and generate learning curves in `saved_models/plots/`.

Now you can can test different policies with:

``` python main.py --mode=test --test_episodes=10 --arrival_rate=0.25 ```

Parameters:

* `--test_episodes`: Number of evaluation episodes (default: 10)
* `--dqn_model`: Path to the saved DQN model
* `--render`: Add this flag to visualize the testing in SUMO GUI

This command evaluates the DQN policy against fixed-cycle and optimal threshold policies, generating performance metrics and visualizations in the `results` directory.

### Results and Insights

Our results revealed something fascinating: both the optimal threshold approach and our DQN solution significantly outperformed traditional fixed-timing traffic lights.

Here’s what we found:

* Fixed-cycle policy: Average queue length of ~**_20.7 vehicles_**
* Optimal threshold policy: Average queue length of ~**_14.6 vehicles (30% improvement)_**
* DQN policy: Comparable to optimal threshold, but more adaptable to varying traffic patterns

![image](https://miro.medium.com/v2/resize:fit:1000/1*wKZlZY6AZfZSitQRDGQbOw.png)

![Comparison of Both systems](https://miro.medium.com/v2/resize:fit:700/1*mQH2PZ9KRJ9K6vP_T3dYYQ.png)

But here’s where it gets really interesting: **_the DQN policy created an unexpected imbalance_**. It actually favored one direction over the other to minimize overall waiting time. This mimics what human traffic controllers sometimes do — prioritizing main arteries over side streets.

Looking at the queue evolution graphs, we saw the West-East direction consistently maintained shorter queues (2–4 vehicles) while the North-South direction stabilized around 12 vehicles.

This kind of emergent behavior wasn’t explicitly programmed — the AI discovered this strategy on its own!
