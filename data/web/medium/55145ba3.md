### Where is the catch?

There are none, except you don’t have 10 Billion free requests per seconds. I was not expecting that, by the way.

So there are a few rate limits that apply to certain types of requests, regardless of account status:

1. Free limit: If you are using a free model variant (with an ID ending in `:free`), then you will be limited to 20 requests per minute and 200 requests per day.
2. DDoS protection: Cloudflare’s DDoS protection will block requests that dramatically exceed reasonable usage.

Now, if we do the math, 200 requests per day, on 30 free available models is equal to 6000 requests per day.

I would say, not bad for a free ride, right?

## How to call the Models API endpoint

The [OpenRouter](<https://openrouter.ai/docs/quickstart>) endpoints are ALL fully compliant with the OpenAI API standards.

And this will simplify things for us a lot!

In few line of python we can call the model completion, and get a response. And we need only one python package to install: so useful that you can do it globally, like this.

Open a terminal window, anywhere is ok, and just type:

```python pip install openai ```

And we are done. For the python code 12 lines are more than enough!

```python from openai import OpenAIYOURAPIKEY = "" #paste your API key between the quotesclient = OpenAI(base_url="https://openrouter.ai/api/v1", api_key=YOURAPIKEY)messages = messages = [{"role": "user", "content": "What is AI?"}]completion = client.chat.completions.create( extra_headers={}, extra_body={}, model="google/gemini-2.0-flash-exp:free", #older are not working anymore messages=messages, temperature=0.2)print(completion.choices[0].message.content) ```

The code above will establish a connection to OpenRouter.ai, and after that it will call the free model “google/gemini-2.0-flash-exp:free” and get a response.

We can print the response

``` print(completion.choices[0].message.content) ```

Lately, the gemini-2.0-flash-experimental has been lagging a lot: sometimes is not even responding becuase of the high number of requests.

So… how do we make sure there is a failover mechanism? If gemini is not replying, can I automatically get a reply from Mistral (for example)?

Meet Model routing!

## How to do the routing

To do model routing with OpenRouter.ai is super easy. I learned about it reading through the [documentation](<https://openrouter.ai/docs/features/model-routing>):

> The `models` parameter lets you automatically try other models if the primary model’s providers are down, rate-limited, or refuse to reply due to content moderation.

```json 1{2 "models": ["anthropic/claude-3.5-sonnet", "gryphe/mythomax-l2-13b"],3 ... // Other params4} ```

> If the model you selected returns an error, OpenRouter will try to use the fallback model instead. If the fallback model is down or returns an error, OpenRouter will return that error.

Remember that, by default, any error can trigger the use of a fallback model, including context length validation errors, moderation flags for filtered models, rate-limiting, and downtime.

In our previous python code, we need to add only 3 lines of code: I decided to put the following models as backup (**but you can set only a mximum of 3**):

* meta-llama/llama-3.3–70b-instruct:free
* qwen/qwen-2.5–72b-instruct:free
* mistralai/mistral-small-3.1–24b-instruct:free

You can read more from my GitHub repository:
