Query Optimization (QO) is a key technique aimed at enhancing the way LLMs understand and respond to questions, especially when tackling complex queries in Retrieval-Augmented Generation (**RAG**) scenarios. I believe anyone who has studied or worked with RAG knows this.

In an earlier article ([Advanced RAG 06: Exploring Query Rewriting](<https://aiexpjourney.substack.com/p/advanced-rag-06-exploring-query-rewriting-23997297f2d1>)), we discussed some related techniques.

I recently read [a survey](<https://arxiv.org/pdf/2412.17558v1>) that I’d like to share with you.

## Four Main Approaches for Query Optimization

As shown in Figure 1, there are four main approaches for query optimization: Expansion, Disambiguation, Decomposition, and Abstraction.

Figure 1: Four atomic operations in QO. [[Source](<https://arxiv.org/pdf/2412.17558v1>)].

### Query Expansion

As shown in Figure 2, **Query Expansion** enriches a query by adding more relevant information, either generated internally by the model or sourced externally from a knowledge base or web data.

Press enter or click to view image in full size

Figure 2: Query expansion techniques in detail. [[Source](<https://arxiv.org/pdf/2412.17558v1>)].

**Internal expansion** leverages the LLM’s own capabilities to enrich a query — for example, by generating context or pseudo-documents.

In contrast, **external expansion** retrieves relevant information from knowledge bases or the web to enhance the query.

### Query Decomposition

As shown in Figure 3, Query Decomposition breaks down a complex query into smaller, manageable parts that can be answered individually, and then combines those answers to form a complete response.

Press enter or click to view image in full size

Figure 3: Query expansion techniques in detail. [[Source](<https://arxiv.org/pdf/2412.17558v1>)].

### Query Disambiguation

As shown in Figure 4, Query Disambiguation rewrites ambiguous queries to make them more precise and clear.

Press enter or click to view image in full size

Figure 4: Query expansion techniques in detail. [[Source](<https://arxiv.org/pdf/2412.17558v1>)].

### Query Abstraction

Query Abstraction extracts the core ideas from a query, making it more general and adaptable.

Press enter or click to view image in full size

Figure 5: Query expansion techniques in detail. [[Source](<https://arxiv.org/pdf/2412.17558v1>)].

This method shines with complex, multi-hop queries, using high-level reasoning to boost answer quality. Unlike a step-by-step breakdown that might increase complexity and reduce accuracy, abstraction helps minimize errors during the intermediate process.

## Thoughts and Insights

It’s worth mentioning that an algorithm I previously introduced ([A New Approach to Optimizing Query Generation in RAG](<https://aiexpjourney.substack.com/p/a-new-approach-to-optimizing-query>)) wasn’t included in this survey. **In my view** , the QOQA method described in that article likely falls under the category of **Query Expansion**. In addition, based on how QOQA uses an LLM to generate new queries, it is closer to an **internal expansion** , relying primarily on the LLM’s own capabilities to enhance the query.

One more thing I’d like to mention is when I was researching query optimization, I couldn’t find a systematic survey like this. This survey fills a gap in the RAG field, where research on query optimization has been fragmented. It establishes a clear technical classification framework, covering expansion, decomposition, disambiguation, and abstraction.

**What disappoints me** about this survey is the lack of experimental validation on which query optimization techniques perform best in real applications. For example, in RAG tasks, how do different optimization methods (e.g., expansion vs. decomposition) compare in terms of accuracy, computational cost, and recall?

Moreover, **in my opinion** , query optimization needs to account for more **domain-specific** rules. For example, in the **medical field** , **time sensitivity** is crucial — consider the difference between “latest drugs in 2024 for arthritis” and “all drugs for arthritis.” In **computer science** , query optimization must be **highly precise to preserve the technical semantics of terms**. Otherwise, it could lead to misleading code, debugging errors, or security risks. For instance, a query for “DDoS mitigation strategies” should not be optimized into “traffic management strategies.”
