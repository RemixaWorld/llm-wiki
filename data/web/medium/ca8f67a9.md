Transforming unstructured documents such as PDF files and scanned images into structured or semi-structured formats is a key part of artificial intelligence. However, due to the intricate nature of PDFs and the complexity of PDF Parsing tasks, this process takes on an air of mystery.

This series of articles is dedicated to demystifying PDF Parsing. In the [previous article](<https://medium.com/generative-ai/demystifying-pdf-parsing-01-overview-130f9e4064c2>), we introduced the main task of PDF parsing, categorized the existing methods and provided a brief introduction to each.

In this article, we focus on the pipeline-based method. We start with an overview, then introduce the implementation strategies of several representative pipeline-based PDF parsing frameworks, sharing the insights we’ve gained.

## Overview

Pipeline-based method views the task of parsing PDFs as a pipeline of models or algorithms, as depicted in Figure 1.

Press enter or click to view image in full size

Figure 1: Overview of pipeline-based method. Image by author.

Pipeline-based method can be divided into the following five steps:

1. Preprocess the original PDF file to fix problems like blurriness or skewed orientation. This step includes image enhancement, image direction correction, etc.
2. Conduct layout analysis, which has two main components: visual structure analysis and semantic structure analysis. The former identifies the document’s structure and outlines its similar regions, while the latter labels these areas with specific document types such as text, title, list, table, figure, etc. This step also involves analyzing the reading order of the page.
3. Treat the different areas identified during the layout analysis separately. This process includes understanding tables, recognizing text, and identifying other components like formulas, flowcharts, and special symbols.
4. Integrate the previous results to restore the page structure.
5. Output structured or semi-structured information, such as Markdown, JSON, or HTML.

Next, this article will discuss a few representative pipeline-based PDF parsing frameworks and share insights gleaned from them.

### Insights Gained from Marker

So far, we have introduced the overall process of Marker. Now, let’s discuss the insights gained from Marker.

**Insight 1** : Layout analysis can be divided into several subtasks. The first subtask involves [calling the PyMuPDF API to obtain page blocks](<https://github.com/VikParuchuri/marker/blob/ad6c97ca916084b225cc3319637449efbd4b0cb6/marker/ocr/page.py#L15C1-L39C18>).

```python def ocr_entire_page(page, lang: str, spellchecker: Optional[SpellChecker] = None) -> List[Block]: if settings.OCR_ENGINE == "tesseract": return ocr_entire_page_tess(page, lang, spellchecker) elif settings.OCR_ENGINE == "ocrmypdf": return ocr_entire_page_ocrmp(page, lang, spellchecker) else: raise ValueError(f"Unknown OCR engine {settings.OCR_ENGINE}")def ocr_entire_page_tess(page, lang: str, spellchecker: Optional[SpellChecker] = None) -> List[Block]: try: full_tp = page.get_textpage_ocr(flags=settings.TEXT_FLAGS, dpi=settings.OCR_DPI, full=True, language=lang) blocks = page.get_text("dict", sort=True, flags=settings.TEXT_FLAGS, textpage=full_tp)["blocks"] full_text = page.get_text("text", sort=True, flags=settings.TEXT_FLAGS, textpage=full_tp) if len(full_text) == 0: return [] # Check if OCR worked. If it didn't, return empty list # OCR can fail if there is a scanned blank page with some faint text impressions, for example if detect_bad_ocr(full_text, spellchecker): return [] except RuntimeError: return [] return blocks ```

**Insight 2** : Fine-tuning small multimodal pre-trained models, like [LayoutLMv3](<https://arxiv.org/pdf/2204.08387>), for specific tasks is quite beneficial. For example, Marker fine-tuned LayoutLMv3 to get the layout segmenter model for detecting [block types](<https://github.com/VikParuchuri/marker/blob/ad6c97ca916084b225cc3319637449efbd4b0cb6/marker/segmentation.py#L32>).

```python def load_layout_model(): model = LayoutLMv3ForTokenClassification.from_pretrained( settings.LAYOUT_MODEL_NAME, torch_dtype=settings.MODEL_DTYPE, ).to(settings.TORCH_DEVICE_MODEL) model.config.id2label = { 0: "Caption", 1: "Footnote", 2: "Formula", 3: "List-item", 4: "Page-footer", 5: "Page-header", 6: "Picture", 7: "Section-header", 8: "Table", 9: "Text", 10: "Title" } model.config.label2id = {v: k for k, v in model.config.id2label.items()} return model ```

[The dataset used for this fine-tuning](<https://huggingface.co/datasets/vikp/doclaynet_processed>) was sourced from a public dataset [DocLayNet](<https://github.com/DS4SD/DocLayNet>).

**Insight 3** : Identifying whether a PDF has single or double columns to establish the reading order is crucial in PDF parsing. Marker’s method involves fine-tuning LayoutLMv3 to create a column detector model. This model determines the number of columns on a page, and then [applies the midpoint method](<https://github.com/VikParuchuri/marker/blob/ad6c97ca916084b225cc3319637449efbd4b0cb6/marker/ordering.py#L83C1-L116C22>)

```python def add_column_counts(doc, doc_blocks, model, batch_size): for i in range(0, len(doc_blocks), batch_size): batch = range(i, min(i + batch_size, len(doc_blocks))) rgb_images = [] bboxes = [] words = [] for pnum in batch: page = doc[pnum] rgb_image, page_bboxes, page_words = get_inference_data(page, doc_blocks[pnum]) rgb_images.append(rgb_image) bboxes.append(page_bboxes) words.append(page_words) predictions = batch_inference(rgb_images, bboxes, words, model) for pnum, prediction in zip(batch, predictions): doc_blocks[pnum].column_count = predictiondef order_blocks(doc, doc_blocks: List[Page], model, batch_size=settings.ORDERER_BATCH_SIZE): add_column_counts(doc, doc_blocks, model, batch_size) for page_blocks in doc_blocks: if page_blocks.column_count > 1: # Resort blocks based on position split_pos = page_blocks.x_start + page_blocks.width / 2 left_blocks = [] right_blocks = [] for block in page_blocks.blocks: if block.x_start <= split_pos: left_blocks.append(block) else: right_blocks.append(block) page_blocks.blocks = left_blocks + right_blocks return doc_blocks ```

which is similar to my approach in [Advanced RAG 02: Unveiling PDF Parsing](<https://pub.towardsai.net/advanced-rag-02-unveiling-pdf-parsing-b84ae866344e>).

**Insight 4** : Specialized models can be trained to manage mathematical formulas. For example, [Texify](<https://github.com/VikParuchuri/texify>), a model from Marker, [uses the Donut architecture](<https://github.com/VikParuchuri/texify/blob/v0.1.8/texify/model/model.py>). This model was trained on the [Donut model](<https://github.com/clovaai/donut/>) using latex images and corresponding equations sourced from the web, including the [im2latex](<https://github.com/guillaumegenthial/im2latex>) dataset. The training was carried out on 4x A6000s for approximately two days, equivalent to roughly 6 epochs.

**Insight 5** : A [model](<https://huggingface.co/vikp/pdf_postprocessor_t5>) can also be used for post-processing. The primary idea is to train a T5 model to take nearly-final text and refine it by [removing artifacts, adding spaces, and inserting new lines](<https://github.com/VikParuchuri/marker/blob/ad6c97ca916084b225cc3319637449efbd4b0cb6/marker/postprocessors/editor.py#L22>).

```python def load_editing_model(): if not settings.ENABLE_EDITOR_MODEL: return None model = T5ForTokenClassification.from_pretrained( settings.EDITOR_MODEL_NAME, torch_dtype=settings.MODEL_DTYPE, ).to(settings.TORCH_DEVICE_MODEL) model.eval() model.config.label2id = { "equal": 0, "delete": 1, "newline-1": 2, "space-1": 3, } model.config.id2label = {v: k for k, v in model.config.label2id.items()} return model ```

Currently, no further details have been found regarding the training of the post-processor and the construction of the dataset.

## PaperMage

[Papermage](<https://aclanthology.org/2023.emnlp-demo.45.pdf>) is an open-source framework for the analysis and processing of visually rich, structured scientific documents. It provides clear and intuitive abstractions for the seamless representation and manipulation of both text and visual elements within a document.

Papermage integrates various Natural Language Processing (NLP) and Computer Vision (CV) models into a single framework. It offers ready-to-use solutions for common scientific document processing scenarios.

Next, we will explain the principles of PaperMage and discuss its overall process in conjunction with source code. Then, we will discuss the insights gained from PaperMage.

### Components

[Papermage](<https://aclanthology.org/2023.emnlp-demo.45.pdf>) mainly includes three parts:

* Magelib: A library that contains primitives and methods for representing and manipulating visually rich documents as multimodal structures.
* Predictors: An implementation that integrates various state-of-the-art scientific document analysis models into a unified interface. This is possible even if the individual models are written in different frameworks or operate in different modes.
* Recipes: It offers turn-key access to well-tested combinations of individual modules, often single-modality, forming sophisticated and extensible multimodal pipelines.

### Base Data Classes

Magelib provides three base data classes for representing fundamental elements of visually-rich, structured documents: Document, Layers and Entities.

### Overall Process and Code Analysis

Test code is as follows.

```python from papermage.recipes import CoreRecipecore_recipe = CoreRecipe()doc = core_recipe.run("YOUR_PDF_PATH") ```

First, `core_recipe = CoreRecipe()` will enter [the constructor of class CoreRecipe](<https://github.com/allenai/papermage/blob/fb270157f0dc61487e06ccabd70327cebda4fc7a/papermage/recipes/core_recipe.py#L78>), where the initialization of related libraries and models will take place.

```python class CoreRecipe(Recipe): def __init__( self, ivila_predictor_path: str = "allenai/ivila-row-layoutlm-finetuned-s2vl-v2", bio_roberta_predictor_path: str = "allenai/vila-roberta-large-s2vl-internal", svm_word_predictor_path: str = "https://ai2-s2-research-public.s3.us-west-2.amazonaws.com/mmda/models/svm_word_predictor.tar.gz", dpi: int = 72, ): self.logger = logging.getLogger(self.__class__.__name__) self.dpi = dpi self.logger.info("Instantiating recipe...") self.parser = PDFPlumberParser() self.rasterizer = PDF2ImageRasterizer() # with warnings.catch_warnings(): # warnings.simplefilter("ignore") # self.word_predictor = SVMWordPredictor.from_path(svm_word_predictor_path) self.publaynet_block_predictor = LPEffDetPubLayNetBlockPredictor.from_pretrained() self.ivila_predictor = IVILATokenClassificationPredictor.from_pretrained(ivila_predictor_path) self.sent_predictor = PysbdSentencePredictor() self.logger.info("Finished instantiating recipe") ```

Since `class Recipe` is the parent class of `CoreRecipe`, the `core_recipe.run() `function will come to [Recipe::run()](<https://github.com/allenai/papermage/blob/fb270157f0dc61487e06ccabd70327cebda4fc7a/papermage/recipes/recipe.py#L16>).

```python class Recipe: @abstractmethod def run(self, input: Any) -> Document: if isinstance(input, Path): if input.suffix == ".pdf": return self.from_pdf(pdf=input) if input.suffix == ".json": return self.from_json(doc=input) raise NotImplementedError("Filetype not yet supported.") if isinstance(input, Document): return self.from_doc(doc=input) if isinstance(input, str): if os.path.exists(input): input = Path(input) return self.run(input=input) else: return self.from_str(text=input) raise NotImplementedError("Document input not yet supported.") ```

Then it will come to [class CoreRecipe:: from_pdf()](<https://github.com/allenai/papermage/blob/fb270157f0dc61487e06ccabd70327cebda4fc7a/papermage/recipes/core_recipe.py#L101>) and [class CoreRecipe:: from_doc()](<https://github.com/allenai/papermage/blob/fb270157f0dc61487e06ccabd70327cebda4fc7a/papermage/recipes/core_recipe.py#L111>):

```python class CoreRecipe(Recipe): ... ... def from_pdf(self, pdf: Path) -> Document: self.logger.info("Parsing document...") doc = self.parser.parse(input_pdf_path=pdf) self.logger.info("Rasterizing document...") images = self.rasterizer.rasterize(input_pdf_path=pdf, dpi=self.dpi) doc.annotate_images(images=list(images)) self.rasterizer.attach_images(images=images, doc=doc) return self.from_doc(doc=doc) def from_doc(self, doc: Document) -> Document: # self.logger.info("Predicting words...") # words = self.word_predictor.predict(doc=doc) # doc.annotate_layer(name=WordsFieldName, entities=words) self.logger.info("Predicting sentences...") sentences = self.sent_predictor.predict(doc=doc) doc.annotate_layer(name=SentencesFieldName, entities=sentences) self.logger.info("Predicting blocks...") with warnings.catch_warnings(): warnings.simplefilter("ignore") blocks = self.publaynet_block_predictor.predict(doc=doc) doc.annotate_layer(name=BlocksFieldName, entities=blocks) self.logger.info("Predicting figures and tables...") figures = [] tables = [] for block in blocks: if block.metadata.type == "Figure": figure = Entity(boxes=block.boxes) figures.append(figure) elif block.metadata.type == "Table": table = Entity(boxes=block.boxes) tables.append(table) doc.annotate_layer(name=FiguresFieldName, entities=figures) doc.annotate_layer(name=TablesFieldName, entities=tables) # self.logger.info("Predicting vila...") vila_entities = self.ivila_predictor.predict(doc=doc) doc.annotate_layer(name="vila_entities", entities=vila_entities) for entity in vila_entities: entity.boxes = [ Box.create_enclosing_box( [b for t in doc.intersect_by_span(entity, name=TokensFieldName) for b in t.boxes] ) ] # entity.text = make_text(entity=entity, document=doc) preds = group_by(entities=vila_entities, metadata_field="label", metadata_values_map=VILA_LABELS_MAP) doc.annotate(*preds) return doc ```

Initially, layout analysis is performed using the [PDFPlumber library](<https://github.com/jsvine/pdfplumber>). * Sentence splitting
* Layout structure analysis
* Logical structure analysis.

### Sentence Splitting

The algorithm used for sentence splitting is [PySBD](<https://arxiv.org/pdf/2010.09657>), a rule-based sentence boundary disambiguation Python package.

The input consists of a sequence of tokens. The output provides the span of each sentence.

``` [Unannotated Entity: {'spans': [[0, 212]]}, Unannotated Entity: {'spans': [[212, 367]]}, …] ```

### Layout Structure Analysis

The model used to analyze layout structure of a page is `LPEffDetPubLayNetBlockPredictor`. This is a deep learning-based efficient object detection model provided by [LayoutParser](<https://arxiv.org/pdf/2103.15348>). Its primary function is to segment the document into visual block regions.

The input is page’s image, referred to as `doc.images`. The output is an object of `class box` and its respective type for each block. A box includes the x-coordinate of the upper-left vertex, the y-coordinate of the upper-left vertex, page width, page height, and page number.

``` [Unannotated Entity: {'boxes': [[0.5179840190298606, 0.752760137345049, 0.3682081491355128, 0.15176369855069774, 0]], 'metadata': {'type': 'Text'}}, Unannotated Entity: {'boxes': [[0.5145780320135539, 0.5080924136055337, 0.3675624668198144, 0.23725746136663078, 0]], 'metadata': {'type': 'Text'}}, …] ```

### Logical Structure Analysis

The model used to analyze the document’s logical structure is the `IVILATokenClassificationPredictor`. It segments the document into organizational units such as the title, abstract, body, footnotes, captions, and more.

The input provided is page-level data in the form of a dictionary.

``` { 'words': ['word1', 'word2', ...], 'bbox': [[x1, y1, x2, y2], [x1, y1, x2, y2], ...], 'block_ids': [0, 0, 0, 1 ...], 'line_ids': [0, 1, 1, 2 ...], 'labels': [0, 0, 0, 1 ...], # could be empty } ```

The output is the span of each entity.

``` [Unannotated Entity: {'spans': [[0, 80]], 'metadata': {'label': 'Title'}}, Unannotated Entity: {'spans': [[81, 157]], 'metadata': {'label': 'Author'}}, Unannotated Entity: {'spans': [[158, 215]], 'metadata': {'label': 'Paragraph'}}, ...] ```

### Insights and Discussion about PaperMage

**Abstraction of PDF Parsing**

For the task of PDF parsing, the abstraction proposed by PaperMage is effective, that is, dividing the entire PDF into types such as doc, layer and entities, which facilitates classification and management.

**Scalability**

PaperMage has designed a framework that is easy to extend, making it convenient for developers to carry out subsequent development.

For instance, to add a custom predictor, all we need to do is inherit from the base class `BasePredictor` and override `_predict()` function.

```python from .base_predictor import BasePredictorclass YOUR_NEW_Predictor(BasePredictor): ... ... def _predict(self, doc: Document) -> List[YOUR_RET_TYPE]: ... ... ```

**About Parallelization**

Figure 7 indicates that there is potential to improve PaperMage through parallelization, which is a viable direction for enhancement.

Although [the current version of PaperMage](<https://github.com/allenai/papermage/tree/fb270157f0dc61487e06ccabd70327cebda4fc7a>) does not contain any code related to parallel processing, adding parallel processing logic could significantly boost the efficiency of parsing PDFs.

## Conclusion

This article provided an overview of pipeline-based method in PDF parsing. It explores this approach using three representative frameworks as examples, offering an in-depth introduction and sharing insights derived from it.

In summary,

* While Marker has a few drawbacks, it is a lightweight and faster tool.
* While PaperMage is primarily designed for scientific documents, its outstanding scalability supports future development.
* Unstructured is a comprehensive pipeline-based PDF parsing framework. Its advantages lie in its detailed layout analysis and strong customizability.

Generally speaking, pipeline-based PDF parsing method is interpretable and easy to customize, making it a widely used PDF parsing method. However, its effectiveness largely depends on the performance of each model or algorithm used in the process. Therefore, the training data and the structure of each model must be carefully designed.
