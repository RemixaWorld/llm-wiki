### 📸 Can Your Code See What I See? 👀

So, here’s the deal: we’ve all been working hard on making our search engine _smarter than our professors_ 🧐🤭, but what if it could also look at pictures and _actually_ know what’s going on in them? Enter the LLaVA model — a brainy AI that can understand both images and text. Imagine if Sherlock Holmes 🕵️‍♂️ and Leonardo da Vinci 🎨 teamed up inside your code. That’s LLaVA, folks! And with Ollama as our trusty sidekick, we’ll be pulling off some serious AI magic. 🎩✨

### Step 1: 🧩 Extract Images Like a Pro

Before our search engine can get all artsy-fartsy with image searches, we need to pull those images out of various document types (PDFs, DOCXs, and PPTXs). This is basically like peeling off the stickers on your laptop without leaving sticky marks. 🏷️🙃

Here’s how we’ll do it:

* **PDFs 📝 ➡️ 📸:** We’ll use `PyMuPDF` (a.k.a. `fitz`, because cool software has multiple names 🤷‍♂️) to extract images from PDFs. Think of it like shaking out all the pictures from a textbook.
* **DOCXs 📄 ➡️ 🎨:** With `python-docx`, we can gently pluck the images out. Like carefully removing a paperclip from your 200-page research paper.
* **PPTXs 📊 ➡️ 🖼️:** We’ll use `python-pptx` to find and extract images from presentations. Because let's face it, nobody wants to read all the slides.

### Step 2: 📜 Describe the Images with LLaVA

After we’ve extracted the images, it’s time for LLaVA to do some magic 🧙‍♂️✨. It’s like asking an art critic to explain what’s happening in a painting (minus the existential crisis). LLaVA can generate a text description of the image that captures all the important details — so even if the picture is of a cat wearing sunglasses 😎🐱, our search engine will know about it!

### Step 3: 🧠 Making Sense of It All — Indexing Images and Text Together

Now that we’ve got image descriptions, we treat them like text documents. 🎉 We feed them into a `SentenceTransformer` model to get vector embeddings that represent the meaning of the images. This way, whether the search is for a paragraph in a PDF or a cool diagram in a PPT, our trusty `FAISS` index will know exactly where to look! 🕵️‍♀️🔍

### Step 4: ✨ Picture Perfect Search — Combining Text and Image Queries

With everything indexed, users can search by typing a query about the content of local files. 🖼️🔎 Whether it’s “finding data from pie charts 📊” or “finding somthing from image” our LLaVA-powered search engine will interpret your requests and return relevant answer that match the descriptions, ensuring you find exactly what you’re looking for.

## 🔍 Image Extraction Functions

Functions to extract images from various document types are defined. Here’s an example for extracting images from PDFs:

```python def extract_images_from_pdf(file_path): images = [] doc = fitz.open(file_path) for page in doc: image_list = page.get_images(full=True) for img_index, img in enumerate(image_list): xref = img[0] base_image = doc.extract_image(xref) image_bytes = base_image["image"] image = Image.open(io.BytesIO(image_bytes)) images.append(image) return images ```

* The function opens the PDF file and iterates through each page to extract images.
* `fitz` is used for accessing the PDF, and images are stored in a list after being processed.

> There are similar functions for extracting images from DOCX and PPTX files.

```python def extract_images_from_docx(file_path): images = [] doc = Document(file_path) for rel in doc.part.rels.values(): if "image" in rel.target_ref: image_data = rel.target_part.blob image = Image.open(io.BytesIO(image_data)) images.append(image) return imagesdef extract_images_from_pptx(file_path): images = [] prs = Presentation(file_path) for slide in prs.slides: for shape in slide.shapes: if shape.shape_type == MSO_SHAPE_TYPE.PICTURE: image = shape.image image_bytes = image.blob image = Image.open(io.BytesIO(image_bytes)) images.append(image) return images ```

## 🧠 3. Embedding Initialization

The code initializes the models needed for generating embeddings and performing semantic search:

``` model = SentenceTransformer('sentence-transformers/msmarco-bert-base-dot-v5')dimension = 768index = faiss.IndexFlatIP(dimension)metadata = [] ```

* `SentenceTransformer` is used to create embeddings for text. The model `msmarco-bert-base-dot-v5` is a pre-trained model suitable for semantic search tasks.
* `faiss` is used to create a similarity search index that stores the embeddings. It allows for fast nearest-neighbor search in high-dimensional spaces.

## 📜 4. Reading and Processing Documents

Functions are provided to read and extract content from different document types. For example, reading a PDF file:

```python def read_pdf(file_path): with open(file_path, 'rb') as file: reader = PyPDF2.PdfReader(file) return ' '.join([page.extract_text() for page in reader.pages]) ```

* This function opens a PDF file and extracts text from each page.
* The text from all pages is joined into a single string.

> There are similar functions for reading DOCX and PPTX files, ensuring the code can handle various document types.

```python def read_docx(file_path): print(f"Reading DOCX: {file_path}") doc = docx.Document(file_path) return ' '.join([para.text for para in doc.paragraphs])def read_pptx(file_path): print(f"Reading PPTX: {file_path}") prs = Presentation(file_path) return ' '.join([shape.text for slide in prs.slides for shape in slide.shapes if hasattr(shape, 'text')]) ```

## ✂️ 5. Chunking Text

Large documents are divided into smaller chunks for processing:

```python def chunk_text(text, chunk_size=500, overlap=50): words = text.split() chunks = [] for i in range(0, len(words), chunk_size - overlap): chunk = ' '.join(words[i:i + chunk_size]) chunks.append(chunk) return chunks ```

* The function splits the document text into smaller chunks of 500 words, with an overlap of 50 words between chunks.
* This is done to preserve some context across chunks.

## 🖼️ 6. Processing Images

The `process_image` function converts images to a byte array format for further processing:

```python def process_image(image): img_byte_arr = io.BytesIO() image.save(img_byte_arr, format='PNG') img_byte_arr = img_byte_arr.getvalue() return img_byte_arr ```

* The function converts the image to PNG format and returns its byte representation.
* This allows for indexing images in the search engine.

## 📈 7. Indexing Documents

The function `index_documents` indexes documents and images from a specified directory:

```python def index_documents(directory): documents = [] file_count = 0 for root, _, files in os.walk(directory): for file in files: file_path = os.path.join(root, file) content = "" images = [] if file.lower().endswith(('.png', '.jpg', '.jpeg', '.gif', '.bmp')): with Image.open(file_path) as img: images.append(img) elif file.endswith('.pdf'): content = read_pdf(file_path) images = extract_images_from_pdf(file_path) elif file.endswith('.docx'): content = read_docx(file_path) images = extract_images_from_docx(file_path) elif file.endswith('.pptx'): content = read_pptx(file_path) images = extract_images_from_pptx(file_path) elif file.endswith('.txt'): with open(file_path, 'r', encoding='utf-8') as f: content = f.read() if content: chunks = chunk_text(content) for i, chunk in enumerate(chunks): documents.append(chunk) metadata.append({"path": file_path, "chunk_id": i, "type": "text"}) for i, img in enumerate(images): img_content = process_image(img) documents.append(img_content) metadata.append({"path": file_path, "chunk_id": i, "type": "image"}) file_count += 1 embeddings = [] for doc in documents: if isinstance(doc, str): embeddings.append(model.encode([doc])[0]) else: image_description = llava_generate("Describe this image in detail.", doc) embeddings.append(model.encode([image_description])[0]) index.add(np.array(embeddings)) ```

* The function processes each file in the directory, extracting text and images.
* Text documents are chunked into smaller parts, while images are converted to byte arrays.
* Embeddings are generated for each document or image (using image descriptions).
* The embeddings are added to the FAISS index, allowing for quick similarity search.

## 🔎 8. Searching the Index

To perform a semantic search, the `semantic_search` function is used:

```python def semantic_search(query, k=10, query_type='text'): if query_type == 'text': query_vector = model.encode([query])[0] elif query_type == 'image': return image_search(query, k) distances, indices = index.search(np.array([query_vector]), k) results = [] for i, idx in enumerate(indices[0]): meta = metadata[idx] content = read_document_chunk(meta["path"], meta["chunk_id"], meta.get("type", "text")) results.append({ "id": int(idx), "path": meta["path"], "content": content, "type": meta.get("type", "text"), "score": float(distances[0][i]) }) return results ```

* The query is embedded using the model.
* The FAISS index is searched for the closest matches, based on the query embedding.
* The top `k` results are returned, including information about the document and its content.

## 📝 9. Answer Generation

The code uses the Ollama model to generate responses to queries based on the retrieved documents:

```python def generate_answer(query, context): prompt = f"""Answer the user's question using the documents given in the context...""" response = ollama.generate(model='tinyllama', prompt=prompt) return response['response'] ```

* The `prompt` is formed by including the query and relevant context from the documents.
* The Ollama model generates a response based on this prompt.
