## 1\. Introduction

Customer support at such a scale requires systems that not only answer straightforward questions but can also manage queries with multiple components and complexities. As detailed in my [previous ](</@hermanwandabwa/from-data-to-dialogue-development-of-a-retrieval-augmented-generation-rag-chatbot-for-fitness-b9fbaf818ace>)article, a RAG system is meant to bridge the gap between a static knowledge base and dynamic conversational AI. This is done by retrieving relevant context and augmenting it with relevant generative responses. The fundamental idea in this article is the same, albeit with some twist. In this implementation, we focus on two key aspects:

* **Data Scraping:** Extracting FAQs from Safaricom’s [website](<https://www.safaricom.co.ke/media-center-landing/frequently-asked-questions>). This is all I had access to for demonstration purposes. However, this can be improved on with the addition of more documents and knowledge bases.
* **Response Generation** where I**** leverage [**Maximum Marginal Relevance (MMR)**](<https://www.cs.cmu.edu/~jgc/publication/The_Use_MMR_Diversity_Based_LTMIR_1998.pdf>) for **reranking.** This is where the magic happens and I’ll explain it later in plain English.
* The final step is utilisation of OpenAI’s GPT model to generate nuanced responses. Remember, any other open-source Large Language Model (LLM) could be used. Let me know if you want me to tweak the code to fit such open models.

By combining the above, the assistant will not only provide contextually relevant answers but also ensure diversity and confidence in its responses. Enough of the theory. Let's move to the interesting part.

## 2\. Core Components of this RAG System

As detailed in my earlier [article](</@hermanwandabwa/from-data-to-dialogue-development-of-a-retrieval-augmented-generation-rag-chatbot-for-fitness-b9fbaf818ace>), RAG apps are driven by a _vector database_ , _query processor, retriever_ , an _embeddings model,_ and an _LLM._ However, I decided to add a Maximum Marginal Relevance (MMR) ranker at the retriever level to handle conflicting questions that are way too common from users. I’ll now take you through the code and explain a little more about MMR:

### a) Data Scraping (`scraper.py`)

The key task for this module is to automatically grab FAQs and respective answers and save them in a structured format ready for ingestion in the RAG pipeline. Key steps are as follows:

1. The scraper finds all the links to the different FAQ categories (like M-Pesa, Data, etc.) from the home page. The `get_category_urls` function handles this.
2. For each category, the `scrape_faq_pairs` function finds each question and its corresponding answer and extracts them. Some of the answers are in ordered lists, so that formatting is also factored in. The extracts are then saved as a dictionary and in JSON format.

Below is the code snippet for handling the data collection process:

```python def get_category_urls(landing_url): """ Scrapes the landing page to collect all category URLs. Adjust the CSS selector if needed. """ response = requests.get(landing_url) random_delay() # Random delay after request soup = BeautifulSoup(response.text, 'html.parser') # Select anchor tags that contain the FAQ category path category_links = soup.select("a[href*='/media-center-landing/frequently-asked-questions/']") urls = set() for link in category_links: href = link.get("href") # Build absolute URL if it's relative if href.startswith("/"): href = "https://www.safaricom.co.ke" + href urls.add(href) return list(urls)def scrape_faq_pairs(category_url): """ Scrapes the FAQ pairs from a given category page. ### b) Loading data and the embeddings process

The output of the above process is a JSON file with question and answer pairs. Vectorisation also happens at this stage after the data has been loaded. For this example, I used [all-mpnet-base-v2](<https://huggingface.co/sentence-transformers/all-mpnet-base-v2>) sentence transformer model to convert each question and answer into a numerical representation called an “embedding.” Embeddings can then allow the LLM to compare how similar different questions and answers are. This is done by computing the semantic distance between embeddings of the different question-answer pairs. I used [FAISS](<https://github.com/facebookresearch/faiss>), a library for efficient similarity search, to quickly find the most relevant FAQs for a given question. The following code snippet captures this:

```json # ------------------------------# Step 1: Load and Preprocess Data# ------------------------------with open("faq_data.json", "r", encoding="utf-8") as f: data = json.load(f)faq_list = []for url, faq_pairs in data.items(): for faq in faq_pairs: faq_list.append({ "source": url, "question": faq["question"], "answer": faq["answer"] })faq_texts = [f"Q: {faq['question']}
A: {faq['answer']}" for faq in faq_list]# ------------------------------# Step 2: Build the Embedding Model and FAISS Index# ------------------------------embedder = SentenceTransformer("all-mpnet-base-v2")embeddings = embedder.encode(faq_texts, show_progress_bar=True)# Normalize embeddings for cosine similarityfaiss.normalize_L2(embeddings)index = faiss.IndexFlatIP(embeddings.shape[1])index.add(embeddings.astype(np.float32)) ```

c) **Smart Question Answering with MMR**

Why MMR in this case? Imagine you are searching for information; you want answers that are both **relevant** to your query and **diverse** , avoiding repetitive information. That’s basically what MMR does. Back to our example, if the chatbot just gives the top few most similar answers, there is chance the same information will be repeated multiple times. MMR helps avoid this with the diversity measure. In this example, MMR works as follows:

1. **Initial Search:** The chatbot first uses FAISS to find the `INITIAL_CANDIDATES` (set to 20 in this example) most similar FAQs to the query. Think of this as a first rough selection of potentially helpful answers.
2. **Question and Answer Embeddings :** Both the question and the candidate FAQs are converted into embeddings that capture the meaning of the text. Ideally, similar questions and answers will have similar embeddings, or their semantic distance (measured by cosine similarity) will be quite close.
3. **The MMR Formula:** The core of MMR is a formula that balances _relevance_ and _diversity_ : `score = λ * relevance - (1 - λ) * redundancy`

* `λ` (lambda) is always a parameter between 0 and 1 (`MMR_LAMBDA`, set to 0.7 in our example). This controls the balance between _relevance_ and _diversity_. A higher λ emphasizes relevance, while a lower λ emphasizes diversity. You can try changing this in your experimentation. Let me know the effect in the comment section.
* `relevance` is just how similar a candidate FAQ is to your question (measured by the cosine similarity of their embeddings, as earlier mentioned).
* `redundancy` is how similar a candidate FAQ is to the already selected FAQs.

I feel obliged to explain this further using an example. Imagine you’re choosing books from a library about “cats.”

* **Relevance** will be a measure of how much each book is about cats.
* **Redundancy** will be a measure of how**** similar each book is to the books you’ve already chosen.
* **MMR:** A score that helps you pick books that are all about cats (high relevance) but also cover different aspects of cats (low redundancy), avoiding picking five books that all say the same thing.

The code snippet for the MMR function is below. The `while` loop iteratively selects the best FAQ based on the MMR score, ensuring a balance between relevance and diversity in the final set of answers provided by the chatbot. The `lambda_param` (0.7) controls this balance.

```python def mmr_rerank(query_emb, candidate_embs, lambda_param=MMR_LAMBDA, final_k=FINAL_RESULTS): """MMR reranking implementation""" query_sims = np.dot(candidate_embs, query_emb.T).flatten() doc_sims = np.dot(candidate_embs, candidate_embs.T) selected = [] remaining = list(range(len(candidate_embs))) while len(selected) < final_k and remaining: scores = [] for i in remaining: if not selected: score = query_sims[i] else: max_sim = np.max(doc_sims[i, selected]) score = lambda_param * query_sims[i] - (1 - lambda_param) * max_sim scores.append(score) best_idx = np.argmax(scores) selected.append(remaining.pop(best_idx)) return selected ```

**4\. Iterative Selection:** To explain further about the iterative part:

* It starts with an empty set of selected FAQs.
* In each iteration, it calculates the MMR score for each remaining candidate FAQ.
* The candidate with the highest MMR score is added to the selected set.
* This process repeats until `FINAL_RESULTS` (set to 5) FAQs are selected. This can of course be extended to more values or reduced to say the top three.

**5\. Cosine Similarity:** The similarity (both relevance and redundancy) is then calculated using cosine similarity. This is just a measure of the angle between the embedding vectors. The smaller the angle (closer to 0) the higher the similarity as the FAQs and answers will be assumed to be in the same semantic space.

## 4\. Deployment Considerations

This app could be moved to an environment where other users are able to test it. The environment can be local or on the cloud.

**Local Deployment:** The entire system can be run locally in a Python virtual environment. All you need is to clone the [repository](<https://github.com/wandabwa2004/LLMs/tree/main/RAG_Safaricom>), setup the environment as per the instructions, and spin up the app.
