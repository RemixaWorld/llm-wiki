A vector database is a critical component in Retrieval Augmented Generation (RAG) applications: besides storing the vectors and the metadata, it efficiently computes similarity measures and powers semantic search.

But picking the right vector database when building production-ready RAG applications is no easy task: this requires a close evaluation of the cost, the query performance, and the scalability. This is even more important when you process millions of vectors or expect real-time use.

> _I’ve recently gone through this decision process. So, in this article, I’ll share with you why I think Weaviate is a good option for managing your vector data and building RAGs, especially if you’re a developer with no particular experience in LLMs._

To make this tutorial easy to follow, I’ll first load some data from a public API, index it in Weaviate, and experiment with some of its cool features.

Here’s the agenda

□ vector search
□ keyword search
□ hybrid search

5 — Generative search: turning your database into a RAG system

## 1 — Load research papers from the Papers With Code public API 🔌

The one we’ll experiment today with consists of research papers about Large Language Models.

We’ll extract this dataset from the public API of [paperswithcode](<https://paperswithcode.com/>).

To collect this dataset, you need to run the following function:

```python import urllibimport requestsfrom tqdm import tqdmdef extract_papers(query: str): query = urllib.parse.quote(query) url = f"https://paperswithcode.com/api/v1/papers/?q={query}" response = requests.get(url) response = response.json() count = response["count"] results = [] results += response["results"] num_pages = count // 50 for page in tqdm(range(2, num_pages)): url = f"https://paperswithcode.com/api/v1/papers/?page={page}&q={query}" response = requests.get(url) response = response.json() results += response["results"] return resultsquery = "Large Language Models"papers = extract_papers(query) ```

* It can perform document reranking after retrieval

## 3 — Index the data in batches 🗂️

Before indexing the data into Weaviate, we must create a collection and define the schema.

This is done via the `create` method that defines:

* The collection name: MLPapers
* The properties (or fields)

``` properties = [ Property( name="context", data_type=DataType.TEXT, tokenization=wvc.config.Tokenization.LOWERCASE, vectorize_property_name=True, ), Property( name="title", data_type=DataType.TEXT, tokenization=wvc.config.Tokenization.LOWERCASE, vectorize_property_name=True, ), Property( name="authors", data_type=DataType.TEXT_ARRAY, tokenization=wvc.config.Tokenization.LOWERCASE, vectorize_property_name=False, ), Property( name="conference", data_type=DataType.TEXT, vectorize_property_name=False, ), Property( name="date", data_type=DataType.DATE, vectorize_property_name=False, ), Property( name="paper_id", data_type=DataType.TEXT, vectorize_property_name=False, ), Property( name="arxiv_id", data_type=DataType.TEXT, vectorize_property_name=False, ), Property( name="nips_id", data_type=DataType.TEXT, vectorize_property_name=False, ),] ```
* The vectorizer that’ll be used to embed the data when indexing it:

``` vectorizer_config = wvc.config.Configure.Vectorizer.text2vec_palm( project_id=GCP_PROJECT_ID, model_id="textembedding-gecko@003",) ```
* The generator that’ll be used to generate answers based on retrieved documents (To perform a RAG operation directly from Weaviate)

``` generative_config = wvc.config.Configure.Generative.palm( project_id=PROJECT_ID, model_id="chat-bison", temperature=0.1,) ```
* The Cohere re-ranker that reranks the documents after they’re retrieved

``` reranker_config=wvc.config.Configure.Reranker.cohere() ```

Here’s the full code that creates the collection:

``` collection_name = "MLPapers"client.collections.delete(collection_name)collection = client.collections.create( collection_name, vectorizer_config=wvc.config.Configure.Vectorizer.text2vec_palm( project_id=PROJECT_ID, model_id="textembedding-gecko@003", ), reranker_config=wvc.config.Configure.Reranker.cohere(), generative_config=wvc.config.Configure.Generative.palm( project_id=PROJECT_ID, model_id="chat-bison", temperature=0.1, ), properties=[ Property( name="abstract", data_type=DataType.TEXT, tokenization=wvc.config.Tokenization.LOWERCASE, vectorize_property_name=True, ), Property( name="title", data_type=DataType.TEXT, tokenization=wvc.config.Tokenization.LOWERCASE, vectorize_property_name=True, ), Property( name="authors", data_type=DataType.TEXT_ARRAY, tokenization=wvc.config.Tokenization.LOWERCASE, vectorize_property_name=False, ), Property( name="conference", data_type=DataType.TEXT, vectorize_property_name=False, ), Property( name="published", data_type=DataType.DATE, vectorize_property_name=False, ), Property( name="paper_id", data_type=DataType.TEXT, vectorize_property_name=False, ), Property( name="arxiv_id", data_type=DataType.TEXT, vectorize_property_name=False, ), Property( name="nips_id", data_type=DataType.TEXT, vectorize_property_name=False, ), ], vector_index_config=wvc.config.Configure.VectorIndex.hnsw( distance_metric=wvc.config.VectorDistances.COSINE ),) ```

After the collection is created, you can index the data in batches. This is another useful functionality of Weaviate that speeds up the indexing process.

``` batch_size = 50indices = range(0, len(papers), batch_size)batches = []for i in range(len(indices)): batches.append(papers[indices[i] : indices[i] + batch_size])ids = []for batch in tqdm(batches): inserted_objects = collection.data.insert_many(batch) ids += inserted_objects.all_responses ```

### 3\. Hybrid Search

One feature that I find particularly useful in Weaviate is hybrid search.

This technique combines multiple search algorithms to improve the accuracy and relevance of search results. It uses the best features of both keyword-based search algorithms and vector search techniques.

By using a hybrid search, you can match relevant keywords while retaining control over semantics.

Running a hybrid search in Weaviate is done by calling the `hybrid` method:

``` hybrid_response = collection.query.hybrid( query=query, limit=3, alpha=0.5,) ```

### 4\. Re-ranking

Re-ranking is a technique that re-orders the search result according to some criteria.

It is commonly used to get the most relevant documents that match the query and have the least amount of irrelevant data.

There are many open-source and proprietary algorithms to perform re-ranking.

Weaviate can connect to some of them and apply re-ranking as a post-retrieval process.

Here’s an example of a vector search that uses re-ranking.

``` semantic_response_with_rerank = collection.query.near_text( query=query, limit=3, return_metadata=["certainty"], rerank=Rerank( prop="abstract", query=query, ),) ```

> _You can combine re-ranking with vector, hybrid, and keyword searches._

### 5\. Advanced Filtering

Weaviate provides advanced filtering options that are not commonly found in other databases.

By using filters, you increase search relevance and add a layer of deterministic logic to vector search.

To perform filtering, Weaviate relies on operators

Here are two examples:

* `greater_than` operator over numeric properties and **dates**

```python from weaviate.classes.query import Filterfilter_time = datetime(2022, 1, 1).replace(tzinfo=timezone.utc)response_with_filters = collection.query.near_text( query=query, filters=( Filter.by_property("title").contains_any( ["Large Language Models", "LLM", "LLMs"], ) & Filter.by_property("published").greater_than(filter_time) ), limit=4,) ```
* `contains_any `that applies to string properties.
Here's an example of how to filter abstracts by searching for keywords in their titles from a pre-defined list.

``` response_with_filters = collection.query.near_text( query=query, filters=Filter.by_property("title").contains_any( ["Large Language Models", "LLM", "LLMs"], ), limit=4, ```

There’s a long [list](<https://weaviate.io/developers/weaviate/api/graphql/filters>) of other operators such as `Like`, `WithinGeoRange` or `IsNull` that you use and combine with others.

## 5 — Generative search: turning your database into a RAG system 🤖

On top of retrieving relevant documents using a variety of search algorithms, re-ranking, and filters, Weaviate can also combine the search result in a prompt, send it to an LLM, and generate an answer.

To perform the generative search, you need to enable the `generative-palm `module when starting Weaviate. (Check docker-compose defined above👆)

To generate an answer with Weaviate, we need to prepare a prompt that will serve as a template to inject the retrieved context.

``` prompt = """Answer the following questions by using the provided context only. If the context is not helpful or doesn't provide any relevant details, just say "I don't know."Question = {query}Context = {abstract}"""prompt = prompt.format(query=query, abstract="{abstract}") ```

Then, to generate the answer with vector search, run this function:

``` response = collection.generate.near_text( query=query, limit=5, grouped_task=prompt, rerank=Rerank( prop="abstract", query=query, ),) ```

And here’s your answer.

``` To fine-tune a large language model (LLM), you can use supervisedfine-tuning (SFT), where the LLM is trained on a dataset of labeledexamples.Another approach is to use adapter-based fine-tuning with LoRA, whichmatches the performance of traditional fine-tuning while reducing thenumber of training parameters.You can also incorporate few-shot examples during fine-tuning to recoverthe original few-shot capabilities while keeping the added benefits offine-tuning. ```

## Conclusion

Weaviate is an AI-native vector database that integrates well into the generative AI landscape.

By connecting to third-party services and even open-source models, it can, on top of retrieving vectors, perform other tasks such as vectorizing data, reranking documents post-retrieval, and generating answers with RAG.

Weaviate can also be deployed to a cluster using K8S or used via its managed service, making it a suitable solution for intensive workloads.

What I liked the most about this open-source database was the developer experience: everything sits in one place, the API is well-designed and everything seems to fit together out of the box.
