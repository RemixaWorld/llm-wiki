Large Language Models (LLMs) have limited knowledge based on their training data.

Retrieval-Augmented Generation (RAG) aims to provide LLMs with additional external knowledge by incorporating documents typically stored in a database. This allows LLMs to provide more accurate and contextually relevant responses. A critical component of a RAG system is the retriever. The retriever’s job is to find matching documents based on a user’s query.

SPLADE is a sparse retriever model based on BERT, a transformer-based encoder model. In this article, we will use SPLADE for information retrieval to build an advanced RAG pipeline.

## SPLADE: Sparse Lexical and Expansion Model for First Stage Ranking

SPLADE stands for “SParse Lexical AnD Expansion.” It is an efficient retrieval model with two key features: **sparsity** and **query expansion**[1].

“Sparse” means that most of the output vectors are zero, with only a few non-zero vectors. The opposite of sparse is dense, where zeros are usually not present.

Sparse (left) vs. dense (right) vectors. Image by author.

**Sparse vectors** can be stored more efficiently in a database because we only focus on the non-zero values, and sparse computations can be performed faster than dense computations.

**Query expansion** rewrites a user query with synonyms to improve retrieval performance. SPLADE learns to perform query expansion automatically during training.

For example, given the query “the cat,” the BM25 algorithm would only search for the words “the” and “cat” in the document corpus. However, SPLADE “knows” to search for “cats” and “kitty,” etc.

This is an example of an input text expanded using SPLADE-doc. The higher the weight, the more important the token. Image by author.

### The SPLADE Model

The SPLADE model converts a sequence of input tokens to a sequence of `N` logit vectors. Each logit vector **z** is the size of the vocabulary. This means that for every possible token in the vocabulary, the logit outputs a number. However, most of the logit values are zero because the logits are sparse.

The SPLADE model converts the input tokens into N=6 output logits. Each logit vector **z** is of size 30,522. Image by author.

The vocabulary is defined by the tokenizer. The **WordPiece** tokenizer converts an input sentence into a sequence of tokens.

### WordPiece Tokenizer

WordPiece is a subword tokenization algorithm developed for pretraining **BERT**. A token is typically a word, but it may also be part of a word or a single character. WordPiece’s vocabulary contains 30,522 possible tokens, though quite a few are unused.

The WordPiece tokenizer vocabulary used in SPLADE. Image by author.

With the WordPiece tokenizer and BERT-based models, a special [CLS] token is always added at the beginning and a special [SEP] token is always added at the end [2].

## Using SPLADE in Python

Let’s use SPLADE to see how it works in practice. First, we need to install `torch` and `transformers`:

```python pip install torch transformers ```

Now, we can load the SPLADE model and tokenizer. Efficient-SPLADE has two separate models, one for the query and one for the document. Both are available on Hugging Face [3].

```python import torchfrom transformers import AutoTokenizer, AutoModelForMaskedLMdevice = torch.device("cuda" if torch.cuda.is_available() else "cpu")# Load the EfficientSPLADE model and tokenizerquery_model_id = "naver/efficient-splade-VI-BT-large-query"doc_model_id = "naver/efficient-splade-VI-BT-large-doc"query_tokenizer = AutoTokenizer.from_pretrained(query_model_id)doc_tokenizer = AutoTokenizer.from_pretrained(doc_model_id)query_model = AutoModelForMaskedLM.from_pretrained(query_model_id).to(device).eval()doc_model = AutoModelForMaskedLM.from_pretrained(doc_model_id).to(device).eval() ```

### Tokenizer

First, let’s use the tokenizer to convert the input text (str) into a list of token IDs (int):

``` tokens = doc_tokenizer("The quick brown fox", return_tensors='pt').to(device)print(tokens['input_ids'])>> tensor([[ 101, 1996, 4248, 2829, 4419, 102]], device='cuda:0') ```

We now have `N=6` tokens. We can decode it back into text to confirm that it worked:

``` print(doc_tokenizer.decode(tokens['input_ids'][0]))>> [CLS] the quick brown fox [SEP] ```

As you can see, the tokenizer has automatically added the special tokens [CLS] and [SEP].

### Logits

Next, we compute the logits, or log probabilities, that the model outputs. We can then verify the shape of the logits.

``` with torch.no_grad(): logits = doc_model(**tokens).logits[0]print(logits.shape)>> torch.Size([6, 30522]) ```

The logits have shape `[N x |V|]` with a vocabulary size of `|V|=30522`.

### Importance Weights

SPLADEv2 introduced a maximum pooling operation that reduces the logits matrix to a vector of size 30,522 [4]:

```python def max_pool(logits: torch.Tensor) -> torch.Tensor: """ Perform SPLADEv2 max pooling operation. Returns a vocabulary-sized tensor with max-pooled values. """ return torch.log1p(torch.relu(logits)).amax(dim=0)splade_vector = max_pool(logits)print(splade_vector.shape)>> torch.Size([30522]) ```

We transform each element in the logits matrix and then keep only the maximum value for each column.

Most entries in the sparse SPLADE vector are zero. We can examine the weights of all the non-zero values using a helper function.

```python def print_splade_weights(vec: torch.Tensor, tokenizer): """Prints a sorted list of token-weight pairs for non-zero weights.""" reverse_vocab = {v: k for k, v in tokenizer.vocab.items()} nonzero_indices = vec.nonzero().squeeze().tolist() weights = vec[nonzero_indices].tolist() # Sort by weight in descending order bow = sorted( [(reverse_vocab[idx], round(score, 2)) for idx, score in zip(nonzero_indices, weights)], key=lambda x: x[1], reverse=True ) print("SPLADE weights:
", bow)print_splade_weights(splade_vector, doc_tokenizer)>> SPLADE weights: [('fox', 2.14), ('foxes', 1.93), ('quick', 1.85), ('brown', 1.76), ('types', 0.92), ('species', 0.83), ('browns', 0.82), ...] ```

The following bar chart shows the top 15 SPLADE weights for the input text, “The quick brown fox.” As you can see, SPLADE also has weights for related words not included in the original text. This is an example of learned expansion.

### Dot Product

We can measure the similarity of vectors using the dot product. Vectors that are similar will have a high dot product, while vectors that are less similar will have smaller values.

```python def compute_score(query_vec: torch.Tensor, doc_vec: torch.Tensor) -> float: """ Computes the dot product between the query and document tensors. The result is a similarity score. """ return torch.dot(query_vec, doc_vec).item() ```

### Putting It All Together

Now, let’s put everything together and use SPLADE to rank a query against some example documents.

```python import torchfrom transformers import AutoTokenizer, AutoModelForMaskedLMdevice = torch.device("cuda" if torch.cuda.is_available() else "cpu")# Load the EfficientSPLADE model and tokenizerquery_model_id = "naver/efficient-splade-VI-BT-large-query"doc_model_id = "naver/efficient-splade-VI-BT-large-doc"query_tokenizer = AutoTokenizer.from_pretrained(query_model_id)doc_tokenizer = AutoTokenizer.from_pretrained(doc_model_id)query_model = AutoModelForMaskedLM.from_pretrained(query_model_id).to(device).eval()doc_model = AutoModelForMaskedLM.from_pretrained(doc_model_id).to(device).eval()def max_pool(logits: torch.Tensor) -> torch.Tensor: """ Perform SPLADEv2 max pooling operation. Returns a vocabulary-sized tensor with max-pooled values. """ return torch.log1p(torch.relu(logits)).amax(dim=0)def encode_splade(text: str, model, tokenizer) -> torch.Tensor: """Encodes text into a sparse vector representation using SPLADE.""" tokens = tokenizer(text, return_tensors="pt").to(device) with torch.no_grad(): logits = model(**tokens).logits[0] # tensor of shape [N, 30522] return max_pool(logits) # tensor of size 30522def compute_score(query_vec: torch.Tensor, doc_vec: torch.Tensor) -> float: """ Computes the dot product between the query and document tensors. The result is a similarity score. """ return torch.dot(query_vec, doc_vec).item() ```

And now we can use it like this:

``` # Example query and documentsquery = "What is the capital of France?"documents = [ "Paris is the capital and largest city of France.", "The Eiffel Tower is a wrought-iron lattice tower on the Champ de Mars in Paris, France.", "France, officially the French Republic, is a country located primarily in Western Europe.", "Harry Potter is a series of seven fantasy novels written by British author J. K. Rowling."]# Encode queryquery_vec = encode_splade(query, query_model, query_tokenizer)# Score each documentfor i, doc in enumerate(documents): doc_vec = encode_splade(doc, doc_model, doc_tokenizer) # Encode document score = compute_score(query_vec, doc_vec) print(f"Document {i + 1} Score: {score:.2f}") ```

Which gives us the following ranking:

``` Document 1 Score: 13.93Document 2 Score: 6.16Document 3 Score: 9.11Document 4 Score: 1.12 ```

Our Efficient-SPLADE implementation successfully ranked the document corpus against our query.

We can use it in a RAG system to retrieve the most relevant documents. Since the documents can be encoded in advance and stored in a database, we only need to encode the query online.

## Advanced RAG Improvements

It makes sense for sparse retrieval (keyword search) using SPLADE to be combined with dense retrieval (semantic search), which is usually used in a RAG system. While this increases complexity and computational effort, it also offers the best of both worlds.

Combining multiple search algorithms into a single score is called a hybrid search. Hybrid search typically combines dense embeddings with BM25, but we can replace BM25 with SPLADE.

## Conclusion

SPLADE is a sparse retrieval model that can be used in an RAG system to search for matching documents based on a given query.

“Sparse” means that we have a fixed-size vocabulary representing our query and documents, where most values are zero. The great thing about SPLADE is that the model learned to include not only the actual words, but also related words. SPLADE expands the input text by adding related words and reduces it by removing unnecessary words, such as “the.”

SPLADE can efficiently replace a dense encoder model, which performs semantic searches. However, it can also be used in combination with a dense encoder model for optimal retrieval results using hybrid search.

Try it out and take your RAG pipeline to the next level.
