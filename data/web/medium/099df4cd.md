### Introduction

Creating a robust and intelligent chatbot has become more achievable in the era of personalized AI assistants. _Porter_ is my personal AI assistant built using cutting-edge technologies like Ollama’s llama3.1 and llama3.2 models, integrated with a memory system for storing chat history, all wrapped in an intuitive Streamlit UI. In this blog, I’ll walk you through the development process, explain the technologies used, and provide insights into the key features that make _Porter_ a powerful assistant capable of answering questions, handling commands, and retaining conversations across sessions.

### Why Porter?

The idea behind _Porter_ was to create an AI assistant that is not only responsive but also intelligent enough to remember past conversations. This allows users to interact with it more naturally, as it evolves its responses based on previous interactions. By using LLMs like llama3.1 and llama3.2 from Ollama, _Porter_ delivers high-quality answers, making it a reliable tool for both personal and professional tasks.

## Features of Porter

**1\. Memory System for Chat History** One of _Porter_ ’s standout features is its ability to retain and recall previous interactions using a file-based chat history system. Unlike many chatbots that forget past conversations, _Porter_ uses memory stored in a JSON file to keep track of dialogue, offering more personalized and context-aware responses.

**2\. Multi-Model Support** _Porter_ integrates two models from Ollama — llama3.1 and llama3.2. These models offer flexibility, allowing users to switch between versions and select the one that best fits their needs. While llama3.1 is highly stable and robust, llama3.2 brings the latest updates, pushing the boundaries of conversational AI. By storing chat history, Porter ensures continuity in its responses, enhancing its usefulness as a true personal assistant.

**3\. Flexible Inference Settings** The chatbot’s flexibility doesn’t end with model selection. The user can adjust parameters such as temperature and max tokens, enabling them to control the creativity and length of the generated responses. This allows _Porter_ to cater to both concise answers and more elaborate, nuanced explanations.

**4\. Command Handling** Besides general queries, _Porter_ can handle system-level commands. This makes it more than just a chatbot; it acts as a mini-assistant capable of executing actions on the system.

### Step 3: Building the Streamlit User Interface (UI)

The Streamlit UI allows users to interact with _Porter_. We will create a sidebar where users can adjust the model settings (model version, temperature, max tokens) and view a logo. The main chat interface will display user queries and model responses.

* **Session State** : Used to store model settings and user messages.
* **Sidebar** : Enables users to select models and adjust parameters.

``` # Streamlit UI for chatst.title("Porter - Your Personal AI Assistant")# Initialize session state for storing messages and settingsif "messages" not in st.session_state: st.session_state.messages = []if "model" not in st.session_state: st.session_state.model = "llama3.1" # Default modelif "temperature" not in st.session_state: st.session_state.temperature = 0.0 # Default temperatureif "max_tokens" not in st.session_state: st.session_state.max_tokens = 500 # Default token limit# Sidebar for uploading documents and adjusting settingswith st.sidebar: logo_path = "/mnt/e/Virtual Agent/Streamlit/montashi_logo.png" st.image(logo_path, caption="AI Enterprise", use_column_width=True) st.subheader("Inference Settings") st.session_state.model = st.selectbox("Model", ["llama3.1", "llama3.2:latest"], index=0) st.session_state.temperature = st.slider("Temperature", min_value=0.0, max_value=1.0, value=0.0, step=0.05) st.session_state.max_tokens = st.slider("Max Tokens", min_value=100, max_value=5000, value=500, step=100) ```

### Step 4: Initializing the Language Model and Memory

The `initialize_chat` a function is responsible for loading the chatbot settings and memory:

* **get_llm** : Initializes the LLaMA model using user-selected settings (model, temperature, max tokens).
* **SafeFileChatMessageHistory** : A custom memory class that loads/saves chat history in a file, ensuring persistence across sessions.
* **get_chat_prompt_template** : Defines the structure of the chatbot responses using a prompt template.
* **create_chain** : Connects the language model and memory, creating a pipeline for conversations.

```python @st.cache_resource(show_spinner=False)def initialize_chat(): def get_llm(): llm = ChatOllama( model=st.session_state.model, temperature=st.session_state.temperature, max_tokens=st.session_state.max_tokens, ) return llm def get_chat_prompt_template(): return ChatPromptTemplate( input_variables=["content", "messages"], messages=[ SystemMessagePromptTemplate.from_template( """ You're a Personal Assistant, and your name is Porter. Give a short answer when you have a question. Answers will be max 50 words and concise, but full sentences. """ ), MessagesPlaceholder(variable_name="messages"), HumanMessagePromptTemplate.from_template("{content}"), ], ) class SafeFileChatMessageHistory(FileChatMessageHistory): @property def messages(self): file_path = Path(self.file_path) if not file_path.exists() or file_path.stat().st_size == 0: file_path.write_text('[]', encoding=self.encoding) return [] try: items = json.loads(file_path.read_text(encoding=self.encoding)) messages = messages_from_dict(items) return messages except json.JSONDecodeError: return [] def add_message(self, message): messages = messages_to_dict(self.messages) messages.append(messages_to_dict([message])[0]) self.file_path.write_text( json.dumps(messages, ensure_ascii=self.ensure_ascii), encoding=self.encoding ) def get_memory(): return ConversationBufferMemory( memory_key="messages", chat_memory=SafeFileChatMessageHistory(file_path="memory.json"), return_messages=True, input_key="content", ) def create_chain(llm, prompt): return LLMChain(llm=llm, prompt=prompt, memory=get_memory()) llm = get_llm() prompt = get_chat_prompt_template() chain = create_chain(llm, prompt) return chain# Load the chain when the app starts, only onceif "chain" not in st.session_state: st.session_state.chain = initialize_chat() ```

### Step 5: Handling User Inputs and Model Responses

In the main part of the app, we handle user inputs via the chat box, and send them to the model. The model generates a response based on the input and memory, and the response time is recorded and displayed.

```json # Display previous messagesfor idx, message in enumerate(st.session_state.messages): with st.chat_message(message["role"]): st.markdown(message["content"]) st.markdown(message.get("response_time", ""))if prompt := st.chat_input("Ask Porter a question"): st.session_state.messages.append({"role": "user", "content": prompt}) with st.chat_message("user"): st.markdown(prompt) with st.chat_message("assistant"): start_time = time.time() with st.spinner("Porter is thinking..."): response = st.session_state.chain.run(prompt) end_time = time.time() response_time = end_time - start_time response_time_str = f"Response time: {response_time:.2f} seconds" st.markdown(response) st.markdown(f"_{response_time_str}_") st.session_state.messages.append({"role": "assistant", "content": response, "response_time": response_time_str}) ```
