# Proximal SFT: SFT Supercharged By RL Is Here

## Deep dive and learn about Proximal SFT, a new algorithm that combines SFT with PPO, leading to improved post-training performance of LLMs compared to conventional SFT.

Supervised fine-tuning (SFT) is the backbone of [post-training](<https://arxiv.org/abs/2503.06072>) LLMs today.

Most post-training pipelines begin with SFT, which helps pre-trained LLMs to get better at domain-specific tasks.

Following SFT, LLMs are [aligned](<https://arxiv.org/abs/2203.02155>) with human values ([RLHF](<https://levelup.gitconnected.com/reinforcement-learning-from-human-feedback-rlhf-doesnt-need-to-be-complex-anymore-7ce6c4ddc8e6>)) or [trained to reason better](<https://arxiv.org/abs/2501.12948>), using [PPO](<https://arxiv.org/abs/1707.06347>) or [GRPO](<https://arxiv.org/abs/2402.03300>).

Although post-training with SFT is straightforward and more efficient compared to RL, LLMs trained using it tend to have [poor generalization](<https://arxiv.org/abs/2501.17161>) capabilities (i.e., they [memorize](<https://en.wikipedia.org/wiki/Overfitting>) the training dataset).

Supervised fine-tuned models also show [diminished exploration capabilities](<https://arxiv.org/abs/2410.23123>) when further post-trained with RL.

To fix these issues in SFT, researchers have borrowed inspiration from RL algorithms and recently introduced [Proximal Supervised Fine-Tuning (PSFT)](<https://arxiv.org/abs/2508.17784>).

This algorithm supercharges SFT by stabilizing the optimization it brings to the model parameters. This leads to better generalization capabilities in an LLM while leaving room for [further exploration](<https://arxiv.org/abs/2505.22617>) and improvement in subsequent RL post-training stages.

Here is a story where we deep dive into how Proximal Supervised Fine-Tuning (PSFT) combines SFT and PPO to create an objective that leads to improved post-training performance of LLMs compared to conventional SFT.

## But First, How Does Supervised Fine-Tuning Work?

Supervised Fine-tuning (SFT) is most commonly the first step when post-training an LLM.

Previous research has shown that LLMs trained with [SFT do not generalise well](<https://arxiv.org/abs/2501.17161>). This means that they can overfit to the training dataset and memorize it to a large extent.

This overfitting results from the large updates to the model parameters in each SFT step, especially when the distributions of the SFT training data and an LLM’s pre-training data differ.

Therefore, SFT-trained models may perform well in domain-specific tasks but tend to [lose their general capabilities](<https://arxiv.org/abs/2507.00432>).

It has also been shown that SFT-trained models can lose their capability to explore and further improve with subsequent RL training.

This phenomenon is called [**Entropy collapse**](<https://arxiv.org/abs/2505.22617>), where the LLM’s uncertainty in token selection (‘action’ in RL terms) rapidly decreases to near zero during training. This generates very predictable responses from the LLM rather than diverse ones.

To understand how SFT works better, let’s deep dive into the mathematics behind it.

## The Mathematics Of Supervised Fine-Tuning

Let’s understand language modeling using a Markov Decision Process (MDP).

If you’re new to this term, [Markov Decision Process](<https://en.wikipedia.org/wiki/Markov_decision_process>), or MDP, is a mathematical framework that is used to model sequential decision-making problems and make optimal decisions when outcomes are uncertain.

In problems modeled by the MDP, the future state depends only on the current state and the chosen action, and not on the sequence of events that preceded it. This is called the [Markov property](<https://en.wikipedia.org/wiki/Markov_property>).

Markov Decision Process (Image from author’s book titled ‘[AI In 100 Images](<https://bamaniaashish.gumroad.com/l/visual_ai>)’)

An MDP is defined using:

* **State space**(`S`): A set of all possible states that an agent can be in.
* **Action space** (`A`): A set of all possible actions or moves the agent can take.
* **Transition probability** (`P(s'|s, a)`): The likelihood of moving from state `s` to `s'` when the agent takes an action `a`. It describes how the environment evolves when the agent takes an action in a given state.

For the MDP of [autoregressive](<https://en.wikipedia.org/wiki/Autoregressive_model>) language modeling in LLMs:

* The state `s(t)` at timestep `t` is the current context, i.e., the input query `x` plus all tokens generated so far (`y(<t)`).
All states, up to the final timestep (when the LLM stops generating tokens), form the **state space**.
* The action `a(t)` at timestep `t` is the next token `y(t)` chosen by the LLM.
All actions (generated tokens) up to the final timestep are a part of the **action space** determined by an LLM’s vocabulary.
* When action `a(t)` is taken in the state `s(t)`, the **Transition probability** is `1`, since the chosen action/ token is simply added to the sequence, making the state evolve from `(x, y < t​)` to `(x, y ≤ t​)` in a [deterministic](<https://en.wikipedia.org/wiki/Deterministic_system>) way.

The LLM’s probability distribution over the following actions/ generated tokens is represented by `π(θ)​` and called the [**Policy**](<https://en.wikipedia.org/wiki/Reinforcement_learning#Policy>), which is [stochastic](<https://en.wikipedia.org/wiki/Stochastic>) in nature.

For a query `x` (with `m` tokens), the model generates an output `y` (with `n` tokens).

## How Does SFT Relate To Reinforcement Learning?

Let’s learn a bit about some RL algorithms that come next in the post-training pipeline.

There are three main classes of RL algorithms for solving MDPs:

1. [Value-based methods](<https://gibberblot.github.io/rl-notes/single-agent/value-based.html#>): These methods learn the [value function](<https://spinningup.openai.com/en/latest/spinningup/rl_intro.html?highlight=value+function#value-functions>) and indirectly derive the policy using it. For example, [Q-learning](<https://en.wikipedia.org/wiki/Q-learning>).
2. [Policy gradient methods](<https://en.wikipedia.org/wiki/Policy_gradient_method>): These methods learn the policy directly without relying on a value function. For example, [REINFORCE](<https://en.wikipedia.org/wiki/Policy_gradient_method#REINFORCE>).
3. Hybrid methods: These combine both of the above. Examples include [Actor-Critic (AC) algorithms](<https://en.wikipedia.org/wiki/Actor-critic_algorithm>) such as [TRPO](<https://arxiv.org/abs/1502.05477>) and [PPO](<https://arxiv.org/abs/1707.06347>).

AC algorithms have two components:

* An ‘Actor’**(** the policy-based component) that determines which actions to take according to a policy function.
* A ‘Critic’ (the value-based component) that evaluates how good the actions are, according to a value function.

We will discuss specific AC algorithms in more detail soon. Let’s first understand Policy gradient methods in view of language modeling.

For a given LLM policy `π(θ)`, we sample trajectories from it, or in simple words, record the sequences of states, actions, and rewards that it generates.

With RL training using Policy gradient, the LLM policy is optimized using the following objective:

The advantage function is the difference between the Q function given an action taken in a particular state, and the Value function given a state.

If for an action, `Â(t)​ > 0`, this action is better than expected, and RL training increases its probability under the policy, and vice versa.

_Can you notice how the Policy gradient objective is similar to the SFT loss?_

**SFT is a special case of Policy Gradient** , but with two simplifications:

1. Instead of sampling trajectories from the current policy, we sample from a fixed training dataset `D`.
2. The Advantage is fixed to `1` or `Â(t) = 1`. This means that the ground-truth action from the dataset is always considered “good”.

## From Policy Gradient Methods To PPO

Policy gradient (PG) methods directly update the parameters of the LLM policy based on sampled actions and their advantages.

In conventional PG methods, such as [REINFORCE](<https://en.wikipedia.org/wiki/Policy_gradient_method#REINFORCE>), if an update is too large, the new policy can drift very far away from the old one. This can lead to instability during training.

To fix this, [Trust Region Policy Optimization (TRPO)](<https://arxiv.org/abs/1502.05477>), a type of Actor-Critic algorithm, was introduced in 2015.

This algorithm uses a surrogate/ approximate objective, based on the trajectories from the old policy `π(θ)(old)`.

Since the new policy `π(θ)` is different, TRPO uses [importance sampling](<https://en.wikipedia.org/wiki/Importance_sampling>) to reweight actions taken under the old policy `π(θ)(old)` so that they reflect what the new policy `π(θ)` would do.

The surrogate objective ([Conservative policy iteration](<https://people.eecs.berkeley.edu/~pabbeel/cs287-fa09/readings/KakadeLangford-icml2002.pdf>)) objective for TRPO maximised with gradient ascent during RL training, where `r(t)(θ)` is the importance sampling ratio.

In TRPO, the policy updates during training are constrained by a [trust region](<https://en.wikipedia.org/wiki/Trust_region>)**** defined using the [KL divergence](<https://en.wikipedia.org/wiki/Kullback%E2%80%93Leibler_divergence>) between the new policy `π(θ)`​ and the old policy `π(θ)(old)`​.

This ensures that the updates in each step are stable and do not change the policy too much in one step.

Press enter or click to view image in full size

In TRPO, the surrogate objective is maximized subject to a constraint on the size of the policy update using the KL divergence between the new policy `π(θ)`​ and the old policy `π(θ)(old).`​

Although effective, TRPO is a computationally heavy algorithm and is difficult to optimize in practice.

It was fixed in 2017 with the introduction of [Proximal Policy Optimization](<https://arxiv.org/abs/1707.06347>), developed at OpenAI.

This algorithm [clips](<https://en.wikipedia.org/wiki/Clamp_\(function\)>) the surrogate objective by penalizing policy updates that move `r(t)(θ)` (the importance sampling ratio), too far from `1`.

This helps prevent too large of updates in the policy during training, acting as a soft trust region (unlike a hard trust region defined by a KL constraint in TRPO), while being computationally efficient.

Clipped surrogate objective maximized in PPO, where `r(t)(θ)` is the importance sampling ratio, and ϵ is usually a small value (e.g., 0.2). In both TRPO and PPO, the approximations of the advantage `Â(t)​ `are calculated using [Generalized Advantage Estimation (GAE)](<https://arxiv.org/abs/1506.02438>)**.**

## Supercharging SFT With PPO

We previously learned how SFT is a special case of the Policy gradient objective with two changes.

If we simply bring these changes to the PPO objective, i.e., set the Advantage to `1` (`Â(t) = 1`) and sample from a dataset instead of an LLM policy, we reach the **Proximal Supervised Fine-Tuning (PSFT) objective** , as follows:

The original SFT loss might cause the model parameters to swing too aggressively and overfit to the training dataset labels.

PSFT fixes this by comparing the new policy with the old and keeping the updates small. This preserves the model’s general prior capabilities while still getting better at the fine-tuning task.

## How Good Is PSFT?

Experiments performed on [Qwen2.5-7B-Instruct](<https://huggingface.co/Qwen/Qwen2.5-7B-Instruct>) and [Llama3.1-8B-Instruct](<https://huggingface.co/meta-llama/Llama-3.1-8B-Instruct>) to improve their general capabilities through math reasoning show that PSFT produces a smoother entropy curve compared to SFT.

PSFT prevents entropy collapse over epochs and encourages exploration by maintaining diversity in the tokens an LLM learns from.
