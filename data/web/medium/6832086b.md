## Overview

> Have you ever attempted to generate a unique image that’s not available anywhere else?

We are lucky to live in the AI era. Artificial intelligence has advanced rapidly and become more accessible nowadays. Most open-sourced models available are well-trained with a decent amount of data from extensive categories so we can generate many images of different categories.

What if the model has never learned the specific subject we want to generate? For example, I want to generate an image of the cake I just made this morning. Although the model can generate myriad types of cake images, the model has no idea how to come out with an image of the cake I just made.

Although training from scratch is nearly impossible for individuals, incorporating a new subject into the model can be a breeze thanks to the evolving model fine-tuning techniques. Stable Diffusion, as the latest trending generation model since 2022, opens a brand-new era for image generation.

In this article, I would like to share the step-by-step guidelines on how to fine-tune the Stable Diffusion model using the modern technique LoRA. The entire exercise is conducted on the Kaggle notebook so everyone can do this exercise without concerns about having the proper device.

Before we jump into the implementation, let's quickly go through the concept of Stable Diffusion and the fine-tuning technique LoRA. If you are already familiar with the knowledge behind it, feel free to jump to the implementation section.

### Stable Diffusion

Press enter or click to view image in full size

Figure 1. Reverse diffusion in Stable Diffusion. Source: Image by author.

Stable Diffusion is a generative AI model that can produce photorealistic images from texts and images. The diffusion models do the magic on the latent space rather than the image space, which makes image generation accessible to the public owing to the lower computation power required. One can even generate a non-existent image over a coffee break on a CPU machine.

There are many online stable diffusion platforms for the general public and developers such as HuggingFace¹ and Stable Diffusion Online². We can generate images without machine learning knowledge.

### LoRA (Low Rank Adaption)

Press enter or click to view image in full size

Figure 2. Stable Diffusion Network. Source: [original paper](<https://arxiv.org/abs/2112.10752>)

LoRA is a fine-tuning approach adding additional weights to the cross-attention layers in the stable diffusion network. The cross-attention layers are represented by the yellow block in Figure 2. The cross-attention layers fuse the intermediate information of the image `ZT` and text `τθ`. Adding weight to the cross-attention layer extends the correlation of text-prompt and image. This is how LoRA introduces new knowledge to the stable diffusion model.

The amended weight is decomposed into smaller (low-rank) matrices. The smaller matrices carry fewer parameters and are stored separately. This is why the LoRA weight file is in a manageable size but has to be used in conjunction with the underly Stable Diffusion model.

The weight size of LoRA is normally between 2 to 200 MB. It is an advantage of sharing and managing the models. Instead of sharing the model as a whole in a few GB, sharing the LoRA weight in a much smaller size is more efficient.

## Experiment

In this exercise, I would like to introduce the [Crayon Shin-Chan](<https://en.wikipedia.org/wiki/Crayon_Shin-chan>) figurine to the model. Let’s go through the steps in the following sections.

### Step 1: Data Collection

Press enter or click to view image in full size

Figure 3. Training samples. Source: image by author.

Firstly, we need to collect a few images of the subject. In this exercise, we collect 25 photos of the Crayon Shin-Chan figurine as our training data. Some samples can be found in Figure 3. Below are the recommended tips I follow for data collection:

1. Standardize the image size: for example, 512x512.
2. High image quality: the pictures are taken in 12M resolution.
3. Keep the subject at the center of the image.

Besides, it is also important to cover as much diversity as possible in the training set so that the model learns the general features such as the eyes, hairstyle, and body figure of the character. In other words, we want the model to learn what is Crayon Shin-Chan figurine rather than that in a specific dressing style (e.g. red t-shirt and yellow shorts) and posture (e.g. standing).

I have done the experiments across training sizes of 5, 15, 25. Although there are only 10 image differences between each round, the degree of model generalization is improved significantly.

### Step 2: Baseline Evaluation

```python from diffusers import AutoPipelineForText2Imagepipeline = AutoPipelineForText2Image.from_pretrained("runwayml/stable-diffusion-v1-5", torch_dtype=torch.float16).to("cuda")prompt = "A crayon shin-chan figurine."image = pipeline(prompt, num_inference_steps=100).images[0]image.save("baseline.png") ```

Before rolling up the sleeve and starting the training, we would like to check if the pre-trained model already knows the specific figurine we want to fine-tune with using the above Python script

1. The `AutoPipelineForText2Image` class is applied to load the Stable Diffusion pre-trained model [stable-diffusion-v1–5](<https://huggingface.co/runwayml/stable-diffusion-v1-5>).
2. Next, we set the text prompt as `A crayon shin-chan figurine`. I keep the text prompt concise so the text information is straightforward to the model.
3. The prompt and number of inferences are passed to the instance of `AutoPipelineForText2Image` and conduct the generation process.

### Step 3: Fine-tuning

Figure 5. Crayons. Source: Image by [WOKANDAPIX](<https://pixabay.com/users/wokandapix-614097/?utm_source=link-attribution&utm_medium=referral&utm_campaign=image&utm_content=879973>) from [Pixabay](<https://pixabay.com//?utm_source=link-attribution&utm_medium=referral&utm_campaign=image&utm_content=879973>).

**Define a new identifier**

In addition to collecting a few images for training, we also need to choose a new name for the subject. Whenever the new name shows up in the text prompt, the revised model understands that it refers to the new subject and generates the content accordingly.

Why do we need a new name? Isn’t the original name `Crayon Shin-Chan` more representative? The idea behind this is we need a unique name that doesn’t mix up with other existing names already trained. In our case, the word `crayon` inside implies the potential connections with the crayon we used for painting. The generated images may include crayon-relevant content if the associated text prompt contains `Crayon Shin-Chan`.

It is recommended to use a randomized name as the new identifier. I choose the name `aawxbc` for this exercise, which hardly overlaps with any existing names. One can have any other distinctive name for the new subject.

**Training**

Press enter or click to view image in full size

Figure 6. Class images generated by the model. Source: Image by author.

In the Kaggle notebook, apart from the workspace: `/kaggle/working/`, another directory commonly used is `/kaggle/input/`, where we store the inputs to the work such as checkpoints and training images. Below is the complete training command based on the script `train_dreambooth_lora.py`.

```bash !accelerate config default!mkdir /kaggle/working/figurine!accelerate launch --mixed_precision="fp16" /kaggle/working/diffusers/examples/dreambooth/train_dreambooth_lora.py \ --mixed_precision="fp16" \ --pretrained_model_name_or_path="runwayml/stable-diffusion-v1-5" \ --instance_data_dir="/kaggle/input/aawxbc" \ --instance_prompt="a photo of aawxbc figurine" \ --class_data_dir="/kaggle/working/figurine" \ --class_prompt="a photo of figurine" \ --with_prior_preservation \ --prior_loss_weight=1.0 \ --use_8bit_adam \ --lr_scheduler="constant" \ --gradient_checkpointing \ --enable_xformers_memory_efficient_attention \ --num_train_epochs=50 \ --output_dir="/kaggle/working/dreambooth-lora" ```

Let’s go through some key configurations:

* mixed_precision [optional]: choose the precision supported on the platform. Options are fp32, fp16, and bf16.
* class_prompt [optional]: The prompt and folder storing the class data. In this experiment, the class name is `figurine` as we want the diffusion model to learn a new type of figurine.
* class_data_dir [optional]: the directory storing the model-generated class image. In our case, the model generates the general figurine images and saves them under this directory.
* instance_prompt [mandatory]: we define a text prompt for the new subject. The format is {new name} {class name} such as `aawxbc figurine`, `uvhhhl cat`, …, etc.
* instance_data_dir [mandatory]: the directory storing the training samples. In this exercise, we upload the 25 samples mentioned previously to this directory.
* num_train_epochs [optional]: Number of epochs for training.

By following the above steps including data collection, installing the library, and completing the training, we can now find the LoRA weight `pytorch_lora_weights.safetensors` saved in the directory defined by `output_dir`. The size of the weight file is 3.2 MB, which is fairly manageable.

### Step 4: Inference — Generating New Image

```python from diffusers import AutoPipelineForText2Imagepipeline = AutoPipelineForText2Image.from_pretrained("runwayml/stable-diffusion-v1-5", torch_dtype=torch.float16).to("cuda")pipeline.load_lora_weights("/kaggle/working/dreambooth-lora", weight_name="pytorch_lora_weights.safetensors")prompt = "A photo of aawxbc figurine."image = pipeline(prompt, num_inference_steps=180).images[0]image.save("aawxbc.png") ```

After successfully exporting the LoRA weight, we can move to the last and most exciting part: generating the new image. Note that the LoRA weight doesn’t work independently, so we need to load both the original stable diffusion and LoRA weight files.

In the Python script, on top of the steps we used in the baseline evaluation, we have an additional step to load the LoRA model using the function `.load_lora_weights()` by passing in the directory and the name of the LoRA weight file.
