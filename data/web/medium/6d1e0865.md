[Large Language Models](<https://github.com/SalvatoreRa/tutorial/blob/main/artificial%20intelligence/FAQ.md#:~:text=What%20is%20a%20Large%20Language%20Model%20\(LLM\)%3F>) have shown incredible capabilities. The largest companies have been busy researching the best recipe for increasing the capabilities of these models. The first idea was to increase the number of parameters (the so-called [scaling law](<https://github.com/SalvatoreRa/tutorial/blob/main/artificial%20intelligence/FAQ.md#:~:text=What%20does%20it%20mean%20emergent%20properties%3F%20what%20it%20is%20the%20scaling%20law%3F>)). Later we realized the importance of data, the greater the amount of tokens used to train a model the better its final capabilities. Finally, it was realized that it is not only the quantity of data that impacts performance but especially the quality of data. In fact, the data must be not only of quality but also diverse. One example, data diversity is important for the emergence of one of the most desired behaviors in a model, in-context learning.

The definition of data quality and diversity is generic. So a question arises:

> what properties of data impart the best general performance?

For example, code is also included in the pre-training data but the model is not explicitly trained to produce code. On the one hand, the ability to understand code is desired in an LLM, on the other hand, the code differs in terms of structure and textural characteristics from high-quality web datasets. This may then impact the LLM's training.

Modern models are trained with more and more code. In recent years, the amount of code in the pretraining dataset has increased proportionally. Some studies suggest that inserting code is beneficial for training. Indeed, it seems that adding code gives benefits in terms of scalability and mathematical reasoning

However, a systematic study is lacking so some open questions remain:

* What is the impact of code on pretraining?
* what should be the proportion?
* how does scaling impact?
* what does code impact?

this newly published study tries to answer these questions.

The authors in this study test the models under two conditions:

* **continued pretraining**. A model that is started by a pre-trained model and then trained with a fixed number of tokens.
* **cooldown**. at the end of training, high-quality datasets are added with a change in learning rate for a short period. This approach shows that it can boost a model’s abilities.

The authors use a text dataset that is quality (SlimPajama) and clean it of code and code-adjacent data sources (such as StackExchange) so they can then decide how much code to add.

As a code dataset, they use:

* Web-based code data. StarCoder is a cleaned dataset of data obtained by scraping GitHub.
* Markdown data, data in markdown, and HTML formats that relate to code.
* Quality synthetic code that refers to programming problems in Python (and that has been verified).
* Code adjacent data including GitHub commits, jupyter notebooks, StackExchange threads

They then decide to evaluate the trained model for world knowledge, natural language reasoning, and code performance. They also use an LLM as a judge to judge the models trained with the various code compositions.

The authors use 470M and 2.8B parameters decoder-only auto-regressive [Transformer](<https://en.wikipedia.org/wiki/Transformer_\(deep_learning_architecture\)>) as models.

The authors begin by comparing different model initializations: Text LM (model trained with text only), balanced LLM (model trained with 50% text and 50% code), Balance-initialized Text LM (first a balanced system and then text only), and Code-initialized Text LM (pretrained with code (80% code data and 20% markup-style code data) and then after text). All these models are initialized with 400B total tokens, only the composition changes.

The results show that:

* models that are pretrained with code have better performance in natural language tasks. This is especially true for reasoning tasks. For knowledge tasks, a balanced composition is better.
* In code generation tasks obviously code is important to be in the pre-training, with balanced models doing better.
* An interesting finding is that balanced models generate better text (according to an LLM judge)

The authors also study what happens with scaling the 470M model to 2.8B parameters:

* Scaling the model clearly improves results in natural language reasoning and knowledge tasks.
* They also confirm the same trends seen earlier. The two models behave in the same way

At this point, the authors ask what is the optimal amount of code to maximize performance on non-code tasks. They then train six models with increasing percentages of code in pretraining (0%, 25%, 50%, 75%, 90%, and 100%).

* Increasing the percentage of code increases performance on reasoning tasks; there is, however, an inverse relationship with knowledge tasks. Not including code strongly impacts reasoning performance. For the reasoning is also important to add some text, a fully-trained model on code has the worst performance.
* In addition, code is important for a model that must then conduct coding tasks

The authors want to better understand the role of code in training. They focus on trying to understand the exact effects of different properties of code data. Secondarily, in understanding whether quality code (high-quality synthetic code) is more important than generic code. For these reasons, they separate markup-style data (programming language that is in markup format) and code adjacent data from code. The results show that high-quality synthetic code data, even in small proportions and budgets, has a strong impact. This is especially true for coding tasks, but also partly true for natural language reasoning tasks.

Similarly, adding code in the cooldown has a positive effect. For the authors, the positive effect of cooldown is reduced if no code is added (especially in reasoning tasks). The cooldown (even without code) allows a boost in generative qualities for an LLM as a judge.

Press enter or click to view image in full size

The authors summarize their results:

* Including code has a positive effect on model performance. For them, the best recipe balances pretraining (a phase in which code and text are in an equal proportion and then trained on text) followed by cooldown that includes high-quality text.
* For a model to perform best on code, a balanced model seems best, followed by a cooldown.

Press enter or click to view image in full size

This study is interesting because it shows the impact of code in pretrained. it is interesting precisely because of its systematic nature and to provide some answers to the impact of code for both reasoning and generative tasks. previous studies showed that code by its defined and rigorous nature gives an advantage for generation. Major companies that train LLM have over the years purchased services that collect code (Google bought Kaggle and Microsoft bought GitHub). This means they have a competitive advantage in producing models.

In any case, more systematics are needed to be able to understand what are the best recipes for training LLM. We have understood the importance of scale but there are many open questions about what elements impact training.
