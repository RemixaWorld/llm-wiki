## 1\. Introduction

### 1.1 Background

The journey of transformers began in 2017 when Vaswani and his team published the paper “[Attention is All You Need](<https://arxiv.org/abs/1706.03762>).” This model emerged to solve the issues faced by older models like recurrent neural networks (RNNs) and long short-term memory networks (LSTMs), which struggled with long-range dependencies in sequential data.

Since then, several key milestones have marked the evolution of transformers. In 2018, Google introduced [BERT (Bidirectional Encoder Representations from Transformers)](<https://arxiv.org/abs/1810.04805>), revolutionizing natural language processing (NLP) tasks by introducing a pre-training and fine-tuning approach. The following year, OpenAI released [GPT-2](<https://openai.com/index/better-language-models/>), demonstrating the power of transformers in generating coherent and contextually relevant text. This was further advanced in 2020 with the launch of [GPT-3](<https://arxiv.org/abs/2005.14165>), boasting 175 billion parameters and showing significant improvements in language understanding and generation. Around the same time, Vision Transformers (ViTs) extended the transformer model to image processing, achieving state-of-the-art results in image classification.

Transformers are fundamentally different from older models like RNNs and LSTMs. Unlike RNNs and LSTMs, which process sequences one step at a time, transformers use a self-attention mechanism to handle entire sequences simultaneously. This ability to process in parallel makes transformers more efficient and better at capturing long-range dependencies. Moreover, transformers don’t struggle as much with the vanishing gradient problem, allowing for deeper architectures and improved performance on complex tasks.

### 1.2 What is a Transformer?

A transformer is a deep learning model designed to handle sequential data, making it especially powerful for natural language processing tasks. What makes transformers unique is their self-attention mechanism. This mechanism allows the model to determine the importance of different sequence parts, no matter where they are positioned. This capability to focus on the most relevant parts of an input sequence has led to significant advancements in various NLP tasks.

Transformers have a wide range of applications. In natural language processing, they are used for tasks like language translation, text summarization, sentiment analysis, question-answering systems, and chatbots. In image processing, Vision Transformers (ViTs) have revolutionized image classification and object detection. Beyond these fields, transformers are also applied to predicting protein folding, time-series forecasting, and building recommender systems.

Think of a transformer as a well-organized team working on a project. Each team member (or part of the model) has a specific role and knows how to focus on the most important aspects of the task at hand, regardless of when they were introduced in the project timeline. This coordination and ability to prioritize information make transformers exceptionally effective in processing and understanding complex data sequences.

## 2\. Architecture of Transformers

### 2.1 Overall Structure

![Transformer Architecture with Encoder (left) and Decoder (right) — Image by Author](https://miro.medium.com/v2/resize:fit:666/0*Q9ajuHWl67X5w9B4.jpeg)

Imagine you’re organizing a large event with hundreds of guests. You can’t possibly keep track of everyone’s needs and preferences all at once, so you break it down into smaller tasks and delegate them to different teams. This is similar to how a transformer model processes information. It’s built around an Encoder-Decoder framework designed to efficiently handle sequential data and capture long-range dependencies through a clever mechanism called self-attention.

The encoder and decoder are the two main components of a transformer. Think of the encoder as a team that processes all the guest information and organizes it into meaningful categories. It takes the input sequence and creates encodings that highlight which parts of the input are relevant to each other. On the other hand, the decoder acts like the team responsible for generating the final event plan, using the information from the encoder and attending to previously made decisions to produce the output sequence step by step.

If you look at the transformer’s architecture diagram at the beginning of this section, you’ll see a stack of encoders on the left and a stack of decoders on the right. Each encoder and decoder is made up of multiple identical layers, typically six to twelve. Every encoder layer has two main sub-layers: a **multi-head self-attention mechanism** and a **position-wise fully connected feed-forward network**. Each of these sub-layers has residual connections and layer normalization, which help stabilize and speed up the training process. The decoder layers are similar but have an extra multi-head attention sub-layer that allows them to attend to the encoder’s output.

### 2.2 Encoder

![Encoder Architecture — Image by Author](https://miro.medium.com/v2/resize:fit:358/1*_DCdp-kUCi8ukvCk7D24Qw.jpeg)

The encoder consists of several key components that work together to process the input sequence and generate meaningful representations. These include Multi-Head Attention, Feed-Forward Neural Network, and Layer Normalization with Residual Connections.

At the heart of the encoder is the multi-head attention mechanism. Imagine it as a group of experts, each focusing on a different aspect of the input sequence. Instead of having a single expert, multi-head attention splits the input into multiple smaller attention heads. Each head independently projects the input into query, key, and value vectors, calculates attention scores, and combines the results. The outputs from all heads are then concatenated and transformed to produce the final result. This process allows the model to capture various relationships within the input sequence.

Following the multi-head attention mechanism, the encoder includes a position-wise fully connected feed-forward neural network. This part is like an analyst who takes the information provided by the experts and refines it. It consists of two linear transformations with a ReLU activation function in between, operating independently on each position in the sequence. This helps transform the attendee information into a richer representation, adding non-linearity to the model and allowing it to learn complex patterns.

Each sub-layer within the encoder, both the multi-head attention and the feed-forward network, is followed by a residual connection and layer normalization. Residual connections, also known as skip connections, help mitigate the vanishing gradient problem by allowing gradients to flow directly through the network. This is done by adding the input of the sub-layer to its output. Layer normalization then stabilizes and speeds up the training process by normalizing the output of the sub-layer, ensuring that the distribution of values remains consistent.

### 2.3 Decoder

![Decoder Architecture — Image by Author](https://miro.medium.com/v2/resize:fit:371/1*jgMThicWI8aeE9I11MhoHQ.jpeg)

The decoder in a transformer shares several similarities with the encoder but also introduces some key differences to facilitate its role in generating output sequences. Just like the encoder, the decoder is made up of multiple identical layers. Each of these layers contains sub-layers that include multi-head attention and a feed-forward neural network. Both the encoder and decoder use residual connections and layer normalization to enhance learning and maintain stable gradients.

However, there are crucial differences between the encoder and decoder. The primary difference is the addition of a third sub-layer in each decoder layer, known as the masked multi-head attention mechanism. This extra sub-layer allows the decoder to focus on previously generated tokens while maintaining the autoregressive property of sequence generation. Additionally, the decoder’s multi-head attention mechanisms are designed to handle two sources of information: the input sequence (from the encoder) and the partially generated output sequence.

The masked multi-head attention mechanism is unique to the decoder. It operates similarly to the standard multi-head attention used in the encoder but includes an additional masking step. This masking ensures that the decoder cannot look ahead to future tokens in the sequence during training, preserving the autoregressive nature of the model. During the attention calculation, a mask is applied to the input sequence, setting the attention scores of future tokens to negative infinity. This effectively prevents the model from considering future tokens when generating the current token, ensuring that each token is generated based only on the past tokens and the encoded input sequence.

The decoder’s multi-head attention sub-layers, including the masked multi-head attention and the standard multi-head attention (which attends to the encoder’s output), work together to generate the output sequence. The masked multi-head attention allows the model to generate tokens one at a time, while the standard multi-head attention integrates information from the encoder, enabling the decoder to produce coherent and contextually accurate outputs.

### 2.4 Attention Mechanism

![Multi-Head Attention Architecture — Image by Author](https://miro.medium.com/v2/resize:fit:700/0*-LwNyiX-TdBoZCtj.jpeg)

The attention mechanism is the core innovation that makes transformers so effective. It allows the model to dynamically focus on different parts of the input sequence, enabling it to capture dependencies regardless of their distance in the sequence. There are two primary types of attention mechanisms in transformers: self-attention and cross-attention.

Self-attention, also known as intra-attention, is used within the encoder and decoder layers. In self-attention, each element in the sequence attends to all other elements, including itself. This means that every word in a sentence, for example, can consider every other word to build a richer representation of the context.

Cross-attention, on the other hand, is used in the decoder when it attends to the output of the encoder. This mechanism allows the decoder to focus on relevant parts of the input sequence while generating each token in the output sequence. In cross-attention, each element of the decoder’s sequence attends to the elements of the encoder’s output, integrating information from the input sequence to produce the final output.

The core computation in both self-attention and cross-attention is the scaled dot-product attention. Here’s how it works:

First, each input element is projected into three vectors: Query (Q), Key (K), and Value (V). The query vector is then dotted with the key vectors to compute attention scores, which indicate how much focus to place on different parts of the input. These dot products are scaled by the square root of the dimension of the key vectors to stabilize the gradients during training. The scaled scores are then passed through a softmax function to convert them into probabilities, emphasizing the most relevant parts of the input. Finally, the value vectors are weighted by these attention scores and summed to produce the final output for each input element.

Imagine you’re trying to understand a story with multiple characters and events happening simultaneously. Self-attention helps you consider each character and event about every other character and event, giving you a comprehensive understanding of the story. Cross-attention, on the other hand, would be like focusing on specific details of the story to ensure you’re incorporating the most relevant information into your understanding as you progress.

## 3\. The Math Behind Transformers

Let’s now dive into the mathematical processes involved, starting from the input and following each step to the final output.

### 3.1 Attention Mechanism

As we said before, the attention mechanism decides how much focus each word in a sequence should give to every other word. This starts with the calculation of attention scores. For each word in the input, we need to determine how much attention it should pay to every other word. This is done using three matrices: **Query (Q), Key (K)** , and **Value (V)**.

Each word in the input sequence is first projected into these three matrices using learned weight matrices **W_Q** , **W_K** , and **W_V** :

![Q, K, and V matrics calculations — Image by Author](https://miro.medium.com/v2/resize:fit:171/1*WXoMlVcptPe5SWY-rzXQFQ.png)

Here, **X** is the input sequence matrix, where each row corresponds to a word embedding. For example, if you have a sentence with 10 words and each word is represented by a 512-dimensional vector, **X** will be a 10x512 matrix. The multiplication of the input sequence **X** by these weight matrices projects each word embedding into three new spaces (query, key, and value), setting the stage for the attention mechanism.

Next, we calculate the attention scores by taking the dot product of the query vector **Q** with the key vectors **K**. This measures the similarity between the query and key vectors:

![Attention Scores Formula — Image by Author](https://miro.medium.com/v2/resize:fit:389/1*lAyuP_IXQat047TBOu0L2A.png)

This operation produces a matrix of raw attention scores, where each element represents the attention score between a pair of words. In particular:

* **Q** is the **query** matrix obtained from **XW_Q**. Each row in **Q** represents a query vector for each word in the sequence.
* **K** is the **Key** matrix obtained from **XW_K** ​. Each row in **K** represents a key vector for each word in the sequence.
* **K^T** is the transpose of the **Key** matrix. Transposing **K** swaps its rows and columns, allowing us to compute the dot product with **Q**.

Therefore, the result of the formula above is a matrix of attention scores. Each element in this matrix represents the attention score between a pair of words in the input sequence, indicating how much focus one word should give to another

However, as the dimension of the vectors increases, the dot product values can become very large, leading to small gradients during the softmax operation. To counteract this, we scale the attention scores by the square root of the dimension of the key vectors **d_k** :

![Scaled Attention Scores Formula — Image by Author](https://miro.medium.com/v2/resize:fit:344/1*KwJhBBuRW4ioFfJdWNdpdw.png)

So, if each key vector has 64 dimensions, then the square root of the dimension of the key vectors​​ would be sqrt{64} ​=8. This scaling factor helps stabilize the gradients and makes the softmax function more effective.

Then, we apply the softmax function to these scaled scores. The softmax function converts the scores into probabilities, ensuring they sum to 1, which highlights the most important relationships between the words:

![Attention Weights Formula — Image by Author](https://miro.medium.com/v2/resize:fit:603/1*rRJ89M5LYrjZjknp4HyUyA.png)

The softmax function normalizes the scaled scores. This is more clear when we plot the softmax function:

![Softmax Plot — Image by Author](https://miro.medium.com/v2/resize:fit:420/0*Y7624dKrAeOPB9CV.png)

Where the function for softmax is:

![Softmax Function — Image by Author](https://miro.medium.com/v2/resize:fit:259/0*S06C95fuaRQIHJXG.png)

Softmax exponentiates each scaled score and divides it by the sum of the exponentiated scores, converting the scores into probabilities. This emphasizes the most relevant words while ensuring all probabilities sum to 1.

The final step in the attention mechanism is to use these attention weights to compute a weighted sum of the value vectors **V** :

![Attention Output Formula — Image by Author](https://miro.medium.com/v2/resize:fit:503/1*dJ69tm79FvgAj730fJxRwg.png)

Here, **Attention Weights** is the matrix of attention weights obtained from the softmax function. Each element represents the probability of attending to a particular word. **V** is the Value matrix obtained from **XW_V** ​. Each row in **V** represents a value vector for each word in the sequence.

The multiplication of the attention weights by **V** results in a weighted sum of the value vectors. This output is a new representation for each word, incorporating the context of the entire input sequence.

### 3.2 Multi-Head Attention

Instead of using a single set of attention scores, transformers use multi-head attention. This means that the input sequence is split into multiple smaller parts, each part processed independently through the attention mechanism described above. Each of these parts is called a head.

For each head, we have different weight matrices **W_Q^i** , **W_K^i** , and **W_V^i**. After processing each head, we concatenate their outputs and project them back into a single vector space using another set of weights **W_O** :

![Multi-Head Attention Formula — Image by Author](https://miro.medium.com/v2/resize:fit:700/1*32IXrXMKuX5TTrZ1gVtDsg.png)

This multi-head attention allows the model to focus on different parts of the sequence simultaneously, capturing a wide range of dependencies.

### 3.3 Position-Wise Feed-Forward Network

After the multi-head attention, each word’s representation is further processed by a position-wise feed-forward network. This network operates independently on each word’s representation and applies the same transformation to each one.

The feed-forward network consists of two linear transformations with a ReLU activation function in between:

![Feed-Forward Network Formula — Image by Author](https://miro.medium.com/v2/resize:fit:557/1*Wzl1USeZPNer0MvhrvyxRQ.png)

Here, **x** is the input from the attention mechanism, **W_1** and **W_2** are weight matrices, and **b_1** and **b_2** are biases. The ReLU activation function introduces non-linearity, allowing the network to learn more complex patterns.

![ReLU plot — Image by Author](https://miro.medium.com/v2/resize:fit:415/0*aQqPbraphZEq95d7.png)

Indeed, ReLU is like a gatekeeper that passes positive values unchanged but blocks negatives, turning them to zero.

### 3.4 Layer Normalization and Residual Connections

To stabilize and speed up training, each sub-layer in the encoder (multi-head attention and feed-forward network) is followed by a residual connection and layer normalization.

Residual connections help mitigate the vanishing gradient problem and allow for the training of deeper networks. The basic idea is to add the input of the sub-layer to its output. Mathematically, it can be expressed as:

![Layer Normalization Formula — Image by Author](https://miro.medium.com/v2/resize:fit:610/1*9-A_GxmDYIKfHn-EfFET1A.png)

Here:

* **x** is the input to the sub-layer (which could be either the multi-head attention mechanism or the feed-forward network).
* **Sublayer(x)** is the output from the sub-layer after processing **x**. This could be the output from either the multi-head attention mechanism or the feed-forward network.
* **x + Sublayer(x)** is the residual connection, which adds the original input **x** to the sub-layer’s output. This addition helps the gradients flow more easily through the network, preventing them from becoming too small (vanishing gradient problem) or too large (exploding gradient problem).

By adding the input **x** to the output of the sub-layer, the model ensures that the original information can be preserved, even if the sub-layer transformation introduces significant changes.

Layer normalization is applied to the combined output of the residual connection to standardize the values. This process helps stabilize the training by ensuring that the inputs to each layer have a consistent distribution of values. The formula for layer normalization is:

![Generic Layer Normalization Formula — Image by Author](https://miro.medium.com/v2/resize:fit:447/1*HaRds2LoixdZKoMg_Vsfzw.png)

Let’s break down the terms:

* **z** is the input to the layer normalization, which in this context is **x + Sublayer(x)**.
* **mu** is the mean of the input **z** , calculated as:

![Mean Formula — Image by Author](https://miro.medium.com/v2/resize:fit:200/1*vL8SadcbPEBObr0KmPVk0Q.png)

where **N** is the number of elements in **z** (the dimension of the hidden layer).

* **sigma** is the standard deviation of the input **z** , calculated as:

![Standard Deviation Formula — Image by Author](https://miro.medium.com/v2/resize:fit:294/1*f9FlvJZ44TogUYZanwk47g.png)
* **epsilon** is a small constant added for numerical stability to prevent division by zero.
* **gamma** is a learned scaling parameter that allows the model to adjust the normalized values.
* **beta** is a learned shifting parameter that allows the model to adjust the normalized values.

The normalized output ensures that each sub-layer receives input with a mean of 0 and a variance of 1, which helps maintain stable gradients and improves the efficiency and effectiveness of the training process.

### 3.5 Positional Encoding

Transformers process all tokens in a sequence simultaneously, rather than one by one like recurrent models (RNNs). While this parallel processing is efficient, it means that the model doesn’t inherently understand the order of the tokens. To give the model a sense of position, we use positional encoding. This encoding adds information about the position of each token in the sequence to its embedding.

Positional encodings are mathematical representations that are added to the input embeddings before the encoder and decoder stacks process them. The most common approach uses sine and cosine functions of different frequencies to generate these encodings. The formulae for the positional encodings are:

For even indices **2i** :

![Positional Encoding for indices 2i (top) and 2i+1 (bottom) — Image by Author](https://miro.medium.com/v2/resize:fit:548/1*TvTHriwN3dumZQmNLxCV5w.png)

Here:

* **pos** is the position of the token in the sequence (starting from 0).
* **i** is the dimension index of the positional encoding.
* **d_model** is the dimension of the model’s input embeddings, which is the same as the dimension of the positional encodings.

These sine and cosine functions ensure that each position in the sequence has a unique encoding. Additionally, the use of different frequencies allows the model to distinguish between different positions in a way that is both smooth and continuous. This is important for the model to effectively learn the relative positions of the tokens.

Let’s look at an example with a smaller dimension. Suppose **d_model** ​ is 4. We want to calculate the positional encoding for the first few positions (pos = 0, 1, 2).

For **pos** =0:

![Positional encoding for indices (0,0), (0,1), (0,2), and (0,3) — Image by Author](https://miro.medium.com/v2/resize:fit:618/1*am-cK6B_k4be7januTuKpA.png)

For **pos** =1:

![Positional encoding for indices (1,0), (1,1), (1,2), and (1,3) — Image by Author](https://miro.medium.com/v2/resize:fit:551/1*yzyL3_T02Xp06PaWp7oV8Q.png)

For **pos** =2:

![Positional encoding for indices (2,0), (2,1), (2,2), and (2,3) — Image by Author](https://miro.medium.com/v2/resize:fit:551/1*dSFaQSKm2HFq4My5FYEwfw.png)

These encodings are added to the original input embeddings to give each token a sense of its position in the sequence. By using sine and cosine functions with different frequencies, the positional encodings ensure that each position has a unique representation, and the encodings vary smoothly, which helps the model learn to distinguish between different positions effectively.

The use of sine and cosine functions provides several benefits:

1. **Periodicity** : Sine and cosine functions are periodic, meaning they repeat their values over regular intervals. This periodic nature is useful for capturing the relative positions of tokens in sequences of different lengths.
2. **Unique Encodings** : Each position (**pos**) has a unique encoding because the frequencies are different for each dimension. This ensures that the model can distinguish between different positions.
3. **Smoothness** : The smooth, continuous variation of sine and cosine functions allows the model to learn patterns in the positional encodings more easily.

### 3.6 Encoder

The encoder transforms the input sequence into a set of encoded representations. First, the input sequence **X** is embedded into a high-dimensional space. This embedding captures the meaning of each word in the sequence. To help the model understand the position of each word in the sequence, we add positional encodings to these embeddings, resulting in **X_pos** :

![Combined sequence Formula — Image by Author](https://miro.medium.com/v2/resize:fit:254/1*1slsh1K_Ox1XLYLMXrjr0w.png)

Next, this combined sequence is fed through the multi-head attention mechanism. This allows the model to focus on different parts of the sequence simultaneously, generating an output **Z_attn** :

![Multi Head Attention Output — Image by Author](https://miro.medium.com/v2/resize:fit:541/1*bduaKHVZntxr8gJ0TXMebA.png)

We then add the original input **X_pos** back to this output (a process known as a residual connection) and apply layer normalization to stabilize the training. This gives us **Z_add_norm_1** :

![First Layer Normalization — Image by Author](https://miro.medium.com/v2/resize:fit:616/1*3hTRuESzYWb2G_PKz7lh9w.png)

The next step is to pass this result through a position-wise feed-forward network, which applies additional transformations. The output from this network is **Z_ffn** :

![FFN Output — Image by Author](https://miro.medium.com/v2/resize:fit:376/1*jHOCAQcnhipgkp9o03G7mA.png)

We again add the input **Z_add_norm_1** back to this output and apply layer normalization to get **Z_encoder_output** :

![Encoder Output after Second Layer Normalization — Image by Author](https://miro.medium.com/v2/resize:fit:700/1*YQHMrq-nw36vg1tbn70Hng.png)

This final output, **Z_encoder_output** , is the encoded representation of the input sequence, ready to be processed by the decoder.

### 3.7 Decoder

The decoder generates the output sequence by using the encoded input and the previously generated tokens. Here’s the process:

First, the input sequence **Y** (shifted right) is embedded into a high-dimensional space. Let’s focus on what “shifted right” means here.
Imagine you have an input sequence of tokens for the decoder:

![Input Sequence — Image by Author](https://miro.medium.com/v2/resize:fit:341/1*EAkEJtWq8NbWyVA68txPsg.png)

When we “shift right,” we insert a special start token (usually `<SOS>` for “start of sequence”) at the beginning and drop the last token. The resulting sequence looks like this:

![Input Sequence shifted right — Image by Author](https://miro.medium.com/v2/resize:fit:624/1*u0TrhzKpGeIHiIXYW7JfBw.png)

This shifted sequence is then used as the input for the decoder during training. The purpose of this is to ensure that the decoder can only use the tokens that have already been generated (or predicted) and not any future tokens, maintaining the autoregressive property of the model.

So, when you read “shifted right”, it means preparing the input sequence so that the model learns to predict each token based on the previously generated tokens and not on the tokens that come after.

Next, we add positional encodings to these embeddings to form **Y_pos** :

![Positional encoding for Decoder inputs — Image by Author](https://miro.medium.com/v2/resize:fit:240/1*qrmpESIshzLW_OTs9IQpHg.png)

This sequence is passed through the masked multi-head attention mechanism, which prevents the model from looking at future tokens in the sequence. The output is **Z_masked_attn** :

![Masked Multi-Head Attention — Image by Author](https://miro.medium.com/v2/resize:fit:700/1*ijF14b4oeOgMyT4gHqfNqQ.png)

### 4.1. Multi-Head Attention

This is the same class that we built in “[The Math Behind Multi-Head Attention in Transformers](</towards-data-science/the-math-behind-multi-head-attention-in-transformers-c26cba15f625>)”, therefore, we will go over it briefly.

**Class Initialization
** The `MultiHeadAttention` class initializes with several parameters:

```python class MultiHeadAttention: def __init__(self, num_hiddens, num_heads, dropout=0.0, bias=False): self.num_heads = num_heads self.num_hiddens = num_hiddens self.d_k = self.d_v = num_hiddens // num_heads self.W_q = np.random.rand(num_hiddens, num_hiddens) self.W_k = np.random.rand(num_hiddens, num_hiddens) self.W_v = np.random.rand(num_hiddens, num_hiddens) self.W_o = np.random.rand(num_hiddens, num_hiddens) if bias: self.b_q = np.random.rand(num_hiddens) self.b_k = np.random.rand(num_hiddens) self.b_v = np.random.rand(num_hiddens) self.b_o = np.random.rand(num_hiddens) else: self.b_q = self.b_k = self.b_v = self.b_o = np.zeros(num_hiddens) ```

Here, `num_heads` specifies the number of attention heads, while `num_hiddens` indicates the dimension of the hidden layers. The `d_k` and `d_v` are the dimensions of the query, key, and value vectors, calculated as `num_hiddens // num_heads`. The weight matrices `W_q`, `W_k`, `W_v`, and `W_o` are used for the query, key, value, and output projections, respectively. Optional bias vectors `b_q`, `b_k`, `b_v`, and `b_o` can be added if `bias` is set to `True`.

**Transposing QKV
** These methods handle the reshaping and transposing of Q, K, and V matrices for multi-head attention:

```python def transpose_qkv(self, X): X = X.reshape(X.shape[0], X.shape[1], self.num_heads, -1) X = X.transpose(0, 2, 1, 3) return X.reshape(-1, X.shape[2], X.shape[3])def transpose_output(self, X): X = X.reshape(-1, self.num_heads, X.shape[1], X.shape[2]) X = X.transpose(0, 2, 1, 3) return X.reshape(X.shape[0], X.shape[1], -1) ```

The `transpose_qkv` method splits and transposes the input matrix for multiple heads. Conversely, `transpose_output` reverts the transposition and concatenates the outputs from different heads back into a single matrix.

**Scaled Dot-Product Attention
** Calculates the attention scores and applies the softmax function:

```python def scaled_dot_product_attention(self, Q, K, V, valid_lens): d_k = Q.shape[-1] scores = np.matmul(Q, K.transpose(0, 2, 1)) / np.sqrt(d_k) if valid_lens is not None: mask = np.arange(scores.shape[-1]) < valid_lens[:, None] scores = np.where(mask[:, None, :], scores, -np.inf) attention_weights = np.exp(scores - np.max(scores, axis=-1, keepdims=True)) attention_weights /= attention_weights.sum(axis=-1, keepdims=True) return np.matmul(attention_weights, V) ```

In this method, `Q`, `K`, and `V` represent the Query, Key, and Value matrices. The `valid_lens` parameter is an optional mask for the attention scores. The method computes the scaled dot-product attention by normalizing the scores and applying the softmax function to ensure they sum to one.

**Forward Pass
** Handles the forward pass through the multi-head attention mechanism:

```python def forward(self, queries, keys, values, valid_lens): queries = self.transpose_qkv(np.dot(queries, self.W_q) + self.b_q) keys = self.transpose_qkv(np.dot(keys, self.W_k) + self.b_k) values = self.transpose_qkv(np.dot(values, self.W_v) + self.b_v) if valid_lens is not None: valid_lens = np.repeat(valid_lens, self.num_heads, axis=0) output = self.scaled_dot_product_attention(queries, keys, values, valid_lens) output_concat = self.transpose_output(output) return np.dot(output_concat, self.W_o) + self.b_o ```

In the `forward` method, the queries, keys, and values are projected using their respective weight matrices and biases. The `transpose_qkv` method is then applied to prepare the inputs for multi-head attention. If `valid_lens` is provided, it is repeated to match the number of heads. The `scaled_dot_product_attention` the method computes the attention scores, and the outputs are concatenated and projected using the output weight matrix and bias.

### 4.2. Positional Encoding

Positional encodings provide the model with information about the position of tokens in the sequence. Since the transformer model does not have recurrence or convolution to infer the sequence order, positional encodings are essential to give the model some notion of token positions. Here’s how the `positional_encoding` function works:

```python def positional_encoding(seq_len, d_model): pos = np.arange(seq_len)[:, np.newaxis] i = np.arange(d_model)[np.newaxis, :] angle_rates = 1 / np.power(10000, (2 * (i // 2)) / np.float32(d_model)) pos_encoding = pos * angle_rates pos_encoding[:, 0::2] = np.sin(pos_encoding[:, 0::2]) pos_encoding[:, 1::2] = np.cos(pos_encoding[:, 1::2]) return pos_encoding ```

The function `positional_encoding` is designed to generate positional encodings for the tokens in a sequence, providing the transformer with positional information. Let's break down this function step by step:

``` pos = np.arange(seq_len)[:, np.newaxis]i = np.arange(d_model)[np.newaxis, :] ```

* `pos` is an array of shape `(seq_len, 1)` where each row corresponds to the position of a token in the sequence.
* `i` is an array of shape `(1, d_model)` where each column corresponds to the dimension of the model.

``` angle_rates = 1 / np.power(10000, (2 * (i // 2)) / np.float32(d_model)) ```

This array defines the rate of change for the positional encodings. The division of `i` by 2 ensures that the angle rates alternate, which is necessary for the sine and cosine functions used later.

``` pos_encoding = pos * angle_rates ```

The positional encodings are computed by multiplying the position `pos` with the `angle_rates`. This generates a matrix where each element corresponds to the encoding for a specific position and dimension.

``` pos_encoding[:, 0::2] = np.sin(pos_encoding[:, 0::2])pos_encoding[:, 1::2] = np.cos(pos_encoding[:, 1::2]) ```

This step alternates the application of sine and cosine functions to the positional encodings. The sine function is applied to even indices (`0::2`), and the cosine function is applied to odd indices (`1::2`).

The result is a matrix of shape `(seq_len, d_model)` where each row corresponds to the positional encoding of a token in the sequence. These encodings are then added to the token embeddings to provide the model with information about the position of each token.

### 4.3. Feed-Forward Network

The `FeedForward` class implements a simple feed-forward neural network with ReLU activation. This type of network is used within the transformer architecture to introduce non-linearity and enable the model to learn complex representations. Here’s a detailed explanation of the class:

```python class FeedForward: def __init__(self, d_model, d_ff): self.W1 = np.random.randn(d_model, d_ff) * np.sqrt(2.0 / (d_model + d_ff)) self.b1 = np.zeros(d_ff) self.W2 = np.random.randn(d_ff, d_model) * np.sqrt(2.0 / (d_ff + d_model)) self.b2 = np.zeros(d_model) ```

In the initialization method `__init__`, two weight matrices `W1` and `W2` are created along with two bias vectors `b1` and `b2`.

* `W1` is a weight matrix of shape `(d_model, d_ff)`, where `d_model` is the input dimension, and `d_ff` is the hidden layer dimension. It is initialized with random values scaled by the square root of the inverse of the sum of the input and output dimensions.
* `b1` is a bias vector for the first linear transformation, initialized to zeros with a length of `d_ff`.
* `W2` is a weight matrix of shape `(d_ff, d_model)`, where `d_ff` is the hidden layer dimension, and `d_model` is the output dimension. It is also initialized with random values scaled similarly.
* `b2` is a bias vector for the second linear transformation, initialized to zeros with a length of `d_model`.

```python def __call__(self, x): return self.forward(x) def forward(self, x): return np.dot(np.maximum(0, np.dot(x, self.W1) + self.b1), self.W2) + self.b2 ```

The `__call__` method is defined to make instances of `FeedForward` callable, which internally calls the `forward` method.

The `forward` method implements the forward pass through the feed-forward network:

* The input `x` is first linearly transformed using the weight matrix `W1` and bias `b1`.
* A ReLU activation function is applied to the result of the linear transformation. ReLU (Rectified Linear Unit) is defined as `np.maximum(0, x)`, which zeroes out any negative values and keeps positive values unchanged.
* The result of the ReLU activation is then linearly transformed using the second weight matrix `W2` and bias `b2`.

The final output is the result of this second linear transformation, which is returned by the `forward` method.

### 4.4. Encoder Layer

The `EncoderLayer` class combines the multi-head attention mechanism and a feed-forward neural network, forming one of the core building blocks of the transformer model. This combination allows the model to focus on different parts of the input sequence while transforming the focused features through a feed-forward network.

```python class EncoderLayer: def __init__(self, d_model, num_heads, d_ff, dropout=0.0, bias=False): self.d_model = d_model self.num_heads = num_heads self.d_ff = d_ff self.multi_head_attention = MultiHeadAttention(d_model, num_heads, dropout, bias) self.feed_forward = FeedForward(d_model, d_ff) ```

In the `__init__` method, the class is initialized with several key parameters:

* `d_model` specifies the dimension of the model.
* `num_heads` indicates the number of attention heads in the multi-head attention mechanism.
* `d_ff` defines the number of hidden units in the feed-forward network.
* `dropout` and `bias` are optional parameters for adding dropout regularization and bias terms.

Within this initialization, two main components are set up:

* `multi_head_attention` is an instance of the `MultiHeadAttention` class, which allows the layer to focus on different parts of the input sequence.
* `feed_forward` is an instance of the `FeedForward` class, which applies non-linear transformations to the focused features.

The class also includes the following methods:

```python def __call__(self, x, mask=None): return self.forward(x, mask) def forward(self, x, mask=None): attn_output = self.multi_head_attention.forward(x, x, x, mask) output = self.feed_forward(attn_output) return output ```

The `__call__` method makes instances of `EncoderLayer` callable, internally delegating to the `forward` method.

In the `forward` method:

* `attn_output` is computed by applying the multi-head attention mechanism to the input `x`. This involves projecting the input into queries, keys, and values, performing scaled dot-product attention, and then concatenating and projecting the results.
* The result of the attention mechanism, `attn_output`, is then passed through the feed-forward network. This network involves two linear transformations with a ReLU activation in between, adding non-linearity and transforming the attended features.

Think of the `EncoderLayer` as a sophisticated filter. First, it looks at the entire sequence and decides which parts are important (multi-head attention). Then, it processes these important parts to make them more meaningful and useful for the model (feed-forward network). This layer is repeated multiple times in the transformer model to build a deep understanding of the input sequence.

### 4.5. Decoder Layer

The `DecoderLayer` class includes two multi-head attention mechanisms and a feed-forward network, enabling it to perform self-attention on the decoder's input and cross-attention on the encoder's output.

```python class DecoderLayer: def __init__(self, d_model, num_heads, d_ff, dropout=0.0, bias=False): self.d_model = d_model self.num_heads = num_heads self.d_ff = d_ff self.multi_head_attention_1 = MultiHeadAttention(d_model, num_heads, dropout, bias) self.multi_head_attention_2 = MultiHeadAttention(d_model, num_heads, dropout, bias) self.feed_forward = FeedForward(d_model, d_ff) ```

In the `__init__` method, the `DecoderLayer` class initializes with several parameters:

* `d_model` specifies the dimension of the model.
* `num_heads` indicates the number of attention heads in the multi-head attention mechanism.
* `d_ff` defines the number of hidden units in the feed-forward network.
* `dropout` and `bias` are optional parameters for dropout regularization and bias terms.

Within the initialization, three main components are instantiated:

* `multi_head_attention_1` is an instance of the `MultiHeadAttention` class, used for self-attention on the decoder's input.
* `multi_head_attention_2` is another instance of the `MultiHeadAttention` class, used for cross-attention, where the decoder attends to the encoder's output.
* `feed_forward` is an instance of the `FeedForward` class, which applies non-linear transformations to the attended features.

```python def __call__(self, x, enc_output, mask=None): return self.forward(x, enc_output, mask) def forward(self, x, enc_output, mask=None): attn_output1 = self.multi_head_attention_1.forward(x, x, x, mask) attn_output2 = self.multi_head_attention_2.forward(attn_output1, enc_output, enc_output, mask) output = self.feed_forward(attn_output2) return output ```

The `__call__` method makes instances of `DecoderLayer` callable, internally delegating to the `forward` method.

In the `forward` method:

* `attn_output1` is computed by applying the first multi-head attention mechanism (`multi_head_attention_1`) to the input `x`. This self-attention mechanism allows the decoder to focus on different parts of its input sequence.
* `attn_output2` is computed by applying the second multi-head attention mechanism (`multi_head_attention_2`) to `attn_output1` and `enc_output`. This cross-attention mechanism enables the decoder to attend to the encoder's output, integrating information from the encoded input sequence.
* The result of the cross-attention mechanism, `attn_output2`, is then passed through the `feed_forward` network. This network involves two linear transformations with a ReLU activation in between, adding non-linearity and transforming the attended features.

Think of the `DecoderLayer` as a multitasking assistant. First, it looks at the current state of the task and determines what parts need attention (self-attention). Then, it checks in with the initial instructions or guidelines (cross-attention with the encoder's output) to ensure it’s on the right track. Finally, it processes all this information to produce a coherent and contextually accurate output, ready for the next step in the sequence.

### 4.6. Transformer Model

The `Transformer` class integrates the encoder and decoder layers to create a comprehensive model for tasks such as sequence-to-sequence learning. This class is designed to handle the entire flow of data through the encoder and decoder, transforming inputs into desired outputs while capturing intricate dependencies in the data. Let's dive into the details of the `Transformer` class:

```python class Transformer: def __init__(self, d_model, num_heads, d_ff, num_layers, input_vocab_size, target_vocab_size, max_seq_len): self.d_model = d_model self.num_heads = num_heads self.d_ff = d_ff self.num_layers = num_layers self.input_vocab_size = input_vocab_size self.target_vocab_size = target_vocab_size self.max_seq_len = max_seq_len self.encoder_layers = [EncoderLayer(d_model, num_heads, d_ff) for _ in range(num_layers)] self.decoder_layers = [DecoderLayer(d_model, num_heads, d_ff) for _ in range(num_layers)] self.embedding = np.random.randn(input_vocab_size, d_model) * np.sqrt(2.0 / (input_vocab_size + d_model)) self.pos_encoding = positional_encoding(max_seq_len, d_model) self.output_layer = np.random.randn(d_model, target_vocab_size) * np.sqrt(2.0 / (d_model + target_vocab_size)) ```

In the `__init__` method, the `Transformer` class initializes several key components:

* `d_model`, `num_heads`, `d_ff`, and `num_layers` specify the model's dimensions, the number of attention heads, the number of hidden units in the feed-forward network, and the number of encoder and decoder layers, respectively.
* `input_vocab_size` and `target_vocab_size` define the sizes of the input and target vocabularies.
* `max_seq_len` specifies the maximum sequence length for positional encoding.

The model comprises:

* `encoder_layers`: A list of `EncoderLayer` instances, each representing a layer in the encoder.
* `decoder_layers`: A list of `DecoderLayer` instances, each representing a layer in the decoder.
* `embedding`: An embedding matrix for the input vocabulary, initialized with random values.
* `pos_encoding`: Positional encodings generated by the `positional_encoding` function.
* `output_layer`: A weight matrix for projecting the decoder output to the target vocabulary size.

```python def __call__(self, input_seq, target_seq, mask=None): return self.forward(input_seq, target_seq, mask) def forward(self, input_seq, target_seq, mask=None): enc_output = self.encode(input_seq, mask) dec_output = self.decode(target_seq, enc_output, mask) output = np.dot(dec_output, self.output_layer) return output ```

The `__call__` method makes instances of the `Transformer` class callable, delegating to the `forward` method internally.

In the `forward` method:

* `enc_output` is obtained by passing the input sequence through the encoder.
* `dec_output` is obtained by passing the target sequence and the encoder output through the decoder.
* The final `output` is computed by projecting the decoder output using the `output_layer`.

```python def encode(self, input_seq, mask=None): seq_len = input_seq.shape[1] x = self.embedding[input_seq] + self.pos_encoding[:seq_len, :] for layer in self.encoder_layers: x = layer(x, mask) return x ```

The `encode` method handles the encoding process:

* It combines the input sequence embeddings with positional encodings.
* It passes the result through each layer of the encoder, sequentially applying the transformations defined in each `EncoderLayer`.

```python def decode(self, target_seq, enc_output, mask=None): seq_len = target_seq.shape[1] x = self.embedding[target_seq] + self.pos_encoding[:seq_len, :] for layer in self.decoder_layers: x = layer(x, enc_output, mask) return x ```

The `decode` method manages the decoding process:

* It combines the target sequence embeddings with positional encodings.
* It passes the result and the encoder output through each layer of the decoder, sequentially applying the transformations defined in each `DecoderLayer`.
