## General OCR Theory (GOT)

The [General OCR Theory (GOT)](<https://arxiv.org/pdf/2409.01704v1>) aims to introduce OCR-2.0, an advanced solution that tackles these problems through a unified and versatile approach.

In OCR-1.0, switching between models for diverse tasks such as detecting plain text, mathematical formulas, tables, or even geometric shapes was both inconvenient and resource-heavy.

Compared to OCR 1.0, OCR-2.0 offers greater versatility, lower maintenance costs, and the ability to support various output formats, improving efficiency in handling complex scenarios and high-resolution images.

### Stage 1: Pre-training the Vision Encoder

The first stage focuses on pre-training GOT’s vision encoder. The encoder plays a crucial role in converting input images into tokens, which are then passed to the decoder for recognition and processing.

The architecture of the encoder is based on [VitDet](<https://arxiv.org/pdf/2203.16527>) (base version with about 80M parameters), a model designed to handle high-resolution images with reduced computational costs. [The corresponding code](<https://github.com/Ucas-HaoranWei/GOT-OCR2.0/blob/d76b7e0e121979c08d3465a7c200b505fe3b4366/GOT-OCR-2.0-master/GOT/model/vision_encoder/vary_b.py#L87C1-L193C17>) is shown below.

```python class ImageEncoderViT(nn.Module): def __init__( self, img_size: int = 1024, patch_size: int = 16, in_chans: int = 3, embed_dim: int = 768, depth: int = 12, num_heads: int = 12, mlp_ratio: float = 4.0, out_chans: int = 256, qkv_bias: bool = True, norm_layer: Type[nn.Module] = nn.LayerNorm, act_layer: Type[nn.Module] = nn.GELU, use_abs_pos: bool = True, use_rel_pos: bool = False, rel_pos_zero_init: bool = True, window_size: int = 0, global_attn_indexes: Tuple[int, ...] = (), ) -> None: """ Args: img_size (int): Input image size. patch_size (int): Patch size. in_chans (int): Number of input image channels. embed_dim (int): Patch embedding dimension. depth (int): Depth of ViT. num_heads (int): Number of attention heads in each ViT block. mlp_ratio (float): Ratio of mlp hidden dim to embedding dim. qkv_bias (bool): If True, add a learnable bias to query, key, value. norm_layer (nn.Module): Normalization layer. act_layer (nn.Module): Activation layer. use_abs_pos (bool): If True, use absolute positional embeddings. use_rel_pos (bool): If True, add relative positional embeddings to the attention map. rel_pos_zero_init (bool): If True, zero initialize relative positional parameters. window_size (int): Window size for window attention blocks. global_attn_indexes (list): Indexes for blocks using global attention. """ super().__init__() self.img_size = img_size self.patch_embed = PatchEmbed( kernel_size=(patch_size, patch_size), stride=(patch_size, patch_size), in_chans=in_chans, embed_dim=embed_dim, ) self.pos_embed: Optional[nn.Parameter] = None if use_abs_pos: # Initialize absolute positional embedding with pretrain image size. self.pos_embed = nn.Parameter( torch.zeros(1, img_size // patch_size, img_size // patch_size, embed_dim) ) self.blocks = nn.ModuleList() for i in range(depth): block = Block( dim=embed_dim, num_heads=num_heads, mlp_ratio=mlp_ratio, qkv_bias=qkv_bias, norm_layer=norm_layer, act_layer=act_layer, use_rel_pos=use_rel_pos, rel_pos_zero_init=rel_pos_zero_init, window_size=window_size if i not in global_attn_indexes else 0, input_size=(img_size // patch_size, img_size // patch_size), ) self.blocks.append(block) self.neck = nn.Sequential( nn.Conv2d( embed_dim, out_chans, kernel_size=1, bias=False, ), LayerNorm2d(out_chans), nn.Conv2d( out_chans, out_chans, kernel_size=3, padding=1, bias=False, ), LayerNorm2d(out_chans), ) self.net_2 = nn.Conv2d(256, 512, kernel_size=3, stride=2, padding=1, bias=False) self.net_3 = nn.Conv2d(512, 1024, kernel_size=3, stride=2, padding=1, bias=False) def forward(self, x: torch.Tensor) -> torch.Tensor: x = self.patch_embed(x) if self.pos_embed is not None: x = x + self.pos_embed for blk in self.blocks: x = blk(x) x = self.neck(x.permute(0, 3, 1, 2)) x = self.net_2(x) x = self.net_3(x) return x ```

The pre-processing involves resizing all input images to a 1024×1024 resolution, ensuring compatibility with the model’s architecture. The encoder then compresses the images into a set of 256×1024 tokens, significantly reducing the input size and making the model more efficient in processing large images, such as PDFs.

At this stage, the encoder is trained using scene text and document-level data to handle various input types, such as natural images and scanned PDFs.

The training data includes 5 million image-text pairs from scene text datasets and document OCR datasets, covering English, Chinese, and handwritten text recognition, as shown in Figure 8.

### Stage 2: Joint-training the Encoder and Decoder

After pre-training, GOT transitions to the joint-training phase, where the vision encoder is connected to a powerful decoder. The decoder is based on Qwen-0.5B, a language model with 500 million parameters. A linear embedding layer serves as the bridge between the vision encoder and the decoder, mapping the 256 image tokens from the encoder to a 1024×1024-dimensional input suitable for the decoder. The decoder supports up to 8,000 tokens, enabling it to handle long-context scenarios, such as multi-page documents or complex charts.

In this stage, GOT is trained on more complex and diverse OCR tasks. These include recognizing mathematical formulas, molecular structures, sheet music, and geometric shapes.

To effectively inject OCR-2.0 knowledge into GOT, rather than using the previously mentioned plain OCR data, several synthesis methods and data engines have been carefully explored at this stage, as shown in Figure 9.

Figure 9: We use six rendering tools to run data engines to make the GOT work well on diverse OCR tasks. We utilize the LATEX for tables, Mathpix-markdown-it for math/molecular formulas, Tikz for simple geometric shapes, Verovio for sheet music, and Matplotlib/Pyecharts for charts, respectively. Source: [GOT](<https://arxiv.org/pdf/2409.01704v1>).

For example, when processing mathematical formulas, the GOT model converts LaTeX source files into Mathpix Markdown format and renders them as image-text pairs. The model is trained to recognize these complex formats and output them in a structured, readable manner. Similarly, for molecular formulas, the model is trained on datasets like ChEMBL_25 using SMILES notation, enabling it to effectively recognize and process chemical structures.

### Stage 3: Post-training for Enhanced Features

In the final stage, the GOT model undergoes post-training to enhance its practical features for real-world applications. Three key features are added:

* **Fine-grained OCR** : Allows users to specify target regions within an image for selective OCR using bounding boxes or color prompts. It is trained on datasets like RCTW and COCO-Text, providing region-level text annotations.
* **Multi-page OCR** : Enables automatic processing of multiple pages, improving efficiency in handling long documents such as papers and reports by using synthetic multi-page data.
* **Dynamic Resolution Support** : Handles high-resolution images by using a sliding window technique to crop and stitch ultra-large images, ensuring accuracy for tasks like stitched PDFs and large charts.

## DLAFormer

Document Layout Analysis (DLA) is crucial for understanding the physical layout and logical structure of documents, which supports applications like RAG, document summarization, and knowledge extraction.

Traditional methods typically use separate models to address sub-tasks such as table/figure detection, text region detection, logical role classification, and reading order prediction. This fragmentation can lead to inefficiencies and increased complexity.

[DLAFormer](<https://arxiv.org/pdf/2405.11757v1>) is an end-to-end transformer-based approach that integrates all these sub-tasks into a single model, streamlining the process and improving overall performance.

### Problem Definition

The document image inherently comprises diverse regions, encompassing both Text Regions and Non-Text Regions.

* **Text Region** : A semantic unit of written content, consisting of text lines arranged in a natural reading sequence and associated with a logical label, such as paragraph, list item, title, section heading, header, footer, footnote, or caption.
**Non-text Regions** : Typically consist of graphical elements like tables, figures, and mathematical formulas. These regions often have multiple logical relationships, with the reading order relationship being the most prevalent.

Consequently, three distinct types of relationships are defined:

* **Intra-region Relationship** : Groups basic text units, like text lines, into coherent text regions, following a natural reading sequence. For text regions with a single text line, the relationship is self-referential.
* **Inter-region Relationship** : These relationships are created between pairs of regions that have logical connections. For example, an inter-region relationship is formed between adjacent paragraphs or between a table and its associated caption or footnote.
* **Logical Role Relationship** : Various logical role units are defined, including captions, section headings, paragraphs, titles, and more. Each text region is assigned a specific logical role, establishing a relationship between each text line in the region and its corresponding role.

Press enter or click to view image in full size

Figure 16. An example of the problem definition for document layout analysis. Purple arrow: intra-region relationship; green arrow: inter-region relationship; orange arrow: logical role relationship. Best viewed in color. Source: [DLAFormer](<https://arxiv.org/pdf/2405.11757v1>).

By defining these relationships, various DLA sub-tasks — such as text region detection, logical role classification, and reading order prediction — **are treated as relation prediction challenges**. The labels for these tasks are merged into a unified label space, enabling a single model to handle them concurrently.

### Overview

Press enter or click to view image in full size

Figure 17: Overall architecture of the DLAFormer for document layout analysis. Source: [DLAFormer](<https://arxiv.org/pdf/2405.11757v1>).

As shown in Figure 17, DLAFormer uses a transformer-based architecture to handle multiple DLA tasks simultaneously by framing them as relation prediction problems. By unifying these tasks into a single label space, the model enables efficient and cohesive analysis. This approach simplifies the model architecture while improving the scalability and performance of DLA tasks.

The detailed Chacteritics is:

* **Encoder-Decoder Architecture** : DLAFormer employs an encoder-decoder architecture inspired by [DETR](<https://arxiv.org/pdf/2005.12872>). The encoder processes multi-scale features extracted from document images, while the decoder refines these features and predicts the relations between them.
* **Type-wise Queries** : To enhance the physical meaning of content queries, DLAFormer introduces type-wise queries that capture categorical information of diverse page objects. This allows the model to adaptively focus on different regions and tasks.
* **Coarse-to-Fine Strategy** : The model adopts a coarse-to-fine strategy to accurately identify graphical page objects, improving the precision of detection.
* **Unified Relation Prediction** : By consolidating the labels of different relation prediction tasks into a unified label space, DLAFormer uses a unified relation prediction module to handle these tasks concurrently. This approach reduces cascading errors and improves the efficiency of the training process.

## Unifying Image and Text Recognition in One Vision Encoder (UNIT)

### Overview

[UNIT](<https://arxiv.org/pdf/2409.04095v1>) is a unified framework that enables simultaneous image and text recognition in a single model. It builds on the Vision Transformer (ViT) backbone but introduces a lightweight language decoder to enhance text recognition, and a vision decoder to retain the image recognition capability of the model.

Press enter or click to view image in full size

Figure 20: Overview of UNIT Architecture. Source: [UNIT](<https://arxiv.org/pdf/2409.04095v1>).

As indicated in Figure 20, the model processes high-resolution documents and low-resolution images, generating a set of visual tokens. These tokens pass through an input embedding layer, with document tokens fed into the language decoder to predict text sequences, enhancing the model’s text recognition capability. Simultaneously, to preserve the model’s original image encoding ability, the visual tokens from natural images are reconstructed via a lightweight vision decoder, mimicking the output of the teacher model. Additionally, an image captioning task is included alongside the OCR task to further enhance image understanding.

### Training

Press enter or click to view image in full size

Figure 21: Illustration of the UNIT training paradigm. Source: [UNIT](<https://arxiv.org/pdf/2409.04095v1>).

As shown in Figure 21, the two-stage training process — intra-scale pretraining and inter-scale finetuning — is designed to handle different input resolutions and improve scale robustness without increasing computational cost.

* **Intra-Scale Pretraining** : The model processes low-resolution images and high-resolution documents separately to learn basic recognition tasks for both images and texts. The vision decoder reconstructs features from the vision encoder to prevent the loss of image encoding capability, while the language decoder handles the text recognition.
* **Inter-Scale Finetuning** : To improve robustness, the model is fine-tuned using high-resolution images and low-resolution documents. This stage ensures that the model can adapt to varying input scales, an important feature for document analysis where images and texts come in different sizes.

### **Evaluation**

For text recognition tasks (e.g., OCR), compared to models like [Donut and Nougat](<https://ai.gopubby.com/demystifying-pdf-parsing-03-ocr-free-small-model-based-method-c71310988129>), which focus on document-specific OCR tasks, UNIT provides superior text recognition without sacrificing image recognition capabilities. While Donut excels in OCR, it struggles with natural image understanding. UNIT’s design ensures it performs well across both text and image domains, which is critical for tasks like document QA and detailed document analysis, as shown in Figure 22.

### How Do Sub-1B Models Achieve Efficient Multi-Task Integration?

In my opinion, GOT, DLAFormer, and UNIT are able to integrate multiple tasks into a model with less than 1 billion parameters while achieving excellent performance due to five key innovations and optimizations:

1\. **Transformer Flexibility** : Transformers handle sequence data (text, images, layout) efficiently using shared encoder-decoder structures, reducing the need for separate task-specific models and cutting down model size.

2\. **Efficient Parameter Usage** : The self-attention mechanism in Transformers and Vision Transformers (ViTs)**** capture global dependencies without heavy convolutional operations, allowing fewer parameters. DLAFormer and UNIT use techniques like query selection and lightweight decoders to optimize performance without increasing model size.

3\. **Multi-scale Input Handling** : GOT and UNIT employ multi-scale feature extraction, ensuring high-resolution details are preserved, while techniques like Cropped Position Embedding (CPE) maintain model robustness without increasing parameter count.

**4\. Task Complementarity** : Tasks like text recognition and image processing share overlapping features. By leveraging this complementarity, these models generalize well across tasks without increasing complexity.

5\. **Lightweight Components** : UNIT introduces lightweight decoders (such as OPT-125M) for OCR, and DLAFormer employs Deformable Transformers, reducing computational load and keeping the model compact while enhancing task handling.
