## What is Self-Rag?

Self-RAG (Self-Reflective Augmented Retrieval Generation) addresses the limitations of traditional RAG (Retrieval-Augmented Generation) by incorporating a mechanism where a Large Language Model (LLM) reflects on its search and decision-making processes. This framework improves the consistency and performance of LLMs teaching them when to search for information, what to search for, and how to evaluate the retrieved data.

**How Self-RAG Works: A Three-Step Process**

Self-RAG uses “self-reflective tokens” to control the LLM’s actions during inference, allowing it to adapt to specific task requirements. The process consists of three key steps:

1. **Search:** Self-RAG first decides if external information is needed to generate a comprehensive response. If so, it triggers an external search module to retrieve relevant documents.
2. **Generation:** If no search is required, Self-RAG predicts the next part of the response based on internal knowledge, like traditional language models. If a search is needed, Self-RAG evaluates the relevance of the retrieved documents before incorporating them into the response generation process.
3. **Critique:** After generating a response using the retrieved information, Self-RAG critiques its output to ensure accuracy and completeness. This includes evaluating whether the retrieved passages support the response and assessing the overall quality of the answer.

## What is Crawl4AI?

Crawl4AI is an open-source web crawler and data extraction tool that aims to simplify the crawling and extraction process of web page data, making it easier to use large language models (LLM) and AI applications. It also makes it much easier to build intelligent AI agents to collect and analyze information! It’s a must-have item for developers 🔧.

## Key Features

1. Efficient Web Scraping: Extract valuable data from websites and ensure the crawling process is efficient and smooth.
2. LLM-friendly output formats: support JSON, clean HTML, and Markdown formats to ensure easy data integration.
3. Multiple URL support: Multiple URLs can be crawled at the same time to improve data acquisition efficiency.
4. Media tag processing: Replace media tags with ALT tags to ensure the integrity of the text content.
5. Completely free and open source: There is no usage fee, and the code is open for community use and improvement.
6. Custom JavaScript execution: Execute custom JavaScript before crawling to meet complex page processing needs.
7. Chunking strategy: supports multiple chunking strategies based on topics, regular expressions, sentences, etc.
8. Advanced extraction strategies: Provides advanced strategies such as cosine clustering and LLM to ensure the accuracy and relevance of data extraction.
9. CSS selector support: Use CSS selectors to accurately extract specific content from web pages.
10. Instruction/Keyword Optimization: Optimize the data extraction process by passing instructions or keywords.

Define Conditional Edges

* `**route_question**`: Determines whether the question should be routed to a web search or RAG based on the source identified by the question router.
* `**decide_to_generate**`: Decide whether to generate an answer or perform a web search based on document relevance and the web search flag.
* `**grade_generation_v_documents_and_question**`: Evaluates if the generated answer is grounded in the retrieved documents and if it addresses the question effectively.

```python def route_question(state): """ Route question to web search or RAG. Args: state (dict): The current graph state Returns: str: Next node to call """ print("---ROUTE QUESTION---") question = state["question"] print(question) source = question_router.invoke({"question": question}) print(source) print(source['datasource']) if source['datasource'] == 'web_search': print("---ROUTE QUESTION TO WEB SEARCH---") return "websearch" elif source['datasource'] == 'vectorstore': print("---ROUTE QUESTION TO RAG---") return "vectorstore"def decide_to_generate(state): """ Determines whether to generate an answer, or add web search Args: state (dict): The current graph state Returns: str: Binary decision for next node to call """ print("---ASSESS GRADED DOCUMENTS---") question = state["question"] web_search = state["web_search"] filtered_documents = state["documents"] if web_search == "Yes": # All documents have been filtered check_relevance # We will re-generate a new query print("---DECISION: ALL DOCUMENTS ARE NOT RELEVANT TO QUESTION, INCLUDE WEB SEARCH---") return "websearch" else: # We have relevant documents, so generate answer print("---DECISION: GENERATE---") return "generate"def grade_generation_v_documents_and_question(state): """ Determines whether the generation is grounded in the document and answers question. We set up a state machine workflow using the `StateGraph` class from the `langgraph` library. It starts creating a `StateGraph` to manage task flow, with `GraphState` defining the initial structure. Nodes represent tasks: `websearch` performs a search, `retrieve` fetches documents, `grade_documents` assesses relevance, and `generate` produces answers.

The workflow entry point, `route_question`, directs the question to either `websearch` or `retrieve` based on the data source. Edges connect nodes, with `retrieve` leading to `grade_documents`, and `grade_documents` routing to either `websearch` or `generate` based on relevance.

The `generate` node routes to either `websearch` or ends the workflow depending on answer quality. This setup creates a dynamic workflow adjusting based on document relevance and answer quality.

```python from langgraph.graph import END, StateGraphworkflow = StateGraph(GraphState)# Define the nodesworkflow.add_node("websearch", web_search) # web searchworkflow.add_node("retrieve", retrieve) # retrieveworkflow.add_node("grade_documents", grade_documents) # grade documentsworkflow.add_node("generate", generate) # generatae ```

Set the Entry Point and End Point

```json workflow.set_conditional_entry_point( route_question, { "websearch": "websearch", "vectorstore": "retrieve", },)workflow.add_edge("retrieve", "grade_documents")workflow.add_conditional_edges( "grade_documents", decide_to_generate, { "websearch": "websearch", "generate": "generate", },)workflow.add_edge("websearch", "generate")workflow.add_conditional_edges( "generate", grade_generation_v_documents_and_question, { "not supported": "generate", "useful": END, "not useful": "websearch", },) ```

Compile the workflow

``` app = workflow.compile() ```
