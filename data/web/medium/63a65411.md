### StabilityAI and Stable Diffusion — a game changer

You may have heard of this name related to image generation. In fact Stability AI came into the _limelight_ with the release of Stable Diffusion.

Stable Diffusion is an artificial intelligence (AI) model that creates images from text descriptions. You can [read more about it here](<https://blog.stackademic.com/blank-page-to-masterpiece-with-stability-ai-bb3207b6df4a>).

When users started to use the SD and SDXL models the world went in uproar: you can imagine that! To draw or create a picture the only craftsmanship needed is to be able to write an instruction…

Press enter or click to view image in full size

One prompt with many styles — Lora and stable diffusion from [Reddit](<https://preview.redd.it/stable-diffusion-mega-set-up-with-loras-visualized-with-the-v0-axu752t5zlla1.png?auto=webp&s=7813df589259ba520db2ce2e8b9e434cff39e3ba>)

But Stability AI text-to-image models can do much more than simply create images:

* **Generates Images from Text:** Similar to how ChatGPT generates text, Stable Diffusion takes a text prompt as input and creates an image based on its understanding of that prompt and its training data.
* **Open-Source Model:** This means anyone can access and use the underlying code behind Stable Diffusion, allowing for transparency and further development by the community.
* **Image Manipulation:** Beyond creating new images, Stable Diffusion can also modify existing ones. It can replace parts of an image (inpainting) or even extend an image to make it larger (outpainting).
* **Training and Capabilities:** you can modify the output of Stable Diffusion checkpoint models to **align with a particular concept or theme, such as an art style, character, real-life person, or object.** They are called LoRA (Low-Rank Adaptation), small changes applied to the most critical part of Stable Diffusion models. According to the [research in this paper](<https://arxiv.org/abs/2106.09685>), it is sufficient to fine-tune the **cross-attention layers** of the model to achieve good training.

### Stable-Diffusion-Cpp-Python — a revolution

Image generation is really fascinating: it makes you feel like there are no limits to your imagination because you can see the results almost immediately.

Except that if you want to do it on your computer it is not really that _immediately_ … The Hardware specs to run Stable Diffusion are quite demanding:

``` \- An NVIDIA GPU with 6 GB of RAM (though you might be able to make 4 GB work)- SDXL will require even more RAM to generate larger images.- You can make AMD GPUs work, but they require tinkering ```

Pioneer [Georgi Gerganov](<https://github.com/ggerganov>) wrote an amazing library in pure C++ to run LLM in a quantized format so that you can run them also with no GPU, but with a CPU and enough RAM: the library is called[ llama.cpp](<https://github.com/ggerganov/llama.cpp>).

Following his example, other amazing programmers adapted the source code to make it available for the Stable Diffusion models.

Meet @leejet’s `[stable-diffusion.cpp](<https://github.com/leejet/stable-diffusion.cpp>)` library, later ported to Python, the real protagonist of this article. We will use [stable-diffusion-cpp-python](<https://github.com/william-murray1204/stable-diffusion-cpp-python/tree/main>) to generate images with our poor equipped Laptops

### So… what is stable-diffusion-cpp-python?

It is a simple Python binding for @leejet’s `[stable-diffusion.cpp](<https://github.com/leejet/stable-diffusion.cpp>)` library. This package provides:

* Low-level access to C API via `ctypes` interface.
* High-level Python API for stable diffusion image generation.
* you can use it as `text2image`
* you can use it as `image2image`
* you can use it as `upscaler`
* you can use it with Stable Diffusion 1, 1.5 and 2
* you can apply [Loras](<https://github.com/william-murray1204/stable-diffusion-cpp-python?tab=readme-ov-file#with-lora>)

### text2image inference

Create a new Python file in your main directory: I called mine `sd15base_FULL.py`.

The basic Python code to generate an image is straightforward. If you have ever used llama-cpp-python, we have to follow the same basic steps:

1. load the model
2. call the inference with parameters to control the generation
3. display and/or save your results

Let’s import the libraries

```python """INFERENCE TEXT2IMAGE WITHv1-5-pruned-emaonly.safetensors"""from stable_diffusion_cpp import StableDiffusionimport randomimport stringimport sysimport datetimefrom PIL import Imagefrom PIL.PngImagePlugin import PngInfo ```

* The first one is the main Class `StableDiffusion. `We use it to load the model in one instance, and then we call the generation method for the text2image generation
* PIL is the pillow library for image manipulation: here we are also importing the `PngImagePlugin.PngInfo` that is really useful to add metadata to the PNG file before saving it. It is like having stored together the image also the generation details

```python def genRANstring(n): """ n = int number of char to randomize """ N = n res = ''.join(random.choices(string.ascii_uppercase + string.digits, k=N)) return resstart = datetime.datetime.now()print('1. Loading pipeline MODEL SD15 with LORAS')modelname = 'v1-5-pruned-emaonly.safetensors'stable_diffusion = StableDiffusion( model_path=f"model/{modelname}",#model_path="" model/v1-5-pruned-emaonly.q5_0.gguf wtype="q8_0", # Weight type (options: default, f32, f16, q4_0, q4_1, q5_0, q5_1, q8_0) # seed=1337, # Uncomment to set a specific seed)delta = datetime.datetime.now() - startprint(f'Completed in {delta}') ```

The first function is used only to generate random characters to assign as filenames for the generated image. Then we start to count the time (just to see how long it takes to load the model and quantize it on the fly).

Finally, we instantiate the model with the StableDiffusion safetnesors downloaded before. Pay attention to the model_path and the wtype: q8_0 is a good quantization method that will not lose too much accuracy (or you can leave it to _default_).

NOTE: don’t be worried about the code. All the files and examples are in my GitHub Repository, created for this article.

Now it is time to set the required parameters for the generation. Text2Image is a pipeline where we have a prompt, but also a negative prompt (optional): this means that we can specify what we don’t want to see in the results.

``` posprompt = "futuristic sci fi spaceship, star atlas, into earth orbit, 8k render, glowing blue light details"negprompt = 'ugly, deformed, out of frame, watermark, blurry, blurred, amateur, low resolution, warped, crooked, low detail'##### 20 STEPS ######SampleStps = 20SampleMethod = 6CfgScale = 7stylestrengt =0.4iWidth = 1024iHeight = 576ClipSkip = 2start = datetime.datetime.now()output = stable_diffusion.txt_to_img( prompt = posprompt, #"a lovely cat", # Prompt negative_prompt = negprompt, sample_method = SampleMethod, # 6 = 'DPMPP2Mv2', cfg_scale = CfgScale, #1 for lowe steps and shorter time, 8+ for higher steps sample_steps=SampleStps, style_strength = stylestrengt, width = iWidth, height = iHeight, clip_skip = ClipSkip, ) ```

> **Positive Prompt** : futuristic sci fi spaceship, star atlas, into earth orbit, 8k render, glowing blue light details
>
> **Negative Prompt** : ugly, deformed, out of frame, watermark, blurry, blurred, amateur, low resolution, warped, crooked, low detail

I decided to help you (and me) a lot by setting the hyperparameters in variables we can reuse. The most important one is the _sample_steps_ , which means how many times the model has to run the diffuser network: the higher the number, the better the results. The **sample_method** is crucial: when we ask for Stable Diffusion to create an image, it starts by generating a noisy picture. Then, it goes through a series of steps to remove the noise and create a clear image. It’s kind of like starting with a block of rough, white marble and chiseling away at it for days until you’re left with a beautiful statue, like Michelangelo’s David.

Press enter or click to view image in full size

data sculptor — Image by [Matteo Orlandi](<https://pixabay.com/users/matteophotopro2020-11599221/?utm_source=link-attribution&utm_medium=referral&utm_campaign=image&utm_content=5275153>) from [Pixabay](<https://pixabay.com//?utm_source=link-attribution&utm_medium=referral&utm_campaign=image&utm_content=5275153>)

There are a few different algorithms that work together to make this happen. One of them called the “sampler”, takes a rough guess at what the final image should look like and adds noise to it. Then, it compares this noisy image to the one it’s trying to clean up and subtracts the noise, kind of like chiseling away at the marble to reveal the shape underneath.

The sampler is in charge of figuring out how to remove the noise, while another algorithm called the “noise scheduler” decides how much noise to remove at each step. It’s a team effort that helps Stable Diffusion create amazing images.

According to the documentation, the possible choices are:

```python class SampleMethod(IntEnum): EULER_A = 0 EULER = 1 HEUN = 2 DPM2 = 3 DPMPP2S_A = 4 DPMPP2M = 5 DPMPP2Mv2 = 6 LCM = 7 N_SAMPLE_METHODS = 8 ```

You can read more about the samplers [here](<https://www.felixsanz.dev/articles/complete-guide-to-samplers-in-stable-diffusion>).

* **cfg_scale** is the Guidance Scale or Classifier-Free Guidance (CFG) scale. A higher value on the Guidance Scale indicates stricter adherence to the input text. However, it also limits creative liberty, potentially yielding less diverse images. Conversely, a lower Guidance Scale value grants the AI greater creative freedom to interpret the text prompt, fostering more diverse and unexpected outcomes, which may be desirable in certain contexts. A CFG value in the range of 7–9 is recommended.
* **style_strength** is the Strength Parameter. It is like a special knob that controls how much randomness is added to the image-generation process. Think of it like a slider that adjusts how much “noise” is introduced into the picture. When you turn the knob up (higher Strength value), you get more noise, which means the image will be more random and less like the original. This can be cool if you want a really unique and creative result, but it might not look much like what you started with. If you set it between 0.4 and 0.6, you’ll get a good balance between randomness and consistency.

### Wait.. and save your image

The generation will start and it will take quite a time, according to the number of steps, the image size, and the CFG. On my mini PC, 16GB of RAM, each step may take around 60 seconds… You do the math!

``` #PREPARE THE METADATAfname = f"image-{genRANstring(5)}.png"print("\033[92;1m")print(f'Completed in {delta}')print(f'3. Save image to file with metadata in {fname}...')metadata = PngInfo()metadata.add_text("ImageName", fname)metadata.add_text("PositivePrompt", posprompt)metadata.add_text("NegativePrompt", negprompt)metadata.add_text("SDMODEL", modelname)metadata.add_text("SampleMethod", f'{SampleMethod} - DPMPP2Mv2')metadata.add_text("ImageSize", f'WxH: {iWidth} x {iHeight}')metadata.add_text("CfgScale", str(CfgScale))metadata.add_text("SampleSteps", str(SampleStps))metadata.add_text("style_strength", str(stylestrengt))metadata.add_text("ClipSkip", str(ClipSkip))metadata.add_text("GenTime", str(delta))#SAVE IMAGE WITH METADATAoutput[0].save(fname,pnginfo=metadata )print('Image saved')targetImage = Image.open(fname)print(targetImage.text)targetImage.show() ```

We can store all the parameters we used for the generation, including the prompts in the metadata, and save them to the file.

Note that I used

``` output[0].save(fname,pnginfo=metadata ) ```

This is because stable-diffusion-cpp-python is returning a list of images (we can also ask to generate more than one from the same prompt…)

Then we display the image simply by calling

``` output[0].show() ```

In the code, you will see me using another variable because I wanted to be certain the image was correctly saved 😁.
