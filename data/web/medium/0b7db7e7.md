## Introduction

SAM 2 is a transformer-based model built for the _promptable_ video segmentation (PVS) and Segmentation annotation (SA) tasks. What can it do exactly?

1. You can select an object (one or more) in any frame using either a box or point (positive or negative) the model masks the valid object present (This is known as SA task) and tracks that object for all the **subsequent frames**(Combinedly this is known as PVS task)**.**
The masked object tracked for all the frames is known as _“masklet”_.

Figure 1: A ball and a person being tracked by SAM 2 model

Did you observe? You can select any number of objects in the initial frame (or any frame) using a point or box prompt the model then tracks (propagates forward) those objects for the rest of the video.

_Note that you can select an object in any frame. It doesn’t necessarily have to be the first frame. But the model only tracks the object for all the subsequent frames, not the frames present before the prompted frame._

2\. You can refine the objects that are selected in the initial frame (or any frame) in any of the subsequent frames using the point or box prompts.

Press enter or click to view image in full size

Figure 2: Refining masks in the subsequent frames

_Note that you only get one chance to select the object you want to track. Once the tracking is done, you can only refine the object you’ve initially selected and cannot select any other object to track (you need to start again to do that). Try the_[ _demo_](<https://sam2.metademolab.com/demo>) _here._

SAM 2 is an extension of its predecessor SAM which is a foundational model for image segmentation. Now you know what SAM 2 can do, let’s understand how it works via [FTI architecture](<https://medium.com/decodingml/building-ml-systems-the-right-way-using-the-fti-architecture-d9cc0cd29abf>).

## Feature Pipeline

What does one data sample contain that is used to train the SAM 2 model? It contains a video and a JSON file.

Let’s look into the JSON file and understand its contents.

**Video Metadata:**

* `video_id`: “ sav_000002” — A unique identifier for the video
* `video_duration`: 12.0833333333 — Length of the video in seconds
* `video_frame_count`: 290 — Total number of frames in the video
* `video_height`: 1080— Height of the video in pixels
* `video_width`: 1920 — Width of the video in pixels
* `video_resolution`: 2073600— Total number of pixels (height × width)
* `video_environment`: “Outdoor” — The setting of the video
* `video_split`: “train” — Indicates this video is part of the training set

Before discussing about the other properties it’s necessary for you to understand the meaning of a _Masklet_.

What is a **_Masklet_**?

_Masklet_ is a segmented object that is tracked **spatio-temporally** unlike a masked object (mask) which is a segmentation in space. For example, you can address the ball and the person that are segmented and tracked in the _Figure 1_ as _masklets_ whereas a segment in a still image is a mask.

**Masklet Metadata (each [4] indicates an array of 4 entries, one per masklet):**

Masklets Meta Data

* `masklet_id`: Unique identifiers for each masklet
* `masklet_size_rel`: Relative size of the mask
* `masklet_size_abs`: Absolute size in pixels
* `masklet_size_bucket`: Size category bucket
* `masklet_visibility_changes`: Number of times object appears/disappears _(determined using occlusion score)_
* `masklet_first_appeared_frame`: First frame where object appears
* `masklet_frame_count`: Number of frames containing this masklet
* `masklet_edited_frame_count`: Number of frames that required manual editing
* `masklet_type`: Type of masklet (e.g., manual or auto)
* `masklet_stability_score`: Quality metric for tracking stability [73]
* `masklet_num`: 4 — Total number of masklets in this video i.e., 4 objects are identified and tracked.

**Masklet Data**

Masklet Data

* `masklet `: Contains the masklets data for the respective `masklet_frame_count` masklets.

In the above example, we have masklet as an array of 73 items where each item is further an array of 4 items. In words, it indicates that 4 objects are segmented in the first frame (see `masklet_first_appeared_frame`) where each mask is defined by counts (contain run-length encoded (RLE) binary mask data) and size indicates the frame size and they are tracked for 73 frames.

So we have `4 masklets` (see `masklet_num`) information (binary mask data) across the first 73 frames in a video that has 290 frames.

Want to know how they have collected this data?

1. Phase 1: They convinced people to work for long hours and given them thousands of videos to annotate. Their task is to go through each frame one by one, track and annotate the objects using [SAM](<https://medium.com/@dinakarchennupati777/curious-to-know-how-metas-sam-works-6ea7b997f6a5>) and manually (using brushes, eraser etc…). Now that’s a gruelling task. In this phase, they collected 16K masklets across 1.4K videos (oof!). In other words, they tracked 16,000 objects frame by frame (god knows how many number of frames for each object).
2. Phase 2: The process is the same but they used SAM 2 Mask (trained using the 16k _masklets_ collected) to propagate the masks thus reducing the effort of the annotators. They collected 63.5 _masklets_ by doing this (poor annotators!).
3. Phase 3: Finally they used the ultimate SAM 2 model to do everything but required annotators for refining masks (put points in here and there in a frame that requires correction in their PoV). They collected 197k _masklets_(Amazing isn’t it?).

Now you know what’s in our feature store (a video and a JSON file). Let’s see how they are fed and the model is trained.

The feature store contains the video in its vector shape. Each video is divided into 8 frames (i.e., (8, 1024, 1024)) and are stored and fed to this model in batches.

SAM 2’s Image Encoder Logic Overview

**Explanation**

1. Image Encoder handles one frame or image at a time.
2. The image is passed through [_Heira Image Encoder_](<https://github.com/facebookresearch/hiera>) as you can observe from the above mermaid diagram. **Feature Pyramid Network** takes Stage 3 and Stage 4 features and fuses them.
3. **The Final Output shape is [256x64x64]** (we will call this _unconditioned frame embedding_) which is fed to **the memory attention** module/component (see Figure 2 (model architecture)).
_If you observe, the image encoder compresses image spatially and increases the number of channels._
_Why not pass the same dimensions as the original image? For computational efficiency without losing features of the image to an extent all the while._
4. The Stage 1 and Stage 2 features (high resolution) are fed to the mask encoder directly. _Why? (I’ll explain this later)_

**Point-Oriented Explanation**

1. Inputs:

* Unconditioned Frame/Image embedding (256, 64, 64) from the image encoder.
* Memory bank containing:
\- Previous frame memories (6, 64, 64, 64)
\- Prompted frame memories (2, 64, 64, 64)
\- Object pointer tokens (8, 4, 64)

2\. Memory Attention Block (repeated 4 times):

* Each block has 3 components: a. Self-attention on current frame features b. Cross-attention to memory bank contents _(making the unconditioned frame embedding learn from the memory bank contents)_ c. MLP layer
* Each component maintains the input shape (256, 64, 64)

3\. Memory Bank:

* Combines all memories into one tensor (16, 64, 64, 64)
* Includes 6 previous frames, 2 prompted frames, and 8 object pointers
* Used for cross-attention to condition current frame features

4\. Output:

* Memory-conditioned features (256, 64, 64)
_Did you observe?_ The output that comes out of the memory attention has the same shape as the input but the difference is that now **the output is enriched with the temporal context thanks to the memory bank**.
These features (this vector) go to the mask decoder for _final mask prediction_ (This is our training objective).

For now digest the terms presented under Memory Bank. We’ll discuss shortly about the contents of the Memory Bank briefly.

So what are the inputs that Mask Decoder takes in?
**Inputs:**

1. `Feature embedding` `(256, 64, 64)` produced by summing _Memory-conditioned features_ from memory attention **element-wise** with _dense embeddings_ from prompt encoder (Kindly read [SAM Blog](<https://medium.com/@dinakarchennupati777/curious-to-know-how-metas-sam-works-6ea7b997f6a5>) to learn about the prompt encoder).
_Remember that the Mask Decoder takes one frame (one image) at a time._
2. `Prompt Tokens
`If you recall, our model takes in three types of prompts: boxes, points, and masks similar to SAM.
`Mask Prompt`: Prompt Encoder produces dense embeddings matching the output shape of the _memory attention_. Eventually it is fused with output of the _memory attention_ element-wise (Read Point 1 again).
`Point and Box Prompts`: Prompt Encoder produces sparse embeddings in this case of shape (256, ) which we’re calling as prompt tokens (1xNx256) where N indicates number of points and boxes as prompts.
_Imagine prompt token as some kind of 1D vector which holds 256 values._
3. `Special/Output Tokens`: These tokens are added to the prompt tokens. So obviously their shape (256,) i.e., each token is a 1D vector.
`MaskTokens`: 3 tokens for ambiguous single prompts, 1 for multiple prompts
`IoU Token`:predicts IoU scores for each mask
`Occlusion Token`: predicts whether the target object is visible in current frame
_The reason these are called output tokens is during training the tokens are updated with their outputs. Its some kind of feedback loop through which the model learns from its mistakes along with backpropagation._
4. The Stage 1 `(64, 256, 256)` and Stage 2 `(128, 128, 128)` features from the image encoder. _Why have these (Remember I’ve told you I’ll explain later?)? For_** _Upsampling_** _purposes.
In simple words, when the frame embedding goes through the two-way transformer block, it is then up-sampled (reshaped as well) using the Stage 1 and Stage 2 features to produce the output mask and compare it against the ground truth mask (See the above picture for more clarification)._

* First upsampling + Stage 2 features: (128, 128, 128)
* Second upsampling + Stage 1 features: (64, 256, 256)
* Final upsampling to full resolution: (1, 1024, 1024). This is the predicted mask (imagine this as a white cutout shape on a black background)

In simple words, mask decoder takes _tokens (prompt + output tokens)_ and _feature embedding_ as inputs.

**Internal Process**(How are these inputs transformed?)

Press enter or click to view image in full size

Two-way Transformer Decoder:

* Observe from the above picture as to how the _tokens (prompt tokens + output tokens)_ and _feature embedding_ are getting transformed inside the two-way transformer decoder.
It’s like interacting with each other in either ways (image to token and token to image via cross-attention) and updating their values.
* Input Tokens Shape (8, 256) —> Output Tokens Shape (8, 256) but enriched with the information of the feature embedding ( thanks to cross-attention).
* Flattened Feature Embedding Shape (4096, 256) (because this is the general input format of a transformer) -> Output Feature Embedding (4096, 256). Same shape but enriched with the information from the tokens. Doesn’t cross-attention make intuitive sense now?

> Note: Always remember that transformers takes a standard input shape `[batch_size, sequence_length, embedding_dimension]` and produces an output of same shape. So whatever type of info you’re passing through it (audio, video, image) you have to flatten their shapes to match this shape.

**Outputs:**

* `Mask/s` : If the prompt is ambiguous three vectors each of shape (1x1024x1024) are produced else one vector. Visualize this as a white cutout on a black background (That’s how you represent a mask in general)
* `IoU score`: A floating point number of shape 1x1 (1x3 if 3 masks are produced).
* `Occlusion Score`: A floating point number of shape 1x1 (1x3 if 3 masks are produced) that produces the confidence score indicating whether the object being tracked present in the current frame or not.
* `Object Pointer` : A mask output token (after it comes out of the 2-way transformer) which is of shape (3x256) for 3 masks. The best one (one with max IoU score) gets stored in the Memory Bank.

Now you know the purpose of the Mask Decoder and why it is done the way it is done inside to a good extent.

### Memory Encoder and Memory Bank

Memory Encoder’s Input and Outputs

Press enter or click to view image in full size

Memory Encoder and Memory Bank’s Logic Overview

**Inputs**

1. `Unconditioned Image/Frame Embedding (256, 64, 64)`: The embedding we obtained from image encoder (see Figure 2 once again) before we fuse it with the contents of memory bank in the memory attention block.
2. `Predicted Mask (1, 1024, 1024)`: The best output mask (if 3 masks are produced) obtained from the mask decoder output.
3. `Original object pointer (1, 256)` : The best output mask token we obtained during the internal process of mask decoder.

**Outputs**

1. `Recent Memories and Prompted Memories`

* `Unconditioned Image/Frame Embedding` is summed element-wise with the **_down-sampled predicted mask_** producing a memory frame of shape `(64, 64, 64`). Why? _Memory features benefit from the strong representations produced by the image encoder_
If the `frame` is prompted (wait till you read the training process to understand this) it goes into prompted memories list if not it goes into recent fame memories (combined with _temporal positional encoding_) list.
_Why store prompted frames? To make the model refine the objects initially selected in the subsequent frames (see Figure 2)_
* `Unprompted Frame Memories` combined with the `Temporal Position Encoding` resulting in frames which we’re calling as `Recent Frames` _Why combine with temporal positional encoding? Understand temporal relationships between frames (Understand Short-Term object motion)
Why didn’t we add temporal positional encoding to prompted frames? Prompted frames can come from any time frame so there’s no point in making the model learn about the position of the objects in them._

2\. `Object pointers (4x64)`: The output masked token is referred as an object pointer which stores semantic information of the object being stored. This gets accumulated for each frame. _Why reshape it? To feed it to the memory attention and blend in with the recent frames and prompted frames using cross-attention._

Up to 6 recent frames, 2 prompted frames, and 8 (6 + 2) object pointers can be stored in FIFO order.

### Model Training with One Data Sample

Till now we learnt about the dots by learning about individual components and how they deal with one single frame. Let’s connect all the dots by understanding how the model gets trained assuming there is only one data sample.

**Pre-trained with SA-1B dataset:** Before we proceed, the model is first pre-trained with [SA-1B (Segment Anything 1 Billion) dataset](<https://ai.meta.com/datasets/segment-anything/>). The training process is similar to the SAM but one major difference is that each data sample (image/frame and prompt) goes through the model only 8 times instead of 11 times _(Read Training Pipeline in_[ _SAM blog_](<https://medium.com/@dinakarchennupati777/curious-to-know-how-metas-sam-works-6ea7b997f6a5>) _for more clarification)._

_Why do this? We want our model to do SA (Segment Anything) task along with PVS (Promptable Video Segmentation) task._

Now let’s turn to how the model is trained to do the PVS task. If you understand the above components well enough words are enough to understand the training process.

1. **Initial Setup
** \- Input: A batch of videos, each containing 8 frames of size (1024x1024).
\- Each frame has corresponding ground truth masks (ground truth masklet) for loss calculation
\- The model selects 2 frames for prompting:
If first frame of video is included in batch, it’s automatically selected
Second frame is randomly chosen
Otherwise, both frames are randomly selected

_Batch size is going to be 1 for simplicity purposes i.e., to understand without clutter._

**2\. Image Encoding Phase
** \- Image encoder processes all 8 frames at once parallelly.
\- Produces frame embeddings of shape (1, 8, 256, 64, 64). Let’s call these as `unconditioned frame embeddings`.
\- These embeddings are stored and used throughout training

**3\. Frame Processing Loop - > Each frame goes through the following components:
**Each frame goes through the following components one by one. Let’s assume we’re at 7th frame.

a) Memory Attention
\- Takes current unconditioned frame embedding
\- Accesses memory bank containing:
— Up to 4 recent frames (with temporal position encoding)
— Up to 2 prompted frames
— Up to 6 object pointers
\- Produces enriched feature embedding through cross-attention

Press enter or click to view image in full size

**4\. Mask Decoder Iterations Each frame goes through 7 iterations in the mask decoder:**

Each frame in turn goes through the mask decoder 7 times (11 times in the case of SAM).

First Iteration:
\- Takes initial prompt (point/box/mask) _(Read_[ _SAM blog_](<https://medium.com/@dinakarchennupati777/curious-to-know-how-metas-sam-works-6ea7b997f6a5>) _to know how initial point or box prompts are collected from the ground truth mask)_
\- Combines memory features (from memory attention) with dense embeddings (if mask prompt is selected as initial prompt else empty mask (a special vector) is added) element-wise. We we will call the end result as **feature embedding**.

\- Special tokens (Mask tokens, IoU token, and Occlusion token) are added to the prompt tokens (if point or box are the initial prompts). Let’s call the mix as **tokens**.
\- Feature Embedding and tokens are fed to mask decoder and following outputs are produced:
— Mask/s (3 Masks for ambiguous mask else 1 Mask)
— IoU score per mask
— Occlusion score

\- Total Loss is calculated and fed back through the backpropagation algorithm.

``` total loss = ( 20 * losses['mask'] + # Focal + Dice loss in practice losses['iou'] + losses['occlusion']) ```

Subsequent Iterations (2–7):
\- For prompted frames (we selected 2 frames as prompted frames, remember?): Updates point prompt by picking a point from the error region between mask predicted and ground truth mask.
\- Updates mask input (prompt encoder then produces dense embeddings) with **previous and best (** if 3 masks are produced) mask prediction
\- Updates special/output tokens with previous outputs i.e., they get the values of their previous outputs.
\- Each iteration helps model improve accuracy i.e., helps it to learn from its own mistakes.

Press enter or click to view image in full size

5\. Memory Update After 7 iterations:
\- Best mask prediction and object pointer sent to memory encoder
\- Memory encoder fuses prediction with unconditioned frame embedding
\- Updates memory bank based on frame type:
— Recent frames: Adds temporal encoding
— Prompted frames: Stores without temporal encoding
\- Maintains FIFO order when bank is full

Press enter or click to view image in full size

This iterative process continues for each frame in the video, maintaining memory context across the entire sequence.

The memory bank’s contents persist across batches for the same video, allowing the model to maintain context even when processing long videos in multiple batches (Read this point again).

That’s the brief and rough training process of the model for PVS task using one data sample. Go through the diagrams again and again for better understanding.

SAM 2 functions like SAM if there is an image (single frame video) as the memory bank will be empty in this case.

## Inference Pipeline

The aim of the inference pipeline is to make use of the model and produce the output in a user-friendly way. In this scenario the inference pipeline has to satisfy the following in the least.

1. When the user selects a object using point or box prompt on the initial frame we need to overlay the predicted mask onto the current frame (This is no different from SAM inference pipeline)
2. When he/she clicks on `Track object` ([Try SAM 2 demo](<https://sam2.metademolab.com/demo>)) we need to have an algorithm that masks and overlays the predictions on the subsequent frames efficiently keeping in mind that our model processes only 8 frames at a time.
3. If our model didn’t track the selected object properly in any of the subsequent frames and then when the user corrects it using prompt or box prompts, the model needs to process all the subsequent frames and do the tracking for them again (Subtask of Step 2)
4. When user wants to track multiple objects we need to run components parallelly handling each object separately as the model can mask and propagate one object at a time.

## Summary

In summary, SAM 2 is a foundational model that can perform promptable video segmentation (PVS task) with good accuracy and speed. Its an extension to the SAM with memory attention, memory encoder, and memory bank components being added to the existing three components (mask decoder, prompt encoder, and image encoder).

One can use model in the field of AR/VR, robotics, autonomous vehicles, video editing that requires temporal localization beyond image-level segmentation, etc…
