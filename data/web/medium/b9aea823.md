> **Wait a min.. only 16??!! 😲**

It might come as a surprise but you don’t need a lot of data to fine-tune a model at this scale & for such tasks. We are not going to train a model & teach it everything from scratch, rather, we are simply trying to teach it ‘how’ to respond to certain inputs.

Having said that, if you need to teach the LLM everything you have in your knowledge base, then a lot of data would definitely be required.

### Generating The Dataset.

This is the prompt I used to generate my training dataset —

```json I want a dataset that contains an instruction, context and a response. The instruction must request for summary generation from the given context. The context can be any raw text comprising of 8-10 sentences from the AI domain. And the response must follow the below format -{ "title": "suitable summary title", "summary_text" : "generated summary", "keywords" : [list of important keywords from the context], "further_research" : "a suggested research topic for the user for deeper understanding"}Give me 16 such training samples as a JSON, and make sure the 'response' JSON within the output is stringified for easy copy paste to code. The instructions must also be varied in nature. ```

Then I copied the response and saved it in a `summary_dataset.json` file. The next step is to create a dataset from this JSON & create train-validation splits before pushing to Hugging Face.

```python # libraries import jsonfrom datasets import Dataset, DatasetDictfrom huggingface_hub import loginimport random# load json filedef load_json_file(file_path): with open(file_path, 'r') as file: data = json.load(file) return data# process data for conversion to datasetdef process_data(data): instructions = [entry['instruction'] for entry in data] contexts = [entry['context'] for entry in data] responses = [entry['response'] for entry in data] return { 'instruction': instructions, 'context': contexts, 'response': responses }# split the datasetdef split_dataset(dataset, split_ratio=0.1): split_index = int(len(dataset) * (1 - split_ratio)) train_data = dataset.select(range(split_index)) val_data = dataset.select(range(split_index, len(dataset))) return DatasetDict({ 'train': train_data, 'validation': val_data })data = load_json_file("summary_dataset.json")# shuffle the dataset to remove any order induced bias# for example you might have first 5 samples of same topic and next 5 of same, it should be completely randomrandom.shuffle(data)# convert the dict into a Datasetprocessed_data = process_data(data)dataset = Dataset.from_dict(processed_data)# verify the datasetprint(dataset[1])# Split the training data into new training and validation datasetssplit_dataset = dataset.train_test_split(test_size=0.2) # 20% for validation# Create a DatasetDict with 'train' and 'validation' splitssplit_dataset = DatasetDict({ 'train': split_dataset['train'], 'validation': split_dataset['test']})# login to HF and push the datasettoken = "YOUR_HF_TOKEN"# Log in with your tokenlogin(token=token)# it will auto create the repo if it doesn't exist on HFsplit_dataset.push_to_hub("YOUR_USERNAME/DATASET_NAME", private=False) ```

### The LoRA configuration.

Even though the 8b model is small compared to other larger LLMs, 8b is still a big number, and training these many parameters is still difficult, given the lack of sufficient hardware.

Instead of training all 8b params, we will attach some additional params to the model and train them instead. This allows for faster & easier training, given limited resources.

``` model = FastLanguageModel.get_peft_model( model, r = 32, # Choose any number > 0 ! Suggested 8, 16, 32, 64, 128 target_modules = ["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj",], lora_alpha = 16, lora_dropout = 0, # Supports any, but = 0 is optimized bias = "none", # Supports any, but = "none" is optimized use_gradient_checkpointing = "unsloth", # True or "unsloth" for very long context random_state = 3407, use_rslora = True, # We support rank stabilized LoRA loftq_config = None, # And LoftQ) ```

Without going in-depth, here are some things to note about important LoRA parameters —

**Rank:** The higher the rank → the more the model learns → the longer it takes to train.

**Target Modules:** The layers of the original transformer architecture to target. More “relevant” layers targeted → Better learning possibility _(Keep in mind, Certain layers will work better for certain tasks, but generally, you can pick the commonly targeted ones)_

**Rank Stabilized LoRA** : Rank Stabilized LoRA has some advantages such as

1. It helps the model generalize better in scenarios where only a **small amount of task-specific training data** is available.
2. Helps in **preventing model degradation** while still allowing flexibility.

### The Trainer & The Training.

I have added a custom callback, so that at every step while training, we get access to the loss and other metrics, for later visualizations.

```python from transformers import TrainerCallbackclass CustomCallback(TrainerCallback): def __init__(self): self.train_losses = [] self.eval_losses = [] def on_log(self, args, state, control, logs=None, **kwargs): if logs is not None: if 'loss' in logs: self.train_losses.append(logs['loss']) if 'eval_loss' in logs: self.eval_losses.append(logs['eval_loss'])callback = CustomCallback() ```

Below we have set up the training arguments. The numbers are optimal based on our use case and the GPU limitations. Once you start training, you will see the training and validation loss in a tabular format.

```python from transformers import TrainingArguments, Trainerfrom unsloth import is_bfloat16_supportedtraining_args = TrainingArguments( per_device_train_batch_size=2, # how many samples to train at a time per step per device gradient_accumulation_steps=4, # total steps will be divided by this warmup_steps=2, # steps to go from 0 to specified lr num_train_epochs=4, # no of samples per step * this would be total steps learning_rate=2e-4, fp16=not is_bfloat16_supported(), bf16=is_bfloat16_supported(), logging_steps=1, optim="adamw_8bit", weight_decay=0.01, lr_scheduler_type="linear", seed=3407, output_dir="outputs", evaluation_strategy="steps", # Evaluate during training eval_steps=1, # Evaluate every 1 step save_strategy="steps", save_steps=10, # save model state every 10 steps load_best_model_at_end=True, # Load the best model when finished training)trainer = SFTTrainer( model=model, tokenizer=tokenizer, train_dataset=train_dataset, # pass in the training split eval_dataset=eval_dataset, # pass in the eval split args=training_args, dataset_text_field = "text", callbacks=[callback] # our custom callback)# check GPU memory before traininggpu_stats = torch.cuda.get_device_properties(0)start_gpu_memory = round(torch.cuda.max_memory_reserved() / 1024 / 1024 / 1024, 3)max_memory = round(gpu_stats.total_memory / 1024 / 1024 / 1024, 3)print(f"GPU = {gpu_stats.name}. > 💡 Even with just 12 training samples & 2 mins of training, we already got a decent loss on the validation set. Keep in mind, that the validation dataset only contained 4 samples.

**If we train for too long or train too many parameters, we risk overfitting** the model to our data. In that scenario, the LLM might start giving our format/data even when it was not appropriate or asked for.

I faced this issue when I was fine-tuning the model to follow my format for generating some content, but it started outputting every answer in that format only.

Playing around with the LoRA config & the trainer params, we can adjust how much our model learns. But keep in mind that in certain cases, where there is **only one possible answer for a question** & you want the model to always give that exact answer, you might **need to overfit the model** slightly by providing more instances of that question.

Here is what worked for me in 2 different scenarios —

**Scenario 1:** The model must mainly learn the ‘format’ for a given instruction & must not use that format for other general QAs.

1. Lower Rank in LoRA
2. Fewer steps/epochs in training

**Scenario 2:** The model must learn facts & must answer them correctly each time.

1. Higher Rank in LoRA
2. More steps/epochs in training
