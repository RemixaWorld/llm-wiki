## Introduction

Over the past few years, large language models (LLMs) that are built upon the transformer architecture and pre-trained on extensive datasets have learned language structures and nuances to perform diverse and complex tasks and enabled a significant transformation in AI.

However, one of the main challenges of LLMs is how to perform well on domain-specific knowledge, such as maintenance and engineering. This is due to the fact that the general-purpose datasets LLMs are trained on do not usually cover specialized technical data, particularly in the field of manufacturing and maintenance. To combat it, methods such as fine-tuning and RAG have been extensively used for such scenarios to learn domain-related meanings and context and improve its accuracy and relevance. But it still often cannot fully comprehend the technical terminology, especially when same terminology is used in different and complex maintenance process. For example, _voltage transducer_ is associated with both _pantograph_ and _inductor_ , and it must be correctly linked with rail vehicle’s hierarchical structure to avoid confusion for reliable analysis and maintenance decisions.

To overcome this challenge, ontology of railway vehicle is adopted to provide definitions and hierarchies specific to railway maintenance terminology and ensure conceptual consistency across examples [1]. This article aims to showcase how to fine-tune and evaluate LLMs using ontology structure and MLflow to improve maintenance decision-making in railways.

## Adoption of Railway Structure Ontology

By definition, an ontology is a formal specification of concepts, relationships, and rules within a particular domain. It often serves as the **schema** or ‘**rule book** ’ for knowledge graphs, which organize the information about domain-specific contexts.

Figure 2: An example of rail vehicle ontology displayed in a hierarchical structure. Image by Author

A railway vehicle’s ontology, illustrated in Fig. 2, can be represented as a tree structure with the top-level concept defined as `Vehicle`. This hierarchical representation forms large parts of the depot and railway-specific maintenance activities. For example, a `Vehicle` has different types of coach, and a coach contains a set of `Components` components, which are usually formed by a number of `Parts` or `Sub-parts`. Maintenance tasks are then applied on the corresponding `Parts` or `Sub-parts`, which covers the set of `Machinery` required for inspection, maintenance, and other related services.

Constructing this hierarchical structure is important for enhancing LLMs’ understanding of railway-specific problems due to two main reasons:

* It overcomes the component **ambiguity** issue by providing a lineage to trace the component accurately and allowing LLMs to have the capability to distinguish and correctly identify them.
* It addresses the **inconsistency** and **variation** often found in maintenance logs, which are typically recorded by different technicians who have their own preferences in writing logs. For example, mix use of abbreviations and full expansion terms or omission of the full hierarchical chain of a component is quite common in practice, leading to confusion and inaccurate interpretations by LLMs.

## MLflow Overview

MLflow is the go-to open-source platform for managing ML and LLM workflows. It includes key components such as **tracking** and **model registry** to record ML training sessions (or runs) and centrally manage the models and their lifecycles.

The benefits of MLflow include:

* Track progress during fine tuning and log relevant model artifacts, hyperparameters, and metrics
* Enhance LLM observability with tracing
* Package and deploy models with ease

## Fine-Tuning LLMs with MLflow

Training LLMs from scratch is expansive, but fine-tuning can also be relatively costly even with a small dataset due to the backpropagation step that needs to compute gradients for billions of parameters.

To fine-tune large foundational models with limited GPU resources, [**QLoRA**](<https://github.com/artidoro/qlora>)**(Quantization + Low Rank Adaption)** is introduced to reduce the number of trainable parameters by learning pairs of rank-decomposition matrices and also apply 4-bit quantization to the frozen pre-trained model to further reduce the memory footprint [2]. [**PEFT**](<https://huggingface.co/docs/peft/en/index>)**(Parameter-Efficient Fine-Tuning)** is a library that enables easy integration of different optimization methods with pre-trained models. With PEFT, one can apply QLoRA to the pre-trained model.

Before diving into the coding implementation, let’s look at how the data flows from the raw maintenance logs through the data preparation and fine-tuning pipelines. This will act as a guidance for adding various components to the fine-tuning script.

Now, I load the base model using the Transformers’ `from_pretrained()` API. The key difference is to provide it with a `quantization_config` parameter. For more technical details, please check out this [link](<https://arxiv.org/pdf/2305.14314>). Here I focus on the implementation of the technique by setting the following quantization configurations in `BitsAndBytesConfig`:

* Use 4-bit Normal Float for storing the base model weights: `bnb_4bit_quant_type="nf4"`
* Activate Double Quantization: `bnb_4bit_use_double_quant=True`
* Load the model with 4-bit quantization: `load_in_4bit=True`
* De-quantize the weights to 16-bit float before the forward/backward pass: `bnb_4bit_compute_dtype=torch.bfloat16`

Having defined the quantization configuration, it now is ready to combine with LoRA for the pretrained Transformer model. First a `LoraConfig` is created for various configurations for LoRA. One main difference with `quantization_config`, these hyperparameters need to be optimized to obtain the best model performance for your specific task. This can be achieved by defining a PEFT model and facilitating the training process with the help of MLflow.

This training process would take hours, depending on your computer specs. But if you only want to get familiar with the fine-tuning process using PEFT and MLflow and a high model performance is not the ultimate goal, then you can specify a much smaller number of steps.

One important step in the script above is to save the trained PEFT model and selected parameters and metrics to MLflow. There are a few critical points to note when logging a PEFT model to MLflow [3]:

* **MLflow logs the Transformer model as a Pipeline.** In the code above, I pass the model and tokenizer as a dictionary, then MLflow automatically deduces the correct pipeline type and saves it.
* **MLflow does not save the base model weight for the PEFT model.** MLflow only saves the small number of trained parameters, i.e., PEFT adapter.
* **Save a tokenizer without padding.** Padding is only needed to standardize the sequence length in a batch during fine-tuning, and is not required for inference.

## Evaluation of LLMs using MLflow

Lastly, it is time to construct a `ModelEvaluator` to evaluate the quality of the generated outputs from the fine-tuned model. Since there are two distinct parts in the response, i.e., the _recommended maintenance action_ and related _component chain_ , it is imperative to use separate evaluation metrics.

For the component chain extracted from the problem description, the **Intersection over Union** (**IoU**) score is selected, which quantifies the degree of word matching between the ground truth and model response. The IoU score is ideal for evaluating structured outputs with a limited number of vocabularies. The IoU score ranges from 0 to 1, where 0 indicates complete irrelevancy of the extracted information and 1 denotes perfect extraction. In addition, **component accuracy** and **component completeness** are also computed to measure how many of the predicted components are actually correct and how many of the actual components are successfully predicted, respectively.

For the recommended action, the semantics of the output must be considered, not just replying on word matching only. The potential large variation in phrasing the same actions makes it difficult to pre-determine a list of candidates. Therefore, **BERTScore** is used to leverage the contextual embeddings that map vocabularies into a high-dimensional space where semantically similar words are close to each other and words with little semantic similarity are separated. Moreover, **BLEU** (**Bilingual Evaluation Understudy**), examining the frequency of _n-grams_ , is used to check how well the generated responses match with the vocabularies used in the ground truth. BERTScore and BLEU range from -1 to 1 and 0 to 1, respectively, with higher values indicating higher similarity between the predicted and the reference texts [1].

```python @dataclassclass EvaluationMetrics: bertscore: float bleu_score: float iou_score: float component_accuracy: float component_completeness: floatclass ModelEvaluator: def __init__( self, base_model_name: str, peft_model_path: str, device: str = "cuda", max_length: int = 2048 ): self.device = device self.max_length = max_length # Load tokenizer self.tokenizer = AutoTokenizer.from_pretrained(base_model_name) self.tokenizer.pad_token = self.tokenizer.eos_token # Load base model base_model = AutoModelForCausalLM.from_pretrained( base_model_name, torch_dtype=torch.float16, device_map="auto" ) # Load fine-tuned model self.model = PeftModel.from_pretrained(base_model, peft_model_path) self.model.eval() # Initialize BERTScore self.bertscore = evaluate.load("bertscore") def format_prompt(self, problem: str) -> str: """Format input following Llama 2 chat format""" system_prompt = """You are an expert railway maintenance system. Your role is to analyze maintenance problems, recommend appropriate actions, and identify the component chain involved in the issue. Provide clear, precise recommendations based on the problem description.""" prompt_template = f"""[INST] <<SYS>>{system_prompt}<</SYS>> Please analyze the following railway maintenance issue and provide recommendations: Problem Description: {problem} [/INST]""" return prompt_template def generate_response(self, prompt: str) -> str: """Generate model response for a given prompt""" inputs = self.tokenizer(prompt, return_tensors="pt", truncation=True).to(self.device) with torch.no_grad(): outputs = self.model.generate( **inputs, max_length=self.max_length, num_return_sequences=1, temperature=0.1, do_sample=True, pad_token_id=self.tokenizer.pad_token_id ) response = self.tokenizer.decode(outputs[0], skip_special_tokens=True) return response[len(prompt):].strip() def parse_component_chain(self, chain: str) -> Set[str]: """Parse component chain into a set of components""" # Clean and normalize the component chain chain = chain.replace("Component Chain Analysis:", "").strip() components = set() # Split by different possible delimiters for part in chain.replace('>', '/').replace(',', '/').split('/'): component = part.strip().lower() if component: components.add(component) return components def calculate_iou(self, pred_components: Set[str], true_components: Set[str]) -> float: """Calculate IoU score for component sets""" if not pred_components and not true_components: return 1.0 if not pred_components or not true_components: return 0.0 intersection = len(pred_components.intersection(true_components)) union = len(pred_components.union(true_components)) return intersection / union if union > 0 else 0.0 def extract_action_and_chain(self, text: str) -> Dict[str, str]: """Extract action and component chain from response""" action = "" component_chain = "" # Extract action if "Recommended Action:" in text: action_parts = text.split("Recommended Action:")[1].split("Component Chain") action = action_parts[0].strip() # Extract component chain if "Component Chain" in text: chain_parts = text.split("Component Chain")[1].split("

") component_chain = chain_parts[0].strip() return { "action": action, "component_chain": component_chain } def calculate_bleu_score(self, predicted: str, reference: str) -> float: """Calculate BLEU score for recommended actions""" # Tokenize the strings into words predicted_tokens = nltk.word_tokenize(predicted.lower()) reference_tokens = nltk.word_tokenize(reference.lower()) # Use smoothing function to handle cases where there are no n-gram overlaps smoothing = SmoothingFunction().method1 # Calculate BLEU score with weights for 1-4 grams try: return sentence_bleu( [reference_tokens], predicted_tokens, weights=(0.25, 0.25, 0.25, 0.25), smoothing_function=smoothing ) except Exception as e: print(f"Error calculating BLEU score: {e}") return 0.0 def evaluate_single_response( self, predicted: Dict[str, str], actual: Dict[str, str] ) -> EvaluationMetrics: """Evaluate a single prediction against ground truth""" # Calculate BERTScore for action bertscore_results = self.bertscore.compute( predictions=[predicted['action']], references=[actual['action']], lang="en" ) bertscore = bertscore_results['f1'][0] # Calculate BLEU score for action bleu_score = self.calculate_bleu_score( predicted['action'], actual['action'] ) # Calculate IoU for component chain pred_components = self.parse_component_chain(predicted['component_chain']) true_components = self.parse_component_chain(actual['component_chain']) iou_score = self.calculate_iou(pred_components, true_components) # Calculate additional component metrics if true_components: component_accuracy = len(pred_components.intersection(true_components)) / len(pred_components) if pred_components else 0.0 component_completeness = len(pred_components.intersection(true_components)) / len(true_components) else: component_accuracy = component_completeness = 0.0 return EvaluationMetrics( bertscore=bertscore, bleu_score=bleu_score, iou_score=iou_score, component_accuracy=component_accuracy, component_completeness=component_completeness ) def evaluate_dataset( self, df: pd.DataFrame, num_samples: int = None, output_file: str = "evaluation_results.json" ) -> Dict[str, float]: """Evaluate model on the entire dataset""" if num_samples: df = df.sample(n=min(num_samples, len(df))) all_metrics = [] detailed_results = [] for _, row in tqdm(df.iterrows(), total=len(df)): # Save detailed results with open(output_file, 'w') as f: json.dump(detailed_results, f, indent=2) return avg_metrics ```
