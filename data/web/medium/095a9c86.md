## Background

In this section, we present several techniques employed during the pre-training of DeepSeek-V3, including document packing, **Fill-in-the-Middle (FIM),** and **long context extension using YaRN.**

### Document Packing

To understand the necessity of document packing, let’s first revisit how Transformer models construct their input token sequences.

Transformer models by default require a fixed-size token sequence as input; however, the input texts within the same batch often vary in length. To address this, the input texts are typically pre-processed through the following steps:

* **Tokenize** each raw text input into a corresponding sequence of tokens.
* **Truncate or pad** each sequence to a predefined fixed length (max_seq_len): if the raw sequence exceeds the limit, truncate it; otherwise, pad it with a special [PAD] token.
* **Generate mask IDs** to enable the model to ignore padding tokens during training.

To make this clearer, the example below demonstrates how the GPT-2 [10] tokenizer processes two sentences:

```python from transformers import AutoTokenizer# Load a tokenizer (GPT-2 example)tokenizer = AutoTokenizer.from_pretrained("gpt2", padding_side="right")# Manually set a padding token (GPT-2 does not have one by default)tokenizer.pad_token = tokenizer.eos_token# Example input sequencesprompt = ["The cat sat on a mat", "I love machine learning but do not have time to read papers" ]# Tokenize and pad to max length of 10tokenized = tokenizer(prompt, return_tensors="pt", padding="max_length", truncation=True, max_length=10)# Print tokenized inputprint("Input IDs:
", tokenized["input_ids"])print("Attention Mask:
", tokenized["attention_mask"]) ```

The truncation and padding approach described above allows the model to handle inputs of varying lengths, but it also introduces issues when sequence lengths differ significantly (a situation quite common in LLM training):

* For overly long sequences, valuable information may be lost due to truncation;
* For short sequences, excessive padding results in a waste of computational resources.

For this reason, LLM training commonly applies document packing techniques to manage input sequences.

More specifically, given several documents of varying lengths, we first divide them into smaller chunks, as illustrated in the figure below where each document is represented by a different color:

Next, we concatenate chunks from different documents to prevent truncating long documents and minimize padding for shorter ones:

In the above example:

* First input contains tokens from document 1 only.
* Second input is a concatenation of tokens from document 1 and 2.
* Third input is a concatenation of tokens from document 2 and 3.
* Fourth input is a concatenation of tokens from document 3, 4, and 5.

While this method reduces the need for padding and truncation to some extent, it simply concatenates chunks from different documents based on their order in the data, and therefore cannot control how the final input sequences are formed.

To address this, [3] proposes a Best-fit Packing technique that fully eliminates unnecessary truncations through two steps, as illustrated in the figure below:

* Step 1: split each document into smaller chunks.
* Step 2: group chunks into training sequences intelligently to minimize the number of sequences, without further splitting any chunks.

### Fill-in-the-Middle (FIM)

In traditional autoregressive generation, models are trained in a strictly left-to-right manner, meaning they can only predict the next token based on preceding tokens. However, in many real-world applications, a model may need to generate missing content within the middle of a given context.

This capability is especially useful in code generation, where we often prompt the LLM with input/output examples and partial code snippets, asking it to fill in the missing logic in the middle, as illustrated in the following example:

```python def calculate_area(radius): // calculate circle area given radius return arearadius = 5print(calculate_area(radius)) ```

To meet this need, [4] introduces a simple yet effective method called Fill-in-the-Middle, which randomly splits documents into three parts — prefix, middle, and suffix — and then moves the middle piece to the end:

### Long Context Extension with YaRN

Modern LLMs are often expected to handle extremely long prompts, such as entire code repositories, but pre-training with long context windows like 128K tokens is impractical.

Instead, a common strategy adopted by many LLMs is to first pre-train the model on smaller context windows and then progressively extend to much longer context windows over multiple stages, significantly reducing the overall training effort.

For example, in DeepSeek-V3, the model is initially pre-trained with a 4K context window and then extended to 128K through two stages:

* Extending from 4K to 32K with 1000 steps.
* Extending from 32K to 128K with another 1000 steps.

It is important to note that this cannot be accomplished by merely setting a larger context window; instead, it requires modifying the positional encoding using a technique called Yet another RoPE extensioN (YaRN), which builds upon Rotary Position Encoding (RoPE).

_For a more detailed introduction of RoPE, please refer to our previous article_[ _DeepSeek-V3 Explained 1: Multi-head Latent Attention._](</deepseek-v3-explained-part-1-understanding-multi-head-latent-attention-bac648681926>)

RoPE is a relative position encoding method whose core idea is to modify the Query and Key vectors using complex rotation embeddings, making their inner product dependent on their relative positions:

However, with a fixed θ, a model pre-trained on 1K tokens may struggle when tested with positions far beyond the pre-training context window, such as 5K or 10K, because cosine and sine functions are periodic, causing the inner product between (pos_i, pos_j) to resemble that of (pos_i, pos_k).

This also results in decayed attention scores for position pairs where the cosine value approaches zero, making it difficult for the model to maintain long-range coherence.

This is illustrated in the figure below, where a model pre-trained with a 32K context window exhibits a dramatic increase in Perplexity when tested beyond that window.

Figure 7. Perplexity vs. context window. Image edited from [6].

So how does YaRN address that challenge?

Since extrapolation does not perform well, YaRN adopts an alternative approach by interpolating the frequency.

Assume we have a model trained on 4 tokens and aim to extend it to 8 tokens, with a base frequency θ of 0.5.

With vanilla RoPE, we directly rotate the Query and Key using cos(θ × pos) and sin(θ × pos).

However with YaRN:

* We first compute a scale factor by dividing the extended context length by the original length, which in this case would be 2.
* Then, we obtain a new frequency given by θ’ = θ / 2 = 0.25.
* We then rotate the Query and Key using this new frequency, specifically with cos(θ’ × pos) and sin(θ’ × pos).

The figure below illustrates the cosine and sine values under RoPE and YaRN, respectively.

According to this figure:

* In RoPE, the cosine and sine values oscillate rapidly as the position index increases, leading to difficulties in scaling to longer contexts.
* In YaRN, the transition is much smoother, as the original cosine and sine functions are interpolated to match the extended context length (highlighted in blue) with a scaled frequency, enabling the model to handle longer sequences more effectively.

### Pre-training

In this section, we discuss how DeepSeek-V3-Base is trained, with a particular focus on data construction and key strategies employed during pre-training.

### Data Construction

Data scale and quality are critical for LLM training. In DeepSeek-V3, the pre-training corpus is constructed by continuously refining the data using insights obtained from previous models:

* **DeepSeek 67B [8]** :
The training corpus is curated using a deduplication-filtering-remixing strategy, where aggressive deduplication is first applied to the Common Crawl corpus, followed by filtering with robust document quality criteria, and finally a data remixing phase to address data imbalances.
* **DeepSeek-V2 [9]** :
The training corpus is expanded by (1) adding more Chinese and high-quality data from various sources, and (2) recovering a large amount of data previously deleted in [8] by optimizing the data cleaning process. Data quality is further enhanced by improving the quality-based filtering algorithm.
* **DeepSeek-V3 [2]** :
The pre-training corpus is further enriched with more mathematical, programming, and multilingual samples beyond English and Chinese.

The collected pre-training corpus is then pre-processed using the Fill-in-the-Middle (FIM) strategy based on the Prefix-Suffix-Middle (PSM) framework introduced earlier, combined with the document-packing technique.

### Training

The original paper [2] provides a detailed description of the pre-training parameters; here, we focus on highlighting a few key points:

* **Long context extension** : pre-training starts with a 4K context window on 14.8T tokens, then extends to 32K over 1000 steps, and finally to 128K with another 1000 steps.
* **Multi-token Prediction** : DeepSeek-V3 applies an optimized version of multi-token prediction, enabling the model to decode multiple tokens simultaneously to speed up training
* **FP8 training** : mixed-precision arithmetic is used by employing lower-precision formats (such as 8-bit floating point numbers) for certain calculations, reducing memory usage and improving computation speed without significantly affecting accuracy.
* **Learning rate scheduling** : the learning rate is linearly increased from 0 to 2.2e–4 during the first 2K steps, kept constant while training on 10T tokens, then decayed to 2.2e-5 over 4.3T tokens following a cosine schedule. During the final 500B tokens, it remains constant for the first 333B tokens and then decays to 7.3e-6 over the remaining 167B tokens.
* **Batch size scheduling** : batch size increases from 3072 to 15360 during the first 469B tokens of training and is kept constant thereafter.

### Summary

This article explores key innovations in DeepSeek-V3’s pre-training strategies to enhance efficiency, scalability and performance. The resulting **DeepSeek-V3-Base** model serves as the foundation for more advanced reasoning models like **DeepSeek-R1-Zero** and **DeepSeek-R1** , which, in turn, help improve DeepSeek-V3 by knowledge distillation.

Beyond previously discussed architectural innovations — **Multi-head Latent Attention** , **DeepSeekMoE** , **auxiliary-loss-free load balancing** and **Multi-token Prediction** — this article introduce several techniques including **document packing** , **Fill-in-the-Middle (FIM)** and **long context extension with YaRN**.
